# AI 辅助大型项目开发规范及工作流

本仓库用于共同研究一套从项目启动、开发、交付到长期维护都可执行的 AI 辅助开发方法。

**适用范围约束（2026-09-02 确立）**：本规范必须在 codex、Claude Code、opencode、DeepSeek harness、VSCode Copilot 等既有 AI 辅助编程工具上通用。因此规范正文只写**语义不变量**，不写任何具体工具的入口文件名、目录结构、配置格式或脚本。判定与检验机制见[跨工具通用性](docs/09-跨工具通用性.md)（D-020，已接受）：**一条要求说不出两种机制类型不同的落地方式，就不得进入正文。** 载体上的实现只作为[附录·载体实例](docs/附录-载体实例/README.md)与[模板](templates/README.md)存在，效力为零。

当前版本：`v0.5-theory-draft`。当前只构建理论、候选协议与 Markdown 模板，不编写业务代码。除元治理规则 D-014 外，尚无候选规则被安装成真实 Gate。

> 决策效力：生效规则为 **D-014 规范效力元治理**、**D-020 跨工具通用性** 与 **D-043 四平面架构**（均已接受，2026-09-02）。其余 D-001～D-013、D-015～D-019、D-021～D-028 仍为`提议`，不产生执行、阻断或授权效力。当前哪些规则可阻断或授权，只查[生效登记表](docs/决策日志.md#effective-register)——文档正文中的任何状态值副本均以该表为准。

## 核心判断

大型项目后期变慢，通常不是代码生成速度不足，而是交付链逐渐失真：事实来源混乱、上下文取并集、状态无法恢复、规则只存在于自然语言、完成声明没有绑定版本和环境的证据。

架构由 52 个独立来源归纳而来（见[架构确定](docs/架构确定.md)）：**四个平面加一条交付线**。知识平面是资产、执行平面是工具、控制平面是纪律、责任平面是人；换 AI 编程工具换的只是执行平面。按部件的失败诊断表见[00 总览](docs/00-总览.md)。
