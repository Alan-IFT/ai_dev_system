### WX-12 Agent 治理：用 Hook 堵住 LLM 的偷懒、越权与失忆（类型：P1；场景：企业 Agent 平台 · 数仓 Agent 引擎 DECO）
- **部件清单**：
  - Hook/Callback 切面（beforeTool / afterTool / onRunEvent，14 个横切 Hook）→ 拦截与守卫
  - Offload Hook（长返回落盘→引用句柄）/ Onload Hook（写回前从文件加载全文覆盖入参）/ ToolResponseTruncator / Formatter → 上下文装配（外部化/压缩）
  - 沙箱文件区（只读快照 `xxx.remote.etl`、工作副本 `xxx.etl`、`copy_file`、`str_replace`；禁 `create_file` 重写）→ 工具与执行环境
  - DangerousToolGuard + 危险工具清单（application.yaml 配置驱动，按租户/环境）→ 权限与边界
  - INTERACTION_BOX 确认框（结构化表单：发布方式/审批人/回刷日期 + 变更预览）→ 人（审批）
  - `session.state`（授权标记 `confirm_pack`、`risk_analysis`、`python_images` 累积）→ 状态工件（会话级）
  - Attachment 注入（下一轮 prompt 前以 system-reminder 注入）→ 上下文装配
  - RiskAnalysisHook → `riskLevelAnalyze(tableId)` 下游影响分析 → 验证与测试
  - PythonImageHook（执行前后文件快照对比）/ ToolCallLog / ConversationPersistence / DocumentSave / 下游防御性日志（探测 Hook 失效）→ 证据与追踪
  - EnvVarCapture、SqlExecuteHook、CopyFileHook、US 平台工具（packCommit / upsertTable / 任务保存）→ 工具与执行环境
  - 工具协议引用参数 `scriptFilePath`（框架契约，转发前剥离）→ 工具与执行环境
  - prompt（"定意图"）→ 意图与验收；Skill（"定规矩"）→ Skill/方法库；Agent 主循环 → 执行者；LLM → 模型
  - 图 003 五步流程（提需求→设计模型→拆任务 DDL/ETL→调工具读写 US→发布+回刷）→ 任务拆分与调度
- **部件关系**：US 平台 →(长 SQL 数据)→ Offload Hook →(写只读快照)→ 沙箱；Offload →(引用句柄)→ LLM；LLM →(copy_file/str_replace 控制)→ 沙箱工作副本；LLM →(带 scriptFilePath 的调用)→ Onload Hook →(读工作副本全文、白名单校验)→ US 平台（写侧不通过即抛异常阻断，读侧失败降级透传）；LLM →(调 packCommit)→ Guard →(查 key)→ session.state；Guard →(CUSTOM 事件)→ 前端弹框 → 用户 →(REST 写授权标记)→ session.state → Guard 放行；afterTool Hook →(触发)→ riskLevelAnalyze →(结果)→ session.state →(Attachment)→ 下一轮 LLM；beforeTool/afterTool →(文件快照对比)→ session.state → Attachment；Hook →(剥离引用字段)→ 下游工具，下游日志若见该字段即报 Hook 失效。
- **不可省略**："能用确定性兜底的，别交给模型"（结语）；"没有 key 就物理走不通，不靠 LLM 自觉"（图 009 底栏）；"prompt 只能引导不能兜底"（C1）；写侧必须阻断、"失败语义非对称"（图 004 底栏）；"确认动作不能由模型触发"（C8）。
- **分层 / 演进**：三类失败↔三类治理（偷懒→Offload/Onload；越权→HITL Guard；失忆→State→Attachment）；Hook 全景五组（A 安全护栏 / B 预处理 / C 长文本护栏 / D 上下文联动 / E 可观测&持久化）；"prompt 定意图，Skill 定规矩，Hook 定边界"；被动模式（LLM 自查 state）→ 主动模式（Hook push）标"进化方向"。
- **失败归因**：偷懒（截断/占位/复印）→ 长产物直接进出模型，缺上下文外部化；越权（未确认发布）→ 缺动作前守卫与人侧授权；失忆（改表不查风险、产图不汇报）→ 缺副作用观察与主动注入；总根因"prompt 是软约束"→ 依赖模型自觉。
- **证据形态**：架构图 004、时序图 009/011/012、流程图 008、配置片段；效果数字（token -90%）为自述脱敏汇总，无对照无消融。
