### WX-03 一文搞懂！Loop Engineering的进化史和本质（类型：S1；场景：编码 Agent 无人值守 Loop）
- **部件清单**：Automations（定时/事件启动）→ ★触发与入口；Worktrees（每任务隔离副本）→ 权限与边界（隔离）；Skills（编码规范/架构约定/工具用法/坑点，含 AGENTS.md/CLAUDE.md/SKILL.md）→ Skill/方法库 + 项目知识；Connectors（触达外部系统）→ ★外部系统交接；Sub-agents（独立验证者，"另一个 Agent 甚至另一个模型"）→ 验证与测试 + 执行者；Memory/State（图 004 命名 External State：尝试了什么、卡在哪）→ 状态工件；控制器（编排逻辑，比对目标差距）→ 任务拆分与调度；执行器（工具调用）→ 执行者 + 工具与执行环境；传感器（验证，返回用例/断言/diff 定位）→ 验证与测试；被控对象 LLM、/goal 独立小模型判停止 → 模型；迭代上限退出 → 拦截与守卫（弱）；人写传感器/决定是否建 Loop → 人。
- **部件关系**：一次 Loop = 触发发现工作 → 隔离工作区 → 读项目规则 → 执行并触达外部 → 另一 Agent 验证 → 结果与卡点写入持久状态 → 下次读取（C3）；控制器 → 执行器 → 传感器 → 回控制器（图 005）；控制器需 Skills + Memory，执行器需 Connectors + Worktrees，传感器需独立性（Sub-agents），Automations 是启动条件（C5）；传感器返回定位信息 → 控制器针对性修正（C9）；发散 → 到迭代上限退出。
- **不可省略**：图 004 副标题"Remove any one. The loop still runs. Remove enough. It becomes dangerous."并逐一绑定：Automation→Inactivity、Worktrees→Interference、Skills→Knowledge Loss、Connectors→Isolation、Sub-agents→Self-Validation、External State→Amnesia；"传感器决定收敛速度…传感器就是设计本身"（C9/C10）；"先建 Inspector，再建 Loop"（C13）；建 Loop 前置判据：能否写出无人值守即可拒绝坏输出的检查（C11）。
- **分层 / 演进**：Prompt → Context → Harness → Loop（图 003 含工作单位轴：一次调用 / 一次会话 / 一个任务 / 持续系统）；控制论三角色 + 触发；建设顺序 Skills → 传感器 → 触发器；闭环三种结局（收敛正确 / 收敛错误 / 发散）。
- **失败归因**：验证与测试（传感器假通过：测试本身错 / 路径未执行 / 审阅者太易同意；二值反馈 → 盲猜修正）；意图与验收（主观目标 = 假闭环；LLM 打分漂移）；拦截与守卫（只有上限型停止，发散耗尽预算）；隔离缺（并行覆盖）；状态工件缺（失忆重复失败尝试）；触发缺（永不启动）；外部交接缺（只读只能建议）。
- **证据形态**：信息图 3 张（六组件表、范式阶梯、三角闭环）+ 引言截图；虚构 CI 场景；无实测、无数据。

### WX-05 Loop Engineering又是啥？企业Agent落地的四层工程进化论（类型：S1；场景：企业 Agent 平台通用）
