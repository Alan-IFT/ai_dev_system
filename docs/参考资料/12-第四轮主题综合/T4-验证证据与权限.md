## 1. 归并后的候选语义（去重）

### T4-S01 阻断型 Gate 的判据必须是可直接观察的确定事实；代理指标（"已读过""声明已做""看起来合规"）只能产生提醒或候选，不得阻断
- 来源：WX-42 S1/C8（合并 F1、F7）、WX-44 S3/C12、WX-14 C9（自然语言红线≠Gate）、WX-26 S6/C7、WX-13 S4、WX-04 图 016 Gate3（IDENTIFY→RUN→READ→VERIFY）
- 证据强度：一手多来源（WX-42 同一 hook 内两条规则待遇对比与 ut-lint 不敢阻断的案例；WX-44 阶段检查五项均为工件事实；WX-14 红线依赖模型遵守；≥3 个独立团队）
- 落地 A（运行时拦截）：动作前按可观测条件（文件存在/退出码/目录一致/版本匹配）拦截 ｜ 落地 B（检查器）：合并/入库前对工件做确定性判定，代理指标只写入报告 ｜ 落地 C（人工检查点）：规则评审必答"判据是事实还是代理"
- 防御的失败：代理指标门禁被上下文污染误判（WX-42 F1）、误报逼人和 AI 为过检查把代码写差（WX-42 F7）、把自然语言红线当"硬关卡"（WX-14）｜删除条件：写不出（责任结构型：误阻断的代价由人承担）
- 与现有理论：改写 05 §1 末句"更强烈的措辞不能替代执行机制"；修订 D-008（下沉的对象限定为"判据可确定的规则"）；D-018 pass_condition 增加判据类型
- 裁决：采纳为提议

### T4-S02 约束等级由两个独立维度定义（检查是否自动进入必经路径；失败是否改变后续状态），只有双是的才可登记为 Gate；"自动运行但失败可继续"只是警告，且警告必须留下被下游必然消费的痕迹，跳过检查须可见
- 来源：WX-44 S3/图 010（四级：提醒/需想起的脚本/自动可继续/自动且阻断）、WX-07 S6/C14（软门禁三处留疤）、WX-42 C8、WX-17 F7（可跳过调试无豁免记录）
- 证据强度：一手多来源（WX-44、WX-07 两团队独立收敛；WX-17 提供反例）
- 落地 A（外部状态存储）：状态工件记录每项检查等级与结果，警告与跳过写入审查输入和交付报告 ｜ 落地 B（检查器）：交付报告生成器汇总全部非阻断失败与跳过项；验收时拒绝把警告级计入通过条件
- 防御的失败：检查存在但从未拦住任何事的"虚假阻断"（WX-44 F3）；软检查失败被静默吞掉，"跳过"与"通过"不可区分（WX-07）｜删除条件：写不出（责任结构型）
- 与现有理论：改写 05 §2 末句"只有材料清单…是 Checklist"为四级表述；D-014 反例表已含"空 Gate 集"，本条补其邻近形态
- 裁决：采纳为提议

### T4-S03 "未执行"（脚本失效、依赖缺失、环境不可用、被跳过、采集失败）必须与"执行且失败"区分为独立第三态；未执行不计入任何通过分数，含未执行层的完成判定为 UNDETERMINED；聚合分数不得把第三态折算为部分通过
- 来源：WX-08 S3/F2/F7（五层未跑仍"可以提交"、综合分照出）、WX-42 F12/F3（采集失败与无数据混显为零；覆盖率 0/0 判假测试）、WX-04 S3/F9（证据不完整→不可判定）、WX-11 S1（blocked 独立三态）
- 证据强度：一手多来源（WX-08 为运行截图观察；WX-42 为事故复盘；WX-04 为设计；WX-11 为状态机图）
- 落地 A（检查器）：每层输出 PASS/FAIL/NOT_RUN，聚合器遇 NOT_RUN 不产生数值分 ｜ 落地 B（人工检查点）：完成声明模板逐层填写"执行了吗"，空项不得签字
- 防御的失败：WX-08 F2（门禁全部未跑、指标满足而目标背叛）；WX-42 F12（事实本身撒谎）｜删除条件：写不出（D-014 空集合条款的推论，与模型能力无关）
- 与现有理论：扩展 08 §4 空集合条款到"单层/单项未执行"（不改 D-014 文本，作为 05 §6 推论并入候选决策 T4-D1）
- 裁决：采纳为提议

### T4-S04 检查器/验证器自身是被验证对象：其结构假设（路径、格式、粒度）与被检对象不一致时必须作为检查器故障上报并阻断，不得降级为警告或"已有问题"；提供事实的机器须有自己的回归 Case
- 来源：WX-08 S4/F1（脚本要求某目录而项目已改名，长期标"已有问题"）、WX-42 C30/S7/F6/F12/F14/F15（判分器格式错、粒度错配、参照测试自身 bug、覆盖率平台混显——同类错误一年四次）、WX-14 S4（派生地图必须配漂移检测）、WX-29 C2（运行时保证逆被调用不保证逆正确）、WX-13 F5（审计处方引用不存在的包）
- 证据强度：一手多来源（≥3 团队各自踩坑；WX-29 为 DSH 一手文档的分工原则）
- 落地 A（检查器自检）：假设的路径/格式不存在时退出码为"配置失效"而非"通过"，并触发阻断 ｜ 落地 B（条件加载规则 + 人工）：项目结构变更评审清单含"受影响检查器"一项；判分器/检查器变更须重跑历史样本
- 防御的失败：WX-08 F1；WX-42 F6（同一产物 0→98 分）｜删除条件：检查器能从当前结构自动推导其假设（不再含硬编码结构假设）
- 与现有理论：D-018 checker 字段增加"自检与失效语义"；新增候选决策 T4-D3
- 裁决：采纳为提议

### T4-S05 评估用判分器须有效度证据；评审/验证类 Agent 的效果指标必须锚定下游真实行为（被指出的问题是否真的被修复、被阻断的动作是否真的有害），不得只统计标记数或本阶段分数
- 来源：WX-42 S7/C16/C18（LLM 裁判与人工一致性低；确定性判分占比下降；变异击杀优于覆盖率，TestGenEval 一手）、WX-10 S4（Cursor Bugbot 以"合并时作者是否真修"为结果指标，一手）、WX-04 C17/F7（上一阶段高分下一阶段翻车，作者自承）、WX-08 F7（仪表盘与过程记录矛盾）、WX-11 F9（同页两处首次通过率不一致）
- 证据强度：一手多来源（含两个厂商/产品一手来源 + 三团队自述）
- 落地 A（检查器 + 外部状态存储）：确定性判分器配已知答案回归集；模型判分器报告与人工判定一致性；在合并/发布点自动回读被标记项是否解决并记入指标 ｜ 落地 B（人工检查点）：定期抽样双评并复核被标记项处置
- 防御的失败：评分链全为模型结论、指标与真实结果脱钩（D-023 评审版）；错误评测信号比没有更危险｜删除条件：写不出（指标设计原则）
- 与现有理论：补充 06 §3 eval manifest 的 grader 字段与 D-011；在本主题体现在 05 §6"评估者持有否决权"须同时受效度约束
- 裁决：采纳为提议（正文落点在 06，本报告只提出，交 T-评估主题并入）

### T4-S06 每个拦截层/Gate 须有独立于自身的失效探测：下游对本应被拦截层消费或剥离的信号做防御性断言；保留可重复运行的"应被拦截"回归 Case；Harness 机制本身是观测面（是否被消费、拦住真实问题还是误伤）；机制生效以运行时观察为准，不以执行者自报为准
- 来源：WX-12 S8/C5/F8（引用参数到达下游即 Hook 失效信号）、WX-17 F8（多宿主一致性校验）、WX-44 S7/图 005/图 016（"存在≠生效"应用于 Harness 自身）、WX-42 F13（配置声明与实际工具列表不符）、WX-13 F4（"问 AI 加载了哪些规则"不算验证）
- 证据强度：一手多来源（≥4 团队）
- 落地 A（检查器/日志）：下游对框架专属字段做断言并告警；机制触发/拦截/误伤计数 ｜ 落地 B（评估）：回归集含未授权调用与残缺工件写回，验证仍被拦截
- 防御的失败：拦截层静默失效无人知晓；机制只是摆设却占用注意力（WX-44 F6）｜删除条件：写不出（元规则）
- 与现有理论：D-018 observability 字段具体化；06 §1 新增"Harness 自身"观测层（交 T-评估）
- 裁决：采纳为提议

### T4-S07 对未知的默认判定偏向关闭：未登记/未分类动作、审批应答者缺席/出错/超时，默认为"需人确认"或"拒绝"，不得"无匹配即放行"；失败处置按后果非对称——只影响模型所见的读路径可降级放行并留痕，导致外部状态改变或不可逆的写路径失败必须关闭
- 来源：WX-17 S4/F3（分级表外工具直接放行，设计如此）、WX-30 F2（Deep Agents 一手文档"无规则匹配即允许"且不覆盖自定义/MCP/sandbox 工具）、WX-29 S2/F7（DSH 一手：应答缺席→unavailable→拒绝；never 策略不可被后注册者绕过）、WX-12 S2/C4/F6（读侧降级、写侧阻断）
- 证据强度：一手多来源（两份厂商一手文档方向相反，恰好构成正反例；两团队实践）
- 落地 A（运行时拦截）：分级表以外的动作一律进入确认档；写侧校验不通过即抛错 ｜ 落地 B（权限与隔离配置）：目标系统侧只授予已登记动作的凭据，未登记动作在协议层不可达；无审批人的时段等于禁止该类动作
- 防御的失败：新工具上线未更新规则被静默执行（WX-17 F3）；应答者未部署时危险动作直接执行（WX-29 F7）；残缺脚本进入生产（WX-12 F2）｜删除条件：能力目录与分级表由同一来源生成且有一致性检查时，"未登记"情形消失，本条降为检查器（写路径 fail-closed 部分写不出）
- 与现有理论：08 §3 分向降级同向；05 §3 动作前 Gate 增补"默认值"要求
- 裁决：采纳为提议

### T4-S08 阻断只对"变更引入的新增失败"成立：验证前冻结变更前失败集合并绑定其版本，阻断判定 = B−A；存量失败进入显式登记且不得掩盖新增失败
- 来源：WX-07 S1/F5/图 014
- 证据强度：单团队实践 n=1（机制可证伪、成本低；作者称多轮才意识到必须做）
- 落地 A（检查器）：门禁程序自带快照/差异模式并输出差异结果为证据 ｜ 落地 B（外部状态存储 + 人工检查点）：变更前把已知失败清单登记在状态工件，验收人只对不在清单中的失败追责
- 防御的失败：AI 以"历史问题"为由让存量与新增混为一谈，人无法逐条核验｜删除条件：主线达到零已知失败并持续保持时基线恒空，退化为普通阻断
- 与现有理论：D-009 证据包新增"变更前基线集合"字段；回答待决策 B.4（CI 已红时如何继续）
- 裁决：采纳为提议

### T4-S09 每一验证层只证明其覆盖范围且须声明盲区；可被"无断言即刷满"的指标（覆盖率）不得单独作 Gate 输入，须配能证明断言有效的独立信号；验证计划从本次改动集派生出可观察终点；多个审查者的失败应彼此独立
- 来源：WX-42 C16/C21（覆盖率 vs 变异击杀，TestGenEval 一手）、WX-08 图 014（E2E 跳过转"真机验证"）、WX-40 C10（多窄域审查者不共享盲区，Anthropic 一手）、WX-14 S6（从 diff 反推验证路径）、WX-04 F7、05 §6 既有句
- 证据强度：一手多来源
- 落地 A（检查器）：从变更集生成验证计划骨架，缺可观察终点的改动类型判"未验证"；覆盖率与变异/断言强度并列报告 ｜ 落地 B（人工检查点）：评审要求每个改动项对应"怎么看到它生效"，验收附盲区清单
- 防御的失败：报"功能正常"但验证路径没经过改动点；测试全绿但杀不死变异体（WX-42 F4）｜删除条件：写不出（覆盖范围声明是证据完整性要求）
- 与现有理论：改写 05 §6 首段
- 裁决：采纳为提议

### T4-S10 生成权与写入权结构分离：AI 只产出候选，进入受治理记录源须经独立写者（人或串行入库机制）；每类工件只有一个可写角色，其他角色的异议只能以阻塞项形式回到该工件所有者；写代码与推代码不得由同一身份持有
- 来源：WX-42 S3/C24/F5、WX-07 S3/F2/C10、WX-40 S8/图 008（Anthropic 一手：起草修复不能推送）、WX-30 S6（证据只读、shared 须显式发布）、WX-26 S8
- 证据强度：一手多来源（≥4 独立来源，含厂商一手）
- 落地 A（权限与隔离配置）：生成者对目标存储只读；按角色限制可写工件类型；委托执行者凭据不含发布/合入 ｜ 落地 B（人工检查点 + 检查器）：合并请求 + 批准；审查阶段比对上游工件是否在下游阶段被改（改即失败）
- 防御的失败：下游顺手改上游验收标准（WX-07 F2）；空 commit 循环、垃圾进仓（WX-42 F5）；AI"修正"证据｜删除条件：写不出（责任结构型）
- 与现有理论：改写 05 §6 第二段"实现 Agent 不能通过弱化验收或测试使自己通过"为结构表述；修订 D-028；新增候选决策 T4-D2
- 裁决：采纳为提议

### T4-S11 验证工件冻结：验收条目确认后即冻结语义，实现期间修改须显式记为"验收变更"并回到原批准人；用于证明修复的测试/断言在修复过程中不得被修复者修改；自动修复/自愈路径中的不可逆动作不继承任何人工确认豁免
- 来源：WX-08 S2/图 007、WX-40 S5/漏项 10（hook 禁止编辑测试文件，一手）、WX-42 S6/C11/F4（断言从验收标准提前冻结）、WX-04 S5/F5/C8（Critical 修复亦须人 yes/no）
- 证据强度：一手多来源
- 落地 A（运行时拦截）：实施阶段对验收工件/测试文件的写操作被拦截并要求变更记录 ｜ 落地 B（检查器 + 人工检查点）：合并前检查测试 diff 与修复 diff 分属不同批准人；变更验收前回到提出验收的人
- 防御的失败：修复者改测试而非改代码（WX-40 F4）；实现污染测试；自愈路径直接改库（WX-04 F5）｜删除条件：写不出（验收归属于人）
