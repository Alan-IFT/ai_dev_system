## 1. 归并后的候选语义（去重）

### T5-S01 规则登记时归入三类并各自声明淘汰条件：能力补偿类 / 组织信息类 / 责任与结构类
- 来源：WX-26 S1（图 008/016）、WX-44 §4（Boris：删的是"纠正模型本应会的行为"，留的是安全/权限/静态分析）、WX-42 冲突二（事实型基础设施）、WX-10 S5（补偿组件登记启用条件与 solo 成本差）、WX-24 S2 对照
- 证据强度：一手多来源（ATT-H 团队实践 + Anthropic harness-design 一手 + Boris 一手访谈 + WX-42 独立实践）
- 落地方式 A（外部状态存储）：规则登记表增加分类、淘汰条件、启用条件字段 ｜ B（检查器）：新增规则缺分类或淘汰条件即拒绝合入 ｜ C（人工检查点）：代际更替时按分类逐条复审
- 它防御的失败：规则只增不减；结构性规则被误当补偿性规则删除；在模型已能 solo 完成的任务上照付重型 harness 成本 ｜ 删除条件：写不出（元规则）
- 与现有理论的关系：修订 D-021（当前一刀切要求删除条件）；改写 09 §4 两条轴表（纵轴细分三类）；补 06 §7 Thin 信号
- 裁决：建议采纳为"提议"。附加要点：组织信息类的归宿是形态迁移（指令→工具/检查器）而非删除；补偿类的"删除条件"可以是触发条件收窄（evaluator 只在任务超出 solo 可靠范围时启用）而非整体移除

### T5-S02 能力补偿类规则的到期审计：三种触发并存，代际审计不可被日常观测替代
- 来源：WX-26 S2/图 008、WX-44 冲突一 + Boris（每代删一批、"simple mode"全删对照、去提示后"更聪明"）、WX-16 S5 + Anthropic best-practices（强调措辞由漏触发补偿翻转为过触发）、WX-26/WX-44 转述 OpenAI 周期性 GC、WX-10 §4（出处依据实为"有理由相信 + 逐个移除观察"）
- 证据强度：一手多来源（Boris + Anthropic 两份平台文档 + ATT-H）；WX-44 反方（只靠日常观测）无数据
- 落地方式 A（检查器）：回归集按规则 ID 分组，不带该规则重跑其绑定 Case ｜ B（人工检查点）：升级评审逐条问"理由是不是模型记不住/不会主动做/容易漏" ｜ C（定时流程）：周期性自动扫描无消费机制并生成删减候选
- 它防御的失败：到期规则反转为负作用（过度验证、过度触发、过度分析）；静默过期规则不产生误伤信号只产生成本 ｜ 删除条件：写不出（元规则）

- 裁决：建议采纳为"提议"。分工：日常观测（无消费/误伤）→ Add 与误伤型 Thin；代际全删对照 → 静默过期型 Thin；周期性 GC → 存量清扫

### T5-S04 Harness 自身是第四观测面：每项机制须能回答是否被消费与是否误伤；无计数的规则不得被判定为有效
- 来源：WX-44 S7/图 005/图 016、WX-34 S3（规则执行成功/失败计数）、WX-02 F9/S10（"每次都通过的摆设门禁"、规则违反频率）、WX-13 F5/S7（审计只查存在性会奖励追加）、WX-38 S4（Skill 在上下文但未被 follow = 占位）、WX-18 S7（拦截器"已配置≠已生效"，字段名错误静默失效）、WX-24 S3（开关设了路径静默跳过）
