### 2.2 精读四篇

**ReWOO（仅读摘要，摘要为逐字）** —— 论证"线性交错"为什么必须被打破，理由不是能力而是**冗余**：

> "Existing ALM systems trigger LLM thought processes while pulling observations from these tools in an interleaved fashion. Specifically, an LLM reasons to call an external tool, gets halted to fetch the tool's response, and then decides the next action based on all preceding response tokens. Such a paradigm, though straightforward and easy to implement, often leads to huge computation complexity from redundant prompts and repeated execution."

它的处置是 **"detaches the reasoning process from external observations"**——先一次性把计划（含依赖）写出来，再去执行。附带一条对本规范有用的观察："ReWOO demonstrates robustness under tool-failure scenarios."（**计划与观察解耦之后，单个工具失败不会污染整条推理链**。）

**LLMCompiler（仅读摘要，摘要为逐字）** —— 把"编译器"隐喻讲到底：

> "current methods for function calling often require sequential reasoning and acting for each function which can result in high latency, cost, and sometimes inaccurate behavior."

注意最后四个字：顺序执行不只是慢，还**更不准**。三段式结构逐字："(i) a Function Calling Planner, formulating execution plans for function calling; (ii) a Task Fetching Unit, dispatching function calling tasks; and (iii) an Executor, executing these tasks in parallel."
报告的观察：相对 ReAct，latency 最多 3.7×、成本最多 6.7×、准确率约 +9%。
**局限（我核对过）**：摘要里**没有**出现 "dependency graph" 字样，"任务依赖图"是 Task Fetching Unit 的实现细节，我没读全文，**不能说 LLMCompiler 用了显式 DAG**——只能说它有一个独立于执行器的 Planner。

**Plan-over-Graph（仅读摘要，摘要为逐字）** —— 这是本子类里对"图"表述最直白的一篇：

> "the model first decomposes a real-life textual task into executable subtasks and constructs an abstract task graph. The model then understands this task graph as input and generates a plan for parallel execution."
> "By normalizing complex tasks as graphs, our method naturally supports parallel execution, demonstrating global efficiency."

关键词是 **normalizing** 和 **global**：图不是为了好看，是为了让"哪些能并行"从**局部即时判断**变成**全局可计算的性质**。

**Flow（ICLR 2025；WebFetch 返回为转述＋嵌引号）** —— 唯一明确提"执行中改图"的一篇。逐字部分：workflow 被定义为 **activity-on-vertex (AOV) graphs**，实现 "continuous workflow refinement by LLM agents through dynamic subtask allocation adjustment based on historical performance and previous AOVs"，并声称带来 "enhanced error tolerance"。（转述：论文以并行度与依赖复杂度两个指标来评价工作流的模块化程度。）
**这一条最值得本规范注意**：它把"模块化"变成一个**可度量的图属性**（并行度＋依赖复杂度），而不是一句形容词。

### 2.3 提炼：这个子类在说"必须有什么，否则怎样失败"

| 必须有 | 否则的失败模式（原文口径） |
|---|---|
| **计划与观察分离**（先出计划，再取观察） | 冗余 prompt 与重复执行，token 成本爆炸；单个工具失败污染整条链（ReWOO） |
| **一个独立于执行器的规划器** | 顺序 reason-act 带来 "high latency, cost, and sometimes inaccurate behavior"（LLMCompiler） |
| **依赖显式化为图** | "能不能并行"退化为局部即时判断，失去 "global efficiency"（Plan-over-Graph） |
| **图可在执行中被改写** | 计划一次成型后无法吸收执行反馈（Flow） |
| **模块化被度量**（并行度＋依赖复杂度） | "模块化"沦为形容词，无法验收（Flow） |

**任务图相对线性拆分的必要性，最硬的一句是 Plan-over-Graph 的**：图化把并行性变成**全局可判定的结构性质**；线性拆分下"能否并行"只能靠 agent 每一步临时猜。
**关于重跑**：本子类**没有一篇**在摘要层面讲重跑语义（哪些节点失效、重跑边界在哪）。重跑的论证在 State Management 那一节（见 §4），不在这里。**这是这份清单分类的一个缺口，别在正文里假装它有。**

### 3.2 精读四篇——四种拓扑，四种失败

**（1）流水线／SOP：MetaGPT（仅读摘要；WebFetch 返回为转述＋嵌引号）**
它命名的失败模式是本卡最有价值的一个词：

> "Solutions to more complex tasks, however, are complicated through logic inconsistencies due to cascading hallucinations."

处置两条，逐字："encodes Standardized Operating Procedures (SOPs) into prompt sequences for more streamlined workflows"；"assembly line paradigm to assign diverse roles to various agents, efficiently breaking down complex tasks into subtasks"。（转述：SOP 编码让 agent 能对中间结果做校验，从而减少错误。）
**语义**：**流水线拓扑的价值不在分工，在于每道工序之间有一个可校验的交付物。** 没有交付物规格，分工只是把幻觉接力传下去。

**（2）稀疏图 vs 稠密图：Information Propagation Effects（EMNLP 2025，仅读摘要）**
这是**唯一一篇正面回答"拓扑该多密"**的：

> "moderately sparse topologies, which effectively suppress error propagation while preserving beneficial information diffusion, typically achieve optimal task performance."

（转述：作者建了一个因果框架，分别追踪**正确输出**与**错误输出**在网络里的扩散，指出此前研究只从"效率"角度主张稀疏是不完整的。）
**语义**：**连接度是一个双刃参数**——同一条边既传好信息也传错信息。稠密＝错误快速全局污染；过稀＝有用信息到不了该到的地方。**"多接几个 agent 更稳"是错的。**

**（3）选择性激活：Graph-of-Agents（ICLR 2026，仅读摘要；返回为转述＋嵌引号）**
逐字部分："GoA achieves superior performance using only 3 selected agents, outperforming recent multi-agent LLM baselines"（相对使用全部 agent 的基线）。（转述：用 model card 做 agent 选择，按相关度排序后做有向消息传递与双向传递，再做基于图的响应聚合。）
**语义**：**参与者数量本身是要被优化掉的东西，不是越多越好。**（同向的还有 AgentPrune "Cut the crap"、AgentDropout。）

**（4）自由协作的反例：Multi-Agent Teams Hold Experts Back（arXiv 2026，仅读摘要；返回为转述＋嵌引号）**
这是本子类里**最该进规范**的一条负面结论，逐字部分：

> LLM teams "consistently fail to match their expert agent's performance, even when explicitly told who the expert is, incurring performance losses of up to 41.1% on ML benchmarks."
> "tendency toward integrative compromise -- averaging expert and non-expert views"

（转述：瓶颈在于**利用专家**而非**识别专家**；该倾向随团队规模变大而恶化；这种趋同确实提升了对抗性 agent 的鲁棒性，是一个权衡。）
**语义**：**自由讨论式协作会把最强成员拉向平均。** 明确告诉团队"谁是专家"**并不能**修复它。

**（5）反向证据必须同时记：Self-Organizing Agents（arXiv 2026，仅读摘要；返回为转述＋嵌引号）**
逐字部分："How much autonomy can multi-agent LLM systems sustain -- and what enables it? We present a 25,000-task computational experiment spanning 8 models, 4--256 agents, and 8 coordination protocols ranging from externally imposed hierarchy to emergent self-organization."
（转述：一个 sequential hybrid 协议比中心化协调高 14%；自治的有效性与模型能力正相关；到 256 agent 仍次线性扩展；结论是"给使命和强模型，而不是给预设角色"。）
**必须与（4）并置**：两篇的结论方向相反。**"该不该设计结构"在这份清单里是未决问题，本规范不能单引一侧。**

### 4.2 The Log is the Agent（读到 HTML 全文，逐字引用）

**核心主张，摘要首句起，逐字：**

> "Most agent frameworks are built around the language model: a conversation loop comes first, then tools, then rules, and finally a logging layer bolted on for observability, with state persisted as retrievable "memory." We describe ActiveGraph, a runtime that inverts this arrangement. The append-only event log is the source of truth; the working graph is a deterministic projection of that log; and behaviors--ordinary functions, classes, LLM-backed routines, or logic attached to typed edges--react to changes in the graph and emit new events. No component instructs another; coordination happens entirely through the shared graph."

**它自己声称由这一个设计决定推出的三条性质，逐字：**

> "This single design decision yields three properties that retrieval-and-summarization memory systems do not provide: deterministic replay of any run from its log, cheap forking that branches a run at any event without re-executing the shared prefix, and end-to-end lineage from a high-level goal down to the individual model call that produced each artifact."

**正文里的定义句，逐字：**

> "The append-only event log is the source of truth. The graph that behaviors read and write is a projection of the log, recomputed by a replay operation that is guaranteed deterministic."

> "Graph state—a typed set of objects and relations—is never mutated directly by external code; it is computed by folding the event log forward."

**determinism contract（这是全篇最可直接搬进规范的一段），逐字：**

> "a behavior body must not read random, wall-clock time, or fresh UUIDs directly (it obtains these from the event, which carries a recorded timestamp, or from the runtime's deterministic id generator); it must not perform I/O outside the framework's tool and model primitives; and it must not depend on mutable global state that changes across fires."

**关于 fork，逐字：**

> "A fork branches a run at a chosen event...the shared prefix is not recomputed by re-running behaviors. The runtime replays the prefix against the fork's in-memory graph, serving every model and tool response for those events from the content-addressed cache."

**它对"检索＋摘要式记忆"的批评，逐字：**

> 这些系统 "share a stance: memory is derived state—summaries, extractions, embeddings—layered onto an agent whose primary representation lives elsewhere, and the provenance of what ends up in context is at best partial."

**关于无编排者，逐字：**

> "There is no orchestrator threading state between steps...only a population of rule-like behaviors that sometimes chain because one behavior's output is another's trigger."

**作者自己划的边界（必须一并记）**，摘要末句逐字：

> "We discuss--without claiming to demonstrate--why this substrate is unusually well suited to self-improving agents, and how it extends the BabyAGI lineage and prior graph-memory research."

即：**"适合自我改进的 agent"是明确标注为未证明的断言。** 论文给的是 "the architecture, a determinism contract that makes replay sound, and a worked diligence example"——一个 worked example，不是评测。**这篇没有基准数字，不要当实证引。**

### 4.3 StateFlow（仅读摘要，摘要为逐字）

> "In StateFlow, we distinguish between "process grounding" (via state and state transitions) and "sub-task solving" (through actions within a state), enhancing control and interpretability of the task-solving procedure."

> "A state represents the status of a running process. The transitions between states are controlled by heuristic rules or decisions made by the LLM, allowing for a dynamic and adaptive progression."

报告的观察：相对 ReAct，InterCode SQL 与 ALFWorld 上成功率高 13% 与 28%，成本分别少 5× 与 3×。
**语义**："**过程接地**"与"**子任务求解**"是两件事，必须分开表示。把二者混在一个自由对话循环里，过程本身就不可观测、不可控制。

### 4.4 Sovereign Agentic Loops（读到 HTML 全文，逐字引用）

**摘要逐字：**

> "Large language model (LLM) agents increasingly issue API calls that mutate real systems, yet many current architectures pass stochastic model outputs directly to execution layers. We argue that this coupling creates a safety risk because model correctness, context awareness, and alignment cannot be assumed at execution time. We introduce Sovereign Agentic Loops (SAL), a control-plane architecture in which models emit structured intents with justifications, and the control plane validates those intents against true system state and policy before execution."

**正文四条逐字：**

> "This tightly coupled pipeline assumes that the reasoning process is sufficiently correct, context-aware, and aligned with system invariants at the moment of execution."

> "reasoning models should yield verifiable intent rather than direct execution authority."

> "model outputs are treated as proposals that require validation before they can affect system state."

> "safety properties can be enforced prior to physical execution by the control plane rather than by relying on model behavior alone."

报告的观察：OpenKedge 云基础设施原型上，"SAL blocks 93% of unsafe intents at the policy layer, rejects the remaining 7% via consistency checks"，中位延迟 +12.4 ms。**这是自建原型＋自建 benchmark，无外部对照。**

**语义（本卡认为这是 State Management 里最可迁移的一条）**：**模型的输出是"意图（提案）"，不是"命令"。执行权在控制面，不在模型。** 校验依据是**真实系统状态＋策略**，不是模型自述。

### 4.5 事务系与归因系（均仅读摘要）

- **SagaLLM**（逐字）：命名四个根本性限制——"unreliable self-validation, context loss, lack of transactional safeguards, and insufficient inter-agent coordination"；做法是把 Saga 事务模式与 "persistent memory, automated compensation, and independent validation agents" 结合；并明说 "Although SagaLLM relaxes strict ACID guarantees, it ensures workflow-wide consistency and recovery through modular checkpointing and compensable execution."
  **语义：不能让 agent 自己验证自己。校验必须由独立主体做。**
- **PatchBoard**（转述＋嵌引号）：逐字——"LLM multi-agent systems often coordinate through natural-language dialogue or loosely structured shared memory, making intermediate state difficult to validate, attribute, and audit."；"a deterministic kernel validates each proposed state mutation against schema constraints, role-specific write contracts, and runtime invariants before committing it transactionally."
  **语义：状态变更必须是"带 schema 的补丁"，不是自然语言对话。而且要有"角色写入契约"——谁能改哪一部分是显式的。**
- **AgentGit**（转述＋嵌引号）：逐字——"AgentGit, a framework that brings Git-like rollback and branching to MAS workflows... supports state commit, revert, and branching, allowing agents to traverse, compare, and explore multiple trajectories efficiently."
- **MAST / Why Do Multi-Agent LLM Systems Fail?（NeurIPS 2025，仅读摘要，逐字）**：

> "Despite enthusiasm for Multi-Agent LLM Systems (MAS), their performance gains on popular benchmarks are often minimal."
> "This process identifies 14 unique modes, clustered into 3 categories: (i) system design issues, (ii) inter-agent misalignment, and (iii) task verification."

（报告的观察：1600+ 条标注轨迹、7 个 MAS 框架；分类法基于 150 条轨迹建构，标注者一致性 kappa = 0.88。）

- **Who & When（仅读摘要，逐字）**：最强的一句负面结果——最好的自动归因方法 "53.5% accuracy in identifying failure-responsible agents but only 14.2% in pinpointing failure steps"，且"some approaches performing worse than random chance"（转述），o1 与 DeepSeek R1 也未达实用水平。
  **语义：事后归因目前不可靠。这正是"日志必须是第一性的"最强论据——如果因果结构无法从日志重建，就没有别的办法找到它。**
- **Aegis（读到 taxonomy 节，六个失败模式逐字）**：
  1. **State-space Navigation Failure**: "Agent fails to navigate the environment to retrieve all necessary data required to complete the task."
  2. **State Awareness Failure**: "Agent has incorrect understanding about its current position within the environment."
  3. **Tool Output Processing Failure**: "Agent makes computational errors (e.g., comparisons, ranking) when processing information gathered from tool outputs."
  4. **Domain Rule Violation**: "Agent fails to follow domain rule by either performs forbidden actions or incorrectly blocks valid actions."
  5. **User Instruction Following Failure**: "Agent fails to follow user's specific instructions as requested."
  6. **Resource Exhaustion Failure**: "Agent fails due to exceeding allocated maximum number of turns or tokens before task completion."

  Aegis 的立场逐字："we study a complementary direction: improving agent success rates by optimizing the system environment in which the agent operates."——**改环境而不改 agent**，报告成功率平均提升 6.7–12.5%，"without any modifications to the agent and underlying LLM"。

### 4.6 提炼

| 必须有 | 否则的失败模式 |
|---|---|
| **状态外置且不可被直接改写**（只能由事件折叠得到） | 状态成为"派生物"，provenance "at best partial"（Log is the Agent） |
| **确定性重放契约**（禁随机/禁墙钟/禁框架外 I/O/禁可变全局态） | 重放不 sound，日志不能复现运行，归因只能靠猜（Who&When：定位失败步骤仅 14.2%） |
| **过程状态与子任务求解分离** | 过程不可观测、不可控（StateFlow） |
| **模型输出＝提案，执行权在控制面** | 随机输出直达执行层，"model correctness... cannot be assumed at execution time"（SAL） |
| **状态变更走 schema + 写入契约 + 事务提交** | 中间状态 "difficult to validate, attribute, and audit"（PatchBoard） |
| **独立校验者（不是自我校验）＋补偿/回滚** | "unreliable self-validation"、无法从中断中恢复（SagaLLM） |
| **可在任意事件处 fork 并复用前缀** | 每次探索都要重跑全程（Log is the Agent） |

### 5.2 精读三篇

**Swarm Skills（读到摘要＋部分正文，逐字）** —— 与本规范最同构的一篇：

> "As artificial intelligence engineering paradigms shift from single-agent Prompt and Context Engineering toward multi-agent Coordination Engineering, the ability to codify and systematically improve how multiple agents collaborate has emerged as a critical bottleneck. While single-agent skills can now be distributed as portable assets, multi-agent coordination protocols remain locked within framework-internal code or static configurations, preventing them from being shared across systems or autonomously improved over time."

> "Swarm Skills turns multi-agent workflows into first-class, distributable assets that consist of roles, workflows, execution bounds, and a built-in semantic structure for self-evolution."

正文逐字：
> "Multi-agent coordination protocols currently exist either as framework-internal code... [or] framework-private configuration files."
> "Swarm Skills elevates multi-agent coordination from ephemeral runtime state to a first-class, distributable, and self-evolving asset."
> "The specification simply declares who needs to collaborate, what dependencies exist between their tasks, and the constraints governing their execution."
> "Coordination improvements are inherently portable. If a Swarm Skill is transferred from Host Agent A to Host Agent B, the accumulated Evolution Records are transferred alongside the base protocol."

演进机制（转述）：CREATE（从成功轨迹蒸馏出新 skill）→ USE → PATCH（按摩擦点打补丁），三档打分 Effectiveness / Utilization / Freshness，摘要明说 "eliminating the need for human-in-the-loop oversight during the refinement process"。规范落地形态是一个 `evolutions.json`，记录 Evolution Record。
**验证边界**：作者为"openJiuwen Team & 中国人民大学高瓴人工智能学院"，证据是 "an architectural compatibility analysis and a comprehensive qualitative case study"——**定性案例研究，无定量评测**。**"无需人类监督"是断言，不是实测结论。**

**EvoFlow（仅读摘要，转述＋嵌引号）** —— 演进的对象是**种群**不是单点：逐字 "automatically search a population of heterogeneous and complexity-adaptive agentic workflows"；用 niching-based selection 同时保 diversity 与 quality；产出 "a population of workflows ranging from simple I/O tasks to complex multi-turn interactions"。报告的观察：比手工与自动基线高 "$1.23\%\sim29.86\%$"，以 o1-preview 12.4% 的推理成本超过它。

**AFlow（仅读摘要，转述＋嵌引号）** —— 演进的载体是**代码**：逐字 "LLM-invoking nodes are connected by edges"；"efficiently explores this space using Monte Carlo Tree Search, iteratively refining workflows through code modification, tree-structured experience, and execution feedback"。

**防退化，这一类几乎没有直接论文；最相关的一条在 State Management 下：TDAD（仅读摘要，转述＋嵌引号）**：

> "AI coding agents can resolve real-world software issues, yet they frequently introduce regressions -- breaking tests that previously passed. Current benchmarks focus almost exclusively on resolution rate, leaving regression behavior under-studied."

做法（转述）：改动前做影响分析，构造源码↔测试的依赖图，**以一个"轻量 agent skill——运行时查询的静态文本文件"交付**。
报告的观察：SWE-bench Verified 上回归率从 6.08% 降到 1.82%（约 -70%）；**而只给 TDD 流程指令、不给定向测试上下文，回归反而恶化到 9.94%**；结论逐字："surfacing contextual information outperforms prescribing procedural workflows."

**这一句是本卡对本规范最尖锐的一条外部证据**：**在他们那个条件下，"告诉 agent 该按什么流程做"比"直接把该看的东西摆到它面前"更差，而且是负收益。**（该团队在该条件下报告的观察：2 个开源权重模型、100/25 个实例。样本很小，不能外推。）

### 5.3 提炼

| 必须有 | 否则 |
|---|---|
| **协作协议本身是可分发的一等资产**（不是框架内代码/私有配置） | 改进无法跨系统迁移、无法自主演进（Swarm Skills） |
| **演进记录与协议同行**（Evolution Record 随协议迁移） | 换个宿主就退回初始版本 |
| **演进对象是种群/多样性，不是单一最优** | 早熟收敛，失去复杂度自适应（EvoFlow） |
| **演进载体是可执行代码/可搜索结构** | 没有搜索空间可优化（AFlow） |
| **变更前做影响分析并把上下文摆出来** | 引入回归；且**只加流程指令会让回归更严重**（TDAD） |

### 6.2 Ontology-to-tools compilation（读到 HTML 全文；本卡认为这是整份 README 里对本规范最重要的一篇）

**摘要逐字：**

> "We introduce ontology-to-tools compilation as a proof-of-principle mechanism for coupling large language models (LLMs) with formal domain knowledge. Within The World Avatar (TWA), ontological specifications are compiled into executable tool interfaces that LLM-based agents must use to create and modify knowledge graph instances, enforcing semantic constraints during generation rather than through post-hoc validation."

**这句 "enforcing semantic constraints during generation rather than through post-hoc validation" 是全篇的题眼，也是本卡要带回规范的那一句。**

**机制，正文逐字：**

> "The compiled tool interfaces collectively define the action space available to the LLM agent, constraining generation through executable semantics rather prompt- or schema-based constraints on the output."

（原文此处 "rather prompt-" 缺一个 "than"，我按原样抄录，未做修补。）

> "The compilation layer treats the T-Box as a machine-readable contract."

**违规时发生什么，正文逐字：**

> "If a violation is detected, for example a missing required field, a type mismatch, or an invalid unit..., the tool returns an error with an explanation. The agent then retries with corrected inputs."

（论文给的例子：单位写成 "C" 时，MCP 工具返回 allowed_values `["degree Celsius", "kelvin"]`，agent 归一化后重试成功。）

**其他逐字：**
> "All extracted, grounded, and derived entities are instantiated into a knowledge graph under the constraints defined by the ontology contract."
> "Tool calls are executed with deterministic decoding (temperature=0) to minimise stochastic variation in argument selection and to make constraint-violation feedback comparable across runs."

**作者自陈的限制，逐字：**
> "The current evaluation covers one ontology and one document collection."
> "We did not test how results change when the ontology is updated and the pipeline is re-run."

**最后一条限制对本规范极其关键：他们没有测过"本体改了以后重编译会怎样"。** 也就是说，**"规范可编译"这条路的可维护性，这篇论文没有证据。**

**领域是金属有机多面体（MOP）合成文献抽取，30 篇论文的基准。这是化学信息抽取，不是软件工程。任何往软件规范上的迁移都是我的外推，不是论文的结论。**

### 6.3 AgentO（Springer 摘要逐字＋项目站）

> "Agentic AI systems are rapidly being deployed as autonomous, goal-directed entities to manage the orchestration of complex, multi-step workflows across diverse domains. Despite their growing adoption, current frameworks often lack a formalized model and architecture. Hence, many implementations remain ad-hoc, relying on simplistic data structures and monolithic designs that hinder scalability, reusability, and interoperability. This paper addresses these limitations by introducing AgentO, an OWL/RDF-based ontology and accompanying knowledge graph that formally represent the core concepts, components, and interactions that underpin agentic AI workflows."

项目站逐字："provides a standardized vocabulary for modeling agents, tasks, workflows, tools, goals, and resource dependencies"；声称使能 "modular design, cross-framework reusability, automated reasoning, and system auditing"。
（转述：18 个主类，建在 PROV-O、P-Plan、BEAM 之上；从 AutoGen、CrewAI、LangGraph、Mastra AI 四个框架抽出 66 个 workflow pattern 做实例化。）
**注意 PROV-O 这个基础**：AgentO 把 agentic 系统建模在**溯源本体**之上——这与 §4 "日志即真相"是同一个直觉的两种表达。

### 6.4 OntoExtend（仅读摘要，转述＋嵌引号）

逐字："Ontology extension refers to the process of enriching an existing ontology in response to emerging requirements, making it more complete."；结果 "few structural issues, satisfy all functional evaluation tests, and are rated by ontology engineers as requiring minor to moderate revision before integration."
（转述：以 **competency questions 作为需求**，对既有本体做 RAG；39 个 competency question，两个真实案例：Onto-DESIDE EU 本体与博世工业本体。定位是"起草工具"。）
**最可迁移的一点：本体扩展是由"能力问题（competency question）"驱动的——即"这份本体必须能回答哪些问题"。这正是需求驱动的规范演进的形式化版本。**

### 6.5 Palantir "The Ontology System"（厂商文档，V1）

逐字：
> "The Ontology is the system at the heart of Palantir's architecture. The Ontology is designed to represent the complex, interconnected *decisions* of an enterprise, not simply the data."
> "semantics must be paired with kinetics"
> "a scalable write architecture which enables atomic and durable transactional updates, high-scale batch mutations, high-scale streams, and mechanisms like Change Data Capture"

（转述：由 data / logic / actions / security 四要素组成；对象是名词，必须配"动词"即 Action 才能建模决策；安全策略在交互时刻被 reconcile，决定谁可以触发哪个 Action。）
**厂商公告，零外部验证。但它给了本卡一个词：语义必须配动力学。** 一份只描述"应该是什么"的本体不改变任何事；只有当本体同时定义了**允许的动作**、且**动作是唯一的写入通道**时，它才有约束力。

### 6.6 提炼：本体与规范文本的关系，以及"可编译"意味着什么

**（a）本体不是规范的同义词，是规范的一个特定形态。** 规范文本约束"人和 agent 应当怎么做"；本体约束"世界里可以存在哪些对象、哪些关系、哪些动作是合法的"。二者的交集是：**都在划定合法状态空间。** 差别是本体是机器可读的。

**（b）"编译成工具"改变的是约束的施加时刻。** Ontology-to-tools 的全部价值在那半句：**during generation rather than through post-hoc validation**。规范如果只以"评审时检查"的形式存在，它作用在**产出之后**；编译成工具之后，它作用在**产出之时**——违规的东西根本无法被表达出来，因为工具签名里就没有那个参数值。

**（c）阻断力来自"动作空间被工具穷尽"，不是来自措辞。** 原文：the compiled tool interfaces **"collectively define the action space available to the LLM agent"**；Palantir：Action 是写入的通道。**两条独立材料指向同一件事：只要还存在一条绕过工具的写入路径，本体/规范就退化为建议。**

**（d）违规不是拒绝，是带解释的重试。** "the tool returns an error with an explanation. The agent then retries with corrected inputs." —— 阻断必须**同时给出可修复的信息**（例子里直接返回 allowed_values），否则阻断只是卡死。

**（e）代价与未知**：需要 T-Box 级别的形式化（"treats the T-Box as a machine-readable contract"），这是重投入；而**本体演进后重编译的行为，作者明说没测**。**"把规范编译成约束"在证据上目前只到 proof-of-principle，单领域、单文档集。**

### 7.3 一条留给下一轮的悬案

**"规范编译成可执行约束"与"规范作为待读的文本"之间，本卡拿到的证据是分裂的：**
- Ontology-to-tools 说：编译成工具、约束在生成时施加，才有力。
- TDAD 说（在编码 agent 这个具体场景下）："surfacing contextual information outperforms prescribing procedural workflows."

这两条不矛盾——**前者约束"能做什么"，后者供给"该知道什么"**——但它们提示一个划分：**规范里的"禁止/合法性"部分应当往工具与通道里编译；规范里的"如何做得好"部分则应当作为上下文被摆到面前，而不是作为流程指令被宣读。** 这个划分我在任何一篇原文里都没读到，**是我的综合，不是文献的结论**，留给下一轮验证。
