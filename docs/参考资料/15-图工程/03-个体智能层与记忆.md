## 3. 记忆管理（本卡主体）

### 3.1 分层：四份互不相同的划分判据

名单里的论文**没有一个共同的分层**。它们分的是不同的东西，判据也不同。把这四种判据分开看，比记住任何一份具体的层数重要得多。

**判据 A —— 按"在不在上下文窗口里"分（MemGPT，读全文）。** 这是最硬的一条判据，因为它是物理的、可判定的：

> "External context refers to any information that is held outside of the LLMs fixed context window. This out-of-context data must always be explicitly moved into main context in order for it to be passed to the LLM processor."

窗口内叫 main context，再切三段：

> "The prompt tokens in MemGPT are split into three contiguous sections: the system instructions, working context, and FIFO Queue."

其中 working context 的定义值得逐字记：

> "a fixed-size read/write block of unstructured text, writeable only via MemGPT function calls"

**"只能通过函数调用写"——这是本卡最可直接落地的一句。** 记忆的可写性不是靠约定，是靠**接口形状**限制的。

**判据 B —— 按"抽象层级/是不是原始数据"分（Zep，读全文）。** Zep 分三个子图，判据是"离原始输入多远"：

> "Episodic nodes (episodes), contain raw input data in the form of messages, text, or JSON. Episodes serve as a non-lossy data store from which semantic entities and relations are extracted."

> "Entity nodes (entities) represent entities extracted from episodes and resolved with existing graph entities. Entity edges (semantic edges) represent relationships between entities extracted from episodes."

> "Community nodes (communities) represent clusters of strongly connected entities. Communities contain high-level summarizations of these clusters and represent a more comprehensive, interconnected view."

**"non-lossy data store"是这套设计的承重墙**：抽取层可以错、可以被推翻，因为原始层无损保留着，随时可以重抽。

**判据 C —— 按"内容类型"分（MemoryBank，读全文）。** 三类并列，不是层级：in-depth dialogue records（带时间戳的原始对话）／hierarchical event summary（"a high-level summary of daily events"，形成 "a hierarchical memory structure, providing a bird's eye view of past interactions"）／user personality portrait（"continuously assesses and updates these understandings … creates daily personality insights. These insights are further aggregated to form a global understanding."）。

**判据 D —— 按"停留时长"分（MemoryOS，仅读摘要）。** 三级 + 两条升级规则，摘要原文：

> "the architecture comprises three levels of storage units: short-term memory, mid-term memory, and long-term personal memory. Key operations within MemoryOS include dynamic updates between storage units: short-term to mid-term updates follow a dialogue-chain-based FIFO principle, while mid-term to long-term updates use a segmented page organization strategy."

**清单外的第五种判据（综述口径）。** README 的 Related Surveys 收了《Graph-based Agent Memory: Taxonomy, Techniques, and Applications》(arXiv 2602.05665)，它给的是三组**正交二分**（仅读摘要）：

> "short-term vs. long-term memory" · "knowledge vs. experience memory" · "non-structural vs. structural memory"

**读数：** 「知识 vs 经验」这一刀是名单里唯一直接对应本规范"项目知识 / 长期记忆"分离的划分。它比"情节/语义/程序性"那套心理学移植更实用，因为它问的是**这条记忆的权威来源是谁**，而不是它长什么样。

**必须说明的空缺：** 本次名单里的 12 篇记忆论文，**没有一篇使用「工作/情节/语义/程序性」四分**。那套四分来自 CoALA（见本仓 `07-coala.md`，第 10 行已记：可从工作、语义、情节、程序记忆以及内部/外部行动来描述语言 Agent 的认知架构）。CoALA 在本 README 的 Individual Intelligence 名单中**不在列**。所以：**四分法在本次材料中没有得到任何新的支撑，也没有被反驳——它只是没被用。** 不要把本卡当成四分法的补强。

### 3.2 写入：什么时候写、谁有权写

这是名单里分歧最大、也最有可操作性的一块。四种截然不同的答案：

**答案一：让模型自己决定（MemGPT / AgeMem）。** MemGPT（读全文）：

> "Memory edits and retrieval are entirely self-directed: MemGPT autonomously updates and searches through its own memory based on the current context."

触发靠"内存压力"：

> "When the prompt tokens exceed the 'warning token count' … the queue manager inserts a system message into the queue warning the LLM of an impending queue eviction (a 'memory pressure' warning)."

超限时：

> "the queue manager flushes the queue to free up space in the context window: the queue manager evicts a specific count of messages … generates a new recursive summary using the existing recursive summary and evicted messages."

AgeMem（ACL 2026，仅读摘要）把这条推到极致——**记忆操作就是工具调用**：

> "AgeMem exposes memory operations as tool-based actions, enabling the LLM agent to autonomously decide what and when to store, retrieve, update, summarize, or discard information."

它承认这需要专门训练："a three-stage progressive reinforcement learning strategy and design a step-wise GRPO to address sparse and discontinuous rewards induced by memory operations."

**这条路线的自曝弱点（MemGPT 原文，读全文）：**

> "MemGPT with GPT-3.5 is unable to complete the nested variant of the task"

> "will often stop paging through retriever results before exhausting the retriever database"

**读数：自主记忆管理是一个随模型能力塌缩的能力。** 弱模型上它不是"效果差一点"，是"根本不发生"。任何把记忆写入完全交给模型自主的设计，都隐含了一个未申明的模型下限。

**答案二：按语义边界成批写，不逐轮写（LycheeMemory V2，仅读摘要）。** 这是本次最重要的一条工程判断：

> "Existing memory systems typically rely on eager consolidation, invoking LLMs after each interaction to extract, summarize, or update memories. This design makes memory construction increasingly costly as conversations grow."

> "Instead of consolidating every interaction, LycheeMemory batches multiple exchanges into segments and encodes each finalized segment into context-independent typed memory records. Segment-level batching lowers LLM encoding frequency, while semantic boundary detection helps preserve coherent event-level and temporal evidence compared with fixed-window batching."

它给出的总结句直接可以进本规范：

> "our results suggest that the accuracy--cost trade-off of long-term agent memory depends not only on what information is retained, but also on the granularity at which it is consolidated."

该团队在该条件下报告的观察（GPT-4.1-Mini）：LoCoMo 89.22%、LongMemEval-S 92.20%；相对 A-MEM 构建 token 减少 86.0%（LoCoMo）/ 75.9%（LongMemEval-S），且"without increasing query-time token usage"。

**注意 "context-independent typed memory records" 里的 context-independent。** 记忆条目必须能脱离写它时的上下文被读懂——这是一条可以直接写成校验规则的形状要求。

**答案三：写入即演化，新记忆回改旧记忆（A-MEM，仅读摘要）。**

> "When a new memory is added, we generate a comprehensive note containing multiple structured attributes, including contextual descriptions, keywords, and tags. The system then analyzes historical memories to identify relevant connections, establishing links where meaningful similarities exist."

> "this process enables memory evolution - as new memories are integrated, they can trigger updates to the contextual representations and attributes of existing historical memories, allowing the memory network to continuously refine its understanding."

**这条最危险，也最该被本规范拒绝其原样形态。** "新记忆可以改写旧记忆的内容"意味着**没有任何一条记忆是稳定的**，也就没有可回溯的真值。它与 §3.4 的日志式设计正面冲突。

**答案四：写入权按信任等级分配（CaMeL，仅读摘要，Runtime Orchestration 类）。** 这是名单里唯一从**权限**而非从**效果**回答"谁有权写"的：

> "CaMeL explicitly extracts the control and data flows from the (trusted) query; therefore, the untrusted data retrieved by the LLM can never impact the program flow."

> "CaMeL uses a notion of a capability to prevent the exfiltration of private data over unauthorized data flows by enforcing security policies when tools are called."

代价被明写，该团队在 AgentDojo 上报告的观察：

> "solving 77% of tasks with provable security (compared to 84% with an undefended system)"

**读数：7 个百分点买"不可信内容永远不能影响控制流"。** 把这条从"防注入"平移到"防记忆污染"，就是本卡 §3.6 草案的核心闸门。

### 3.3 遗忘与淘汰

名单里只有两种真正的淘汰机制，其余都是"检索时不排上去"而非"删掉"。

**机制一：时间衰减 + 召回强化（MemoryBank，读全文）。** 这是唯一一个显式的遗忘曲线：

> "R=e^{-t/S}"

变量逐字：R 是 "memory retention, or what fraction of the information can be retained"；t 是 "time elapsed since learning the information"；S 是 "memory strength, which changes based on factors such as the depth of learning and the amount of repetition"。

强化规则逐字：

> "When a memory item is recalled during conversations, it will persist longer in memory. We increase S by 1 and reset t to 0, hence forget it with a lower probability."

**这是全名单唯一一条可以照抄的淘汰规则**：被用到的记忆变强，没被用到的自然衰减。它不需要谁去判断"这条还有没有用"——**使用本身就是投票**。

它给的理由是产品理由，不是工程理由：

> "Forgetting less important memory pieces that are long time ago and have not been recalled much can make the AI companion more natural"

**所以本规范取它的机制，不取它的理由。** 我们要遗忘不是为了"更自然"，是为了控制检索池规模（见 §4.2 的 5→100 精度崩塌）。

**机制二：检索时三因子打分（Generative Agents，读全文）。** 严格说这不是遗忘，是"排不上号"：

> "score=αrecency·recency+αimportance·importance+αrelevance·relevance"

三个 α 全为 1。recency 用指数衰减，衰减因子逐字为 "0.995"。importance 由模型自评，提示词逐字：

> "On the scale of 1 to 10, where 1 is purely mundane (e.g., brushing teeth, making bed) and 10 is extremely poignant (e.g., a break up, college acceptance), rate the likely poignancy"

反思的触发是**累积重要性过阈**，不是定时：

> "Generated periodically when the sum of the importance scores for the latest events perceived by the agents exceeds a threshold (150)"

结构逐字：

> "Agents generate trees of reflections: the leaf nodes represent base observations, and non-leaf nodes represent increasingly abstract thoughts"

该团队报告的消融观察（数值为该论文的信度评分 μ）：完整架构 29.89；去掉反思 26.88；去掉反思与计划 25.64；三者全去 21.21；人类众包基线 22.95。**去掉观察+反思+计划后低于人类基线**——这是名单里少见的、消融跌破基线的干净结果。

**机制三（严格说是"不遗忘"）：作废而不删除（Zep，读全文）。** 见 §3.4。

### 3.4 污染、矛盾与漂移——本规范最缺的一块

**Zep 的双时间轴是这一节的核心（读全文）。** 两条时间线逐字：

> "Timeline represents the chronological ordering of events, and timeline T′ represents the transactional order of Zep's data ingestion."

四个时间戳分工逐字：

> "t′ created and t′ expired ∈ T′ monitor when facts are created or invalidated"

> "t_valid and t_invalid ∈ T track the temporal range during which facts held true."

**"事实何时被系统知道" 与 "事实何时为真" 是两件事，必须分开存。** 这一条直接解决"记忆漂移"的取证问题：漂移发生时，你能区分是"世界变了"还是"我们当时就记错了"。

矛盾处置逐字：

> "When the system identifies temporally overlapping contradictions, it invalidates the affected edges by setting their t_invalid to the t_valid of the invalidating edge."

> "Graphiti consistently prioritizes new information when determining edge invalidation."

**"作废而非删除"是可审计性的前提。** 注意第二句是一条**未加论证的策略选择**——"新信息永远优先"在对话记忆里合理，在工程记忆里未必（一条新的错误观察不该推翻一条经过验证的旧结论）。**本规范取"作废不删除"，不取"新的永远赢"。**

去重逐字：

> "The system embeds each entity name into a 1024-dimensional vector space. This embedding enables the retrieval of similar nodes through cosine similarity search."

> "The system also performs a separate full-text search on existing entity names and summaries to identify additional candidate nodes. These candidate nodes, together with the episode context, are then processed through an LLM using our entity resolution prompt."

**另一条路线：不要可变记忆，要不可变日志（The Log is the Agent，arXiv 2605.21997，Interaction Paradigm 类，仅读摘要）。** 这是名单里对整个"记忆"范式最尖锐的反对：

> "The append-only event log is the source of truth; the working graph is a deterministic projection of that log; and behaviors--ordinary functions, classes, LLM-backed routines, or logic attached to typed edges--react to changes in the graph and emit new events. No component instructs another; coordination happens entirely through the shared graph."

它明确点名 retrieval-and-summarization 式记忆做不到三件事：

> "This single design decision yields three properties that retrieval-and-summarization memory systems do not provide: deterministic replay of any run from its log, cheap forking that branches a run at any event without re-executing the shared prefix, and end-to-end lineage from a high-level goal down to the individual model call that produced each artifact."

作者自己划了边界（逐字）："We discuss--without claiming to demonstrate--why this substrate is unusually well suited to self-improving agents"。**这是一个架构主张，不是一个实验结论。** 但它提出的三条属性（确定性重放、廉价分叉、端到端血缘）是**可判定的验收条件**，比"记忆质量更好"这类说法硬得多。

### 3.5 图结构的记忆：理由与代价

**理由侧（名单内材料）。**

Zep 的理由是"静态文档检索不够用"（摘要，逐字）：

> "While existing retrieval-augmented generation (RAG) frameworks for large language model (LLM)-based agents are limited to static document retrieval, enterprise applications demand dynamic knowledge integration from diverse sources including ongoing conversations and business data."

综述侧的理由（arXiv 2602.05665，仅读摘要，逐字）：图的价值在于其

> "intrinsic capabilities to model relational dependencies, organize hierarchical information, and support efficient retrieval."

A-MEM 的理由是"现有系统组织力不足"（摘要，逐字）：

> "Current memory systems enable basic storage and retrieval but lack sophisticated memory organization, despite recent attempts to incorporate graph databases."

Memoria（仅读摘要）用的是混合结构："dynamic session-level summarization and a weighted knowledge graph (KG)-based user modelling engine that incrementally captures user traits, preferences, and behavioral patterns as structured entities and relationships."

**代价侧（名单内材料，作者自曝）。**

Zep 自曝两处（读全文）：

> "While this dynamic updating enables efficient community extension as data flows into the system, the resulting communities gradually diverge from those that would be generated by a complete label propagation run."

> "The decrease in performance for single-session-assistant questions—17.7% for gpt-4o and 9.06% for gpt-4o-mini—represents a notable exception to Zep's otherwise consistent improvements, and suggest further research and engineering work is needed."

**图记忆会在增量维护下缓慢偏离"从头重算"的结果——这是一种结构性漂移，不是 bug。**

Mem0（仅读摘要）给出的收益幅度小得值得注意：该团队报告 "Mem0 with graph memory achieves around 2% higher overall score than the base configuration"。同时报告 "a 91% lower p95 latency and saves more than 90% token cost" ——但**这个延迟与成本优势是相对全上下文法的，不是图相对向量的**。**图变体买到的是约 2 个百分点。**

**代价侧（名单外材料，单独标注）。**

> ⚠️ **以下一整块来自《Anatomy of Agentic Memory: Taxonomy and Empirical Analysis of Evaluation and System Limitations》(arXiv 2602.19320)，不在 DEEP-JLU 名单内，是我另行检索到的。仅读 HTML v1，且我只拿到了抓取工具返回的片段，未通读全文。它是本卡里唯一的名单外来源，其结论不应与名单内材料同等看待。**

该文报告的观察（均为该团队在其条件下的自报）：

- 弱模型下**记忆会静默损坏**："Qwen-2.5-3B exhibits significantly higher format error rate during memory updates compared to gpt-4o-mini"，被其称为 "Silent Failure"，"memory becomes corrupted due to failed write operations"。
- 图结构对骨干模型能力**高度敏感**："extracting entities, constructing relations, and performing logical deduplication significantly increase format errors"。
- 延迟：MemoryOS "latency exceeding 32 seconds"，被其判为 "impractical for interactive settings"。
- 构建成本：A-MEM 约 "approximately 15 hours"；Nemori "over 7.04M tokens during index construction, nearly five times that of SimpleMem"。
- 评测本身可疑：许多数据集 "high saturation risk"，能整个塞进现代 128k 窗口，"making external memory unnecessary"。

**读数（我的综合，非任何单篇的结论）：图记忆的收益是"关系与时间的可查询性"，代价是"抽取质量成为新的单点故障，且这个故障是静默的"。** 抽取错了不会报错，只会安静地存进一条假事实。这一点与 §3.4 的 "non-lossy episodic store" 合起来看才成立：**图层可以错，前提是原始层没丢，可以重抽。没有无损原始层的图记忆，是不可回滚的。**

### 3.6 可直接落地的记忆分层与写入规则草案

> 本草案是我从上述材料综合的**提案**，不是任何单篇论文的结论。每条后面标注它的来源依据；无标注者为我的补齐，需另行论证。

#### 四层 + 两条硬闸门

| 层 | 内容 | 谁写 | 可变性 | 生命周期 | 依据 |
|---|---|---|---|---|---|
| **L0 活跃上下文** | 当前阶段正在用的内容 | harness 装配 | 每轮重建 | 阶段结束即弃，不落盘 | MemGPT main context |
| **L1 事件日志** | 原始交互、工具调用与**回执原文** | **只有 harness 能写，只能追加** | **append-only，任何角色不得改写或删除** | 永久 | Zep "non-lossy data store"；The Log is the Agent "source of truth" |
| **L2 事实层** | 从 L1 抽取的实体-关系-事实 | agent 提议，**证据门放行** | 只能**作废**，不能删除 | 随作废退出检索 | Zep 双时间轴与 t_invalid |
| **L3 方法层（＝本规范方法库）** | 可复用的**约束与规程** | **只有人能写** | 版本化 | 按"触发但未遵守"计数淘汰 | 见 §4.2；本规范 23 §2 P1 |

#### 闸门一：写入权按信任等级，不按能力

- **L1 对所有角色只读只追加。** agent 不得改写自己的历史。这是"确定性重放/廉价分叉/端到端血缘"三项属性的**唯一前提**（The Log is the Agent）。
- **不可信来源的内容（网页、第三方文件、他人产出）进入 L1 时必须带来源标记，且永远以"某来源声称 X"的形式存在，不得直接晋升为 L2 的事实。** 依据是 CaMeL 的 "the untrusted data retrieved by the LLM can never impact the program flow" 的平移。
- **控制流不得来自 L2/L3 的内容。** 记忆里的一句话不能改变本轮该做什么。这条是 CaMeL 原义，在记忆场景里是防污染的根。
- **L3 只有人能写。** 对应 §4.2 的证据：技能的作用是 "procedural anchors that stabilize execution"，不是知识注入；能被 agent 自己改写的锚不是锚。

#### 闸门二：写入必须过证据门

沿用 Proof-or-Stop 的口径（逐字）："treats agent outputs as claims rather than lifecycle state"。平移到记忆：

- **agent 说"我记住了 X"只是一个 claim。** L2 的一条事实要成立，必须**绑定至少一个 L1 事件 id**（lineage）。无法回指 L1 的事实一律拒收。
- 拒收比写错便宜：污染进了 L2 会被后续检索反复放大，而拒收只是丢一条。

#### 写入时机与粒度

- **按语义段写，不按轮写**（LycheeMemory V2）。轮级 eager consolidation 的成本随对话长度线性增长，且切碎了事件与时序证据。
- **只写"跨阶段仍为真"的东西。** 本阶段内用完即弃的内容留在 L0，不进 L1 以外的任何层。
- **每条 L2 记录必须 context-independent**（LycheeMemory V2 的 "context-independent typed memory records"）——脱离写入时的上下文仍可读懂。**这是一条可机械校验的形状规则**：把记录单独拿出来，读不懂就不合格。

#### 时间与矛盾

- **每条 L2 事实存四个时间戳**：`t_created` / `t_expired`（系统何时知道 / 何时作废）与 `t_valid` / `t_invalid`（事实何时开始为真 / 何时不再为真）。依据 Zep 逐字定义。
- **矛盾时作废旧边，不删除**：`t_invalid ← 新边的 t_valid`（Zep 原文机制）。
- **但不采纳 Zep 的 "consistently prioritizes new information"。** 工程记忆里"新的自动赢"是错的。**改为：新事实与旧事实冲突时，比较各自 lineage 的证据等级**——经环境回读验证过的旧事实 > 未经验证的新观察。这条是我的修改，需另行论证。

#### 遗忘与淘汰

- **L1 永不遗忘**，只做冷归档。
- **L2 用"使用即强化"的衰减**（MemoryBank）：被检索并实际用于产出的记录，`S += 1`、`t ← 0`；长期未被召回的自然沉底。**使用本身就是投票，不需要额外的判官。**
- **L2 检索排序用三因子**（Generative Agents）：recency + importance + relevance，权重先各取 1，再按实测调。
- **L3 的淘汰判据不同**：不按时间衰减，按 **"被触发但未被遵守"** 的计数（依据 Skill-Use 把 Trigger 与 Compliance 分开度量的做法）。一条方法总被命中却总不被遵守，说明它写得不可执行，该改或该删——**不是该更用力地提醒**。

#### 容量硬约束（这条是最容易被忽略的）

Demystifying Agent Skills 报告的观察：候选池从 5 涨到 100，实际使用精度从 29.6% 掉到 3.3%。

**推论：L3 方法库不是越全越好，检索池规模本身就是失效变量。** 本规范应当对"单次可见方法数"设上限，并把"方法库增长"当作一个**需要主动裁剪的负债**，而不是一个成果指标。

#### 这套草案与本规范已有条文的关系

- L3「只有人能写」对应 `23-方法库.md §2 P1`「方法库承载方法约束，不承载执行边界」——本卡为它补了三份新的支撑（见 §4.2）。
- L1 append-only 与「不可信内容不得晋升」是**本规范目前没有的**，是本卡建议新增的两条。
- `07-coala.md` 第 16 行已记「本规范运营上仍将项目知识与非权威长期记忆分开，避免 PRD/架构被模型摘要覆盖」——本草案的 L2/L3 分离正是这条的机制化，且 §3.1 的「knowledge vs. experience memory」判据为它提供了一个更好的命名。

## 4. 其余六个子类

### 4.1 Tool Integration —— 工具描述怎么进上下文而不炸

**核心答案来自 SWE-agent（读全文）。** 四条 ACI 原则逐字：

> "Actions should be simple and easy to understand for agents. Many bash commands have documentation that includes dozens of options."

> "Actions should be compact and efficient. Important operations (e.g., file navigation, editing) should be consolidated into as few actions as possible."

> "Environment feedback should be informative but concise. High quality feedback should provide the agent with substantive information about the current environment state … without unnecessary details."

> "Guardrails mitigate error propagation and hasten recovery. Like humans, LMs make mistakes when editing or searching and can struggle to recover from these errors."

为人设计的接口为什么不行，逐字：

> "commands that print files to standard output (e.g. cat, printf) can easily flood a language agent's context window with too much file content, the majority of which is usually irrelevant to the issue."

> "distracting context can harm performance"（对比人类 "can flexibly ignore unnecessary information"）

该团队在 SWE-bench Lite 上报告的消融观察（我按抓取结果转录，**未逐格核对原表**）：带 lint 的编辑 18.0% vs 不带 15.0%；文件查看窗口 100 行 18.0% vs 30 行 14.3% vs 全文件 12.7%；检索界面"摘要式"18.0% vs 迭代式 12.0%。

**读数：把全文件塞进去比给 100 行窗口低 5.3 个点。上下文管理不是省钱，是能力。**

**第二条答案：不进上下文，进检索器。** ToolLLM（仅读摘要，且抓取返回的摘要不完整）："equip it with a neural API retriever to recommend appropriate APIs for each instruction"。16000+ API 显然不可能全塞。**注意我没有拿到他们解释"为什么不全塞"的原文句子，不引。**

**第三条答案：渐进披露。** Skill-Use（仅读摘要）描述的正是这个形状：

> "a benchmark that evaluates skill use under progressive disclosure, where an agent sees only a skill's name and short description and must retrieve the full procedure before following it."

**一句话结论：工具/方法的描述分两级——常驻的只有名字与一句话，完整规程按需拉取。**

### 4.2 Skill Composition —— 「方法库承载约束不承载执行」的正反证据

**支持本规范立场的三份新证据。**

**(a) Skill-Use 对"技能"的定义本身就是规格式的（仅读摘要，逐字）：**

> "skills, structured documents that specify when to act, which procedure to follow, and which tools are allowed."

**"specify"，且三项全是约束（何时、按什么规程、允许用哪些工具），没有一项是执行。** 这与本规范 23 §2 P1 完全同构。

**(b) Demystifying Agent Skills 给出了机制层面的解释（仅读摘要，逐字）：**

> "skills work when noisy trajectories become procedural anchors that stabilize execution."

> "Procedural anchoring accounts for 65.7% of skill cases, versus 4.5% for explicit knowledge injection, showing that skills stabilize action rather than inject missing facts."

**"stabilize action rather than inject missing facts" —— 这是本卡为 23 §2 P1 找到的最硬一句。** 方法库的作用是**稳住执行的形状**，不是补知识、更不是替执行。该团队还报告：技能相对 Workflow Memory "improve … by 6.06 points in matched comparisons"。

失效条件逐字："Skills fail under brittle assumptions, incompatible contexts, or insufficient adaptation."

**(c) Loop Architecture 的 "loop specification" 是同一立场的独立复述**（见 §4.4）。

**反对/张力侧：Voyager（仅读摘要）。** Voyager 的技能库是**可执行代码**，逐字：

> "an ever-growing skill library of executable code for storing and retrieving complex behaviors"

> 技能 "temporally extended, interpretable, and compositional, which compounds the agent's abilities rapidly."

**这是名单里唯一一份对本规范立场的实质反例。** 但它的适用域窄：Minecraft 是一个**动作空间封闭、环境反馈即时确定**的域，可执行代码技能在那里能被环境直接证伪。软件工程域不具备这个条件。**我未取到 Voyager 去掉技能库的消融数据，无法判断技能库贡献了多少——记为未核对项。**

**Agent Workflow Memory（仅读摘要）处在中间。** 它把 workflow 定义为 "commonly reused routines"，"inducing commonly reused routines, i.e., workflows, and selectively providing workflows to the agent to guide subsequent generations"。**"guide"不是"execute"，偏向规格侧。** 但抓取工具在回答"是可执行程序还是可复用抽象"时给的是它自己的判断（"Reusable abstractions/routines (not executable programs)"）而**不是原文引用**——**这一条我没有逐字证据，不采信。** 该团队报告的观察：Mind2Web 相对成功率 +24.6%、WebArena +51.1%。

**最硬的一条运营约束（前已引，此处重申其对方法库的意义）：** 候选池 5→100，实际使用精度 29.6%→3.3%。**方法库的规模上限是一条真实存在的物理限制。**

### 4.3 Runtime Orchestration —— 最有价值的是那条统一视角

30 个条目里 24 个是 2026 年预印本，**整体证据强度低**。但 Externalization（arXiv 2604.08224，仅读摘要）给了一个值得记的统一视角，逐字：

> "Large language model (LLM) agents are increasingly built less by changing model weights than by reorganizing the runtime around them."

> "memory externalizes state across time, skills externalize procedural expertise, protocols externalize interaction structure, and harness engineering serves as the unification layer that coordinates them into governed execution."

**"memory externalizes state across time, skills externalize procedural expertise" —— 记忆与方法库是同一件事的两个面**：都是把模型内部不可靠的东西挪到外部可治理的位置。这为本规范"记忆与方法库分章但同源"提供了一个干净的说法。

它还给了一条历史线："a historical progression from weights to context to harness"。**这与 Loop Architecture 那篇的 "from prompt to context to harness to loop" 是两份独立材料给出的同一条演进线**——这是本卡里少见的、跨材料互证的地方。

安全侧最硬的是 CaMeL（已在 §3.2 引）。

### 4.4 Loop Architecture —— 单 loop 的极限在哪

**"loop specification" 的定义（Stop Hand-Holding Your Coding Agent，arXiv 2607.00038，仅读摘要）逐字：**

> "a bounded, reusable artifact, made of a trigger, a goal, a verification step, a stopping rule and a memory, that a human hands to an agent harness (such as Claude Code or Codex) so the agent pursues a goal on its own, in place of step-by-step prompting."

**它明确把 loop 与两样东西区分开，逐字：**

> "We distinguish this external loop specification from two things it is often confused with: an ordinary programming loop, and the internal perceive-act-observe cycle that the harness already provides as plumbing."

**这与 "A pattern is a specification rather than an executable program"（Antigravity，见本仓 14 号卡）是同一立场的第二份独立表述**——一份来自厂商，一份来自学术侧，措辞不同而结构相同。

**它明确反对"loop 取代 prompt"的强主张，逐字：**

> "we argue, against the stronger headlines, that it does not retire prompt engineering; loop and prompt are distinct tools with distinct uses."

**单 loop 的极限，作者自己列的三条，逐字：**

> "the verification burden, comprehension debt and the risk of cognitive surrender."

该团队对 50 个真实 loop 的编码观察：70% 的 loop 在"验证阶梯的自主区"验证，74% 命名了终止状态，而 "automated triggering and durable memory remain comparatively underdeveloped"。

**loop 不够用的第二个答案：loop 会不停（When Agents Do Not Stop，arXiv 2607.01641，仅读摘要）。** 逐字：

> "an agent may repeatedly execute model calls, tools, workflow transitions, or agent handoffs when the feedback path is not effectively bounded. We call this problem Infinite Agentic Loops (IALs)."

后果逐字："cost exhaustion, model denial of service, context growth, and repeated external side effects."

成因逐字：非终止源自 "interaction between agent logic, framework semantics, runtime observations, and termination mechanisms"。**注意"framework semantics"——不停有一半责任在框架，不在 agent。**

该团队报告的观察：静态分析工具 IAL-Scan 在 6,549 个仓库上发现 "68 IAL failures across 47 projects, achieving 91.9% precision"。

**综合读数：单 loop 的极限有三处——(1) 验证负担随自主度上升而上升，且无人代付；(2) 终止条件必须显式命名，否则反馈路径无界；(3) 长期记忆是当前实践中最欠发达的一环（该 50-loop 语料的自述）。**

### 4.5 Interaction Paradigm —— 最硬的是"日志即真值"

见 §3.4 对 The Log is the Agent 的完整引用。其可判定的三条属性（确定性重放、廉价分叉、端到端血缘）是本卡建议作为**验收条件**而非"设计理念"来用的东西。

本子类另有 MCP 攻击面（TSE 2026）、LACP 标准化（NeurIPS 2025）、AgentRx（从执行轨迹诊断失败）等，本次未精读，记为未核对项。名单第一条 Beyond Message Passing 页面为空，未核到。

### 4.6 Environment Feedback —— 回读环境 vs 相信自述

**最硬的一句来自 Proof-or-Stop（arXiv 2607.14890，仅读摘要）逐字：**

> "lifecycle states such as reviewed, tested, DONE, and ready-to-merge remain claims unless supported by current evidence."

> "The method treats agent outputs as claims rather than lifecycle state, and uses proof operationally to mean gate-admissible evidence under a stated trust model, not semantic program correctness."

**注意最后半句是作者主动划的边界**："proof" 指的是"门可接受的证据"，**不是**"程序语义正确"。这个自我限缩很重要，避免把"过了门"读成"对了"。

该团队报告的观察：无人值守 loop 引擎 "passed 10 of 10 scenarios with zero false-DONE"；收据包 "rejected 18 tamper classes with zero false accepts"；在 9,240 格的消融里，"visible-pass/hidden-fail" 放大从朴素 loop 的 31/1800 降到门控 loop 的 2/1800，"a 1.6 percentage-point improvement in not-amplified rate with a 95 percent confidence interval of [0.8, 2.5]"；近等算力对照 A3 vs A4 为 14/1800 vs 2/1800，作者据此称收益来自 "enforcing review as a lifecycle gate rather than merely adding a reviewer"。

**"把评审作为生命周期闸门"与"多加一个评审者"是两回事——这条区分本卡认为是本子类最有迁移价值的一条。**

**第二份支撑：LEVER（arXiv 2302.08468，仅读摘要）。** 训练验证器 "determine whether a program sampled from the LLMs is correct or not based on the natural language input, the program itself and its execution results"，**判据里包含执行结果，而非只看生成概率**。该团队报告的观察：相对基线提升 "4.6% to 10.9% with code-davinci-002"。

**第三份：OSWorld（arXiv 2404.07972，仅读摘要）。** 用 "a custom execution-based evaluation script for reliable, reproducible evaluation"，而非模型自评。该团队报告的观察逐字：

> "While humans can accomplish over 72.36% of the tasks, the best model achieves only 12.24% success, primarily struggling with GUI grounding and operational knowledge."

**关于 CRITIC 的一条负面核对（重要）：** 我原本想引 CRITIC 中"没有外部反馈的自我纠错不足"那句常被转述的话。**我在 arXiv abs 页上没有找到这句话。** 摘要里能逐字引的只有：

> "our research highlights the crucial importance of external feedback in promoting the ongoing self-improvement of LLMs."

**这句说的是"外部反馈很重要"，不是"没有外部反馈就不行"。二者强度不同。本卡按前者记，不做加强转述。** 若本规范要引"自我纠错不足"这条更强的主张，需另找原文（该主张的常见出处是 Huang et al. 的 self-correction 论文，不在本名单内）。

**综合读数：'回读环境优于相信自述'在本材料里有三份支撑（Proof-or-Stop 的门控消融、LEVER 的执行结果验证、OSWorld 的执行式评测），但都是各自团队的自报，无一独立复现。它作为一条工程默认值成立；作为一条被证实的定律不成立。**

## 5. 对本规范的可取用点 / 不可取用点

### 5.1 可取用（按可取用强度排序）

### 5.2 不可取用

| # | 不取 | 理由 |
|---|---|---|
| 1 | **A-MEM 的"新记忆回改旧记忆"** | 记忆演化意味着没有任何一条记忆稳定，与 L1 不可变、与可回溯真值正面冲突。它的链接生成可取，内容回改不可取。 |
| 2 | **Zep 的 "consistently prioritizes new information"** | 对话记忆合理，工程记忆错误。一条新的未验证观察不该推翻一条经环境回读验证的旧结论。本卡改为"按 lineage 证据等级裁决"。 |
| 3 | **MemGPT / AgeMem 的"完全自主记忆管理"** | MemGPT 自曝在 GPT-3.5 上"unable to complete"；AgeMem 需三阶段 RL 专门训练。这条能力随模型塌缩，把它作为规范默认值等于引入一个未申明的模型下限。 |
| 4 | **Generative Agents 的 importance 自评（1-10 poignancy）** | 让模型给自己的记忆打重要性分，是自证。本规范已有"自证的探测等于没有探测"（31 §2 P9 / 33 §2 P10）。可取三因子检索排序，不取模型自评的 importance 来源。 |
| 5 | **Voyager 式"技能=可执行代码"** | 适用域是动作空间封闭、环境即时证伪的 Minecraft。软件工程域不满足前提。列为已知反例并保留，不采纳。 |
| 6 | **README 的三层分法本身** | 这是该实验室的编排口径，不是被验证的结论，且预设了"图结构"为组织手段。可作为检索索引使用，不作为架构依据。 |
| 7 | **Runtime Orchestration 子类的 24 篇 2026 预印本** | 无同行评议、无第三方复现、大量同题材自我引用。本轮只取 Externalization 与 CaMeL 两条，其余不进正文。 |
| 8 | **任何"图记忆更好"的一般性断言** | Mem0 自报图变体仅高约 2 个百分点；Zep 自报 single-session-assistant 一类反而下降 17.7%/9.06%；名单外材料另报静默损坏与延迟问题。收益条件性极强。 |
| 9 | **"没有外部反馈就无法自我纠错"这条强主张** | 我在 CRITIC 摘要页未见此句，只见"external feedback 很重要"。强度不同，不加强转述。 |
