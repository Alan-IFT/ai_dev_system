## 1. 文章在讲什么
作者维护一个驱动数据质量异常检测 Agent 的 Skill（作者称其为 system prompt）。上线后模型反复违反明确指令（工具选错、输出被禁字段、跳过"正常"维度）。作者接入自动修复工具：每个 bad case → 自动生成规则 → 追加 → 发布，人只看结果不审文档。几十轮后 Skill 从约 400 行膨胀到约 1500 行，同一规则最多出现在 8 处，违规反而更多。作者归因四个结构性原因（位置注意力 U 形、隐性冲突静默择一、训练偏差/否定指令、多轮上下文淘汰），并解释修复工具为何总选择追加（局部视角、安全追加偏好、无健康度概念、自动化拆掉了"人的懒惰"这个刹车）。解法八条：分层（位置即优先级）、冲突显式化、正向替代否定、表格化、三明治、外置参考、参考文件一致性审计、给自动修复加刹车。结果：压回约 300 行（-80%），作者称遵循率"明显"改善，无数字。

## 2. 核心主张
- **C1** 模型违反明确指令主要不是"故意"，而是结构性原因：位置、冲突、训练偏差、上下文淘汰。｜支撑：引用 Lost in the Middle + 作者案例｜适用条件：长指令集（数百行以上）｜文中位置：01
- **C2** 指令位置决定遵循率：首尾高、中间低；把规则从前 50 行推到中间等价于降低其优先级。｜支撑：论文（QA 准确率，非遵循率）+ 作者观察｜适用条件：单文档一次性加载｜文中位置：1.1、3.1
- **C3** 两条有张力的规则不会报错，模型静默择一，且会为跳过找"合理"理由（规则 B 给了跳过规则 A 的许可）。｜支撑：四维度/只展开异常维度案例｜适用条件：规则集中存在未声明范围的成对约束｜文中位置：1.2
- **C4** 否定指令先激活被禁概念，反而抬高其出现概率；应改写为"场景→正向行为"，禁止项降为补充。｜支撑："多项研究"（无出处）+ 类比"粉红大象"｜适用条件：输出内容类约束｜文中位置：1.3、3.3
- **C5** 自动修复工具的默认动作是追加，因为它局部视角、偏好安全追加、没有文档健康度概念；自动化移除了人的懒惰这个天然刹车。任何"提取经验→自动追加规则"的反馈系统不加约束都会重蹈覆辙。｜支撑：git 历史四阶段表｜适用条件：无人审核文档本身的自动迭代｜文中位置：02
- **C6** 修复前应先归因：措辞不清 / 位置不对 / 与他规则冲突，再选最小修改；而不是读到 bad case 就生成新规则。｜支撑：推理，作者描述工具"理论上应该做的"｜适用条件：对既有规则的违反｜文中位置：02
- **C7** 全局禁令只在最前层写一次，后续章节只引用不复述；合并 8 处重复是 1500→300 的主因。｜支撑：作者实践｜适用条件：同上｜文中位置：3.1
- **C8** 冲突消解的形式是给每条规则标注适用范围与例外（"总览表不受此规则影响"）。｜支撑：改写前后对比｜适用条件：成对张力规则｜文中位置：3.2
- **C9** 表格、编号、标题层级比自然语言段落更易被"扫描"到；同样信息量表格遵循率"显著更高"。｜支撑：无数据｜适用条件：条件映射类规则（表类型→工具）｜文中位置：3.4
- **C10** 三明治（首尾各写一遍）只用于 2–3 条最关键规则；它与无序重复的区别是只放在两个注意力高峰区。｜支撑：推理｜文中位置：3.5
- **C11** 规则类内容留在 Skill，参考类内容（表结构、SQL 模板、报告格式）外置按需加载。｜支撑：作者实践｜文中位置：3.6
- **C12** 参考文件是模型的"课本"：模板中含被禁字段、示例只覆盖部分维度，会让模型在"听规则"与"照课本"间摇摆；注释掉也无效，注释也是 token。｜支撑：作者审计发现｜适用条件：规则与外置模板并存｜文中位置：3.7
- **C13** 自动修复须加四种刹车：规模预算触发重构模式、插入前语义去重、单次追加上限、每 N 次修复强制全局合并；这等同于技术债管理。｜支撑：类比｜文中位置：3.8
- **C14** 注意力是固定带宽，重复一条规则是在抢占其他规则的配额；"少即是多"在此不是风格而是约束。｜支撑：推理｜文中位置：04

**冲突一：文章把全部违规留在提示层解决，本项目 D-008 要求可确定规则下沉。** 文章列举的三类典型违规——按表名前缀选工具、跳过 idmapping 前缀字段、总览表必须含四个维度——全部是机械可判定的，按 D-008 应由过滤器/校验器在输出或工具调用处拦截，而不是靠分层、表格化、三明治提高"遵循率"。文章八条解法没有一条离开提示层，其"遵循率明显改善"仍是概率性的。证据强度：本项目 D-008 是提议，但 Anthropic context-engineering 一手材料也反对把复杂逻辑硬编码进提示；两者可共存——提示层做本文的减法，确定性约束另走检查器。这暴露的是本文的**盲区**而非错误：它的检查清单缺一项"这条规则能不能不靠模型遵守"。

**冲突二：位置与优先级的方向不通用。** 文章：禁令放最前、末尾放模板。Anthropic：长文档在上、指令/问题在末尾；GPT-4.1：冲突时靠后者胜。三者都有各自场景（纯指令集 vs 数据+指令；单轮 vs 多轮）。结论：本项目只能采纳"位置携带优先级、且优先级要显式声明"这一语义，不能采纳任何具体方向。可共存。

## 6. 建议采纳（候选语义）
- **S1** 指令集内每条行为规则只有一个权威位置，其他位置只引用不复述；规则的优先级必须显式声明，而不是靠出现次数或"严禁/铁律"等措辞强度暗示。｜落地方式 A（静态指令）：指令文档内设优先级分层，低层用引用指向高层｜落地方式 B（检查器）：变更前对指令集做语义近似扫描，发现同义重复即拒绝合并｜它防御的失败：同一规则多版本漂移、重复抢占注意力（本文 8 处重复）｜删除条件：同一规则集在不同规模/重复度下的评估显示遵循率不再随之变化
- **S2** 成对有张力的规则必须显式标注各自适用范围与例外，不得依赖模型自行裁决。｜落地方式 A（人工检查点）：规则变更评审清单含"逐对冲突检查"项｜落地方式 B（检查器）：用冲突检测评估（ConInstruct 类）对规则集做判定，检出未声明范围的冲突对即阻断｜它防御的失败：静默择一（C3 案例：规则 B 成为跳过规则 A 的许可）｜删除条件：模型在指令冲突时可靠地报告冲突并请求澄清（当前一手证据显示不做）
- **S3** 模型可见的一切参考材料（模板、示例、注释、被禁用的片段）都会被当作示范；参考材料不得含规则禁止的内容，示例必须覆盖规则要求的全集。｜落地方式 A（检查器）：扫描模板/示例中的禁用项与覆盖率｜落地方式 B（条件加载 + 人工检查点）：参考材料按需加载时附一致性审计记录，审计由人签署｜它防御的失败：教材与规则打架（C12）｜删除条件：写不出——这是信息一致性问题，不随模型能力消失
- **S4** 对既有规则的违反，修复前必须先归因（措辞歧义 / 位置稀释 / 规则冲突 / 训练偏差 / 参考材料打架 / 上下文丢失），并优先修改既有规则；新增规则须附"不存在等价规则"的证据。｜落地方式 A（人工检查点）：bad case 处理模板必填归因字段｜落地方式 B（工作流状态 + 检查器）：修复变更必须引用被修改的既有规则 ID，否则进入"新增规则"路径并触发去重检查｜它防御的失败：读到 bad case 即追加（C5）｜删除条件：修复工具能可靠地做全局语义扫描与最小化修改（本文观察当前做不到）
- **S5** 强调性措辞（全大写、"严禁"、"铁律"、"务必"）是对特定模型代际漏触发的补偿，须绑定代际并在模型升级时消融。｜落地方式 A（检查器）：指令集 lint 统计强调词密度，超基线告警｜落地方式 B（评估）：模型升级时对去强调版本与原版本跑同一评估集（对应 D-012）｜它防御的失败：过触发/注意力争抢（Anthropic 一手：Opus 4.5/4.6 过触发）｜删除条件：本条自身即删除条件的实例——当评估显示去强调版本不劣于原版本时删除强调词
- **S6** 规则的"能否不靠模型遵守"是规则进入指令集前的前置问题：可机械判定的约束应下沉为检查器或过滤器，指令集只保留需要判断的规则。（强化 D-008，本文反例）｜落地方式 A（运行时拦截）：工具调用/输出前的确定性过滤｜落地方式 B（人工检查点）：规则评审时必答"能否机械检查"｜它防御的失败：把确定性约束当概率性遵循问题反复调提示｜删除条件：写不出——责任类约束不因模型变强而回到提示层

## 8. 该文暴露的失败模式
- **F1** 改进闭环全自动且无人审文档本身 → 40 次修复追加约 1100 行，同一规则 8 处，违规反而上升 → 作者事后手工重读全文并重构 → **可构造**：给定一份规则集 + N 个 bad case，让修复 Agent 迭代，度量每轮增删行数比、语义重复数与评估集遵循率；预期不加刹车时单调膨胀
- **F2** 两条规则有未声明的范围重叠（"必须覆盖四维度" vs "只展开异常维度"）→ 模型选后者并跳过长期正常的维度，不报冲突 → 改写为带范围与例外的两条 → **可构造**：注入成对张力规则，检查模型是否报告冲突或静默择一（ConInstruct 范式）
- **F3** 关键规则未变但文档从 300 行涨到 1500 行 → 同一规则遵循率下降 → 压缩并前置 → **可构造**：固定目标规则与位置，改变填充长度与位置（Levy 范式），测遵循率
- **F4** 外置模板含被规则禁止的字段、示例只覆盖部分维度 → 模型"时灵时不灵" → 删除模板中禁止内容（含注释）、补全示例覆盖 → **可构造**：同一规则配一致/不一致两版模板，比较违规率
- **F5** 否定式禁令（"禁止给建议"、"禁止提 ID 映射"）→ 被禁内容仍出现 → 改写为正向行为 + 补充禁止项 → **可构造**：同一约束的否定式与正向式两版，比较违规率；注意本文三列表仍保留了禁止项列，与其自身"别想粉红大象"论证不完全自洽
- **F6** 机械可判定的约束（字段前缀过滤、按表名选工具）只靠提示遵循 → 概率性违规长期存在 → 文章仍在提示层修 → **可构造**：同一约束以提示 vs 输出过滤器两种落地，比较违规率与成本（用于验证 D-008）
