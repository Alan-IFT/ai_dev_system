## 1. 文章在讲什么

作者团队把部门 harness 的根指令删掉 61%、skills 删 40%、agent 从 10 减到 6，同期 Anthropic 公布为 Claude 5 系模型删掉 Claude Code 系统提示词 80% 以上而编码评测无可测损失。文章据此提出：在指令遵循足够强的模型上，**冗余指令从中性变为负资产**——缩小搜索空间、被字面执行、导致过度触发、覆盖模型更好的判断。第二部分给出写 harness/skill 的五道关卡（该不该写→规则改判据→路径放开验收收紧→先建裁判→沉降到工具层）。第三部分回答"什么值得留"：harness 里每条内容都是对"模型做不到什么"的赌注，凡补能力缺口的都会到期；不会到期的是三类——只有你们知道的信息、只有人能承担的责任、评价者不能是被评价者本人。四层归属（L0 模型本体 / L1 通用 agent 机制 / L2 组织特有流程与工具 / L3 判断与授权）把它们定位在 L2、L3，自建 harness 的立足点也在 L2、L3 而非 L1。结尾给四个动作：每加一条先写清防哪个失败；每个模型代际做一次到期审计；力气从 L1 挪到 L2/L3；能沉降到工具层的别留在指令层。

## 2. 核心主张

- **C1** 冗余指令在强模型上是负资产而非中性成本：缩小搜索空间、字面执行削减召回、激烈措辞过度触发、否定指令引入被否定概念。｜支撑：OpenAI GPT-5.5 指引、Anthropic Opus 5 文档原话（§4 核实一致）｜适用条件：指令遵循能力强的新一代模型｜文中位置：§1.2
- **C2** 官方处置是"删除而不是改写"：显式验证指令、"不要思考"类规则、legacy harness 中的独立验证步骤应直接移除。｜支撑：Opus 5 文档原话（核实一致）｜适用条件：Opus 5 代模型；对旧模型不适用｜文中位置：§1.2
- **C3** 四个可操作转变：规则→判据；前置全量上下文→渐进披露；示例→接口设计；markdown 规格→可执行引用物（测试、签名、rubric）。｜支撑：Anthropic 2026-07-24 博客（核实：原文为六个转变，作者略去两个，见 §4）｜文中位置：§1.3
- **C4** 删除判据：agent 读代码库能找到的信息不写；写了就制造第二个事实来源，过期的文档比没有文档更危险。｜支撑：Addy Osmani 引文 + 推理｜文中位置：§2.1
- **C5** 逐行扫描判据："一个没有本次会话记忆的 agent 读到这一行，行为会怎么变？答不出来就删。"三类必然出局：元评论、自我辩护、防御性否定；其中"告诉模型某条边界没有强制力，等于主动削弱那条边界"。｜支撑：作者团队实践，无数据｜文中位置：§2.1
- **C6** 绝对措辞只留给真正的不变量（不可逆动作）；判断题一律改写为决策规则；正例优于禁令。｜支撑：OpenAI 指引原话 + 作者团队做法｜文中位置：§2.2
- **C7** "放开的是路径，收紧的是验收"：目标、成功判据、约束必须写死，只有路径交给模型；验收判据必须能被机械判定并产出证据（测试变绿/产物存在/diff 为空/命令 exit 0）。｜支撑：OpenAI、Addy、Anthropic 三方并列（图 004）｜文中位置：§2.3
- **C8** 例外：操作脆弱（顺序错了不可挽回）的任务要写死路径；判据是**脆弱性而非重要性**。｜支撑：Anthropic skill 指南比喻（核实一致）｜文中位置：§2.3
- **C9** 先建评测再写内容：不带 skill 跑出具体失败→建三个场景→基线→写"刚好够"的最少内容→迭代。副产品是每条规则天然绑定它防御的失败，成为日后判断"是否过期"的唯一依据。｜支撑：Anthropic skill 指南五步（核实一致）｜文中位置：§2.4
- **C10** 能沉降到工具层（linter/测试/CI 门禁）的就别留在指令层，因为"指令层的强度取决于模型当下怎么读它，工具层不取决于"；指令文件是"还没修掉的摩擦清单"，应越修越短。｜支撑：OpenAI harness-engineering（核实一致）+ Addy｜文中位置：§2.5
- **C11** harness 每个组件都编码一条"模型做不到什么"的假设，假设会过期；凡补能力缺口的都会到期，只是早晚。已到期的例子见图 008。｜支撑：Anthropic harness-design 一文（核实：语义一致，引文非逐字）｜文中位置：§3.1～3.2
- **C12** 你预测不了哪条会被内化，但可以让"已被内化"可检测：每条规则写下时绑定它防御的具体失败模式；说不清防什么的规则从写下那一刻就无法淘汰——这是 AGENTS.md/CLAUDE.md 只增不减的根因。｜支撑：推理 + Addy "棘轮法"（核实一致）｜文中位置：§3.3
- **C13** 四层归属：L0 已内化仍在吸收；L1 正被 runtime 吸收、最不保值；L2 不会内化但会迁移到工具层；L3 永远不会。自建 harness 立足点在 L2/L3。｜支撑：作者框架，无数据｜文中位置：§3.4、3.8
- **C14** L3 永不内化的两条理由：信息不可达（源头在人的头脑与组织结构，不在公开语料也不在 repo）；责任不可转移（只有人能继承后果，与技术进步无关）。人必须持有 Verdict / Answerability / Accountability 三件事。｜支撑：推理 + Addy 引文（未追读）｜文中位置：§3.5
- **C15** 第三类不会消失的东西是结构性偏差：评价者与被评价者是同一个（self-preferential bias），不是能力缺口；独立 reviewer 与跨模型校验的价值不随模型变强而衰减，只是价值边界外移。｜支撑：Anthropic 两篇（harness-design 核实一致：evaluator 在能力边界处仍有收益）+ Addy｜文中位置：§3.7
- **C16** 自主度上界 = 能廉价可靠验证的量（back pressure），与任务重要性和模型能力无关；三个判定问题：多快知道错、多干净撤销、什么能证明对。Gate 数量上限 = 人能真正判断的数量；对策不是减 Gate 而是让每个 Gate 便宜到能真判（裁决事项、证据、推荐前置，全文和 diff 作可选附录）。｜支撑：Addy（未追读）+ 作者团队实测经验（无数据）｜文中位置：§3.7（度）
- **C17** harness 不会消失，会迁移：更强模型消灭某些脚手架，同时解锁需要另一类脚手架的能力。L2 的价值是"让 agent 能做"（能力接入）而不只是"告诉它怎么做"（知识注入）。｜支撑：Anthropic/Addy（语义一致，逐字未确认）+ 图 014/015｜文中位置：§3.8
- **C18** 自建 harness 是在偿还意图债：agent 每个 session 冷启动，凡未外化成它能读到的工件的意图，它就没有；人靠口口相传分期偿还的债，对 agent 变成每次重复付费。｜支撑：Addy 引文（未追读）｜文中位置：§3.8

- `图 010`（§3.5）→ 人必须持有的三件事：Verdict 判决（上不上生产的决定，"The model may write the line, but the Verdict is mine"）；Answerability 可解释（必须有人能说清改了什么、为什么安全、错了会怎样）；Accountability 担责（后果由谁承担，无法委托给任何 agent）。
- `图 011`（§3.6）→ Anthropic《Agent Harness Design: 3 Patterns》第三模式的留/删：留下不可逆动作的安全边界（API 调用、删除操作）；删掉新模型已能自理的冗余脚手架（例子正是 context resets）。

- `图 013`（§3.7 度）→ 四个自主度反模式：Autonomy as status（把高自主度当能力证明而非安全证据）；Permission laundering（逐次审批太累，一次性给出过量权限）；Summary substitution（接受 agent 摘要而不是完整证据包）；Fleet cosplay（并行跑一堆 agent 但依赖关系全靠人手工编排）。
- `图 014`（§3.8）→ 作者团队 L2 的具体内容：内部平台打通（TAPD 工作项状态流转/必填字段校验、工蜂 issue 与 MR、蓝盾流水线触发/结果解析/失败归因）→ 跨系统协作契约公开语料和代码库里都没有；环境与排障接入（测试集群部署登录、日志抓取、堆栈与性能剖析、MTR/集成测试、流水线失败 RCA）→ 运维知识只在少数人头脑里；规范与标准固化（C++ 规范、存储模块约束、RocksDB 修改约定、评审规则、设计文档标准、P0 用例规范）→ 团队意见而非行业共识。共同点："换一个团队，这条会不会不一样"答案全是"会"。
- `图 015`（§3.8）→ 只有 L0+L1：能读懂代码、写改动、解释思路，但"跑流水线""去测试环境复现""提 MR"都要人接手；加上 L2+L3：从领取工作项开始，查改代码、部署、跑测试、分析流水线失败、提 MR、处理评审意见、回写状态——完成闭环交付。
- `图 016`（§4.2）→ **三类不会过期的东西及其 harness 形态**：只有你们知道的信息 → 验收标准、内部平台用法、模块 gotcha、价值排序；只有人能承担的责任 → 不可逆动作授权边界、gate、最终验收；评价者不能是被评价者本人（结构性偏差非能力缺口，模型再强也无法在写它的同一上下文里客观审它）→ 独立 reviewer、跨模型校验、验证类 skill。

## 6. 建议采纳（候选语义）

- **S1** 每条 harness 规则登记时归入三类之一并各自声明淘汰条件：**能力补偿类**（防某个模型当前做不到的事；须写出可复现失败与"模型不再犯此错"的检测方式）、**组织信息类**（源头在人与组织；不因模型变强过期，但可从指令形态迁移到工具/检查器形态）、**责任与结构类**（不可逆授权、最终验收、评价者与生产者分离；声明无到期并说明理由）。｜落地 A（外部状态存储）：规则登记表增加分类与淘汰条件字段｜落地 B（检查器）：新增规则时缺失分类或淘汰条件即拒绝合入｜落地 C（人工检查点）：模型代际更替时按分类逐条复审｜防御的失败：规则只增不减（F11）；结构性规则被误当补偿性规则删除（F9 之后的回归）｜删除条件：写不出（元规则）
- **S2** 模型代际更替时对"能力补偿类"规则做到期审计：不带该规则重跑其绑定的失败 Case；通过则删除，并记录到期证据。｜落地 A（检查器）：回归评估集按规则 ID 分组运行｜落地 B（人工检查点）：升级评审会逐条问"理由是不是'模型记不住/不会主动做/容易漏'"｜防御的失败：到期规则反转为负作用（F2、F3、F12、F13）｜删除条件：写不出（元规则）
- **S3** 新增指令内容须先有"无此内容时观察到的具体失败"与基线；"最少内容"定义为使该失败从复现变为不复现的内容，其余为待辩护。｜落地 A（检查器）：新增规则的变更必须引用一个已登记的失败 Case｜落地 B（人工检查点）：评审时拒绝无失败引用的规则追加｜落地 C（外部状态存储）：失败 Case 注册表（06 §2 已有）｜防御的失败：为想象的需求写文档；规则膨胀（F11）｜删除条件：写不出
- **S4** 逐行淘汰判据："一个没有本次会话记忆的执行者读到这一行，行为会怎么变？"答不出则移除；元评论、自我辩护、防御性否定默认出局。｜落地 A（人工检查点）：指令文件评审清单｜落地 B（检查器）：对指令文本做分类判定并标记无行为差异的行｜防御的失败：上下文被无动作内容占用；边界被"这条尚未强制"类元评论削弱｜删除条件：模型对无动作内容完全免疫时——目前无法检测，实际写不出
- **S5** 绝对措辞只用于真正的不变量（不可逆动作、权限边界）；判断题一律写成带条件的决策规则；优先给正例而非禁令。｜落地 A（静态指令）：措辞规范｜落地 B（运行时拦截/权限与隔离配置）：不变量本身由拦截或权限强制，指令层只做说明｜防御的失败：激烈措辞过度触发（F3）；"保守一点"被字面执行削减召回（F1）；否定引入被禁概念（F14）｜删除条件：F1/F3 回归 Case 在新模型上不再复现
- **S6** 验收判据必须能被机械判定并产出证据；"做完 X → 拿出证据 → 达标才继续"取代"先做 X 再做 Y"的路径规定；路径自由度由操作的可逆性与顺序敏感性决定，而非任务重要性。｜落地 A（检查器）：退出条件以可执行断言表达（测试通过、产物存在、命令返回码）｜落地 B（人工检查点）：验收会只接受证据不接受描述｜落地 C（静态指令）：任务定义模板含成功判据字段｜防御的失败：读完不执行、生成像样文字跳过真实测试（F5）；部分完成即宣布完成（F8）｜删除条件：写不出（组织信息类）

## 8. 该文暴露的失败模式

- **F1** 评审指令含"只报高危/保守一点" → 模型字面执行，召回下降 → 处置：让它全报、另一轮过滤 → **可构造**：同一 diff、两版指令，比较发现数
- **F2** 指令含显式自验证步骤/子代理验证，模型本身已会自查 → 过度验证、token 浪费、质量无提升 → 处置：删除 → **可构造**：同任务有/无指令的 token 与质量对照；同时是 S2 到期审计的范例
- **F3** "CRITICAL: MUST use tool"/"If in doubt use tool" → 过度触发 → 处置：降为普通措辞 → **可构造**：不需要工具的任务集上统计调用次数
- **F4** 指令文件描述目录/架构/技术栈，与代码不一致 → 执行者信过期描述或花推理调和两个来源 → 处置：删描述，只留代码读不到的约定 → **可构造**：注入与代码矛盾的架构说明，观察执行者依据
- **F5** 上下文塞入长篇"最佳实践"散文 → 执行者读完生成像样文字，跳过真实测试 → 处置：改为带证据检查点的退出条件 → **可构造**：散文版 vs 退出条件版，检查是否真实运行测试
- **F6** 审核者接受执行者摘要而非证据包（Summary substitution） → 错误未被发现 → 处置：证据包前置 → **可构造**：摘要声称测试通过但无工件，检查审核是否放行
- **F6b** 逐次审批太累 → 一次性授予过量权限（Permission laundering） → 处置：让审批便宜而不是取消审批 → 可构造为权限审计 Case（D-027）
- **F7** Gate 数量超过人的判断带宽 → 快速点头，"已审过"假象 → 处置：裁决项/证据/推荐前置 → **难以构造为回归 Case**，只能作观测指标（审查时长、否决率）
- **F8** 复杂多部分任务只完成一部分即宣布完成（Agentic laziness） → 处置：机械可判的退出条件 → **可构造**：多子目标任务，检查完成声明与子目标覆盖
- **F9** 生产者在同一上下文评价自己的产出 → 自评宽容（self-preferential bias） → 处置：独立上下文/模型验证 → **可构造**：同一产出在生产者上下文与新上下文中评分对照
- **F10** 多轮后目标漂移 → 处置：目标与成功判据写死 → 可构造：长任务中途插入干扰，检查终态是否对齐初始判据
- **F11** 同一规则在根指令、skill、agent 描述多处重复 → 改一处忘一处，冲突指令消耗推理 → 处置：单一位置 → **可构造**：制造两处版本不一致，观察执行者行为
- **F12** 模型感知上下文将满时提前收尾（context anxiety） → 处置：context resets（后随模型升级过期为 dead weight） → **可构造且已过期**：作为"到期规则"的标准样本，其价值是证明 S2 审计可执行
- **F13** 对无需分解的模型强制任务分片 → 额外开销 → 处置：移除 → 可构造：有/无分片对照
- **F14** 防御性否定"这不是指某某" → 把被否定概念引入上下文，反而诱发 → 处置：正例替代 → 可构造：否定式 vs 正例式指令对照
- **F15** 指令中的元评论"这条边界目前还不强制" → 边界被削弱 → 处置：删除元评论 → 可构造：有/无该句时越界率对照；与 D-014 冲突二直接相关
