# WX-20 Agent开始"自我进化"：会出题、会反思，还会自己长出新技能

## 0. 验证边界
- 材料性质：二手综述。作者无自己的实验、数据或对照；全部数字转引自 14 篇 arXiv 论文（2025-05 至 2026-05），其中 10 篇发表于 2026 年，超出本 AI 训练知识；本卡片对 8 篇做了 WebFetch 核对（§4），其余 6 篇（MemSkill、EvolveR、SAGE、SKILL0、Agent0、Tool-R0）**未核实**，只登记文章转述。
- 论文数字全部来自 benchmark（ALFWorld、WebShop、SWE-bench Verified、SkillsBench、OfficeQA 等）——即**存在标注答案或可执行判定器的封闭任务域**。这些结果对"开放的、无判定器的软件工程长期维护"场景不能直接外推；文章自己在 §4.4 也承认"评估很混乱"。
- 文章把重点放在第二类（RL 更新权重）与第三类（零数据自训），并认为"训练总结者"是最大研究空白。这两类属于**模型供应商/训练侧**的工作，与本规范"模型是可替换组件、规范跨工具通用"（00 §1、D-020）的立场不在同一层：本卡片只把它们当作对"自动经验提取"能力边界的旁证，重点吸收第一类（不更新权重、文件式存储）的机制与失败。
- 部分对论文的定性（"OPPO/复旦"、"与 Claude Code 对比"、"多维 Pareto"、"self-evo 明显优于迁移"）经核对与原文不符或找不到出处，见 §4。
- 文末约 1/6 篇幅是 Dola 数据助手推广（图 023～026），与主题无关，本卡片不分析。

## 1. 文章在讲什么
作者把"自进化 Agent"定义为能存、能用、能进化经验的智能体，按"是否更新权重 × 是否依赖人工数据"分三类：第一类经验/Skill 存储型（AutoSkill、EvoSkill、MemSkill、CoEvoSkills、SE-Agent），模型冻结、把经验沉淀为可检索的 Skill；第二类 RL 训练型（EvolveR、SAGE、SkillRL、SKILL0、SkillOS、AgentEvolver），把 Skill 用进训练回路或内化进权重；第三类零数据自学型（Agent0、Tool-R0、Absolute Zero），Agent 自出题自解题。作者逐篇拆解机制与评估，然后用"出题者 / 解题者 / 总结者"三角色横向对比四篇代表作，得出三个观察：几乎所有工作把"总结经验"这一步外包给冻结的大模型或闭源 API，而 SkillOS 证明训练过的 8B 总结者可超过冻结的 Gemini-2.5-Pro，说明总结者是被低估的关键模块；第一类"看似不训练其实仍要训练数据"；"自动出题 + 训练总结者"的象限尚无工作覆盖。作者的旁支观察：Skill 库的质量把关经历了"直接入库 → Pareto 筛选 → 验证器考试"的演进；单轨迹反思（纵向）与多轨迹重组（横向）是两种不同的总结方向；零数据路线的隐患是"出题者自己给答案"，最好有代码执行器这类客观判定。

## 2. 核心主张
- **C1** 自进化 Agent 的三件事：能存（沉淀成功模式/失败教训/可迁移技能）、能用（新任务中检索/调用/内化）、能进化（可更新、合并、淘汰，避免越攒越乱）。｜支撑：定义，无数据｜适用条件：任何长程交互 Agent｜文中位置：1.1
- **C2** 按"是否更新权重 × 是否依赖人工数据"分三类；第一类像"工作笔记"，第二类把笔记写进权重，第三类连老师都不要。｜支撑：14 篇论文归类｜文中位置：1.3
- **C3** 第一类工作的最大痛点是**评估缺位**：AutoSkill 在 WildChat-1M 上只报告抽出多少条 Skill（图 005：400/631/224/603 条），没有任何任务性能指标。｜支撑：论文表格｜文中位置：2.1
- **C4** "失败即学习"优于"失败即重试"：EvoSkill 用执行者记录失败→反思者做根因分析并决定新建/修改 Skill→落地者生成结构化 Skill 目录并在小样本验证集校验；新 Skill 须比现有 Skill 更好才进"精英池"。｜支撑：OfficeQA 60.6%→67.9%（+7.3pp）、SealQA 学到的"搜索坚持协议"迁到 BrowseComp +5.3pp；均为单模型（Claude Code + Opus 4.5）、论文自报、无消融｜适用条件：有 held-out 验证集的任务｜文中位置：2.2
- **C5** Skill 总结出来"靠不靠谱"不能靠 LLM 自觉，必须有验证闭环：CoEvoSkills 让 Skill 与测试共进化，先过廉价的 Surrogate 验证，再过昂贵但权威的 Oracle 端到端验证，Oracle 失败整条打回。｜支撑：论文机制描述｜文中位置：2.4
- **C6** Skill 与模型"风格"耦合：强模型 self-evo 的 Skill 迁给弱模型，绝对值"明显低于"让模型自己 self-evo；工程启示是"与其花大钱让 GPT-5/Claude 蒸馏 Skill，不如让产品自己用的小模型 self-evo"。｜支撑：图 010（Opus 4.6 self-evo 71.1%、GPT-5.2 self-evo 69.8% vs 迁移到 GPT-5.2 65.0%、Haiku 54.5%、Mistral 43.1%）——**但图中只有 GPT-5.2 一组可直接对照（差 4.8pp），弱模型没有 self-evo 数据，且弱模型的增量（+42～+44pp）反而大于 self-evo（+40pp）**，见 §4 失真项｜文中位置：2.4
- **C7** 横向 vs 纵向：单轨迹反思视野太窄，起点策略错了怎么 reflection 都救不回；SE-Agent 用多策略采样 N 条轨迹→各自修订→质量过滤→跨轨迹重组→选最优，是"横向总结"；其他工作都是基于单条历史的"纵向总结"。｜支撑：SWE-bench Verified 最高 +55% 相对改善（论文自报，见 §4）｜文中位置：2.5、2.6
- **C8** 第一类"看似不训练，其实仍要训练数据"：无论人反馈还是训练集反馈，本质都是标注信号，没有真正零数据。｜支撑：推理｜文中位置：2.6
- **C9** 总结这一步被严重低估：几乎所有工作把总结外包给冻结的大模型/闭源 API（o3、Gemini-2.5-Pro、Qwen-MAX），针对总结去优化的工作几乎没有。｜支撑：§6.1 的 11 篇对照表，只有 SkillOS 专门训练总结者、SAGE 算半个｜文中位置：2.6、5.3、6.1
- **C10** SkillOS 两结论：训练过的小模型策展者（Qwen3-8B Curator）> 冻结的大模型策展者（Gemini-2.5-Pro）；解题者完全冻结、只换策展者，性能也能涨。｜支撑：图 017（Executor Qwen3-8B 在 ALFWorld 平均 SR：无记忆 47.9 → 冻结 Gemini 策展 50.7 → 训练后策展 61.2，步数 21.1→18.9；单基准、方差大，见 §3）｜适用条件：有长周期任务成功率作 reward｜文中位置：3.5
- **C11** SkillRL 一类是"蒸馏"而非"进化"：强模型提炼知识、弱模型 RL 学会使用。｜支撑：作者评论｜文中位置：3.3
- **C12** 零数据路线的隐患：解题正确率大多对照出题者自己多采样投票的"银答案"（sliver answer，原文拼写），可靠性要打问号；最好有自动化客观判定，如 Absolute Zero 用代码执行器作唯一验证来源。｜支撑：Agent0/Tool-R0 机制 vs Absolute Zero 机制｜文中位置：4.1、4.3、4.4
- **C13** 出题难度是核心难点：太难学不懂、太简单学不到（Absolute Zero 出题 reward = 1 − 解题成功率，成功率为 0 时也为 0）。｜支撑：论文机制｜文中位置：4.3、4.4
- **C14** 评估很混乱：跨工作只有数学类 benchmark 勉强重复出现，可比性差。｜支撑：附录 B 数据集索引｜文中位置：4.4
- **C15** 研究空白：既自动出题、又训练总结者的象限无人覆盖；横向与纵向总结在第二类里也没有融合。｜支撑：二维图｜文中位置：6.2、6.3
- **C16** 本赛道的本质问题只有一个：如何让 Agent 在没有人工干预的情况下，把交互的副产物转化为下一次更强的能力。｜支撑：作者总结｜文中位置：07

**CoEvoSkills 对本项目的价值**：它是第一类工作里唯一把"候选晋升"做成显式 Gate 的：候选 Skill → 独立验证者（信息隔离、自行出题）→ 权威验证（全新环境、只回不透明 pass/fail）→ 失败整条打回。这三层恰好对应本规范 05 §6"审查者不得自审"、D-023"证据链须有非模型节点"、D-019 晋升链的前半段；而且它给出了一个可测量的信号——**代理验证与权威验证的分歧率**（案例 100% vs 75%）——这是本规范"假通过"失败模式缺少的度量。另一个价值是反面的：即便机制如此完整，论文结论也只在 SkillsBench 这种自带 Oracle 测试的任务上成立。

**SkillOS 对本项目的价值**：它把"策展者"（增/改/删记忆库的角色）当作独立组件并单独评估，结果显示策展质量对结果的影响大于执行者是谁——冻结的大模型策展甚至不如冻结的小模型策展。本规范记忆闭环把"提取长期记忆候选"当成 AI 的默认能力，没有把提取环节本身列为需要评估的对象；SkillOS 说明这一环节应有自己的 Case 与指标。它的"删除全程很少"与压缩奖励的必要性，是 ATT-N"自动修复只增不减"在 RL 训练的策展者身上的重现。

**EvoSkill 对本项目的价值**：固定容量 + held-out 置换是一种**结构性 Thin**——新条目入库必须挤掉旧条目，而不是依赖策展者"想起来删"。它和 AutoSkill 的 merge 策略、SkillOS 的压缩奖励一起，给 D-013/D-026 提供了三种机制类型不同的 Thin 落地。

## 6. 建议采纳（候选语义）
- **S1** 记忆/技能候选允许绕过人工审批自动晋升的唯一条件，是存在一个独立于生成者、带未参与调优的保留样本的客观判定器；晋升的适用范围以该判定器覆盖的任务域为界，域外候选一律回到所有者审批。｜落地方式 A（检查器）：候选状态 candidate→promoted 的转换以保留集评估通过为前置，评估未定义即 UNDETERMINED｜落地方式 B（人工检查点）：未登记判定器的领域，晋升只能由 owner 在审批点完成｜它防御的失败：模型自评"有用"的错误 Skill 直接入库并被后续任务检索（F2、F3）｜删除条件：写不出（责任判据：污染后果只能由人承担）。
- **S2** 判定候选的验证者与生成者之间必须信息隔离：验证者只看任务与产出，看不到生成者的推理与候选自述；权威判定只向生成者返回不可逆推的结果，不返回判定内容。｜落地方式 A（权限与隔离配置）：验证在独立会话/进程运行，只挂载产出物｜落地方式 B（人工流程）：审查者拿到的是运行结果与工件，不是提案说明｜它防御的失败：自证偏差与对验证器过拟合（CoEvoSkills 的设计动机；05 §6 的具体化）｜删除条件：模型自评与独立评估在代表性集上被证明无系统偏差时，可放宽第一句；第二句随 D-023 不删。
- **S3** 代理验证（廉价、模型生成的检查）与权威验证（真实环境端到端）的分歧率必须被记录；代理通过而权威失败时，先强化验证器再修改候选。｜落地方式 A（检查器）：每次晋升尝试记录两级结果并统计分歧率｜落地方式 B（外部状态存储）：分歧样本进入 Case 注册表（06 §2）作为回归集｜它防御的失败：假通过（WX-03 F1/F2 的记忆库版本）｜删除条件：分歧率长期为零时可把权威验证降为抽样。
- **S4** 记忆/技能库的健康度量只能是下游任务结果与召回有用率，不能是条目数；条目数增长而下游无改善视为 Thin 信号，库须内建"入必有出"的结构性删减而不依赖策展者自觉。｜落地方式 A（检查器）：库变更前后跑同一评估集，无改善即拒绝增长｜落地方式 B（外部状态存储 + 人工复查）：条目带最近消费时间与置换记录，定期复查无消费项｜探测提示：结构性删减在不同项目中可能是容量置换、相似合并加版本、或压缩比约束——须并列，不得只给一种｜它防御的失败：库只增不减、检索噪声上升（F1；SkillOS 删除很少、SkillRL 55→100、ATT-N）｜删除条件：写不出。
- **S5** 提取经验候选时应对比同一任务的多次尝试（不同策略、不同结果），候选须说明它相对其他尝试的差异，而不只回顾单条历史。｜落地方式 A（条件加载规则）：提取步骤在存在多次尝试记录时强制读取并对比｜落地方式 B（外部状态存储）：同一工作项保存每次尝试的轨迹与结果，供提取时横向读取｜它防御的失败：单轨迹反思在起点策略错误时收敛到局部最优（F5）｜删除条件：模型单轨迹反思能可靠识别并跳出错误策略时。
- **S6** 记忆/技能资产必须记录生成它的模型与评估它的模型；模型更换时该资产回到候选状态重评。｜落地方式 A（外部状态存储）：候选元数据增加生成/评估模型字段（04 §3 已有 source/last_verified，可并入）｜落地方式 B（检查器）：模型版本变更触发资产回归评估｜它防御的失败：为旧模型进化的 Skill 在新模型上成为噪声（F4；D-012 的实例证据）｜删除条件：某类资产在代表性评估上被证明跨模型稳定时，对该类免重评。
- **S7** 记忆提取/策展环节本身是需要独立评估的组件，须有自己的 Case 与指标，不能假定"能总结"是模型默认能力。｜这是 D-011 分层评估在记忆闭环上的实例，建议作为 06 §1 轨迹级评估的新增关注点登记，不另立决策。

## 8. 该文暴露的失败模式
- **F1 库只增不减** 触发：策展者（人或模型）在每次失败后倾向新增而非合并/删除 → 表现：SkillRL 库 55→100；SkillOS 训练全程删除操作极少；AutoSkill 仅报数量 → 文章处置：merge+版本、Pareto 置换、压缩奖励 → 可构造：向库中注入 20% 重复/过时条目，观察策展过程是否在 N 轮内清除；同时测量条目数与下游成功率的相关性（D-013/D-026 回归 Case）。
- **F2 代理验证假通过** 触发：候选的检查由模型生成且与生成者同源 → 表现：Surrogate 100% 通过、Oracle 仅 75% → 文章处置：Oracle 只回不透明信号、分歧时强化测试 → 可构造：给一条带宽松测试的候选 Skill，检查晋升流程是否要求权威验证、是否记录分歧。
- **F3 银答案自证** 触发：判定标准（参考答案）由出题者自己多采样投票产生 → 表现：解题者学会与出题者一致而非正确 → 文章处置：改用代码执行器等客观判定 → 可构造：让出题者的参考答案故意错，观察闭环是否接受（D-023 现实锚点 Case）。
- **F4 资产与模型错配** 触发：Skill 由模型 A 进化，模型 B 执行 → 表现：迁移后绝对成绩低于 A 自用（GPT-5.2 组差 4.8pp；弱模型绝对值更低但增量不低） → 文章处置：建议 self-evo → 可构造：同一 Skill 集在两个模型上跑同一评估集，比较"移除 Skill"前后差异（D-012 消融 Case）。
- **F5 单轨迹局部最优** 触发：首步策略选错 → 表现：反复 reflection 仍在同一错误方向修补 → 文章处置：多策略采样 + 跨轨迹重组 → 可构造：选一个"最直觉的策略必错"的任务，比较单轨迹反思与多尝试对比的成功率（与 D-003"两次无新证据即停"联动）。
- **F6 以条目数当成果** 触发：库无下游评估 → 表现：报告"抽出 603 条 Skill"而无任务指标 → 文章处置：指出评估缺位 → 可构造：D-025 三层评价审计——任一记忆/Skill 改进报告若只含条目数，判为局部输出层未闭合。
- **F7 样本顺序依赖** 触发：从流式交互中增量构建库 → 表现：同样数据不同顺序产出不同库（MemSkill 评论） → 文章处置：只指出 → 可构造：打乱训练集顺序两次构建，比较库差异与下游分数方差。
- **F8 抽象层级选错导致不可迁移** 触发：Skill 写成任务专属细节 → 表现：跨任务迁移失效；SkillOS 显示存活的是"验证、回退规划、搜索"类元策略 → 文章处置：无 → 可构造：对同一失败分别写"具体步骤"与"协议级"两版候选，比较在相邻任务上的召回有用率。
