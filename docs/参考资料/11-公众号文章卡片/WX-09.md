## 1. 文章在讲什么
问题：进入 Agent（"龙虾"）时代后，用户手打的提示词只是模型输入的零头，工具调用、Skill 装载、文件读取和历史对话使上下文几何级膨胀；上下文越长，账单越贵而模型召回越差（context rot），形成"花更多钱买更差的脑子"的剪刀差。作者的解法是把"省 token"重新定义为"工程化地用 AI"，浓缩成一句话：**在合适的时间，把合适的上下文，装载进合适的模型**，展开为四个动作：(1) 最小上下文——JIT 按需检索 + 把上下文当分层存储系统来卸载 + 命中提示缓存；(2) 清晰理想态——出发前回答"完美产物长啥样 / 哪些路不能走 / 怎么算干完了"，示例 > 规则 > 让模型猜；(3) Harness 架构分层——会话三段生命周期（FRESH/DRIFT/ROT）主动压缩，以及"轻主虾 + 重子虾"的调度架构；(4) 动态选型——按阶段切换模型，或"大脑 + 手脚"让强模型只做决策、便宜模型做原子任务。作者声称的结果：子任务用便宜模型后成本"降到原来的 20~30%"，按需读取"省 90%"，且效果"没掉"甚至更稳。全文结论是"省 Token 和把 AI 用好是同一件事"。

## 2. 核心主张
- **C1** Agent 时代用户输入只是账单零头，历史对话（20–40%）和工具返回/检索（10–30%）是最大两笔。｜支撑：图 002 分布图，来源为作者看板观察 + 未指明的"公开分析"，无方法说明｜适用条件：长会话、多工具的编码 Agent｜文中位置：为什么 AI 越用越贵
- **C2** 上下文越长成本线性上涨而有效注意力衰减（context rot），根因是 Transformer n² 两两关联；工具的自动压缩是有损的，会丢约束、重复提问。｜支撑：推理 + 图 003 示意图（无数据）；一手来源见 §4（Anthropic 博客、Chroma 报告）｜适用条件：通用｜文中位置：同上
- **C3** 好的上下文 = 最小的、信号最强的 token 集合；不是喂得多而是喂得准。｜支撑：转述 Anthropic 原文（未署名）｜适用条件：通用｜文中位置：别让 AI 读全文
- **C4** JIT 检索：不把整个代码库塞进上下文，只维护轻量索引（路径/查询/链接），用到时现场 grep/glob/read。｜支撑：图 004"实测 15000→1500 token，省 90%"（无条件说明）；转述 Anthropic｜适用条件：代码仓库场景｜文中位置：同上
- **C5** 把上下文当分层存储管理：当前对话窗口（L1/用完即丢）— Prompt Cache（RAM/固定前缀）— Spec/文件/知识库（硬盘/按需加载），并给出对应卸载策略：只装当下需要、稳定内容放前缀、进度摘要与中间产物落盘。｜支撑：类比 + 图 005/006/007，无数据｜适用条件：长多轮会话｜文中位置：同上
- **C6** 每隔 3–5 步让 AI 把"当前理解 + 已完成 + 待办"写进摘要文件；RAG/API 大段返回直接存文件，新会话只读结论摘要。｜支撑：图 007 操作建议，无案例｜适用条件：长任务｜文中位置：图 007
- **C7** Prompt Caching：固定系统指令和工具定义放前缀，命中部分按零头计费，"最多可降低 90% 输入成本"。｜支撑：厂商定价（见 §4 核对，一致）+ 作者 DeepSeek 账单体验｜适用条件：API 级可控前缀的场景｜文中位置：同上
- **C8** 很多 token 烧在"猜来猜去"；提示词要在正确高度（right altitude）：太低是硬编码 if-else，太高是"请专业完成"；给目标和约束，不把每步规定死。｜支撑：转述 Anthropic（未署名）+ 图 008 对比｜适用条件：通用｜文中位置：越约束越自由
- **C9** 出发前回答三问：完美产物长啥样（贴一个最像的例子）、哪些路不能走（红线）、怎么算干完了（验收标准）。精确度金字塔：示例（One-Shot）> 规则/Spec > 只提需求。示例要"策展"不是"堆砌"。｜支撑：推理 + 图 009；"策展"一句转述 Anthropic｜适用条件：通用｜文中位置：同上
- **C10** 约束和示例固化下来即"护栏"，护栏是信任的基础；工具集臃肿、功能重叠、规则模糊时人都说不清，AI 也猜不对。｜支撑：推理，无案例｜适用条件：通用｜文中位置：同上
- **C11** 会话三段生命周期：FRESH（<20 轮）放心用；DRIFT（20–60 轮）出现重复犯错、忘早期约定、啰嗦，应主动摘要后开新窗口；ROT（>60 轮）风格突变、答非所问，必须重开。三个行动信号：它问你之前说过的事 / 重复犯同一种错 / 任务阶段切换了。｜支撑：作者经验，轮数阈值无数据｜适用条件：作者的个人使用｜文中位置：主动压缩·三段生命周期 + 图 010
- **C12** 主虾只做决策与调度（理解全局、拆任务、整合结论），子虾各拿一个最小粒度原子任务、干净上下文、只交回结果不回灌过程。三个好处：主虾永不疲劳、子虾原子化可用便宜模型、需求变更只重拆受影响子虾。｜支撑：一个"写系统设计文档拆 5 子任务"的举例（非实录）+ 图 011｜适用条件：月级长期项目、中途改需求频繁｜文中位置：子智能体架构
- **C13** 拆分粒度是关键：不是拆成 5 个大阶段，而是拆到"补单测 / 校验 JSON 结构 / 从文档提取决策点"这种完全独立、不需跨轮上下文、中等模型一把搞定的原子单元。｜支撑：推理｜适用条件：同上｜文中位置：同上 + 大脑+手脚
- **C14** 动态选型方案一：按阶段切换模型（聊需求用快模型 → 起草批量用中等模型 → 啃硬骨头才用最强）；方案二"大脑+手脚"：强模型当主 Agent，性价比模型当 Sub-Agent 并行执行原子任务，整体成本"可能只有全程 Opus 的 20–30%"。｜支撑：图 012/013，数字为作者估计（"可能"）无测量｜适用条件：同上｜文中位置：别全程开着最强模型
- **C15** 省 token 和把 AI 用好是同一件事：约束越精确 → 越不用猜 → 一次到位 → 返工少 → token 省 + 质量高。｜支撑：推理链，无数据｜适用条件：通用｜文中位置：全文结论

## 6. 建议采纳（候选语义）
- **S1** 会话压缩或重开的触发条件应包含**行为信号**（执行者重复询问已确认的事项、重复同一类错误、任务阶段切换），不只依赖上下文长度或窗口余量。｜落地方式 A（人工检查点）：操作者在观察到任一信号时手动执行摘要 + 新会话｜落地方式 B（检查器/运行时拦截）：对轨迹做重复问题/重复错误检测，达到阈值时提示或强制 compaction；或在工作项状态转换（阶段切换）时自动触发 handoff｜它防御的失败：DRIFT 状态下继续工作，丢失早期约束、反复确认已定事项（F1）｜删除条件：模型在长上下文下的召回不再随长度退化（可用 Context Rot 类评估在项目模型上证伪）
- **S2** 长任务执行**过程中**应周期性外部化"当前理解 + 已完成 + 待办"，而不只在会话结束时生成交接快照；周期以可独立验证的步骤为单位而非固定步数。｜落地方式 A（外部状态存储）：执行者按步骤写入工作项状态或进度记录｜落地方式 B（运行时拦截）：在每次工具调用后/每个 Gate 通过后由 harness 自动快照状态｜它防御的失败：会话中途崩溃或压缩后无法恢复到最近一致状态；摘要仅在结束时写导致中途信息永久丢失｜删除条件：会话本身可无损持久化并可从任意点恢复
- **S3** 交给低能力/低成本执行者的子任务必须满足**原子性**：完全独立、不需跨轮累积上下文、输入输出与验收在派发时即可写清；不满足者不得降级执行者。｜落地方式 A（人工流程）：主导者按此标准拆分并在 Worker 合同中声明｜落地方式 B（检查器）：派发前校验合同字段（目标、非目标、事实入口、输出格式、验收）齐全，缺项拒绝派发｜它防御的失败：把需要全局上下文的任务派给干净窗口的子执行者，返回结果看似完成实则偏离（"指标满足而目标背叛"的多 Agent 变体）｜删除条件：写不出（这是任务结构约束，不随模型能力消失）
- **S4** 大段工具返回、检索结果和原始数据**默认不留在推理上下文**，落到可回读位置并只保留结论与位置引用；后续会话按引用重读。｜落地方式 A（外部状态存储 + 文件约定）：结果落盘，上下文只留路径/ID｜落地方式 B（运行时拦截）：harness 对超阈值工具输出自动截断并替换为可回读引用｜它防御的失败：每轮为已消化的长输出重复付费并稀释注意力（C1 ④ 项、F3）｜删除条件：模型注意力不再被无关长文本稀释，且成本不再按上下文长度计费
- **S5** 意图澄清阶段的最小产物应包含三者：一个具体的理想产物示例（或最接近的参照）、明确的非目标/红线、可判定的完成标准；三者缺一则不进入实施。｜落地方式 A（静态指令/模板字段）：工作项模板要求三字段｜落地方式 B（人工检查点/Gate）：计划评审时检查三者是否存在，缺失则退回｜它防御的失败：以模糊需求启动，靠多轮猜测收敛，返工消耗（F2）｜删除条件：写不出（意图来自人的头脑，D-020 判据一"必须写"类）
- **S6** 上下文成本应按**来源分项**可观测（系统指令、工具/技能描述、历史、工具返回、用户输入、输出），使 Thin 决策有依据。｜落地方式 A（外部状态存储/日志）：从 API 用量记录人工统计｜落地方式 B（检查器/观测工具）：轨迹分析器自动按来源拆分｜它防御的失败：只知道总账单高而不知道哪一类在膨胀，无法定位该 Thin 什么（ATT-L 同一起点）｜删除条件：上下文不再是主要成本与质量瓶颈

## 7. 明确不采纳
- 20 / 60 轮的 FRESH/DRIFT/ROT 阈值：数字外推，无数据，且轮数不等于 token 量（一轮可含数万 token 工具返回）；只采纳"行为信号"语义（S1）。
- "每隔 3–5 步写 summary.md"：具体步数与文件名均为载体绑定；采纳周期性外部化语义（S2）。
- 图 002 六项百分比、"实测 15000→1500 省 90%"、"成本降到 20–30%"、"缓存最多省 90%"：全部为该作者/厂商在未说明或特定条件下的报告，不进入任何规则；90% 是厂商上限值，官方多轮示例仅 53%。
- Opus 当大脑 / Sonnet 当手脚、"龙虾"工具、grep/glob/read 工具名：具名模型与工具，载体绑定（D-020 判据三）。
- "示例 > 规则 > 只提需求"的固定优先级排序：无证据，且与 ATT-N"参考文件必须与规则一致"的观察相比，示例与规则冲突时更需治理而非简单排序；作为经验记录，不作规则。
- "把上下文当三层存储"类比中把 Spec/知识库与中间产物同列硬盘层：与 D-006 五类区分冲突，不采纳其分类，只采纳"按需加载"。
- "多 Agent 成本剧降"作为方向性结论：与一手来源方向相反且基线不同（§5），按项目参数处理。
- "省 token 和把 AI 用好是同一件事"作为总原则：只在"上下文与提示"这一层成立；对事实来源、状态恢复、验收证据等层，省 token 与用好 AI 可能相互制约（例如为保证证据完整需额外回读成本），不作为跨层原则。

## 8. 该文暴露的失败模式
- **F1** 长会话 20+ 轮后经工具自动压缩 → 已确认的约束丢失，模型重复询问已定事项、重复犯同一种错、输出变啰嗦 → 文章处置：出现任一信号即人工摘要 + 新会话，摘要作首条消息 → 可构造：固定一条早期约束，持续注入无关工具输出使上下文膨胀并触发压缩，检查约束是否仍被遵守（回归 Case，对应 03 章 §8 与 S1）
- **F2** 以一句模糊需求（"帮我写个登录页"）启动 → 模型猜测、五六轮来回、结果仍不对 → 文章处置：启动前给示例 + 红线 + 验收标准 → 可构造：同一任务用"裸需求"与"三要素"两种输入各跑 N 次，比较轮次与验收通过率（注意 ATT-F 警告：路径噪声可能大于效果量，需组件级对照）
- **F3** 整篇文档/全部历史一次灌入窗口 → 每轮为未用内容重复付费、注意力稀释（读 5000 token 用到 10 行）→ 文章处置：只留索引，按需读取；长结果落盘只留摘要 → 可构造：同一检索任务对比全量注入与索引+按需读取的 token 与正确率（Chroma "聚焦 vs 全量提示"为现成设计）
- **F4** 单会话全程最强模型承担月级项目 → 上下文越堆越厚，中途需求变更被早期细节"压住"而被忽视 → 文章处置：主 Agent 只做决策，重拆受影响的原子子任务 → 可构造：在长会话中途注入需求变更，检查变更是否被反映（可作 D-016/D-028 相关 Case）；但文章处置的成本收益需项目自测
- **F5** 拆分粒度过粗（拆成 5 个大阶段而非原子任务）→ 子任务仍需跨轮上下文，便宜模型无法一把完成，主 Agent 被迫回灌过程 → 文章处置：拆到"补单测/校验 JSON/提取决策点"粒度 → 可构造：对同一任务用两种粒度派发，比较子 Agent 返回可用率与主 Agent 上下文增量（对应 S3）
