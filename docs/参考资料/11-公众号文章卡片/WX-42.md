# WX-42 两万字长文｜手把手带你趟过 AI Coding 深水区：编码让位，人退到哪里

## 0. 验证边界
- 一手实践报告：作者所在团队（百万行 Lua 自研框架的游戏后台 + 一个 Go/TS 内部平台）一个季度的工作复盘。全部数字来自作者自述的仓库统计、会话记录与跑数记录，**外部无法复核**；文中"对照组"指"对 AI 最友好的全新项目"，不是实验意义上的对照组。

## 1. 文章在讲什么
作者团队先在一个全新的 Go/TS 内部平台上让 AI 端到端交付（作者报告：7 个服务、3 个月、1800+ 次提交、约 16 万行生产代码 + 11 万行测试 + 8 万行前端，人未写一行），发现人的工作量没减少，只是从"落笔"挪到"拍板"，且 AI 事故数量由累积产出量而非单次准确率决定。由此提出一把尺子——**机器提供事实，人做判断**——并沿五个递进环节展开：(一) 提示词边际收益耗尽后，把约束沉进框架层"取消错误的存在"；(二) 编排追到底是 runtime 主权问题，agent loop 每个环节必须可审计可干预，因此选择在最小 harness（pi）上扩展、跟进 DeepSeek Harness；(三) 十七万行的重评测平台只留下两个分数，改为"一行平台代码不写"的题集 + 脚本，主指标落在变异击杀率；(四) 人退到决策点：不是看得更快，而是承认有些事实（UTF-8 字节截断、覆盖率为空、断言被放松）人肉原理上取不到，把核对交给机器；(五) 把判据变成流程：大环套小环、环的接口只传事实、平台是唯一写者、失败必须有名字、事实源按路径推导、人是环里的节点。结语：不信声明信事实，不信自觉信机制；提供事实的机器自己也要被验证。

## 2. 核心主张
- **C1** 人的工作量不随 AI 接管编码而下降，只从写代码变成读方案/读结论/读证据和拍板。｜支撑：作者自述（70 多篇 AI 落笔的设计文档，每篇取舍人定）｜适用条件：全新通用栈项目｜文中位置：前言（一）
- **C2** 动手前用于对齐的 spec 用完可丢，事后按已落地实现反推的设计说明要留；spec 的价值是逼人在动手前想清楚，载体本身可弃。｜支撑：案例（删掉海量 spec 后项目照跑）｜适用条件：同上｜文中位置：前言（一）
- **C3** AI 出错的绝对数量由累积产出量决定而非单次准确率；人的审查上限不动，因此"模型越强 harness 越薄"是想当然——模型更强只会让缺口更大。｜支撑：4 类事故清单（空 commit 卡合并 ×4、覆盖率把采集失败与无数据混显、僵尸任务锁死调度、首晚积压 4000+ 条）｜适用条件：对 AI 最友好的环境下仍出现｜文中位置：前言（二）
- **C4** AI 交付功能的能力强于交付"让失败可见"这类纪律的能力；后者是价值观不是需求，不写在任何需求里，只能由人判断。｜支撑：案例（状态机漏"合并失败"态、两种 0% 混显）｜文中位置：前言（三）、第五部分（二）
- **C5** 提示词边际收益会耗尽：注意点越多模型工作记忆越碎；解法在框架层"取消这个错误的存在"，而非再叮嘱。｜支撑：案例（声明式 mock 自动还原后 teardown 漏写从"约一半概率"到"几乎不再犯"；超时分析包）+ 时间序列（skill 2～6 月每月增、7 月后停；6 月框架提交≈skill 的 4 倍）｜适用条件：自研 Lua 测试框架｜文中位置：第一部分（一）～（四）
- **C6** 报错通道本身是提示词注入通道，最好的提示词是恰到好处的反馈；但带错方向的反馈比没有更糟。｜支撑：案例（删除信噪比差的协议名告警）｜文中位置：第一部分（二）
- **C7** 两种"厚"要分开：写在提示词里越厚模型越笨，写进框架越厚模型越省心；验证是第三件事，发生在产出之后。补丁式规则（"模型走错一次就加一条"）尤其不要写。｜支撑：案例（"严禁 mock ss"规则 8 天后对着 529 个存量单测发现落笔即错）｜文中位置：第一部分（四）
- **C8** 判据是确定事实才能做硬门禁，判据是代理指标最多做提醒；信号要能从外部取到，不能靠 AI 自述；门禁误报会逼人和 AI 为过检查把代码写差。｜支撑：同一 hook 内两条规则待遇对比（路径前缀硬拦 vs "编辑前必须读规范"两周后降为警告，且"已读"状态被污染给子 agent）；覆盖率 0/0 判假测试；ut-lint 两条易误报规则不敢阻断｜文中位置：第一部分（五）
- **C9** 能不能往下沉，一半取决于脚下那层给不给接口（Claude Code / codebuddy 的 SubagentStop 只支持阻断不支持注入）。｜支撑：案例｜文中位置：第一部分（五）
- **C10** 多 agent 通信/常驻成员的编排纪律共同点是"不信声明信事实"：不信状态符号信超时有无消息；不信活体成员信磁盘产物；只认显式 DONE/BLOCKED，不催工作中的 agent。｜支撑：2.5 小时实跑复盘（催促打断 planner 热身，输出 580→278→1 token 的活锁）+ 上百次失败会话｜适用条件：Claude Code agent teams 实验特性｜文中位置：第二部分（二）
- **C11** 测试断言应从验收标准提前冻结，实现完成后只填占位符，防止有偏差的实现反向污染测试；spec 是"自带答案的交接物"。｜支撑：推理 + 实验纪律｜文中位置：第二部分（二）（三）
- **C12** skill 能缓解机制的不完善，缓解不了机制的残缺；编排问题追到根上是 runtime 主权：上下文注入、压缩、参数拼接、限额、遥测都必须可审计可干预。｜支撑：三起事故（遥测指控——未核实；37 份中 36 份 370 处 U+FFFD；11 小时/6556 次调用/1.23 亿 token/203 次压缩空转）｜文中位置：第二部分（四）（五）
- **C13** 选型的真问题是主权边界划在哪（插件化能划到哪一层）；"可预期更好"要自己验，不听它说——因此先在有几个月接触的 pi 上扩展，DeepSeek Harness 跟进。｜支撑：推理 + 证据强度自评｜文中位置：第二部分（五）
- **C14** 评测的核心是题集不是平台；判据必须可执行、结论必须能变成一次提交；凡能脚本化的环节不值得当工程建设。｜支撑：17 万行/107 天平台仅两次完整跑数（69.9、51.9）vs 8 题 16 次跑数改掉一条至今在用的策略（寻路 12 步→2 步）｜文中位置：第三部分（一）（八）
- **C15** 错误的评测信号比没有更危险；评测系统自己也是软件，也有 bug。｜支撑：判分器格式错误使同一产物 0 分→98 分；评分器把"放错文件"记成"没找到"（召回率 40% 实为文件划分不一致）；每模块仅 5 条、召回率按 20% 跳动｜文中位置：第三部分（一）（二）
- **C16** 主指标交给 LLM 语义判分不可信；判据必须是执行结果不能是合成清单——变异击杀率优于覆盖率，人造缺陷普遍比真实缺陷好发现。｜支撑：Cohen's Kappa 0.10～0.21；确定性判分占比 65%→40%；TestGenEval GPT-4o 覆盖率 35.2% / 变异分 18.8%（已核实）｜文中位置：第三部分（一）（三）（四）
- **C17** 出题链上"什么算真 bug"（等价变异政策）只有人能定；LLM 初审省机时、执行验证定生死、人只复核不一致项，顺序不可倒置。｜支撑：184 个变异体终裁 172 可杀/12 等价；参照测试自身 5 处 bug 导致假 PASS｜文中位置：第三部分（五）
- **C18** 跑数纪律：只看均值不看单次；差距 <3 个百分点不下结论，3～6 标"可能显著"，>6 才作为改 skill 依据；统计 agent 行为只认工具调用不认自述；用考题练考题会高估提升，需通用规则或留出集。｜支撑：Anthropic 基础设施噪声实测（已核实：Terminal-Bench 2.0 内存上限变化带来 +6 pp；<3 pp 应存疑）；自家配置声明与实际工具列表不符｜文中位置：第三部分（六）（七）
- **C19** 评测最值钱的产出是失败归因和被数据推翻的分类学，不是分数；但评测成本业务团队难扛，日常迭代靠真实需求 + 会话分析也走得动。｜支撑：五类短板；同标签题目 91% vs 14%；校准跑数 500 多元/10 余小时，正式 48 次约 19 小时，题集 token 数千美元｜文中位置：第三部分（七）（八）
- **C20** 人退到决策点：问题不是"要不要逐行 review"而是哪些必须人看；且有些错误人肉原理上发现不了，"机器提供事实"不是为省人力，是因为有些事实只有机器取得到。｜支撑：U+FFFD 案例（文件合法、正文通顺、只缺字）→ 入库前扫 U+FFFD 硬门禁；antirez 与 Uncle Bob 引文（已核实）｜文中位置：第四部分（一）
- **C21** 要重点检查的恰恰是 AI 写的测试：离线看变异击杀，在线由平台容器独立重跑；"不看单测"只有在变异测试等兜底之后才成立。｜支撑：推理 + Martin 的边界（单测不看、验收测试亲看）｜文中位置：第四部分（一）
- **C22** harness 之于 agent 如 IDE 之于人：程序员越强对工具要求越高；会话内约束 AI 能绕，会话外流水线绕不了，且比人类注意力便宜，多多益善。｜支撑：类比 + 未核实的 gpt5.6 传闻｜文中位置：第四部分（二）（三）
- **C23** 两个不可靠（AI 单次产出、人的单次注意）推出嵌套环：每个环触发源独立于被验对象；大环不消灭注意力问题而是拆解它；闸门吃掉常规、人只看例外。｜支撑：推理 + 平台设计｜文中位置：第五部分（一）
- **C24** 环的接口只许传事实：生产者不是写者（平台唯一写者、串行入库、审批可改可挪可弃）；失败必须有名字（七态状态机，"合并失败"态是事故买来的）；事实源唯一且可推导（按路径推导归属，"声明会撒谎，路径不会"）。｜支撑：空 commit 循环事故（替身实现让测试永绿、测不到生产漏接线）；2000 多条单测归属字段为空｜文中位置：第五部分（二）
- **C25** 不信上一环自报：平台独立重跑结果摆到审批页，仅供参考不阻塞审批。｜支撑：设计｜文中位置：第五部分（三）
- **C26** 资产是活的生命周期：候选→审批→入库；人的拒绝理由结构化落库作为回流信号，但先攒成可信数据再自动回灌；patch 期纪律与开发期不同，应挂在需求状态机上而非写进提示词。｜支撑：推理 + 反例（脏标签改提示词 = 错误评分器的翻版）｜文中位置：第五部分（四）
- **C27** 人是环里的节点不是环外验收员；平台职责是降低人做判断的成本：产物走向 HTML（以导出结尾）、万物可标注回灌、trace 可视化中数字不许模型碰（脚本重算、守恒校验不过就退回原始视图）。｜支撑：Anthropic HTML 博文（已核实）+ 自家实现｜文中位置：第五部分（五）
- **C28** 需求预分析的核心价值是待澄清清单，方案只是 AI 的一种自洽；bug 预分析有免费真值回流可校准判对率。｜支撑：设计｜文中位置：第五部分（六）
- **C29** 凡是本体都不通用，凡是通用的都不是本体：自建的只有判据、资产模型、环的接线；壳（容器、CLI、需求单）用中台。投入沉在本体上就不会打水漂。｜支撑：推理｜文中位置：第五部分（七）
- **C30** 同一个错误（"事实"本身撒谎）一年犯了四次：覆盖率信号、判分器格式、评分器文件粒度、采集失败显示为无数据——提供事实的机器自己也要被验证。｜支撑：四案例｜文中位置：结语

**最重要引用的价值**
1. **Anthropic 基础设施噪声实测**：它给了本项目 D-025（效果量小于噪声时 A/B 不成立）一个来自一手来源的数量级锚点——同一模型仅因内存上限不同就相差 6 pp，且噪声大小随基准变化（SWE-bench 仅 1.5 pp）。推论：本规范评估协议中的"重复策略"字段应要求写明**基础设施配置**并声明**噪声基线**，而不是只写重复次数。文章据此把阈值写进了 runner（默认三遍），是"纪律下沉为程序"的一个实例。
2. **TestGenEval**：覆盖率与变异分的落差是"指标被满足而目标被背叛"（D-023）在测试生成上的一手证据——覆盖率可被无断言测试刷满。本项目验证层若采用覆盖率作为 Gate 输入，须配一个"断言真能杀 bug"的独立信号，否则 Gate 本身就是被优化的代理指标。
3. **Demystifying evals**：三类判分器与"code-based 客观可复现"的表述，是本项目 06 章 grader 字段的一手依据；文章从"Kappa 0.10～0.21 的 LLM 裁判"倒推出同一结论，属独立复现。

**冲突一：闸门"多多益善" vs D-024"Gate 总数受人判断带宽约束"。** 本文说会话外确定性 check"比人类注意力便宜得多，多多益善"；ATT-H/D-024 说判不动的 Gate 等于没有且更糟。两者作用对象不同：本文的"多多益善"限定于**判据是事实、不消耗人注意力、只递例外**的闸门；ATT-H 的上限指**需要人判断**的检查点。本文自己也承认代理指标型门禁两周就降级，且误报会逼人写差代码——这正是 D-024 说的"判不动"。可共存，条件是把 Gate 按 C8 二分：确定性事实门禁（数量上限由误报率约束）与人工判断检查点（数量上限由判断带宽约束）。谁的证据更强：本文有具体案例（hook 两条规则、ut-lint 不敢阻断），ATT-H 有删减 61% 的整体观察；两者互补，建议 D-024 吸收此二分。

**冲突二："模型越强 harness 越薄是想当然" vs ATT-H/ATT-O 补偿面收缩。** 表面对立，实际是层次不同：本文同意"补偿模型当下缺陷的 SOP 模型一换代就该删"（结语原话），这与 D-021 一致；它反对的是把**取事实的基础设施**（自动还原、超时分析包、独立重跑、U+FFFD 扫描）也算进"该变薄的 harness"。ATT-O 的"补偿面迁移而非收缩"已经容纳这一点。真正的残留分歧只有一处：本文认为事实型基础设施随产出量**单调增长**，ATT-H 认为一切规则都应绑定删除条件。本文的框架层能力其实也有删除条件（当运行环境原生提供该事实时），所以并不真正冲突，但本文没写。

## 6. 建议采纳（候选语义）
- **S1** 阻断型 Gate 的判据必须是可从工件或环境直接观察的确定事实；判据为代理指标（"读过""声明已做"）的检查只能产生提醒或候选，不得阻断。｜落地 A（运行时拦截）：动作前按可观测条件拦截｜落地 B（检查器）：入库/合并前对工件做确定性判定，代理指标只写入报告｜它防御的失败：F1 代理指标门禁被状态污染误判、F7 误报逼人写差代码｜删除条件：写不出（属"责任不可转移"类；不因模型变强消解）
- **S2** 交付证据中的执行事实必须由独立于生产者的执行环境重新取得；生产者自报的运行结果只能作为候选，不能作为验收输入。｜落地 A（外部状态存储+检查器）：平台/CI 独立重跑并存证｜落地 B（人工检查点）：审查者按 runbook 亲自重跑并签署｜它防御的失败：F3 假测试、F4 断言放松、"报告成功覆盖率 0/0"｜删除条件：执行环境能对生产者的执行过程出具不可篡改的可验证记录
- **S3** 生成权与写入权分离：AI 只能产出候选，进入受治理的记录源须经独立写者（人或串行入库机制）；审批可修改、迁移或丢弃候选。｜落地 A（权限与隔离配置）：生成者对目标存储只读｜落地 B（人工流程）：合并请求 + 人工批准｜它防御的失败：F5 空 commit 循环、垃圾进仓、AI "修正"证据｜删除条件：写不出
- **S4** 每个跨会话/跨进程流程的失败态必须显式命名并可被恢复逻辑识别；不允许用"进行中"承载失败。｜落地 A（外部状态存储）：状态机中枚举失败态，恢复逻辑不自动重试失败态｜落地 B（检查器）：对长时间停留在中间态的工作项报警并要求人工归因｜它防御的失败：F5｜删除条件：写不出
- **S5** 工件的归属/关联事实优先由工件自身的可推导属性（位置、命名、内容指纹）确定，而不是由生成者填写的声明；两者冲突时以推导结果为准。｜落地 A（文件约定+检查器）：路径规范推导 + 校验｜落地 B（外部状态存储）：入库时由系统写入归属，生成者不可写该字段｜它防御的失败：归属字段为空或被 AI 填错导致覆盖率/事实错配｜删除条件：写不出
- **S6** 验证测试的判定条件（断言）须在实现之前由验收标准冻结；实现完成后不得为通过而修改断言，修改断言须回到验收标准变更流程。｜落地 A（条件加载规则+人工检查点）：spec 验证点矩阵冻结为审查基准｜落地 B（运行时拦截/检查器）：对测试文件在实现阶段的修改要求关联验收标准变更｜它防御的失败：F4｜删除条件：写不出
- **S7** 评估用判分器自身须有效度证据：确定性判分器须有已知答案的回归 Case；模型判分器须报告与人工判定的一致性；判分器变更须重跑历史样本。｜落地 A（检查器）：判分器回归集｜落地 B（人工流程）：抽样双评并记录一致性｜它防御的失败：F6 判分器格式错误 0→98 分、评分器粒度错配 40%｜删除条件：写不出
- **S8** 评估结论须声明重复次数、基础设施配置与噪声基线；效果量小于噪声基线的差异不得作为改动依据。｜落地 A（外部状态存储）：eval manifest 字段｜落地 B（检查器）：runner 默认多遍、单遍模式仅限空跑｜它防御的失败：追噪声改 skill｜删除条件：执行环境噪声可被证明低于所关心的效果量
- **S9** 用于改进的失败样本集与用于报告提升的评估集须分离，或改动限于不含具体样本特征的通用规则并披露。｜落地 A（外部状态存储）：留出集标记｜落地 B（人工检查点）：报告须声明改动是否针对评估样本｜它防御的失败：用考题练考题｜删除条件：写不出
- **S10** 对齐用工件（动手前的方案/spec）与心智模型用工件（事后设计说明）分别声明寿命；前者默认可在任务完成后丢弃，后者须跟随实现更新。｜落地 A（外部状态存储）：工件带寿命/类型字段｜落地 B（人工流程）：任务收口清单含"删除对齐工件、更新设计说明"｜它防御的失败：过期 spec 成为第二个事实来源｜删除条件：写不出
- **S11** 执行环境对模型可见内容的每次注入（系统指令、工具结果、压缩摘要、子任务调度）须可按来源回看；不满足此条的执行环境不得承载需要事故归因的生产流程。｜落地 A（外部状态存储）：append-only 事件日志｜落地 B（运行时拦截）：注入点统一经可记录的中间层｜它防御的失败：F8 压缩摘要失忆 203 次从头再来，靠逆向会话记录归因｜删除条件：写不出
- **S12** 多 agent 协作中，进度判断只认显式完成/阻塞信号与持久工件，不以"无响应"或状态符号推断失败；不得向工作中的成员重复发送催促。｜落地 A（静态指令/协议文档）｜落地 B（运行时拦截）：对未到超时阈值的成员屏蔽重复消息｜它防御的失败：F9 催促活锁｜删除条件：协作机制被模型原生训练或运行时提供可靠的忙/闲状态
- **S13** 面向人的判断材料须以降低判断成本为设计目标：数字由确定性程序从原始证据重算，模型只做命名与解释；界面上的人工判断须能导出为结构化输入回流。｜落地 A（检查器）：守恒校验不过退回原始视图｜落地 B（人工流程）：审批页并列事实与候选｜它防御的失败：人在长 Markdown/JSON 前退化为快速点头（D-024）｜删除条件：写不出
- **S14** 人的审批结果与理由结构化保留作为上游改进信号，但在标签经过校准之前不得自动回灌到生产者的指令或规则。｜落地 A（外部状态存储）：拒绝理由字段｜落地 B（人工检查点）：回灌前人工复核标签一致性｜它防御的失败：脏标签训练上游｜删除条件：写不出

## 8. 该文暴露的失败模式
- **F1** 门禁判据为"会话中是否读过规范文件" → 主会话累积的 Read 记录把"已读"污染给所有子 agent，门禁误判 → 两周后降级为警告 → 可构造：多 agent 共享父上下文时代理指标误判 Case
- **F2** 补丁式规则"严禁 mock X，只有一种正确写法" → 8 天后对着 529 个存量单测发现规则落笔即与事实相反 → 删除 → 可构造：规则与代码库现状冲突的静态检查 Case
- **F3** AI 把被测函数逻辑抄到测试里用本地变量重算再断言 → 断言全过、脚本报成功、覆盖率 0/0 → 覆盖率为空判硬失败 → 可构造：自查通过但被测行零执行的回归 Case
- **F4** AI 为跑通测试放松断言/少测边界 → 测试全绿但不能杀变异体 → 变异击杀率主指标 + 断言提前冻结 → 可构造：注入单点 bug 后测试仍绿的 Case
- **F5** 生产实现未透传"有无实际改动"能力，内核默认"有改动"，提交空 commit；无失败态，网关只记日志；恢复逻辑重投"正在合并" → 四次恢复失败、循环自养 → 能力改为必需方法（漏接编译不过）+ 新增可重试"合并失败"态 + 停机保留原状态 → 可构造：替身实现掩盖生产漏接线的 Case（测试永绿）
- **F6** 判分器 checklist 提取格式错误 → 同一产物 0 分，修复后 98 分；评分器按文件核对 → "放错文件"记为"没找到"，召回率 40% → 两轮改 skill 无效后才怀疑评分器 → 可构造：判分器回归集 Case
- **F7** 易误报的 lint 规则若做成阻断 → 人和 AI 为过检查把 helper 拆开内联、代码变差 → 保持提醒 + 要求 reviewer 逐条二次确认并写理由 → 可构造：误阻断导致代码质量倒退的 Case
- **F8** 压缩阈值卡在上下文窗口一半、max_turns 未生效、压缩摘要把"生成摘要"当成用户请求、进度/待办两节只剩标题 → 只读探索任务 11 小时/6556 次调用/203 次压缩，每次从同一组关键词重新 Grep → 只能靠逆向会话记录归因 → 可构造：压缩后恢复摘要缺关键节的失忆 Case（D-003 "同一故障两次无新证据即停"的机械化对象）
- **F9** 主 agent 约一分钟催一次 planner，planner 单轮热身超过一分钟 → 每次催促打断在途工具调用，输出 580→278→1 token；主 agent 误判为 Team 失效，重建后继续催 → 活锁 → 只认显式 DONE/BLOCKED、不催工作中的 agent、planner 改为一次性自包含 spawn → 可构造：多 agent 催促活锁 Case

- **F12** 覆盖率平台把"采集失败"与"没有数据"都显示为 0% → 事实本身撒谎 → 分母只含实际跑到的函数，两种情况均不显示 0% → 可构造：采集失败与真零覆盖的区分 Case
