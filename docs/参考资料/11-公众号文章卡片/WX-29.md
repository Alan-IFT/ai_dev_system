## 1. 文章在讲什么
DeepSeek 发布开源 agent harness DSH，口号"everything is a plugin"。作者跳过所有框架都一样的"检测工具调用—执行—回填—循环"，专讲 DSH 与他人不同的几处运行时设计：(1) 底座 Cordis 的插件生命周期（Fiber 状态机）与"可逆副作用"（每次副作用登记一个撤销函数，卸载时 LIFO 回放）；(2) 框架靠 API 唯一入口、Proxy、状态机、事务性 HMR 四层约束保证副作用被追踪，并明确声明"边界外不追踪"；(3) `ctx.<service>` 靠 Proxy + 沿 Fiber 链查找解析，作用域隔离天然成立；(4) agent loop 里的几处细节：工具结果可自行宣告轮次结束、max-tokens 状态粘性、turn-stopping 可被插件截住、并发安全按参数动态判定、工具执行前/防护/执行/后四段各自独立注册；(5) preset 的两层 scope 链（真实派生 + WeakMap 影子路由）让一份预设实例被多会话复用；(6) Code Mode 用 `worker_threads` 而非 V8 isolate/`node:vm`，把 worker 当敌对方；(7) 工具注册的分层遮蔽算法与 `run_code` 保留名。最后与 Codex 比五点差异（核心循环可否替换、沙箱位置、拆分粒度、隔离选型、工具暴露方式是静态标记还是运行时计算），并展望"可对自己热更新的运行时"会成为"Agent 界的 VSCode"。作者没有声称任何效果结果，只声称架构上的可能性。

## 2. 核心主张
- **C1** "可逆副作用"是"一切皆插件、可热插拔"成立的前提：每次上下文修改都通过唯一原语登记并附带撤销函数，卸载 = LIFO 回放撤销，子插件随父插件级联卸载。｜支撑：源码片段 + 论文定义（时间可组合性）｜适用条件：单进程 TS/JS 运行时｜文中位置：一、二
- **C2** 运行时只保证"逆会被调用"（结构性），不保证"逆写得对"（语义性）；逆的正确性是作者义务而非运行时验证的性质。｜支撑：作者转述论文原话，本卡未能核到原文｜适用条件：同上｜文中位置：三
- **C3** 框架用四层机制堵住"绕过登记"的路径：API 入口唯一、Context 是 Proxy、已卸载 fiber 上建 effect 直接抛错、HMR 导入失败整体回滚。｜支撑：源码片段｜适用条件：同上｜文中位置：三
- **C4** 边界按"位置"而非"介质"划分：系统能独占修改且能恢复原状的位置在边界内、可追踪；公共文件、别的进程也在写的东西、发射出去的数据在边界外，框架不追踪也不声称能恢复。获取阶段可逆，发射阶段不可逆，只能靠暂缓发射（withholding）或补偿（compensation）。｜支撑：转述论文 §6.1，未核到原文｜适用条件：任何有外部副作用的系统｜文中位置：三
- **C5** 边界可以移动：把外部资源包成"服务"，所有访问受限于一组各自带逆的操作，义务从"每个插件作者"收敛到"少数服务实现者"。｜支撑：转述论文 + `ctx.database/ctx.assets` 例子｜文中位置：三
- **C6** 恢复的正确性标准是**观察等价**而非物理复原：没有任何观察者能区分恢复前后即算恢复。｜支撑：论文 §3.3.2（本卡已核到原文"two states are related when no observer can distinguish them"）｜文中位置：三
- **C7** 服务解析 = Proxy 拦截 + 沿 Fiber 链向上查找；子看得到父、父看不到子，所以作用域隔离不需要额外可见性逻辑，"挂在哪一层"即"谁能看到"。｜支撑：源码片段｜文中位置：四
- **C8** 同一接口两套独立实现（自家模型适配器 + 第三方多厂商适配器）互不知情却都能满足接口，是接口通用性的旁证（"设计验证双胞胎"）。｜支撑：官方文档说法（未核）｜文中位置：四
- **C9** 轮次结束权从 loop 内部移到外部：工具结果可带 `concludesTurn`，`agent/turn-stopping` 让任何插件在最后一刻决定"还没完"；loop 不需要预知有多少种"还没完"的理由。｜支撑：源码片段；DSH 文档确认 `agent/turn-stopping` 为 serial 事件｜文中位置：五
- **C10** 被截断过的信号不能被后续正常步骤覆盖（max-tokens 粘性）。｜支撑：一行源码｜文中位置：五
- **C11** 并发安全不是静态白名单，而是每次调用前按参数询问工具；结果按模型给出的原始顺序提交而非完成顺序。｜支撑：源码片段｜文中位置：五
- **C12** 工具执行前检查、内置防护、执行、后处理是四个固定顺序、独立注册的挂载点；新增审批策略不改执行链路。｜支撑：源码描述；DSH 官方流水线图证实（见 §5.1）｜文中位置：五
- **C13** preset 两层 scope 链：全局→预设是真实上下文派生（一份预设实例只建一次），预设→会话是 WeakMap 逻辑父子表（不新建节点）；子 agent 继承父 preset 只是查表，同步、零挂载。当前生效 preset 从事件日志倒扫最新一条 `agent-preset/selected` 得出。｜支撑：源码片段｜文中位置：六
- **C14** Code Mode 选 `worker_threads`：同进程 `node:vm` 原型链可逃逸、热循环无法外部打断；独立线程换来独立 V8 堆与可强杀。宿主把 worker 当敌对方：消息逐字段校验、`Object.create(null)`、`Object.hasOwn`。代码里的工具调用走与模型直接调用完全相同的流水线，只是入口不同。｜支撑：源码片段；DSH 文档确认"fresh Node worker thread""每次运行独立无状态"｜文中位置：七
- **C15** 工具可见性按 scope 链在运行时实时计算：全局层 → 祖先层就近覆盖 → 限制规则筛一遍 → 当前 scope 自己注册的覆盖一切（**即使限制规则禁了这个名字**）。｜支撑：源码描述；DSH 文档 `ToolRestriction` 一节证实"own registrations stay exempt"｜文中位置：八
- **C16** 与 Codex 的差异归结为一个判断：DSH 里没有地位特殊的模块，循环本身、沙箱、UI、会话记录都处在同一可替换层级；Codex 的模块最终服务于一个不可替换的核心循环。｜支撑：作者对两边源码的观察，无实测｜文中位置：九
- **C17** agent 产品的竞争力除了模型还取决于运行时层：扩展成本、换组件的代价。｜支撑：推理，无证据｜文中位置：结语

**Codex 源码**：证实同一语义"工具对模型的可见性"在 Codex 是**静态声明枚举**、在 DSH 是**运行时按作用域链计算**——这是 D-020 硬性检验所需的"两种机制类型"的现成实例。

## 5. 与本规范现有理论的对照

## 6. 建议采纳（候选语义）
- **S1** 模型每一次推理所见的全部输入，必须能从一份只追加的记录完整重建；不存在与该记录不一致的第二份上下文。｜落地方式 A（外部状态存储）：事件日志为唯一源，提示词、恢复、界面都从它派生｜落地方式 B（检查器）：会话结束或压缩后校验"提示词中每一段都能在记录中找到来源"，找不到即失败｜它防御的失败：压缩摘要、注入的指令或工具输出脱离记录，恢复时无法解释模型为何如此行动｜删除条件：写不出（这是可审计性要求，不随模型能力消解）
- **S2** 审批的结果集合是封闭的，且"无人应答/应答者缺失/应答者出错"必须等价于拒绝；"永不询问"策略必须在任何可插拔应答者之前生效，后加入的应答者不能推翻它。｜落地方式 A（运行时拦截）：审批服务在分发前先应用策略，缺席即拒绝｜落地方式 B（人工流程 + 权限配置）：无审批人的时段等于禁止执行该类动作，写入权限配置而非提醒｜它防御的失败：应答者未部署或超时时动作被默认放行；后配置的自动应答者绕过"不询问"策略｜删除条件：写不出（责任不可转移）
- **S3** 只能"拒绝或弃权"的检查器与能"授权"的机制必须是不同的组件，且前者不可被后者重排到其之后。｜落地方式 A（运行时拦截）：守卫链单调、身份受保护，审批在守卫之前解析｜落地方式 B（人工检查点 + 文件约定）：否决清单与授权清单分开维护、分开签批｜它防御的失败：把一个授权机制注册在守卫之前使守卫失效（DSH 明确防此事）｜删除条件：写不出
- **S4** 每个可增删的 Harness 组件，其对共享环境的修改必须能在移除该组件时被完整逆转；不能逆转的组件不算"可删减"。｜落地方式 A（运行时拦截）：注册即登记撤销动作，卸载时逆序回放｜落地方式 B（外部状态存储 + 人工流程）：每个组件登记它写入了哪些文件、配置、权限，Thin 时按登记逐项回退并回读确认｜它防御的失败：Thin 一个组件后残留其副作用（悬挂监听、多出的权限、遗留的规则文件）使评估结果无法归因｜删除条件：环境能自动发现并归因所有残留副作用时可删
- **S5** 区分"边界内"与"边界外"动作：数据尚未离开系统的动作可自动回退；数据已发射（写公共位置、对外发送、付款）的动作只能靠暂缓或补偿。人工检查点应放在发射之前而非动作之前。｜落地方式 A（权限与隔离配置）：发射类工具默认需要审批，获取类工具默认放行｜落地方式 B（人工检查点 + 状态工件）：工作项状态机把"待发射"设为独立状态，跨越它需要指名责任人｜它防御的失败：把审批带宽耗在可逆动作上（D-024 判不动的 Gate），而真正不可逆的发射无人看｜删除条件：写不出
- **S6** 上下文注入的静态指令必须有显式总预算，超预算时先整份丢弃更宽泛的来源、最后才截断最具体的来源，并把丢弃/截断事实告知模型。｜落地方式 A（条件加载规则）：加载器按"具体优先"策略裁剪并输出可见提示｜落地方式 B（检查器 + 人工流程）：规范仓库设字数上限，CI 拒绝超限，调上限须在变更中辩护｜它防御的失败：宽泛指令挤掉具体指令、指令被无声截断（ATT-N 注意力 U 形）｜删除条件：模型对超长指令的遵循率不再随长度下降时可删
- **S7** "当前生效的是哪套配置/预设"是一项可从记录推导的状态，切换必须留下事件，而不是只改内存。｜落地方式 A（外部状态存储）：选择事件追加进日志，倒扫得出当前值｜落地方式 B（文件约定 + 检查器）：配置指针文件带版本，变更由检查器核对与日志一致｜它防御的失败：恢复会话时用错预设/权限档｜删除条件：写不出
- **S8** 决策记录必须写出被否决的备选；被否决的记录只在"仍能阻止一个可能的错误"时保留，否则删除；已归档的记录冻结并不再作为当前行为的权威。｜落地方式 A（文件约定 + 检查器）：路径编码生命周期，格式与链接由检查器校验｜落地方式 B（任务系统 + 人工流程）：决策条目带状态字段，定期复审删除无防错价值的否决项｜它防御的失败：决策日志只增不减（ATT-N）、过期记录被当成现行规则（D-016 过期 handoff 同型）｜删除条件：写不出

## 7. 明确不采纳

- `worker_threads` vs V8 isolate vs 独立进程的隔离选型——载体绑定；且 Codex 一侧正在变化，任何对比结论都会过期。
- 核心循环是否可替换、沙箱是插件还是内建、包/crate 数量——载体特性；D-020 §7：正文不因某工具的约定而改。
- preset 的两层 scope 链、WeakMap 影子路由——实现细节。
- "Agent 界的 VSCode""龙虾可以下班了""原型到成品的距离被压缩"——无证据的展望；DSH 自身 SAFETY.md 声明"未经安全审计、不得视为生产就绪"。
- 1008 个仓库、各 star 数、近 40 家厂商——规模计数，未核实且与规范无关。
- 文章对 Pi 的定性比较——已发现一处事实错误（§4），整段对比不作依据。
- 把 Claude Code / Codex hooks.json 桥接当作"跨工具通用"的解法——它证明的是载体可被翻译，不是语义可以写成某一家的事件名；正文仍只写语义。

## 8. 该文暴露的失败模式
- **F1** 热更新期间加载一个配置缺字段的 UI 插件 → 整个 Web 前端进入"Failed to load plugins"页，作者称"把 UI 搞崩"（图 005）→ 文章处置：无，归因为 HMR 不稳定；但截图显示是 loader 配置校验失败（fails loud），而"UI 也是插件"意味着**恢复用的界面本身可被坏插件拿掉**——正是论文警告的"有缺陷的自我修改可能废掉唯一能用来恢复的进程"的界面版 → 可构造：装入缺字段的界面插件，观察是否还能通过非界面通道回滚
- **F2** 某步因输出上限截断，后续步骤正常完成 → 若状态可覆盖，上层看到"正常完成"而丢失截断信号 → DSH：max-tokens 状态粘性 → 可构造：强制一次截断后再正常一步，检查最终结束原因
- **F3** 一个 preset 注册了名为 `run_code` 的工具 → 与 Code Mode 传输入口冲突 → DSH：注册时无条件拒绝该保留名 → 可构造（命名空间冲突类）
- **F4** Code Mode 中模型代码在消息里塞 `__proto__`/`constructor` 字段 → 宿主原型污染 → DSH：逐字段校验、`Object.create(null)`、`Object.hasOwn` → 可构造：安全回归 Case
- **F5** preset 挂载过程中某个服务泄漏到预设作用域之外，或某行插件停在不可用状态 → 其他会话被污染 → DSH：整体回滚 → 可构造
- **F6** 同一工具带同样参数被连续调用多次 → 循环空转 → DSH `guard`：advisory 提醒（不阻断） → 对应 D-003"同一故障连续两次无新证据时停止"的**运行时提醒形态**，可构造
- **F7** 审批应答者未部署/崩溃/返回非法值 → 若默认放行则危险动作直接执行 → DSH：一律 `unavailable` → 拒绝 → 可构造：拆掉应答者后发起需审批工具
- **F8** 子作用域自行注册与上层限制同名的工具 → 限制被绕过 → DSH：设计上允许（见 §5 冲突） → 可构造为 D-027/D-028 的反例 Case
- **F9** 插件初始化中途抛错（配置校验失败、依赖缺失）→ 残留半初始化状态 → DSH：fiber 进 FAILED 并逆序清掉已应用的效应 → 可构造：Thin/Add 的原子性 Case
