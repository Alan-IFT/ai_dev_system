## 1. 文章在讲什么
与 WX-21 §1 完全相同，此处只压缩为三句：(1) Graph Engineering 一词由 Steinberger 2026-07-17 的一句推文催生，词是旧酒新瓶，但"从编排一个智能体到编排一群智能体"的重心迁移是真的；(2) 单循环有五个结构性缺陷加目标失明，解法是把任务、依赖、状态、权限、预算、审批做成机器可执行的图，其杠杆在确定性（判断/验证分离、确定性工作交给代码、现实锚点）而非智能体数量；(3) 是否上图是一笔摊销账（重复任务值、一次性任务是税），角色图必须慢变可审计，LangGraph 检查点机制与 LinkedIn/Uber 案例证明它已在生产。

**对本项目最有价值的三个引用**
- **引用 4（durable execution）**：给第 5 层"检查点/恢复"补上本规范和 WX-21 S3 都没写的一条约束——恢复不是"从断点继续"，而是"从上一个检查点之后**重放**"，因此任何跨检查点的副作用（发邮件、付款、提 PR、写库）必须幂等或有回执可查；持久化时点应由"丢失状态的后果"决定。这直接关联 D-016（状态工件）与 D-009（证据绑定），并是 F1 的来源。
- **引用 1/2（ADK 2.0）**：一个头部框架在 2026-06 把"顺序/并行/循环模板"标为被"基于图的工作流"取代，并把"任意节点可持久等待人回答、跨进程重启恢复"做成一等能力。这是本文论点（loop → graph 是真实的工程重心迁移）**最强的一手证据，而本文没有用它**。对本项目：它印证"人工审批是图内一等节点"（WX-21 图 005 观察）在两个独立框架（LangGraph、ADK）上都成立，是 D-020 两种机制类型检验的现成素材。

## 6. 建议采纳（候选语义）
仅列 WX-21 S1～S6 未覆盖的：
- **S1** 从持久化状态恢复长任务时，恢复点与上次检查点之间已发生的**不可逆副作用**必须被识别并跳过或补偿；执行单元不得假设"恢复 = 从中断行继续"。｜落地方式 A（外部状态存储）：每个不可逆动作先写回执（动作标识 + 目标 + 时间），恢复时执行前先查回执，存在即跳过｜落地方式 B（人工检查点 / 交接合同）：交接工件列出"已执行的不可逆动作清单"，接手者按清单核对后再续做｜它防御的失败：恢复后重复发送邮件、重复付款、重复提交变更（F1）｜删除条件：执行环境对全部外部副作用提供 exactly-once 保证——这仍是载体能力而非模型能力，语义不会消失，写不出
- **S2** 状态持久化的时点由"丢失该状态的后果"决定：在不可逆动作之前必须同步持久化；纯计算步骤可延迟持久化以换取吞吐。｜落地方式 A（权限与隔离配置）：不可逆工具的调用前置条件包含"当前状态已落盘"｜落地方式 B（人工流程）：任务立项时按动作不可逆性标注哪些步骤需要"先记录再执行"｜它防御的失败：进程崩溃后状态丢失，重跑时把已付款/已发布当成未发生（F1 的另一面）｜删除条件：写不出
- **S3** 规范与决策日志引用的案例必须登记证据等级三态：**实测报告 / 具名二手转述 / 说明性示例**；说明性示例不得作为决策的"原因"栏证据，只能作为失败分类的命名来源。｜落地方式 A（检查器）：决策条目的引用字段必须含等级，缺失则条目不进入生效登记表｜落地方式 B（人工流程）：评审时对每个案例追一次出处链｜它防御的失败：虚构示例经两次转述升格为"真实案例"进入决策依据（F2）｜删除条件：写不出（这是治理纪律，不随模型能力变化）
- **S4** 材料入库前做内容级去重（而非按标题/作者/账号去重），同源材料只登记一次并互相链接。｜落地方式 A（检查器）：入库时计算与已有材料的段落级相似度，超过阈值即标同源｜落地方式 B（人工流程）：阅读员在卡片 overlap 字段必须写明比对方法与结论｜它防御的失败：同一二手材料被计为多份独立证据，抬高某主张的"被反复引用"权重（F3）｜删除条件：写不出
