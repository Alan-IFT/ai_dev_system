## 总图为了画出那两条关系，动了什么

上一版把「超限与门禁失败 → 升级到人」与「不可逆动作 → 只能由人授权」**刻意没画成边**，理由记作「会压过交付线」。本轮复核确认：那不是可读性偏好，是**在原坐标下拓扑不可解**——
`human` 在证据与追踪以西、`guard` 在其以东，而交付线的 `verify → evidence` 必须从东侧下来插进 `evidence`，于是任何「守卫绕底走到人」的路线都要穿它；八组走法实测最小错误数恒为 1，且每次都撞在交付线上。

结论是「原骨架不可解」，不是「这两条边不可画」。本轮重排了两个坐标，两条边随即变成西侧短边：

- **控制行次序改为：守卫与权限边界 · 评估与演进 · 证据与追踪 · 验证与测试**（守卫与证据对调）。`verify → evidence` 退化成同行短边，底部走廊整条空出来。
- 「超限、门禁失败、告警升级到人（21）」走守卫左侧 → 西侧竖廊 → 人的右侧；「不可逆动作只能由人授权（17）」走人的底部 → 西侧竖廊 → 下方走廊 → 守卫底部。两条边零相交、零走廊冲突。
- 连带改动：**「动作或阶段转换前阻断并回显原因（29）」的落点从上下文装配改为状态工件**。这不是走线调整而是语义调整，依据是 [31 §1](../31-守卫与权限边界.md)「给 20 状态工件 阻断结论、屏障范围与失败回边」——改指之后这条边才有章节级出处，此前挂在上下文装配上只有平面级出处。
- 同时补画：「范围与预算在创建时固化、执行中只能收窄（15）」（守卫 → 执行者与模型）、「确定性判断先由程序做、模型只判残余（18）」（工具与执行环境 → 验证与测试），并给「确认并冻结意图」「每轮先读状态」补上括号里的来源数。

## 本轮如实记下的取舍（不是「全部达成」）

1. **总图仍有两条 [00 §4](../00-总览.md) 的关系没画成边**：「子执行者只回结构化结果（18）」（三种端点组合分别 4/7/5 个穿节点错）与「状态转换处提取记忆候选并经治理写回（15）」（忠实端点对实测 10 错）。它们已由执行平面展开图与不变量专题图的卡片承接——**这是「移到平面展开图」，不是「画了」**。
2. **各图内部也有降级**：控制平面图把控制→执行的「独立验证者给出裁定与定位（22）」、执行→控制的两条（18）、控制→知识的（15）收进卡片；执行平面图把「动作或阶段转换前阻断（29）」降级为接口桩的 sublabel、把「超限与停机升级到人（21）」留在节点语义里；不变量专题图六条各只画了一到三条边，其余进卡片。每张图的成品页里都能读到这些语义，但**它们不在连线上**。
3. **一处形态与图例不严格对齐**：证据与追踪在本套图里一律用「判定与阻断」一色（与控制平面其余部件同色，保平面带的视觉整体），而它的形态严格说是「写下来并被回读」。这是沿用上一版总图的着色，已知取舍。
4. **跨边界专题图的图例 `external` 标注为「人 / 外部权威侧」**，因为那张图上没有「人」节点，唯一的 external 是不归我们管的对方。其余七张写「人」。
5. **viewBox 宽度上限约 1395**：1440 视口下 sublabel 的投影字号须 ≥6px，超宽会被 `composition/desktop-readability` 判死。本轮八张图全部靠**往下长**解决，没有缩字号、删标签或压节点。这条对以后改图同样成立。
6. **`archify visual-check` 仍是 fail**（四种视口都报 `viewer/viewport-overflow`，整页放不进一屏）。**这不是缺陷，是取舍**——每一页都是文档（图 + 说明卡），本来就要滚动。

## 读法

**总图**：四个虚线框是责任、知识、执行、控制四个平面；**绿色粗线是交付线**（人确认意图 → 派生工作项与用例 → 每轮先读状态 → 派发切片 → 装配上下文 → 执行 → 环境回读与三态裁定 → 证据写回状态）；**紫色虚线是回流**（记忆治理后的晋升、证据喂给演进、失败驱动规则增删）；**红色虚线是控制平面的阻断与升级**。
本轮起，「超限与门禁失败 → 升级到人」与「不可逆动作 → 只能由人授权」**已经画出来了**，都在图的西侧。

**四张平面展开图**：每张图里，部件主节点挂着它的子节点（取自各章 §1「它必须做到的」与「它自己维护什么」），边上写「必须做到 / 自己维护」；
另外三个平面各出现一个**接口桩**节点，桩上的边照 [00 §4](../00-总览.md) 带括号里的独立来源数。卡片写该章最硬的几条原则并注明 `§2 Pn`。

**三张专题图**：按主题切不按平面切。不变量专题图是「不变量 → 它约束的边 → 违反时的症状」三列；L0–L3 专题图是四条横带加一条「升不上去的时候」；跨边界专题图是中间一条边界带、左右两段角色相反的关系。

## 改图与重新生成

```bash
archify validate architecture docs/架构图/<名字>.architecture.json --quality showcase
archify deliver  architecture docs/架构图/<名字>.architecture.json docs/架构图/<名字>.architecture.html --quality showcase
```

`validate` 会逐条报出标签压组件、连线穿节点、走廊交叉、桌面视口下文字过密等问题，并给出可直接照抄的修法（`labelAt`、`labelDy`、`via` 坐标）。**showcase 档必须 0 错 0 警**——八张图当前都是 9/9 artifact 检查通过、0 错 0 警。
一次修复只加一个几何控制；连续两轮错误数没有创新低就停下如实报告，不要靠删标签过关。

**PNG 预览的重出方式（2026-09-06 换了做法，比原来简单得多）**：用 Playwright 驱动 Chromium 打开成品页 → 点主题按钮并**确认 `document.documentElement.getAttribute("data-theme")` 是想要的那个** → 点「导出 → PNG（无损图像）」→ 用浏览器的 download 事件落盘。
不再需要原来那套「钩住页面自己的 `URL.createObjectURL` 拿 Blob、再同源 POST 回本地小服务」的绕法。导出分辨率仍是页面自己决定的 4140 宽。
**只在节点、连线、边界或图例变化时才需要重出**——引导视图说明与卡片只在 HTML 里，不进导出图。

历史版本（保留供对照）：`three-planes.*`（三平面，人尚未单列）、`ai-dev-system.*`（五部件 + 两胶水，最初按示例画的）。

生成工具：[tt-a1i/archify](https://github.com/tt-a1i/archify) v2.17.0-dev.1（`npm install -g` 自仓库 `archify/` 子目录安装；仓库根目录没有 package.json，直接 `npm i -g github:tt-a1i/archify` 会失败）。
