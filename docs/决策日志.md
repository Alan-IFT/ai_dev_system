## D-014 决策记录

**背景**：本仓库全部规范正文使用命令语气写成，执行者无法从措辞区分"已生效门禁"与"讨论中的提议"，产生三类失效——虚假授权、虚假阻断、空集合合规。v0.2 审计已识别前两类并加了效力声明，但状态值散落各处会过期，且第三类（空 Gate 集被读成已通过）没有机制拦截。

## D-047 决策记录

**日期**：2026-09-02　**状态**：已接受（Alan）　**上游依据**：D-014、D-020、D-043

### 背景

第五轮架构裁决把 14 个部件定下来后，留下两块无处安放的内容：外部系统交接（9/52）与触发和入口（6/52）。两者都在统计断崖之下，但性质是场景相关——需要它们的场景把它们列为不可省略，不需要的场景里它们根本不出现。初评给出三个选项（A 保持边缘适配 / B 升为一等部件 / C 并入现有部件），三者都有不可避免的代价。

### 方法

不接受"放进哪个盒子"这个问法，先问三个选项的代价有没有共同来源。有：它们都默认这是**两个部件**。回到 §6.1 与 §6.2 列举的全部纪律逐条看它们在讲什么——读多写少、写限窗口、幂等、软降级、必需与推荐分档、判定器先于触发器——没有一条在讲"这个部件自己要做什么"，全部在讲"跨过这条边界时什么不许变"。部件回答"谁做"，约束回答"做的时候什么不许变"，两者形状不同；架构里已有安放后者的位置。

### 选择

不设部件。改为：

1. 一条可判定的"外部"判据：权威记录源不由本项目治理，或其上已发生的事不能单方面撤销，满足任一即为外部。
2. 第六条架构级不变量「边界外不由我们控制」，四条推论各自收紧一条已有规则（11 的记录源与派生缓存规则、30 三态与 32 证据字段、31 的豁免须带失效期、21 P3 与 40 的授权规则）。
3. 三处一行标注：11 的权威记录源、24 的工具、21 的一次运行起点。

同时澄清：不变量与平面接口是架构级内容，与 14 个部件并列，D-043 的"须归属某个部件"针对部件级内容，不约束这一类。这是澄清而非对 D-043 的修正——§5.3 原本就有五条不变量，第三类内容一直存在。

### 备选与不选的理由

| 选项 | 不选的理由 |
|---|---|
| A 保持边缘适配 | 纪律散在两节"待定"里，长期悬置；且没有回答"这算不算外部"这个前置问题 |
| B 升为一等部件 | 每个项目多两个必答问题，个人项目要写两次"不适用"；正文约增 110 行；与"简单且灵活"相悖 |
| C 并入现有部件 | 七条纪律并入后失去共同来源，在被并入的章节里显得突兀，且仍然无判据 |

### 风险与证伪信号

- 不变量比章节更容易被跳过。缓解：三章各有一句交叉引用，[00 总览](00-总览.md) §5 与诊断表各有一处，成长路径在 L2 点名。
- 判据第二条依赖"能否单方面撤销"的判断，边界情形需个案裁定；规则是判不清按外部处理。
- **证伪信号**：跨边界纪律在实际使用中反复被绕过（说明约束力不足以替代章节），或出现一条无法由判据与四条推论覆盖的跨边界纪律（说明这里确有部件级内容）。任一出现即回到选项 B。

### 验证方式

在走通第一个完整切片时（D-043 的验证方式）一并检验：切片中每一个跨系统的读与写，是否都能由判据判定内外、并被四条推论之一覆盖。

## 记录规则

每个决策至少包含：背景、选择、备选项、取舍、状态、日期和验证方式。进入`试行`或`已接受`时还必须补充 `approved_by`、`approved_at`、`effective_scope`（含 blocks/grants 分栏）；试行项增加 `review_at` 与 `expiry`，并同步写入生效登记表。

当决策变化时不要删除旧记录。新增记录并标明"取代 D-xxx"，使后续维护者能理解变化路径。
