## 1. 三句结论

1. **不推荐把「判据 + 现取命令」推广到全仓。** D-076 那次是**特例**不是**模板**：它对「原则条数」成立的全部原因，是那一处的外延有行形态级判据（`^- **Pn`）**且被 C7 逐条咬住**。全仓五类量里只有这一类满足。对其余各类照抄这个做法，等于把漂移从数值层搬到配方层——本轮实测已有三处配方失守（§3 P-04、§2.2）。
2. **本仓库真正用得最多、且零例外的动作是第四种：删副本 + 指向具名权威，不写命令。** 四处先例（PROJECT_STATUS §0/§2/§5、CONTEXT_MANIFEST §3）全部是这一种，没有一处是「删掉不留替代物」，也没有一处写了现取命令。三个候选的题面漏掉了它。
3. **复核后成立的实质问题只有 5 处**（P-01～P-04、P-08），其余是表述锚不锚时点的低优先级问题或不成立。**本批的全部推荐动作都是删除，零新增命令**——这是它与 D-076 那一批在「以少就是多」上的分界。

## 5. 三步判据（供下一处未见过的会漂计数使用）

本仓库已有一条三分支判据（`失败Case清单` 读数十的处置段）。本轮实测暴露它两个洞：**分支一与分支二可同时触发而无优先级**；**完全没写「谁保证现取命令算得对」**。补丁后收敛为三步，比原判据少一个分支：

1. **存在一个不碰这句话的动作，能使这个数变假吗？**
   - **不会** → **留字面量**，并在同句锚住它的时点，或锚住关死它的那条 blocks。（正例：「14 章」被 D-043/D-047 的 blocks 关死；「§5.3 原本就有五条」锚在 D-047 那次裁决上。）
   - **会** → 第 2 步。
2. **有人会据它判事吗？**（三条任一成立即算：有检查器对账它 / 它划定某条生效规则的成员集 / `git` 里有据它做过判断的书证）
   - **不会** → **删字面量改定性，指向权威，不写命令。** 本批 P-01、P-02、P-06 全在这一格。
   - **会** → 第 3 步。
3. **它的外延有没有「行形态级判据 **且** 有一个检查器咬住」？**
   - **有** → 可以写现取命令。**这是 D-076 对「原则条数」成立的全部原因，也是全仓唯一满足的一处。**
   - **没有** → **不许写命令。写指针，并把「口径写不死」明写出来。**

**这三步能判没见过的那一处**，因为它只依赖三件现场可取的事实：有没有一个动作能不碰这句话就使它变假；`git` 里有没有据它判事的书证；外延有没有行形态判据加检查器。三件都不需要事先认识那一处。
