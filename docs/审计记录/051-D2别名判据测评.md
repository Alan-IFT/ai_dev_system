# D2 · "仓的历史别名"判据：独立测评

只读复核。被观察项目 NFBY 未写入一个字节，全部用 `git --no-optional-locks grep`。

## 〇、结论先写

**两位都对，但对的是两个不同的字符串。** P8 说的是 `NFBY_CMS_Ops`（容器仓的历史别名）；
P9 的 31.81 秒与 82% 误报测的是 `NFBY_CMS`（**仍在 `repos[]` 里挂着 `role: retired` 的在册仓名**）。
后者根本不是别名，一条配置校验就能把它挡在判据之外。P9 的反对意见成立，但它反对的不是这条判据。

**建议：加，按第五节的形状，进通用工具 `check_cross_repo`。**
实测：FAIL 11 个文件 / 28 行，**逐条人工核对 11/11 是真的死指针，0 误报**。

## 一、两位判断谁对

| | P8（判最严重） | P9（判暂缓） |
|---|---|---|
| 说的字符串 | `NFBY_CMS_Ops` | `NFBY_CMS`（P9 §5 表格原文：`NFBY_CMS/` 的命中分布） |
| 该串是什么 | 容器仓 2026-08-27 之前的名字，**今天不对应任何仓** | `repos[]` 第 4 条的 `name`，**今天是一个在册的退役仓** |
| 事实对不对 | 对：BE 5 文件、FE 6 文件仍写旧名 | 对：`NFBY_CMS/` 92 个文件命中、真问题 2 处 |
| 结论对不对 | 对 | **对于它测的那个串成立，对于别名判据不成立** |

P9 提的"`NFBY_CMS` 是三个在役仓名的子串"这条，正是它自己不该被当成别名的证据：
**一个字符串同时是 `repos[].name` 时，它不是别名，是现名。** 判据加一句配置校验即可，见第七节 §2。

P8 有一处口径要修正：它说"G7 不通过是因为第二跳落在作废名字"。
实测两个应用仓的 `CLAUDE.md` 各自明写 `NFBY_CMS_FullStack`（BE 3 处、FE 5 处），
所以 `check_cross_repo` 判据四（两跳投影）**在第一跳就 PASS**。
死指针在入口指出去的那份 `docs/decisions/README.md` 里，检查器看不见。
**这不是"漏报"，是"对着一条已断的接手路径报 PASS"——比漏报重。**

## 二、复核那两个数

### 31.81 秒 → **复现不出来，实测 0.31 秒**

本仓 1513 个跟踪文件，同一台机器：

| 写法 | 实测 | 说明 |
|---|---|---|
| naive 全量读（读完再判二进制） | **0.31 秒** | 读 1513 个文件 / 522.5 MB |
| 扩展名 + 2 MB 过滤 | 0.03 秒 | 读 542 个 / 10.7 MB |
| `git grep -I -l -F` | 0.063 秒 | |

522 MB / 0.31 秒 ≈ 1.7 GB/s，是页缓存命中。P9 的 31.81 秒（≈17 MB/s）是**冷缓存首读**，不是稳态。
两个数都真，但**"九倍于整轮扫描"这个论据只在冷缓存那一次成立**。

**NFBY 四仓 5657 个跟踪文件，`git grep -I -l -F` 全跑一遍 0.131 秒。耗时不构成暂缓理由。**

### 82% 误报 → **数对，但测的不是别名**

`NFBY_CMS/` 在容器仓命中 92 个文件，`docs/features/_archived/**` 占绝大多数（frozen 区）；
去掉 frozen 后剩 7 个文件（`.gitignore`、四份决策文档、`deploy-production.sh`、`nfby-backup.service`），
真问题 2 处。P9 的 11 报 2 真、82% 误报，**核对无误**。

但对真正的别名 `NFBY_CMS_Ops`：

- 四仓共 22 个文件命中，**落在 frozen 区的 0 个**——frozen 过滤对这条判据一点用没有，也一点害没有。
- 容器 11 / BE 5 / FE 6 / 老仓 0，与 P8 的计数完全一致。

形态：路径分隔符锚定 + `git grep -I -F` + 只对 `.sh`/`.service`/CI 等机器面报 FAIL、其余聚合成一条未定。

**两条都测了，两条都不适用于这个缺陷。**

它的注释写的就是"不能用裸子串——`NFBY_CMS` 会被 `NFBY_CMS_Backend` 假命中"。同一个坑同一个解，不必新造。

进了聚合未定。

**这条缺陷 100% 长在文档面上。"只对机器面报 FAIL"正好把它全部关掉，同时把 3 条假的开出来。**

## 四、通用工具还是 NFBY 自己的 verify_all

判据（三条全中才进通用工具）：

1. **判据的全部输入能由 `project.yaml` 声明**，不需要项目知识；
2. **判据的对象是标准条款直接点名的对象**；
3. **处置对任何项目一样**。

别名判据三条全中：输入是 `repos[].former_names`（项目自己登记）；
对象是 01 §3.8「跨仓引用按契约处理——移动前先改全部引用方，或保留指向新位置的指针」，改名就是一次移动；
处置一律"改引用方或留指针"。→ **进通用工具**。

反例（该留项目侧）：NFBY `verify_all.sh` 的 A.7(a) 查 `Alan-IFT/NFBY_CMS.git`，
理由是"**这个远端还活着，克隆会静默成功并部署一份三个月前的实现**"。
"远端还活着"不是任何 `project.yaml` 能声明的通用事实，A.7(a) 留在 NFBY 是对的。
A.7(b) 查 `NFBY_CMS_Ops` 的那一半，正是可以上收的那一半。

**放进 `check_cross_repo`，不新建检查器。** 它与现有退役仓那条是互补的两半：
那半查"退役仓自己的规则标没标失效"，这半查"别人还在不在指一个不存在的名字"。

## 五、不加的话，那 11 处靠什么被发现（最关键的一问）

### 逐个查过，答案是：**没有。而且这已经是第二次没有。**

**现有八个检查器**：全瞎。`check_cross_repo` 判据七的 `scope` 明写
"只扫 `*.md`、只认 markdown 链接语法、不看 `*.sh`/`*.json`/`*.yaml`/`*.service`、也不看正文裸路径"。
这 11 个文件里是裸路径、表格文字、`.py`/`.css`/`.ts` 注释，以及一条
`https://github.com/Alan-IFT/NFBY_CMS_Ops`——http 链接被 `_link_targets` 显式跳过。
更糟的是判据四**报 PASS**（见第一节）。

**NFBY 自己的闸门**：`scripts/verify_all.sh` A.7(b) 确实查 `NFBY_CMS_Ops`，
但作用域是容器仓的 `scripts/*.sh`（注释剥掉后再数），且 `verify_all.sh` 自己被 `continue` 掉。
`verify_all.sh:479` 原话：**"it is in NFBY_CMS_Backend / NFBY_CMS_Frontend, or it is not happening."**
——容器闸门不下钻应用仓，这是写进注释的设计决定。
两个应用仓自己只有 `scripts/hygiene.sh`（跑 lint/format），**没有任何别名断言**；
它们的 `hygiene.sh:7` 本身就是 11 处死引用之一。

**人工步骤**：`docs/decisions/full-audit-2026-09.md` 的 **B-3** 就是这一条，评为 P1。
它的推荐方案原文：

> 同时把 A-2 的那条 QA 断言扩写成"三仓任何 markdown/脚本不得再出现 `NFBY_CMS_Ops` 作为**现称**"
> —— 一条断言同时守住 A-2 与 B-3。

**这条推荐已经写下来了，落地时只落了容器 `scripts/*.sh` 那一小半，B-3 本身至今未修。**

### 所以"暂缓"的真实代价

不是"晚点再发现"，是：

1. **NFBY 自己判为 P1 的缺陷，在它自己的审计里已被推荐修一次、被缩水实现一次，再暂缓就是第三次。**
2. **G7「接手演练：新会话只读仓库能否继续」在 NFBY 今天实际走不通，而通用工具对着这条路径报 PASS。**
   一条报 PASS 的断路径比一条没检查的断路径更贵——它让后面每一轮复核都跳过这里。
3. 这条契约是 NFBY **自己声明**的（`CLAUDE.md:44`"这些路径是契约，搬动要同步改"）。
   一条项目自己写下、自己违反、且没有任何执行点的契约，等价于 01 §5.6 所说
   "写在入口、提示词或流程说明里的同一句话只是提醒，不构成受控"。

**"暂缓 = 永远没人发现"在这里成立，而且已经有一次实证。**

## 六、对"与判据 3 同型、是同一根因第 8 次"的反驳

同型这件事是真的。但**判据 3 的先例不是"暂缓"，是"收窄而非删除"**。
commit `c5a3131` 的标题原文：**"按审核收窄而非删除：未定 43→26，四项拟删被否决"**。
做法三步：① 按构造挡掉链接（`_mask_links`）；② 召回阈值从 2 提到 3（`_CLAIM_MIN_FILES`）；
③ **加一条反例自检**（探测三之二）钉住这次收窄。31 条降到 15 条，判据留下了。

拿"与判据 3 同型"当暂缓理由，是把那个先例用反了。

根因（"标准的条款说的是角色，工具手上只有名字"）在这条上**恰恰不成立**：
别名判据手上的不是"名字"，是**项目自己签字登记的"这个名字已经作废"**——这是确定事实，不是代理指标。
01 §5.6 允许对确定事实做硬拦截。

判据 3 判不了的是"这两处重复里哪处是权威"（人的取舍）；
别名判据判不了的只是"这处出现是记录历史还是当现称用"，
而这一条**可以用"出现在谁的仓里"机械切开**：
旧名出现在**它自己那个仓**里 → 可能是改名记录，记未定；
出现在**别的仓**里 → 那正是 §3.8 说的"一个仓的文档指向另一个仓"，指向一个不存在的名字，是确定事实。

## 七、可执行规格

**位置**：`tools/std/checks/check_cross_repo.py`，作为判据八。不新建检查器。
**规模**：约 100～120 行（P9 估的 80~120 正确，40 行不够）。
复用 `stdlib.tracked_files`、`in_frozen`，与本模块已有的 `_name_appears`。

### 1. 配置（契约 §5 同步补一条键）

```yaml
repos:
  - name: NFBY_CMS_FullStack
    path: .
    role: system
    former_names: ["NFBY_CMS_Ops"]     # 新增，可选，字符串列表
```

**不声明 `former_names` 的项目，本判据什么都不报**（连 SKIP 都不发，避免给每个从未改名的多仓项目
制造一条噪音）。这条边界写进 `scope.not_covered`：
**"本检查发现不了未登记的改名——项目没登记 `former_names` 时它一个字都不查。"**

### 2. 配置校验（这一条把 P9 的 82% 挡在门外，必须有）

一个 `former_name` 与**任何** `repos[].name` 相等（大小写不敏感）→ 不扫描，报一条 UNDETERMINED：
"`X` 同时是在册仓 `Y` 的现名，不能登记为别名"。在 NFBY 上这条会把 `NFBY_CMS` 直接挡掉。

### 3. 匹配

- `git --no-optional-locks grep -I -n -F <alias> -- .` 逐仓跑（`-I` 自带二进制识别）。
  拿不到 git 或命令失败 → UNDETERMINED，不静默跳过（契约 §1）。
- 命中行再过一遍 `_name_appears()` 的**词边界**正则，滤掉别名只是更长标识符一部分的行。
- 落在 `layout.frozen` 的路径不参与（与其它判据一致）。NFBY 上这一步不改变结果（frozen 命中 0）。
- 同一行含改名标记词（`前身`/`曾用名`/`改名`/`更名`/`formerly`/`renamed`）→ 白名单，不计。
  **词表要窄**：实测把 `归档`/`archived` 放进去会误白名单掉 `_archived/<slug>/` 那类路径行。

### 4. 三态处置

| 命中位置 | 处置 | NFBY 实测 |
|---|---|---|
| 别名**不属于**该仓（在别的仓的文件里） | **FAIL**，每个引用仓一条，evidence 给文件数/行数 + 前 10 个位置 | **2 条 FAIL，共 11 文件 / 28 行，人工核对 11/11 真，0 误报** |
| 别名**属于**该仓（在它自己仓里） | **UNDETERMINED**，每仓一条，聚合计数 + 前 10 个位置 | 1 条未定，6 文件 / 17 行（其中真问题 ≥4 行：`parallel-validation-lab.md` 三处可执行 clone、`dependabot.yml` 一处） |
| 白名单挡掉 | 不计，但在 evidence 里报数 | 11 行 |

**FAIL 侧那 11 个文件逐条核过**：
BE `app/reports/definitions/shop_coverage/render.py:214,215`、`app/reports/render/html.py:469`、
`docs/decisions/README.md`（8 行，NFBY 自评 P1 的那份）、`docs/decisions/test-count-ratchet.md:11,17`、
`scripts/hygiene.sh:7`；
FE `README.md:153,170`、`docs/decisions/README.md`（8 行）、`playwright.config.ts:78`、
`scripts/hygiene.sh:7`、`src/index.css:235`、`tests/reportLogicDocsAdversarialQa.spec.ts:121`。
**每一处都在用旧名指称权威的当前位置，无一处是历史记述。**

### 5. 自检（契约 §3，正反例各一 + 一条收窄反例）

1. 反例：三仓样本，A 仓声明 `former_names: [OldA]`，B 仓文件里写 `OldA/docs/x.md` → 必须 FAIL。
2. 正例：同样声明，B 仓只写 A 的现名 → 必须无 FAIL 无未定。
3. **收窄反例（钉住这次的取舍，对应判据 3 的"探测三之二"）**：
   B 仓写 `本仓前身 OldA`（同行带改名标记）→ 不得报；
   且 `former_names: [B]`（与在册仓名相撞）→ 必须 UNDETERMINED 而非扫描。

### 6. 触发与误报处置

- **触发**：`check_all` 每轮都跑（0.131 秒，无需条件触发——条件触发本身是要维护的机器）。
- **误报处置**：不做 allowlist 文件。**唯一豁免通道是同行写改名标记词**——
  与 NFBY A.7 同源（它靠"剥掉注释"，这里靠"同行说明这是改名"），
  且豁免写在被检查的那一行上，无人能悄悄往一张清单里加东西。
  若某项目误报确实压不下去，走既有 `tailoring` 裁剪（必须写理由），不新造机制。

### 7. 采纳次序

P9 第 8 项写的"先做成 `--alias-scan` 一次性子命令跑一遍看真实误报量"——
**这一步本测评已代做完毕**（11 报 11 真 / 0 误报）。可直接进检查器；
仍建议排在 P9 第 3 组（角色表原子改动）之后，与那组无依赖。
