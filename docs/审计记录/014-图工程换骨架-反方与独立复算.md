## 2. 换骨架的迁移成本：117 条逐条判定

### 2.1 候选新骨架的准确形态（先把被判定的对象写清）

按任务书，新骨架取**图工程的三层智能 + 16 子类**，取自 [卡片 01 §4](../参考资料/15-图工程/01-仓库测绘与定义.md)：

| 层 | 子类（16） |
|---|---|
| **Model Intelligence**（4） | Pre-Training / Post-Training / Prompt Engineering / **Context Engineering** |
| **Individual Intelligence**（7） | Tool Integration / Memory Management / Skill Composition / Runtime Orchestration / Loop Architecture / Interaction Paradigm / Environment Feedback |
| **System Intelligence**（5） | Task Organization / Agent Coordination / State Management / System Evolution / *Ontology Engineering* |

**在开始判定之前，必须先记三条来自卡片自身的减记**（不是我的推断，是卡片 01/02 自己写的）：

1. **这份分类树本身被卡片 01 列为不可取用。** [卡片 01 §8.2 B3](../参考资料/15-图工程/01-仓库测绘与定义.md) 逐字：「**README 的分类树本身** | 它与论文的树不一致（Ontology 挂错层、Harness/Loop 被抹平）。**若要用分类，以论文为准，不以 README 为准**」。而「三层 + 16 子类」正是 README 的挂法。
2. **Ontology Engineering 不属于图工程。** [卡片 01 §4](../参考资料/15-图工程/01-仓库测绘与定义.md) 逐字：「**论文里不属于 §4，属 §6 Future Direction。README 未给任何说明文字。**」——它**没有定义句**。可用子类实为 **15**。
3. **五个 System 子类不是正交分层。** [卡片 02 §7.2 第 1 条](../参考资料/15-图工程/02-系统智能层.md) 逐字（该行是表格两格，此处分格照录）：判定格「**不要把这五个子类当作正交的架构分层。**」／理由格「19 条 System Evolution 里 11 条与别处重复；README 没有给切分依据。」

再减：**Pre-Training 与 Post-Training 两个子类装不进本规范任何一条原则**（本规范不训练模型）。**实际可用的容器是 13 个**，而现有骨架是 14 章。换骨架**买不到容器数量的下降**。

### 2.2 判定口径（我自己定，写在前面，判完不改）

对每条原则问：

1. 16 子类里，哪些子类的**定义句**（论文原文优先；卡片标【归纳，非原文】的说明次之）覆盖它的规范对象？记候选集 C。
2. `|C| = 0` → **新骨架下无位置**。
3. `|C| ≥ 1`，且该条落入其所在章的**众数子类**，且该子类定义覆盖它的**全部**规范对象 → **可整章平移**。
4. 其余 → **需重判归属**。典型两形态：(a) `|C| ≥ 2` 且无判据可选；(b) `|C| = 1` 但只覆盖一半——最常见的是**「责任结构型」那半句在 16 子类里找不到载体**。

**为什么第 4 条的 (b) 形态可以机械助判**：图工程三层的定义句**全部以 "the ability of" 开头**（[卡片 01 §3.2](../参考资料/15-图工程/01-仓库测绘与定义.md) 逐字）：

> Model Intelligence：「"the ability of an individual model to leverage its knowledge and reasoning capabilities to solve tasks within a given context"」
> Individual Intelligence：「"the ability of an individual agent to extend model-level reasoning into persistent, goal-directed execution through resource orchestration and iterative interaction with the environment"」
> System Intelligence（正文版）：「"the ability of an intelligent system to decompose and organize complex objectives, allocate responsibilities across heterogeneous computational agents, coordinate their interdependent execution, and maintain system-level state throughout the task lifecycle."」

**三层分的是「能力」。** 而本规范四平面里有一个平面分的不是能力——[架构确定 §4](../架构确定.md) 逐字：「**控制平面是纪律，可以只用文档和人工流程实现；执行平面是工具，随时可换；知识平面是资产，随项目积累；责任平面是人，不可转移。**」

所以「责任结构型」半句在一个按能力分层的骨架里找不到载体，**不是巧合，是定义决定的**。§1.3 那个 88 条的量，因此直接就是迁移成本的下界。

**这套 16 子类不是一份架构，是一份文献分类法。** 三条可核对的依据：

2. 16 个子类的「它管什么」一列，绝大多数带标注【归纳，非原文】——[卡片 01 §8.2 B7](../参考资料/15-图工程/01-仓库测绘与定义.md) 逐字：「那是我按收录条目反推的，不是作者的定义。**不得当作原文引用**」（原文句末无句号，此处照录——本文自己在核对时踩到过一次[读数九](../失败Case清单.md)记的那个形态，已改正）
3. [卡片 02 §7.2 第 1 条](../参考资料/15-图工程/02-系统智能层.md) 逐字：「README 没有给切分依据。」

而 [架构确定 §1](../架构确定.md) 的方法逐字：「**不预设部件清单。**对每个来源只问四件事：它的系统里有什么部件（先用来源自己的词，再归一化）；部件之间谁给谁什么；它明确说"没有它不行"的是什么；它把失败归因到哪个部件。然后跨来源计数。」

**一份按「收了多少篇论文」组织的主题目录，与一份按「哪些部件不可省略、失败归因到哪」归纳出的部件划分，不是同一种对象。** 用前者替换后者是一次范畴替换，不是一次结构改良。这一点独立于任何百分比。

## 3. 六条不变量在新骨架下是否站得住：逐条裁定

判定方法：逐条问「这条不变量在 16 子类里由哪一个承载」，只认**定义句**（原文优先）。

| # | 不变量（逐字取自 [架构确定 §5.3](../架构确定.md#invariants)） | 新骨架下的载体 | 裁定 |
|---|---|---|---|
| **1** | 「控制平面独立于执行平面：验证者不是生成者，守卫在模型控制流之外。」 | **无**。三层分的是能力规模（单模型 → 单 agent → 多 agent 系统），不是「控制 vs 执行」的职责切分。验证者与生成者可以同在 I 层，也可以同在 S 层——层界与这条边界**不平行**。图工程里 `independent verification` 只作为越过 I 层天花板的**触发信号**出现（§2.4 C 表已引） | **失去载体** |
| **2** | 「状态外置且朴素：一份进度、一份清单、一份交接，编排靠读状态不读对话。」 | **S·State Management**，定义句逐字覆盖：「"determines how the evolving state of execution is represented and maintained, enabling the system to track progress, reconcile concurrent updates, preserve provenance, isolate failures, and recover or adapt when execution deviates from plan."」 | **站得住**。**但「朴素」一句未定**——图工程要的是图，不是三份文档；[卡片 01 §6.3](../参考资料/15-图工程/01-仓库测绘与定义.md) 说它不要求图数据库（「"必须上 Neo4j"是过度解读」），故不冲突，但也**不支持**「朴素」 |
| **3** | 「项目知识是唯一记录源，入口短、细节就近；代码图谱和记忆都是它的派生或候选，不是第二权威。」 | **无**。「唯一记录源」是治理权指派，I2·Memory Management 只管「跨轮次、跨会话保留什么」。更硬的一条：[卡片 05 §11 不可取用第 6 条](../参考资料/15-图工程/05-工具基准与应用.md) 逐字——「**这份材料的"图"不包含代码图。** 不能引用它来支持"codegraph 是图工程的公认部件"——恰恰相反，35 人署名的综述资源库里没有这个条目。」**本条后半句在新骨架里连对象都没有** | **失去载体** |
| **4** | 「执行事实来自环境回读与只追加日志，模型可见的都被记录；证据喂给演进。」 | **三段各有落点，但分落三处**：「环境回读」→ I7·Environment Feedback；「只追加日志」→ S3 的 `preserve provenance`；「证据喂给演进」→ S4 定义句逐字「"leverages execution feedback and state evidence"」 | **降格**。一条架构级不变量被切成三条分属三个子类的部件级条文，就不再是「各章原则的公共前提」 |
| **5** | 「责任不可转移：人是稀缺资源，检查点集中在少数状态转换，不可逆动作只能由人授权。」 | **与 System Intelligence 正文定义句正面冲突**。该定义句逐字：「"…**allocate responsibilities across heterogeneous computational agents**…"」——图工程的 S 层定义里，责任（responsibilities）恰恰是**被分派到异构计算 agent 上**的东西。本规范说责任只能落人、不可转移 | **失去载体，且方向相反**。这不是「没地方放」，是**定义相反** |
| **6** | 「边界外不由我们控制。」（含权威侧/消费侧关系模型 + 三项可执行前提） | **无**。16 子类无一涉及「跨边界」。S2·Agent Coordination 管的是**系统内部**异构 agent 之间的映射与通信；I1·Tool Integration 管「调用什么外部能力」，是能力面不是权威面。D-047 明写这条是「约束的形状而非部件的形状」，而 16 子类连「部件的形状」都不是（§2.5） | **失去载体** |

**§3 裁定汇总：6 条里 —— 完整站得住 0 条；站得住但有保留 1 条（第 2 条，「朴素」未定）；降格 1 条（第 4 条）；失去载体 4 条（第 1、3、5、6 条，其中第 5 条与新骨架的定义句正面冲突）。**

补一条来自卡片自身的旁证：[卡片 02 §7.2 第 6 条](../参考资料/15-图工程/02-系统智能层.md) 逐字已登记过一次同向冲突——「**且这条与本规范"人类保留目标与最终验收"的立场直接冲突**，采纳前须走冲突处置。」

## 4. 与卡片 06 的对照：差异及差异原因

> 本节在 §1～§3 判定全部写完之后才打开卡片 06。**对照结果没有回改上面任何一个数。**

### 4.1 第一个、也是解释掉大部分差异的发现：**两份分析测的不是同一个骨架**

[卡片 06 §5 口径 1](../参考资料/15-图工程/06-与既有材料及正文的对照.md) 逐字：「**判定方法**：新骨架的顶层容器取图工程自己给的四要素 `G=(V, E, S, P)`（A4，两个来源共用的唯一形式定义）。」

- **卡片 06 测的是 `G=(V,E,S,P)`**——4 个槽位，来源是三篇公众号文章（WX-21/WX-23/ATT-J 与 WX-28）。
- **本文测的是三层智能 + 16 子类**——名义 16、实际可用 13 个槽位，来源是图工程综述仓库（卡片 01～05）。

**槽位数 4 vs 13，是两组数字分岔的主因**，且方向可预测：槽位多 → 无处安放少，但落点歧义多 → 需重判多。

### 4.2 数字对照

| 量 | 卡片 06（G=(V,E,S,P)，4 槽） | 本文（三层 + 16 子类，13 可用槽） | 差 |
|---|---|---|---|
| 可整章平移 | 36 / 117 = **30.8%** | 14 / 117 = **12.0%** | −22 条 |
| 无处安放 / 无位置 | 57 / 117 = **48.7%** | 20 / 117 = **17.1%** | −37 条 |
| 需重判（06 的合并口径 = 拆分 + 无处安放） | 81 / 117 = **69.2%** | 83 + 20 = 103 / 117 = **88.0%** | +22 条 |
| 需重判（本文口径，**不含**无位置） | （06 无此列） | 83 / 117 = **70.9%** | — |
| 不变量失去载体 | **3 条**（1、3、6）+ 1 条降级（5）+ 1 条部分（4）+ 1 条完整（2） | **4 条**（1、3、5、6）+ 1 条降格（4）+ 1 条站得住带保留（2） | +1 条 |
| 支持换骨架的独立来源 | **2 / 52 = 3.8%** | 见 §4.4 | — |

**必须说清的口径陷阱**：06 的 48.7% 与 69.2% **不能相加**（69.2% 已包含 48.7%）。本文的三档是互斥划分，相加恰为 100%。两份报告若并排引用，很容易造出一个 117.9% 的假数——这正是 [审计 010 §2.2](010-标准结论的独立重算.md) 记的「分母错」形态。

### 4.3 我推翻卡片 06 的一处：它的「36 条可整章平移」与它自己的其它判定互相矛盾

06 的判定粒度是**章**（逐字：「逐**章**问：这一章的原则整体能不能挂到某一个要素下」），然后把整章条数计入一档。这产生至少 5 处内部矛盾：

| 06 判为「可整章平移」的条 | 与 06 自己哪一句矛盾 |
|---|---|
| **21-P8 验证者分离是默认允许的拆分**（06：21 章整体 → E） | 06 口径 2 判**不变量 1**（「验证者不是生成者」）**失去载体**，逐字：「节点与节点之间没有"独立于"的结构含义」。**承载不变量 1 的那条原则，不可能同时是干净可平移的** |
| **21-P5 三类停机条件**（同上） | 该条删除条件逐字含「上限型写不出（责任结构型：预算上限是**人侧**的成本约束）」；而 06 把整个 40 章（人）判为无处安放 |
| **25-P3 委托合同必须声明是否继承治理规则**（06：25 章整体 → V） | 治理规则继承是授权语义；06 判 40 章（授权）无处安放 |
| **31-P3 Gate 二分，两类上限的来源不同**（06：31 章整体 → P） | 该条的第二类上限逐字是「人工判断检查点的数量上限由**判断带宽**约束」；06 判 40-P2（判断带宽）无处安放 |
| **31-P8 交互式审批不得沉淀为永久授权**（同上） | 审批与授权；同上 |

**这不是抠字眼，它改变数字的方向**：若这 5 条按 06 自己对 40 章的处理方式移入「无处安放」，06 的无处安放变成 62/117 = **53.0%**，可整章平移变成 31/117 = **26.5%**。也就是说，**06 的 48.7% 在它自己的判据下是低估，30.8% 是高估。**

**公平记账**：06 §0 已声明「§5 的解释按未定读」，并注明「本文的生产方与验证方是同一方」（[30 §2 P5](../30-验证与测试.md)）。本节即是它请求的那个第二判。**本文自己没有第三判，同样按未定读。**

### 4.4 我复算不出、因而不采信的一处：06 的「2/52 = 3.8%」不覆盖本轮新材料

06 的 3.8% 只数了三篇公众号文章（合并后 2 个独立来源）。**卡片 01～05 引入的是另一个来源**——图工程综述仓库（README + arXiv:2608.21156）。它在 52 源统计里**没有登记**，因为 52 源是四轮材料的合并结果，本轮是第五轮材料。

我不给一个新的百分比，理由是分母未定：MERGED.md 的 N=52 是四轮口径，把第五轮的一个来源塞进这个分母属于「未定不得折算」（[30 §2 P1](../30-验证与测试.md)）。**能说的只有**：支持换骨架的独立来源从 2 个增至 3 个，且第 3 个的效力上限由 [卡片 01 §8.2 B8](../参考资料/15-图工程/01-仓库测绘与定义.md) 自己封顶，逐字：「它是 2026-08 提出的**主张**，论文自称 "an emerging paradigm"。V3 类第三方综述，无独立复现，**效力上限是"该领域有人这么组织问题"**。」

### 4.5 与 06 一致的三处（独立到达，不是对账）

1. **52 源统计不作废**（详见 §5）。
2. **第 6 条不变量失去载体**——我的理由与 06 不同（06：两个来源均无「边界」概念；我：16 子类中 S2 管系统内部、I1 管能力面，皆非权威面），结论相同。

### 4.6 与 06 的实质分歧一处：不变量 5

06 判「**被降级**」（人被做成图内一个节点）。我判「**失去载体，且方向相反**」，依据是 System Intelligence 正文定义句原词 `allocate responsibilities across heterogeneous computational agents`（§3 表已引）。**降级与反向不是同一档**：降级还能靠加一条约束补救，定义相反必须先走冲突处置（[08 §8](../08-规范效力元治理.md) 的失败关闭）。

## 5. 52 源统计是否作废：统计对象是「部件」还是「平面」

### 5.1 逐字取证

[架构确定 §1 方法](../架构确定.md) 逐字（着重号为原文所无，我加以指认对象）：

> 「不预设**部件**清单。对每个来源只问四件事：它的系统里有什么**部件**（先用来源自己的词，再归一化）；**部件**之间谁给谁什么；它明确说"没有它不行"的是什么；它把失败归因到哪个**部件**。然后跨来源计数。」

[架构确定 §2 统计结果](../架构确定.md) 逐字（三张表的条目名）：

**这三张表里没有一个条目名是平面名**（知识 / 执行 / 控制 / 责任四个词一个都没出现）。全部是部件名。

[架构确定 §5.1](../架构确定.md#component-stats) 的表结构逐字：

> 「| 平面 | 部件 | 回答的问题 | 频次 / 不可省略票 / 失败归因 | 最小形态（L0，文档级） | 工具形态（L2+） |」

**「频次 / 不可省略票 / 失败归因」这一列挂在「部件」行上；「平面」只是第一列的分组标签。**

### 5.2 裁定（分三问答）

**(a) 如果只换顶层分组、部件不变，统计还成立吗？——成立。**

统计证明的是「这 16 个东西各被多少来源提到 / 说不可省略 / 被归因失败」。这个事实与它们被分成几组、组叫什么名字无关。换分组不改变「50/52 个来源提到工具与执行环境」。

**(b) 但换成三层 + 16 子类，不是「只换分组」。——它同时换掉了被分组的对象。**

16 子类**不是** 14 部件的重新分组，两边不存在一一对应：

- **16 子类里有、52 源统计里没有对应行的**：Pre-Training、Post-Training（52 源统计里「模型 42」是一个部件，不区分训练阶段）、Ontology Engineering（且它在论文里不属图工程）。
- **52 源统计里有、16 子类里没有对应格的**：**「人」**（频次 40、**不可省略票 21，全表居首**）、「意图与验收」（34/9）、「证据与追踪」（41/12/22 —— 只有 S3 的 `preserve provenance` 沾一半）。

也就是说：**这份统计里得票最高的那个部件，在新骨架里没有容器。** 而 D-043 的裁决理由逐字正是建立在它之上：

> 「52 个来源的统计显示"被提得最多的部件"与"最不能缺、最常出事的部件"不是同一批；原八层并列无主次，范式阶梯是历史叙事而非架构；**人在不可省略投票中以 21 票居首且责任不可转移**」

**(c) 一条卡片 06 没提、我认为更要紧的：新骨架的数不能替代这份统计。**

16 子类各自的「数」是**论文篇数**（[卡片 01 §4](../参考资料/15-图工程/01-仓库测绘与定义.md) 逐字：「数字为 README 该子类下实际收录的**条目数**」）。52 源的数是**独立来源的票数**（提到 / 说不可省略 / 归因失败）。

**篇数不是票数。** 一个子类收 138 篇只说明这个方向论文多，不说明它在工程上不可省略；而 52 源统计的整个价值恰恰在于它把「被说得最多」和「最不能缺」分成了两张表并发现两者不重合（[架构确定 §2](../架构确定.md) 逐字：「**被说得最多的部件（工具、执行者、上下文、模型）和被认为最不能缺、最常出事的部件（人、验证、守卫、证据、状态）不是同一批。**」）。**换骨架等于只保留了「被说得最多」那一张表的形态，丢掉了另外两张表的判据。**

**§5 裁定**：**§5.1 的统计本身不作废，但它在新骨架下变成孤儿证据**——既不能被继承（无一一对应物），也不能被反驳（新骨架不产生同口径的数）。而它正是 D-043（`已接受`）的论证基础。**留着一份无法被新骨架消费的裁决依据，与作废的实际后果相近，但记账上必须分开写：不作废（结论），无法继承（结论），继承成本（未定）。**

## 6. 换骨架买的是什么：可检验的答案

### 6.1 先分类：换骨架是压条文、是移位，还是别的

- **不删条文**：117 条一条不少（我的三档里「无位置」20 条不是删除，是**需另设容器**——06 §5 已指出：「新骨架必须再长出至少三个非图要素的顶层容器」）。
- **不改条文文本**：三档里只有归属变，条文正文不动（「需重判」改的是它挂在哪里）。
- **重排容器**：14 章 → 13 个非空子类 + 20 条无容器条文。

**结论：换骨架是一次移位，且是本仓库做过的最大一次移位。**

### 6.2 仓库自己的实测教训（逐字，并更正一处轮次）

[附录-载体实例/仓库工作须知 §5](../附录-载体实例/仓库工作须知.md) 逐字：

> 「唯一值得记住的那个实测结论：**第十轮**把写作期内容移出正文，**正文明显下降，而正文 + 账本的总量反而上升**——账本的逐章标题、回指链接与表头是移位凭空产生的开销。**要降总量只能删，不能移。**」

## 8. 结论与本文的已知空缺

### 8.1 结论

**不应换骨架。** 三条互相独立、任一成立即足以否决：

1. **范畴不对。** 三层智能是**能力的分层**（三个定义句全部以 "the ability of" 开头），四平面里有一个平面分的不是能力（「责任平面是人，不可转移」）。88/117 = 75.2% 的原则带「责任结构型」半句，在一个按能力分层的骨架里**系统性地**找不到载体。这不是精度问题，是定义决定的。
2. **它买不到任何可检验的净减。** 不删条文（Δ = 0）、不降字符（Δ ≥ 0）、总量净增（第十轮已实测「要降总量只能删，不能移」）。它买到的三样东西——外部命名法、对综述读者的可引用性、一个已被同一份 52 源证据以「演进史不是架构」裁掉过的候选形态——受益人集合为空或未定。
3. **提案材料自己不支持这个用法。** [卡片 01 §8.2](../参考资料/15-图工程/01-仓库测绘与定义.md) 逐字把 B3（README 分类树）、B4（层级替代叙事）、B5（17 子类）、B8（当作已验证范式）四条列为**不可取用**；[卡片 02 §7.2 第 1 条](../参考资料/15-图工程/02-系统智能层.md) 逐字「**不要把这五个子类当作正交的架构分层**」。**用这份材料换骨架，第一个被违反的是这份材料自己写下的边界。**

**应做的是 §7 的替代方案**：修订 9 条、净增 0 条、删除 1 条（25-P3），六条不变量不动，三条生效规则不受影响。
