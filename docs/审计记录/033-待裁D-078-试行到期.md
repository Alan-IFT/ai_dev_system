### 2.1 出路① 复审时重新批准，写新 `approved_at` 与 `expiry`

- **类别：实质修改。** [D-077](../决策日志.md#decision-index) 第 ② 句逐字，且 [08 §6](../08-规范效力元治理.md#trial-expiry) 逐字「需要继续生效必须重新批准并写入新的 approved_at 与 expiry」。

- **对"这套正文还算不算生效"**：连续生效，无中断，无空窗。
- **可逆性**：可逆——`试行`本来就是为此设计的，下一个 `expiry` 再裁一次。
- **成本（要动哪几处、谁批）**：**实测一处**：`docs/决策日志.md` 生效登记表 D-057 行的 `approved_at`／`review_at`／`expiry` 三格；改完两项自检 `PASS`、`生效规则：6`、`0 条断链`。另加 [D-077](../决策日志.md#decision-index) 第 ③ 句要求的一句 `**修订**：…` 留痕。**批准人 Alan，不得由执行者就地改。**

### 2.2 出路② 让它按 [08 §6](../08-规范效力元治理.md#trial-expiry) 自动失效、正文整套退回`提议`

**这一条必须拆成两半，D-078 那一行没拆。**

**语义那一半不需要任何人动手。** 08 §6 逐字「试行规则到达 `expiry` 后**自动失效，退回`提议`**：不再阻断，也不再授权」。到 12-04，效力已经变了，**没有任何人执行任何动作**。

**记账那一半是实质修改，且必须有人做。** 实测三处（§0.2 场景"出路② 做全"），全在 `docs/决策日志.md`：① 删生效登记表 D-057 行；② 决策索引状态列 `试行`→`提议`；③ 散文「当前生效规则数：**6**（…）」→ 5 并去掉 D-057。**只做 ① 会 `FAIL 2 项`（C4 ＋ C9）。** 按 D-077 第 ② 句这属实质修改（blocks 覆盖的动作集合被清空），须 Alan。

> **本文由此点出 D-077 的一处盲区**：它只分「记账修改／实质修改」两档，判据都是"改动使动作集合有没有增减"。而出路② 的记账那一半，**改动本身不使任何集合增减——集合已经被日历改掉了，编辑只是把它记下来**。这是**第三类：追认一件不由人触发的效力变更**。按 D-077 第 ② 句末「判不出属哪一类的按实质修改办」，落在实质修改，处置无误；**但判据本身缺这一档，建议在 D-077 收窄时补一句作用域，而不是新增第三条规则。**

**「历史不追溯」逐字是什么意思。** 08 §6 逐字：「依据该规则在其有效期内已经通过的 Gate 结果、已经形成的验收证据和已经完成的状态转换，**不因规则到期而作废**。到期只影响到期之后的判定。」具体到本仓库：第十五～二十六轮按 D-057 做出的全部裁决（D-058～D-080）、写下的审计记录、[C-038](../失败Case清单.md) 与 [C-045](../失败Case清单.md) 那两条拦截、D-072／073／074／076 的裁定，**一件不作废**。作废的只有一件事：**12-04 之后还能不能援引正文任一条原则**。

**退回`提议`不等于回到零 —— 这一点 D-078 那一行也没写。** [08 §3](../08-规范效力元治理.md#unmarked-default) 分向降级逐字：`governed_by` 指向的决策不在生效登记表中时，「用它作为**拒绝**、暂停、要求补充证据或升级给人类的理由」→**允许**；「用它作为**执行**动作、跳过检查、放宽条件或自我授权的理由」→**不允许**。而 D-057 的 `grants` 格逐字授权的是「援引正文任一条原则作为**拒绝、停止或要求补齐工件**的理由」——**这三个动作全落在拒绝方向上**。

- **判定**：**grants 一侧的实质损失未定，不折算。** 两处的动作词不逐字同（D-057「停止」「要求补齐工件」vs 08 §3「暂停」「要求补充证据」），判不出是不是同一集合，按 30 §2 P1 记未定。
- **blocks 一侧的损失是确定的**：D-057 的 blocks 逐字给的是「各自声明的禁止项具有**阻断力**」，而 [08 §1](../08-规范效力元治理.md#force-states) 表里`提议`那一行「可阻断」逐字是"否"。**这一格确定失去。**

- **可逆性**：**可逆，但不免费**。恢复须走一次完整的重新批准（＝出路①），而那次批准同样卡在 33-P6 的"评估通过"格上；且中间那段时间做出的裁决，其效力依据变成 08 §3 的拒绝方向，不是 D-057——**追溯时这两种依据要分开记，否则就是把两种效力混成一种**。

### 3.2 出路⑤ 改 C3 判据为"报告而不失败"——**实测可行，但被否**

## 4. 这是 D-057 一次性的问题，还是这套制度的设计缺陷

**诚实回答：是结构性的，但缺陷不在 [08 §6](../08-规范效力元治理.md#trial-expiry)，因此"真正该处置的是那条设计"这个说法只对一半。**

**结构性成立，逐条可验**：C3 遍历登记表全部条目，对每一条 `状态 == "试行"` 的比 `expiry < today`（命令 4）；而 [08 §1](../08-规范效力元治理.md#force-states) 规定 `试行` 的生效必需字段**必须**含 `expiry`，且「缺少任一必需字段的决策**不视为已生效**」。所以**每一条`试行`条目，在它 `expiry` 的次日，都会把仓库推进 `FAIL`，直到有人手工编辑 `docs/决策日志.md`**（实测：出路① 一处，出路② 三处）。这不是 D-057 的意外，是这套设计的一个属性。

**但 n=1**：命令 3 现跑，全仓`试行`条目**只有 D-057 一条**，其余五条全是`已接受`、无到期。所以"每个试行到期日制造一次停摆"目前是**结构推论，不是观测频率**。

**"停摆"这个词要收窄。** [D-064](../决策日志.md#decision-index) 实测零钩子零 CI，**那个 `FAIL` 拦不住任何动作**。真正停摆的只有一句话：[仓库工作须知 §2](../附录-载体实例/仓库工作须知.md) 标题逐字「**两项自检（每次改完都要跑，都要 PASS）**」。所以结构产出的是"**一条纪律不可满足**"，不是"工作停摆"。

**而"到期时要人来决定"本身是对的，不该被消掉**：[08 §3](../08-规范效力元治理.md#unmarked-default) 的非对称默认逐字「错误阻断的代价是多问一次人；错误授权的代价可能是不可逆的数据或权限损害」；[40 §2 P6](../40-人的检查点与授权.md) 逐字「慢变、可审计的授权变更」。**一条到期的试行规则理应把人叫回来。**

**缺陷精确落在哪一处**：**两项自检那一个退出码，同时承载了两种不同性质的消息**——「你写错了东西」（C1、C2、C4～C10）与「日历翻页了，需要一个人做决定」（C3 的到期分支）。而那句纪律是照第一种写的。**一个通道，两类消息，且纪律只认其中一类。** 处置面因此在纪律（＋可选地在检查器的报告分层），**不在 08 §6**——08 §6 的语义是对的，改它反而要动一条`已接受`的宪法性规则，档次比"加一句作用域"低两档。

**长期成本，说清楚**：一旦 C3 恒亮，`FAIL  N 项不合规` 里的 N 恒 ≥ 1，读的人从"看退出码"退化成"逐条 diff 报文"，新出现的 C1～C10 缺陷会被这盏灯盖住。本仓库对它的镜像形态已有登记（[C-006](../失败Case清单.md)），也在 [40 §2 P2](../40-人的检查点与授权.md) 里有同型判据（「否决率长期为零……都说明它已不再产生判断」——恒为非零是同一句话的另一侧）。

**结论**：**该处置的不是 D-057 这一例，也不是 08 §6，是 §2 那句纪律；而 D-078 正好是登记这件事的地方。** 出路④ 之所以是"处置那条设计"而不是"处置 D-057"，就在于它写的是通例。
