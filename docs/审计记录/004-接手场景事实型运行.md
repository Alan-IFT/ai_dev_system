## 0. 为什么跑这一次

两个理由叠在一起：

1. [失败 Case 清单](../失败Case清单.md)的 12 条**全部来自"改条文"这类运行**，没有一条来自事实型运行；
2. [D-015](../决策日志.md#effective-register) 于同日生效并给合同加了**事实型视图，而该视图从未被用过**；
3. 有一个真正未答的问题：规范登记的风险之一是"为『从头开始』写得完备，为『从半路接上』没有留合法降级路径"，D-055 声称已处置，**没有人验证过**。

一次运行同时办三件事。**本次运行按合同的事实型列加载**：合同、生效登记表、00 总览、目标章正文；不读 PROJECT_STATUS、不读待决策清单、不读追溯账本。

## 1. 问题

> 风险四指出接手者会被**同时**要求三件互相打架的事：**少读**、**读完再问**、**一旦读出矛盾就停止**。D-055 落地之后，这三条各自有没有合法的降级路径？

## 2. 事实（带成立条件）

<a id="conclusion"></a>

### 结论

**D-055 确实给接手场景开出了合法降级路径，但覆盖不完整，且路径的分布方式使它不可被机械发现。**

### 逐条

**① 「少读」——有路径，但路径不在它该在的地方。**

[22 §2 P2](../22-上下文装配.md) 的正文段已经写明：*"分层的依据是与当前判断的相关性，不是与当前任务的距离——当任务对象本身就是历史时，第三层正是当前判断所需，不因它是历史而后置，此时预算由本次运行声明的停机条件控制而不由分层控制。"*

这句话精确解掉了「少读」与「接手必须读历史」的冲突。**但 22 整章没有任何一条原则的「删除条件」带运行类型限定**——路径写在散文里，不在字段里。按 [09 §4](../09-跨工具通用性.md#two-axes) 的明文规定"**一条原则的适用范围由它自己的这个字段承载**"，这是把作用域写在了字段之外。一个按字段扫描"哪些条对接手运行另有规定"的人会**整章漏掉 22**。

**② 「一旦读出矛盾就停止」——五处有路径，两处没有，而且没有的两处形状相同。**

| 冲突发生在哪一侧 | 降级路径 |
|---|---|
| 状态新鲜度（[20 §2 P3](../20-状态工件.md)） | **有**：记录成立条件后可带降级标记继续用，但依赖它的不可逆动作与验收判定必须停止 |
| 证据字段缺项（[32 §2 P2](../32-证据与追踪.md)） | **有**：追溯登记的主张按成立条件表达，不因缺字段整体判不成立 |
| 记忆候选来源（[12 §2 P4](../12-记忆与知识治理.md)） | **有**：接手与追溯运行按成立条件降级，判不出时记未定并按弱置信登记 |
| 方法条目的失败绑定（[23 §2 P5](../23-方法库.md)） | **有**：轨迹不可得时以可定位的观察与产生事件替代 |
| 人的提问预算（[40 §2 P3](../40-人的检查点与授权.md)） | **有**：接手型运行中输入预算耗尽本身即构成合法的提问理由 |
| **知识主张冲突**（[11 §2 P1/P2](../11-项目知识.md)） | **无**。两条的删除条件都是"写不出（责任结构型）"，不含运行类型限定 |
| **效力冲突**（[08 §8](../08-规范效力元治理.md#conflicts)） | **无**。"两条生效规则在同一 scope 内给出相反判定时，失败关闭：停止并报告，不由执行者挑选"，对接手无例外 |

**③ 「读完再问」——事实型有，交付型 × 接手没有明说。**

[00 §3](../00-总览.md#default-scope) 给了事实型运行一条通路："事实型运行读到停机条件时记未定并进入下一步，不转阻塞"。40-P3 又补了"接手型运行中输入预算耗尽本身即构成合法的提问理由"。

但 [22 §2 P3](../22-上下文装配.md) 要求**开工前**执行者能基于工件说清九项事实，"答不上来就先补工件，不靠回忆"，删除条件为"写不出（责任结构型）"，**不含接手例外**。对"接手一个停滞的工作项并把它做完"这类**交付型 × 接手**运行，工件残缺恰恰是接手的定义，"先补工件"就是全部工作量——等于把接手运行还原成从头运行。

### 本结论的成立条件

- **只查了两处**：全部 117 条原则的「删除条件」尾标，以及正文中含"接手 / 考古 / 状态重建 / 冷启动"字样的段落。**没有逐条通读全部正文**，漏检可能存在，方向是"可能还有别处已给出路径"。
- **未在任何真实接手运行中验证**，是静态阅读的结论。真实接手运行会不会真的被这三条卡住，未观测。
- **元治理两章只读了 08 §8**（因为它是效力冲突的落点），没有通读 08 与 09；08 可能另有例外条款未被本次覆盖。
- 本次运行按事实型视图加载，**刻意没有读 PROJECT_STATUS 与待决策清单**，因此不知道这三处缺口是否已在别处被登记或裁决过。

## 3. 一个假设

三处缺口（11-P1/P2、08 §8、22-P3）**可能不是遗漏，而是有意为之，只是没有写出理由**。它们有共同形状：

> **D-055 改动 3 的"结论 + 其成立条件"解决的是「证据不足」；而这三处全部是「两个权威打架」。**
> 证据不足可以带成立条件继续，因为降级只是把不确定性显式化；权威冲突不能降级，因为"带成立条件继续"在这里等价于**让执行者自己挑一个权威**，而那正是 11-P1、11-P2 与 08 §8 三条各自要防的失败。

如果这个假设成立，正确的处置**不是**给这三处补降级路径，而是在 [00 §3](../00-总览.md#default-scope) 用一句话写清降级的适用边界：**降级适用于证据不足，不适用于权威冲突**。那是一句话的澄清，不是三处新增。

假设的证伪方式：找一个真实接手运行，其中权威冲突无法在合理成本内消除，而停止的代价高于"带成立条件继续"的代价。找得到即假设被推翻，三处确实需要各自的路径。

## 4. 待人裁决

1. **22 章的接手路径要不要写进删除条件字段。** 现状与 09 §4 的明文规定不一致（作用域应由字段承载）。两种解法：补进 22-P2 的删除条件；或承认正文段也是合法载体、修订 09 §4 的措辞。
2. **§3 的假设成立吗。** 若成立，00 §3 加一句"降级适用于证据不足，不适用于权威冲突"即可结案；若不成立，11-P1/P2、08 §8、22-P3 三处各需一条运行类型限定。
3. **22-P3 对"交付型 × 接手"要不要例外。** 这一项与第 2 项的答案相关：若接手时工件残缺属于"证据不足"，则应有路径；若属于"不知道谁说了算"，则不应有。
