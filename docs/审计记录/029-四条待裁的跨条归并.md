## 1. 先核 027 那个 `grep`——它比依赖图严重

Alan 的提问把这一条排在依赖图之后，但**按后果排它在前面**：依赖图错了，四条待裁的顺序错；这一条若属实，本轮多份记录在用一条**不在生效正文里的句子**当判据。先核这一条。

### 1.1 现跑结果：**属实**

```
grep -c "动作空间" docs/31-守卫与权限边界.md   →  0   （退出码 1）
```

**[31 §2 P1](../31-守卫与权限边界.md) 全条逐字**（`sed -n '24p' docs/31-守卫与权限边界.md` 现取）：

> - **P1 约束力由两个独立维度决定，据此分四级。** 两个维度是：检查是否自动进入必经路径；失败是否改变后续状态。只写在指令里的是提醒；写成程序但要执行者想起来运行的是工具；自动运行而失败仍可继续的是警告；只有自动运行且失败使下一步无法进行的才是约束。更强烈的措辞不构成任何一级。警告必须留下被下游必然消费的痕迹，跳过必须可见。

**「动作空间被该通道穷尽」这九个字不在其中。027 §3.1 的现跑与推论，这一步核实无误。**

### 1.2 但"不存在的话"这个说法不对——那句话存在，且来路完整

`grep -rn "动作空间" --include=*.md .` 现跑，把命中按时间顺序排成一条链：

**B-1 的现状逐字**（[D-065](../决策日志.md#decision-index)）：「**B-1**：015 自己写着须在 C-1 之后，C-1 已随 D-064 跑完，但 B-1 的措辞依赖试点结果，而试点（D-068）的判据本身未定」，后续验证栏「B-1 是顺序问题，待 D-073 裁出判据、试点跑过之后重提。」

**所以这句话的效力状态是 `提议`。** 按 [08 §1](../08-规范效力元治理.md#force-states) 逐字，`提议` 的可阻断栏与可授权栏都是"否"。

**因此"引一句不存在的话"这个说法应更正为**：那句话存在、有明确出处、且从未进入正文；缺陷是**这四处援引没有一处标出处，且第 5 处把它与 [31 §2 P1](../31-守卫与权限边界.md) 的链接并置在同一分句里**，读起来像是 31-P1 的正文。这正是本仓库已登记的第三类错法（"节存在但内容不在那一节"）的一个变形：**内容存在但不在生效层**。

### 1.3 后果分两半：一半是虚惊，一半是真的

**这一步四路都没做，本文补。**

**（a）D-064 结论②不倒——它有一条不经过那句话的独立路径。**

结论②逐字：「按 31-P1 的四级，本仓库的「约束」级与「警告」级都是空集」。

按 31-P1 **正文原文**判：两个脚本是人工调用的（`check_normative_force.py`、`linkcheck.py`），逐字命中「**写成程序但要执行者想起来运行的是工具**」——落"工具"级。而"警告"与"约束"两级的共同必要条件是「**自动运行**」，两个脚本都不满足。**故结论②在不引用「穷尽」判据时同样成立。**

> **裁定**：D-064 结论②、[C-041](../失败Case清单.md)、[023 §2](023-执行清单-冻结版.md) 结论②——**结论对，理由错**。它们援引的是一条 `提议` 判据，而正确的理由只需要 31-P1 正文的「自动运行」四个字。**这是一处理由更正，不是结论推翻。**

**（b）[D-074](../决策日志.md#decision-index) 的收益命题倒，且倒两次。**

D-074 依据栏逐字：「**能把「警告」级从空集变成非空的唯一动作就是这一行配置**」。

- **第一次倒（按 B-1 拟定原文）**：027 §3.1 已判——`git commit --no-verify` 是一条绕过写入路径，「穷尽」不成立，钩子同样够不到"警告"级。**本文独立核对：成立，且它是同一条判据的对称应用**——那句判据被用来否掉两个脚本的"警告"级（因为绕过它们需要 0 个动作），却没有被用到钩子上（绕过它需要 1 个动作，但仍然是一条绕过路径）。**同一条判据被单向应用，这是这处援引里最实的一个缺陷。**
- **第二次倒（按 31-P1 正文原文，与 B-1 无关）**：钩子是自动运行的；「失败是否改变后续状态」这一维**有两读**——读作"提交被中止"则落**约束**级，读作"敲 `--no-verify` 即可继续"则落**警告**级。**取任一读，那句话都不成立**：前一读让"约束"级非空而不是"警告"级，后一读才是"警告"级。**两读只有一读支持那句话，按 [30 §2 P1](../30-验证与测试.md)「缺成立条件即记未定」，该收益命题记未定，不折算。**

> **裁定**：D-074 行那句唯一的正向收益命题**按两条独立路径都不成立或未定**。这不改变 027 的推荐（不挂），但它**取消了"若裁准要挂"那一侧的唯一理由**——027 §8 第 6 条留了一句「若 Alan 要的就是"让警告级非空"，那么只有选项二三做得到」，**这句话现在也不成立了**：选项二三做不做得到"让警告级非空"本身记未定。**本文把这一格补上。**

### 1.4 这件事该怎么处置（记账，不需要 Alan）

**四处援引各加一句出处标注即可**，不改任何结论：D-064 行、[C-041](../失败Case清单.md)、[023 §2](023-执行清单-冻结版.md) 第 94 行与第 106 行。标注内容一句：「该判据出自 [015 §2.3](015-图工程三原则综合审计.md) 的 B-1 拟增文本，状态 `提议`（[D-065](../决策日志.md#decision-index)），不在 [31 §2 P1](../31-守卫与权限边界.md) 正文内；本处结论另有一条只依赖 31-P1 正文「自动运行」的独立路径。」

**这个用法本身不违规。** [33 §2 P4](../33-评估与演进.md) 要求「先写成功与失败标准，再运行」，它**不要求判据必须是生效正文**——一次运行可以自定判据。且 C-1 那次用它是**拒绝方向**（否掉两个脚本的"警告"级），[08 §3](../08-规范效力元治理.md#unmarked-default) 逐字允许「用它作为**拒绝**、暂停、要求补充证据或升级给人类的理由」。**违规的是 D-074 那一处**：它把同一条 `提议` 判据用在**论证一个动作值得做**上，而 08 §3 对该方向逐字写"不允许"。

**这条更正进本文 §4 的动作 5。**

- **核 §5.1 问二（价值质变）**：**部分成立，且必须按 §1.3(b) 打折**。026 写「挂：类型头导出的检查器可以直接进入必经路径，试点买到的是**阻断力**而不是**提醒**」——**这一句用的正是 D-074 行那条现已记未定的收益命题**。按 §1.3(b)，"挂上之后落哪一级"本身记未定。**故"质变"这个判断降为：挂上之后试点产物的级别由未定的一格决定，而不是确定地从"提醒"升到"阻断"。**

## 3. 归并：这四条是不是同一个根因的不同表述

照 [003](003-综合审计.md) 第九轮归并路的做法：**归因 → 聚类 → 四层级取最小 → 论证下界 → 反向检查净行数。**

### 3.1 第一步·归因：把"提议"和"它防的失败"分开写

| 待裁 | **提议是什么**（动作） | **它防的失败是什么**（逐字或逐字改写） | 该失败在本仓库发生过吗 |

**第二个读数（本文认为更要紧）**：**只有 D-072 一条是"提议 = 新增一条条文"。** 另外三条的提议分别是"定义一个判据"（D-073）、"改一行配置"（D-074）、"删三个字面量"（D-076）。**四条里三条不是加条文，D-072 那一条自己也逐字写着「可以删掉现有的什么：指不出」。**

### 3.2 第二步·聚类：三个根因，不是一个

**四条不是同一个根因的不同表述。** 逐条归位后落在三处：

| 根因 | 一句话 | 覆盖哪几条 |
|---|---|---|
| **R-a 无执行点** | 本仓库不存在任何自动通道；任何"写一条新条文"或"产出一个新检查器"的动作，按 [31 §2 P1](../31-守卫与权限边界.md) 都只能落"提醒"或"工具"级 | **D-074**（直指）、**D-073**（试点产物是一个检查器）、**D-072③**（新条文按 31-P1 落"提醒"级） |
| **R-b 效力源里的会漂字面量** | 唯一效力源自己身上长着别处权威的手写投影 | **D-076**（直指）、**D-072③**（被它挡住）、**D-069 前半**（被它挡住） |
| **R-c 改一份已生效文本没有判据** | "实质修改"与"记账修改"没有分界，于是每一次改都要上会一次 | **D-076**（改登记行）、**D-073·Q2**（改被观测的正文）、**D-072②③**（改试行期内的章） |

**R-b 与 R-c 是同一件事的对象侧与动作侧**（前者是"那个数会漂"，后者是"改它的动作算什么"），但它们的处置不同：R-b 的处置是**删对象**，R-c 的处置是**写判据**。**两者不可互相替代**——删掉 117 之后，"改登记行算什么"这个问题依然存在（下一次改 blocks 格仍要问）。

**R-a 与 R-b/R-c 之间没有共同上游。** R-a 是"仓库里没有自动通道"这个物理事实，R-b/R-c 是"记账制度缺一条判据"。**因此四条合并不成一个动作，下界不可能是 1。**

### 3.4 028 报出的那件 D-076 自己没看见的事：核验，并加强一档

`grep -n "不变量、控制平面与责任平面的原则对一切运行成立" docs/00-总览.md` 现跑，命中 [00 §3](../00-总览.md#default-scope) 第 62 行，逐字：

**三条后果，逐条：**

## 6. "两条都推荐不做"，是不是系统性保守偏差

**诚实回答：是，有一种系统性保守偏差；但它不是四路的偏好，是规则本身写进去的。四条推荐各自的实证依据独立成立，但它们被同一套非对称规则一致地放大了。**

### 6.1 先把事实摆准：不是"两条都不做"，是三条半

- [025](025-待裁D-072-记忆与控制流.md) 推荐 ④：正文 0 行，**但自带一处删除**（落地包 §7 表那一栏归零）。
- [026](026-待裁D-073-试点判据与观测窗.md) 推荐 丙：**不试**。
- [027](027-待裁D-074-执行点.md) 推荐 一＋四：**不挂**，加一句分句。
- [028](028-待裁D-076-效力源里的会漂计数.md) 推荐 A：**做减法**——这是一个实打实的动作，四处删除。

**所以是"三条推荐不新增、一条推荐删"，不是"四条都不做"。** 但 026 与 027 那两条确实是纯粹的"不做"，Alan 的问法命中了它们。

### 6.2 偏差的三条结构性来源，逐条可核

**来源一：最高原则的三档里，第一档在本仓库结构上取不回来，于是三档退化为两档，而那两档都反对新增。**

- 第一档「以行业标准规范推荐」——四份深挖**全部在这一格记未定或平**：[026 §4.2](026-待裁D-073-试点判据与观测窗.md)「三个选项在这一格并列，判不出」；[028 §11](028-待裁D-076-效力源里的会漂计数.md)「四个选项在这一格上本文分不出高下……**这是"未定"，不是"都合格"**」；[027 §8](027-待裁D-074-执行点.md)「中性偏支持」；[025 §5.1](025-待裁D-072-记忆与控制流.md) 判该档不支持任何新增选项。
- **成因是结构性的，不是懒惰**：[015 §1.3](015-图工程三原则综合审计.md) 已裁「图工程……不是行业标准」；[D-071](../决策日志.md#decision-index) 记「三份标准的正文在付费墙内，本轮取不回来」。
- **后果**：唯一可能推向"做"的那一档在本仓库**结构上不可用**，裁决实际只由第二档（少就是多）与第三档（避免修修补补）决定，**而这两档都天然反对新增。**

**来源二：[08 §3](../08-规范效力元治理.md#unmarked-default) 的分向降级是设计上就非对称的，且它是 `已接受` 的。**

逐字：「用它作为**拒绝**、暂停、要求补充证据或升级给人类的理由｜**允许**」「用它作为**执行**动作、跳过检查、放宽条件或自我授权的理由｜**不允许**」，理由逐字「**风险不对称**……**默认值因此偏向保守**」。

**所以每一个记未定的格，在处置上都倒向"不做"。** 而四份深挖合计记了十几处未定（子原因几乎全是"生成者与验证者同一"，来自 [30 §2 P5](../30-验证与测试.md)）。**这不是四路选择保守，是规则规定未定必须保守。**

**来源三：三档里第三档"避免修修补补"在本仓库有一个已裁的诊断，它把新增机制一律推向负分。**

[022 §3.1](022-执行前审计-价值与顺序路.md) 逐字引 [015 §3.2](015-图工程三原则综合审计.md) 的判定：「**修修补补发生在账本层与记账层，不在条文层**」，并加一句「**在一个已诊断出"记账层过重"的仓库里，本轮的六项记账工作是在给病灶加料，不是治它**」。**任何新机制都会新增记账，因而在第三档天然扣分。**

### 6.3 但四条推荐各自的证据独立成立，且各自可被证伪

**这一格必须写，否则"是偏差"会被读成"结论不可信"。**

| 推荐 | 承重证据 | 它的证伪路径（一条就够） |
|---|---|---|
| 027 不挂 | 41 条 Case 对账**零条**满足"这两个脚本本来就能查出、只是当时没人跑"；28 次提交重放真阳性 0 / 假阳性 2 | **找到一条满足该判据的 Case**，或重放出一次真阳性 |
| 026 不试 | [D-064](../决策日志.md#decision-index) 实测本仓库无任何自动执行点；试点判据**没有对照臂** | **补出对照臂**（需要第二个独立执行者），或 D-074 裁"开" |
| 025 拒绝 | [08 §1](../08-规范效力元治理.md#force-states) 效力表逐字（`提议` 两栏皆否）；权限侧七重覆盖 | **找到一条不被那七处覆盖的场景** |
| 028 删数 | 登记行两处自述「不是名单」「不枚举编号」；D-047 grants 逐字授权修改不变量 | **证明「117」承担范围界定**（须驳倒那两处自述） |

**四条都写下了自己的证伪条件，且都是可复跑或可逐字回查的。这是"保守但不封闭"的形态，不是"先有结论再找理由"。**

### 6.4 诚实的代价陈述

**保守是有价签的，四份深挖各自写了一半，合起来是这样：**

> [D-057](../决策日志.md#effective-register) 的 `expiry` 是 **2026-12-03**（`sed -n '24p' docs/决策日志.md` 现取）。按 [08 §6](../08-规范效力元治理.md#trial-expiry)，到期后 117 条**自动失效、退回 `提议`**，且「**到期不追溯**」。这扇窗的检验① 问的是"有没有任何一条原则真的拦住过东西"。**若本动作集执行（三条不新增、一条删），到 2026-12-03 这扇窗的读数仍将是"拦住 0 条"，而成因已由 [D-064](../决策日志.md#decision-index) 实测锁死为"没有任何自动执行点"。**
>
> **也就是说：这一轮的保守，代价是这个试行期到期时什么也没测到。** 四份深挖没有一份把这句话写出来。**本文写下它，但不据此改变推荐**——因为改变推荐要么是挂一个真阳性为 0 的钩子（[027 §2.2](027-待裁D-074-执行点.md)），要么是跑一个没有对照臂的试点（[026 §1.5](026-待裁D-073-试点判据与观测窗.md)），**两者都不会把那个读数变成非零，只会让它变得更难解释。**

**本格按未定读**（单人判定，无第二判者）。
