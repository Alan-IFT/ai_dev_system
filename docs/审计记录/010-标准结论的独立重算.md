### 2.1 最该记住的一条

> **`本节刻意不写任何计数字面值。`** ——这句话写在[仓库工作须知](../附录-载体实例/仓库工作须知.md) §6，而**同一节里同时写着八个计数字面值**。它在写下的那一刻就被自己所在的段落证伪，此后九轮无人发现。

### 2.2 其余的形状

- **分母错**："永久豁免从 84 条（72%）降到 41 条" —— 84 是 127 条里的 84，占 **66%**；72% 是拿 84 去除以整改**之后**的 117。整改后独立重算为 **40 条**。
- **抄写错**：正文"807 行"实为 **792**（这条第十三轮已按 C-009 修过一次，又漂回来了）；"多 6.2%"实为 **6.6%**；一手来源"9 个"实为 **8**；"其余十一章"实为 **8 章**。
- **口径错**："正文只改 10 行（1.1%）"实为 **8 行**，而 1.1% 只在一种 diff 口径下成立，换口径在 0.89%～2.55% 之间摆动。
- **方向反了**：第二十轮写的"默认加载集 45,358 → 45,288，只省 70 字符"，实为**净涨 687**——把本文件自己涨的那部分排除在了口径之外。**这一行就写在"我被五比零驳倒、错法是量错了口径"的下一行。**
- **改标点**：读数一引 [23 §2 P1](../23-方法库.md) 时把分号改成顿号、双引号改成单引号——与第二十轮那次"给 [22 §2 P2](../22-上下文装配.md) 加了个原文没有的冒号"同型。

### 2.3 一条实质更正，不只是数字

**读数一「117 条原则拦住 0 条」已不成立。** 它写于正文全是`提议`的第十一轮。D-057 之后，**至少四次由正文原则拒绝或停止了具体改动**：30 §2 P1 → [D-059](../决策日志.md#decision-index) 已拒绝；22 §2 P2 → D-058 ②；11 §2 P1/P2 → D-058 ①；33 §2 P9 的删除门槛 → 第二十轮放弃删除合同第 5 项。

**并附一处口径陷阱**：这四次拦住的是**提案**不是**失败**，清单里没有对应行。若照 D-057 后续验证栏说的"对账「当时被拦住了吗」那一列"，会得出"仍然拦住 0 条"的错误结论——**那一列只登记失败，不登记生效。**

## 4. 核查者自己也错了两处——这是本轮最深的一条

**独立核查一旦以仓库内另一处手写数为基准，就退化成对账。**

- 一组把 PROJECT_STATUS 正确的"26 份版本号副本"判成`从来就错`，理由白纸黑字写着"按同文件 C-001 自己给的口径"——**而 C-001 那个数从没被查过**。
- 另一组算出"永久豁免 21 条"，并说与[审计记录 007](007-D-057作用域与本仓库自身合规.md) 的 21 "独立吻合"——实为**同一个分号解析 bug 的两次复现**（不剥括号就按分号切，"写不出（责任结构型：…；…）"被拆成不含"写不出"的子串）。正确值是 **40**。

**第二十轮把教训记成了"量错了口径"。真正的教训是"不要拿自家的数当基准"**——本仓库的全部问题恰恰是所有手写数同出一源。（[Case C-033](../失败Case清单.md)）

## 5. 一处已知空缺，本轮没补

**分工是按投影切的，源表因此无人查。** 五组分别负责三份文件，而它们**全都是[失败 Case 清单](../失败Case清单.md) §2 那张 30 行表的投影**——表本身落在每一格外面。完备性批评抽查两行即得两处错（C-001 的"27 份"、C-022 的"第 15 行"）；§0 与 §5 同样无人负责。

**这与本清单反复登记的那个病同形：每次都去查副本，不去查源。**（[Case C-032](../失败Case清单.md)）**§2 表体至今仍未被独立核查过，这是目前最大的已知空缺。**
