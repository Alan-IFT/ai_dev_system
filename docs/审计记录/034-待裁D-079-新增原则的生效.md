## 1. 事实层：加一行 `- **Pn` 之后实际会发生什么

### 1.5 C7 是什么，不是什么

**C7 是对账，不是闸门。** 代码逐字（`check_normative_force.py` 第 224–236 行）：

```python
in_body   = re.findall(r"^- \*\*(P\d+)", p.read_text(encoding="utf-8"), re.M)
in_ledger = re.findall(r"^\|\s*(P\d+)\s*\|", sec, re.M)
...
miss = [x for x in in_body if x not in in_ledger]
```

它比的是**两份文件的编号集合相不相等**，两边都由提交者自己写。它答不出"这条原则是谁批准的"，因为它的比对面里根本没有"批准"这个对象。[追溯账本 §1](../追溯账本.md) 那条硬约束逐字是：

> 本文与正文之间只有一条硬约束：**每条原则在本文中有且只有一条强度记录，编号与正文一致**……**改动一条原则的编号或增删原则时，本文同步更新**；对不上即为待修复缺陷。

**它逐字预设了"增删原则"可以发生**，课的是同步义务，不是批准义务。**账本自己的效力逐字是「零」**（文件头第 4 行：「效力：**零**。本文不阻断、不授权、不构成落地要求」），把它当闸门是 [C-044](../失败Case清单.md) 记过的那一形态——拿一份效力为零的材料当承重判据。

**这直接改变 D-079 的危害评估，但方向与直觉相反。** [D-076](../决策日志.md#decision-index) 那一行逐字写「外延由各章 `^- **Pn` 的行形态固定并被检查器 C7 咬住」，[D-079](../决策日志.md#decision-index) 行也照抄了这个"咬住"。**实测 B 与 C 证明"咬住"只咬住了对账，没咬住准入**：多一行账本即通过。所以不能说"C7 拦住了一半"——它拦住的是**忘记同步账本的那一半**，不是**未经批准的那一半**。

## 2. 语义层：[08 §3](../08-规范效力元治理.md#unmarked-default) 的分向降级，答了没有

### 2.1 逐字

> ## 3. 未标注规则的默认行为：分向降级
>
> 执行者遇到没有 `governed_by`、或 `governed_by` 指向的决策不在生效登记表中的命令式语句时：
>
> | 使用方向 | 是否允许 |
> |---|---|
> | 用它作为**拒绝**、暂停、要求补充证据或升级给人类的理由 | 允许 |
> | 用它作为**执行**动作、跳过检查、放宽条件或自我授权的理由 | 不允许 |
>
> 理由是风险不对称：错误阻断的代价是多问一次人；错误授权的代价可能是不可逆的数据或权限损害。默认值因此偏向保守。
>
> 推论：未标注规则不能被用来论证"某动作被允许"，因此也不能被用来把空检查集解释成已通过（见 §4）。
>
> 本条不要求为仓库中每一句现存文字补标注。未标注即按上表处理。

### 2.2 触发条件成立吗——成立，而且对**全部**原则都成立

§3 的触发要件逐字是「没有 `governed_by`、或 `governed_by` 指向的决策**不在生效登记表中**」。按 §1.7 第 1 条的现跑结果：31 章章头六个 ID 无一在登记表内，14 章无一章头指向 D-057。**按字面，31 章每一条现存原则今天就落在 §3 的触发档里**，新写的那条与旧的没有任何区别。

**这不使它们失效**——它们的效力来自 D-057 那一行，不来自章头。**但它正是 §3 答不了 D-079 的结构性原因**：§3 的触发条件里没有"这一行是什么时候写的"这个维度，它给不出任何区分新旧的判据。

### 2.3 答案：**答了一半，且答的那一半与另一半方向相反**

**授权方向——已答，明确「不允许」。** 一条刚写进正文、还没被任何决策认领的原则，**不能**被用作执行动作、跳过检查、放宽条件或自我授权的理由。这不是推论，是 §3 表格第二行的字面。[D-014](../决策日志.md#effective-register) 的 blocks 格把它写进了唯一效力源，逐字「阻止把**未登记规则**用作**执行/授权**依据」。[D-079](../决策日志.md#decision-index) 行末格自己已经这样记了：「新写下的原则**不得被援引为授权依据**」。

**阻断方向——也已答，但答案是「允许」。** §3 表格第一行逐字把「用它作为**拒绝**、暂停、要求补充证据或升级给人类的理由」列为**允许**；[D-014](../决策日志.md#effective-register) 的 **grants** 格逐字「授权执行者按分向降级使用**未标注规则**作为**拒绝理由**」。

**所以"凭空造出一条有阻断力的规则"这件事，08 §3 不但没堵，而且是唯一效力源明文授予的默认。** 而且这个默认**不依赖 `- **Pn` 这个行形态**：按 §3 末句逐字「本条不要求为仓库中每一句现存文字补标注。未标注即按上表处理」，任何人在仓库任何地方写下**任何一句命令式语句**，都已经可以据 D-014 的 grants 格援引它拒绝。**加不加那个 `- **Pn` 前缀，在阻断方向上一分钱也不多买。**

§3 自己给了这么设计的理由，逐字：「**错误阻断的代价是多问一次人**；错误授权的代价可能是不可逆的数据或权限损害。」——即：D-079 忧虑的那一侧，正是本仓库宪法性地判定为便宜的那一侧。

### 2.4 那么入不入 D-057 集合，差额到底是什么

不是"能不能阻断"（§3 已给），是这两项：

1. **义务差。** [08 §1](../08-规范效力元治理.md#force-states) 状态表 `试行` 行逐字「在 effective_scope 内**执行**，每次执行须记录结果供复查」——这是**课在所有人身上的义务**。§3 给的是**许可**（"允许"用作拒绝理由）。入集把"我可以援引它拒绝你"变成"你必须遵守它"。
2. **裁剪差，方向与直觉相反。** D-057 的 grants 格逐字另给一项 §3 没有的：「授权按各条「删除条件」的起始档与运行类型限定**裁剪其适用范围**」。而 §3 表格第二行逐字把「**放宽条件**」列为**不允许**。**推论：一条不入 D-057 集合的新原则，它的「删除条件」尾标反而不能被用来裁掉适用范围——它在 §3 下比在 D-057 下更宽、更难被限缩。** 让它"不自动生效"并不使它更弱。

### 2.5 [33 §2 P6](../33-评估与演进.md) 说了什么

逐字：「晋升链是唯一入口，晋升检查口径而不是分数。链路是：观察到失败 → 可复现 Case → 基线 → 候选实验 → 评估通过 → **人类批准** → 决策进入试行或已接受 → 受控发布 → 线上观察 → 保留、修改或回退。」删除条件逐字：「运行类型限定——**本链的对象是本系统的规则、方法条目、记忆与机制的变更**……作用域内写不出（责任结构型：**链上的"人类批准"一步不可省，实验结果不能自动升格为生产规范**）」。

往正文加一条原则，逐字落在「本系统的**规则**……的变更」里。所以 P6 正面回答了 D-079：**不自动生效**。

**它的两个限定必须同时写出**：① 它是正文原则，效力来自 D-057，**它自己是否被触发记未定**（§1.6 末）；② 但**援引它去拒绝**"把一条未经批准的新行当成生效规则"，是 §3 表格第一行的**拒绝方向**，**无论 P6 是否被完整触发都允许**。所以 P6 这条腿在拒绝方向上是稳的，在"它自己生不生效"上是未定的——**两者不折算**。

### 2.6 [31 §2 P1](../31-守卫与权限边界.md) 的四级：D-079 行那句援引不成立

[D-079](../决策日志.md#decision-index) 原因栏逐字写「一条无人必经审批、写下即取得阻断力的通道**恰好落在那一档**」（指「约束」级）。按 31 §2 P1 正文逐字：「**只写在指令里的是提醒**；写成程序但要执行者想起来运行的是工具；自动运行而失败仍可继续的是警告；**只有自动运行且失败使下一步无法进行的才是约束**。」一行写进 md 的文字是"只写在指令里"，落**提醒**级——四级里最弱的一档，而不是「约束」。且 [D-064](../决策日志.md#decision-index) 实测、[C-041](../失败Case清单.md) 登记：本仓库「约束」级与「警告」级**都是空集**。

**结论：D-079 行那一句把危害定高了一档。** 这不推翻 D-079 值得裁，但它把"危害有多大"这一格从"落在最强的一档"改成"落在最弱的一档"，而这一格是 §4 排序的输入。

> **更正（[036](036-三条待裁的独立复验.md) §2.4）**：本节这个反驳**不成立，因为它换了对象**。[D-079](../决策日志.md#decision-index) 那一句分类的不是"一行写进 md 的文字"——逐字是「一条无人必经审批、写下即取得阻断力的**通道**恰好落在那一档」，**它分类的是通道**。本节拿"那行文字落提醒级"去驳"那条通道落约束级"，两个对象不同，**没有正面驳到**。而按 [D-057](../决策日志.md#effective-register) 的成员判据，从"写下一行"到"取得阻断力"中间**没有任何人工步骤**（本文 §2.3 第 5 点与 §1.4 实测 C 已证），是自动的；它也改变后续状态（该行自此有阻断力）。按 31-P1 的两个维度，把这条**效力赋予通道**判到高档并非无理——**本条按 [30 §2 P1](../30-验证与测试.md) 记未定，但本节的反驳不成立**。
>
> **后果本节自己写明过**：这一格是 §4 排序的输入；反驳不成立 → 危害那一格回到**未定** → §4 的排序少一个输入。**另有一处本节内部自相矛盾**：同一段里既写"把危害定高了**一档**"，又写把这一格"从**落在最强的一档**改成**落在最弱的一档**"——提醒到约束隔着三档，**两句不能同时成立**。（本文其余三条主张经复验全部属实，含三个实测与 `governed_by` 那条；后者另立为 [C-046](../失败Case清单.md)。）
