### D-047（边缘部件不设部件）：**裁决方向成立，但四条推论不完备**

D-047 在[架构确定 §6.4](../架构确定.md#edge-components) 自己登记的证伪信号第二条是"出现一条既不属于四条推论、也无法由外部判据推出的跨边界纪律"。**这条信号在三个切片里各触发了一次，且三次同源**：

> 第六条不变量的四条推论**全部站在"我方是主动方"的位置**——我方读外部（推论一）、我方写外部（推论二）、我方依赖外部（推论三）、外部唤醒我方（推论四）。**边界的另外两个方向没有建模**：我方被外部消费（A1），以及外部内容合法变成我方资产（B3、C 5.3）。

三名 Agent 独立得出同一判断：**这仍然是约束的形状，不是部件的形状**，修补需要两条推论而不是两个部件，因此不构成回到选项 B 的理由。裁决保留，推论需补（见 §3 的 D-048）。

**另有一处是 D-047 压缩带来的真实损失**：把"触发与入口"压成"唤醒不等于授权"时，只保留了授权语义，丢掉了分流、去重、误报计数与**退场**。切片 B 的样本极典型——半年前为一次同类告警加的规则，从此每次必触发，现在所有人已习惯忽略它。这组纪律有归属（[33 评估与演进](../33-评估与演进.md)的机制误伤计数与结构性删减），但 33 的作用域没写清是否包含"我们依赖的外部触发机制"，于是没人认领。

## 2. 最重要的发现：规范为"从头开始"写得完备，为"从半路接上"没有留合法降级路径

这是切片 C 的结论，也是**唯一一条直接命中本项目立项动机的发现**（"大型项目到后期越来越慢、新会话一开始就臃肿"）。长期维护的项目，绝大部分时间处在"接手"而不是"开工"状态；而现有正文的默认场景是增量、从头、事发当时。具体表现为六处，它们互相独立地指向同一个缺口：

| 现象 | 冲突在哪 |
|---|---|
| 状态工件只有"有效 / 冲突"二值 | 20-P3（冲突即停止）与 20-P5（低可信可继续）在接手场景给出相反指令且无优先级；置信态三档被 12-P1 锁死在记忆一侧，状态工件借不到 |
| 提问前须穷尽可读事实（22-P10、40-P3） | 与"有限可预算输入"正面冲突，且没有预算例外——接手者被同时要求少读、读完再问、一旦读出矛盾就停 |
| 记忆候选由状态转换自动提取（12-P4） | 只能在事发当时执行；照字面读，等于宣布二十次会话里的一切经验作废 |
| 方法库要求绑定已登记 Case 并附轨迹（23-P5） | 追溯登记时轨迹不存在，把幸存的历史经验挡在门外 |
| 证据六项最小字段（32-P2） | "精确版本""工作区身份""观察时间"在考古场景补不出来，于是旧坑作为主张一律不成立 |
| 接手时几乎一切都是未定 | 而未定的纪律是"必须停止并报告" |

**这不是某一章的缺陷，是全篇的一个默认假设。** 处置方式不是加规则，而是给这几条补一档合法降级（见 §3 的 D-052）。

## 6. 本次演练自身的边界

- 三个切片都是**构造的**，不是真实项目的真实记录。它们能证伪"理论接不住某类内容"，不能证明"理论在真实项目里有效"。
- 三名 Agent 都读过同一套正文，可能共享同一种误读。三份产出中互相独立复现的发现（第六条不变量的方向缺失）可信度高于只出现一次的发现。
- 走查步数与"无归属条数"不是可比指标，不同 Agent 的切分粒度不同。
