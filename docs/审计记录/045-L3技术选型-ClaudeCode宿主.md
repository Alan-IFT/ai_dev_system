# 045 L3 技术选型（Claude Code 宿主）

## 0. 本文是什么

- **是**：把 [043](043-L3技术选型-DSH宿主.md) 那套 L3 栈的宿主从 dsh 换成 Claude Code，逐格说明哪些不动、哪些重写、代价在哪、开工前要验什么。**换宿主要重写的只有 043 §5 那一张接触面表**——这不是本文的发现，是 043 §5 自己写下的设计意图（"换宿主时只重写这一张表"），本文是对那句话的第一次兑现。
- **不是**：不写代码（Alan 2026-09-02 方针未改）；不改正文；不改生效登记表；不推翻 043。043 的三个信任域、零新服务、六个开关、DBOS 编排、GitHub 承载人的检查点——全部沿用，本文不重复论证。

## 1. 三句结论

1. **能。Claude Code 能当 L3 宿主，且 043 §5 那六个洞它堵掉两个半、新开一个。** 堵掉的：**网络边界**（Claude Code 沙箱原生做出口域名白名单加代理，dsh 官方明写"network stays unrestricted"，043 只能靠容器 iptables 补）【文档】；**最终结果无 schema**（`--json-schema` 是原生标志，dsh 的 headless 没有 JSON 输出，043 §5 洞 3 只能自定义一个写文件的工具再回读）【一手】。半个：**版本风险**（Claude Code 是正式发布、有版本号、有升级通道，不是 alpha；但仍是天级发版，pin 与回归集照跑）。新开的一个：**有损压缩的损失信号没有原生载体**——dsh 的指令预算超限点名通告是 043 §1 列的"两样 dsh 独有"之一，Claude Code 的 `InstructionsLoaded` 事件存在但官方文档未写它报告被丢弃或截断的内容【文档】，这条退回 041 §6 L3 行早就写好的"其余宿主自建不变量指纹核对器"。
2. **栈不动，只动宿主绑定层。** 043 §4 那张十四行表里，**「载体」列几乎整列不动**——它本来就落在 git、GitHub、PostgreSQL、文件系统上，与宿主无关；动的是「dsh 侧」列，本文改名为「宿主侧」并整列重写。三个信任域不变（仓库 / 编排进程 / 执行容器），零新服务不变，DBOS 承担跨切片持久化不变，GitHub 承载 [40 §2 P1](../40-人的检查点与授权.md) 五处检查点不变，§6 六个开关一个不改。**这正是 043 §5 那张表存在的理由，本文是它的第一次兑现。**
3. **代价集中在两处，都不在承重结构上。** 一是上面那条压缩损失信号要自建；二是**沙箱只罩 Bash**（官方逐字是"sandboxed Bash tool"，`Read` / `Edit` / `Write`、MCP server、hooks 不在其中）【文档】，所以容器仍是唯一硬边界、不能因为沙箱原生管网络就把容器撤掉——沙箱的网络白名单管的是 Bash 子进程的出口，管不到宿主进程自己。**换来的是一处结构性收紧**：`dontAsk` 模式加 `--permission-prompts none`，官方逐字"anything that would prompt is denied automatically"且"the session never waits for input"【文档】，与 dsh 的 `approval: never` 是同一种结构性保证，不是超时约定。

## 2. 换 Claude Code 买到了什么、丢了什么、代价是什么

Alan 选 dsh 的三条理由是"自由度、可监测、可定制程度最高"（043 §2）。逐条对照换宿主后的变化：

**自由度——降一档，且降的那一档买回了确定性。** dsh 是插件运行时，压缩、审批应答者、沙箱后端、子代理后端都是可整体替换的能力位；Claude Code 的扩展点是固定的一组（hooks、权限规则、settings、subagents、skills、MCP、plugins），**能力位不可替换**。代价是"想换压缩算法"这类事在 Claude Code 上做不到。买回的是：扩展点固定意味着**接触面本身稳定**——043 §5 那张表在 dsh 上要盯着 alpha 版逐日漂移，在 Claude Code 上盯的是有版本号的公开标志集。043 §2 末段那条"必须写在最上面的风险"（README 全大写 THERE WILL BE COMPATIBILITY-BREAKING CHANGES、无 CHANGELOG、无迁移指南）在本文没有对应物。**但不等于零风险**：本轮就撞到一处——`--permission-mode` 的取值 `default` 已改名为 `manual`【一手】，旧值仍受但帮助里只列新名。烈度与 dsh 不同量级，处置相同：pin 版本、升级前跑回归集。

**可监测——各有一块强项，且强的地方不重叠。**

- Claude Code 强在**结构化出口**：`--output-format json` 的结果对象本轮实测含 `is_error`、`api_error_status`、`num_turns`、`total_cost_usd`、`duration_ms`、`session_id`、`terminal_reason`、`permission_denials` 等字段【一手】。**`permission_denials` 是一个数组，直接就是 [31](../31-守卫与权限边界.md) 要的"被拒动作清单"，不需要事后从日志里刨。** 另有 `--include-hook-events`，把钩子生命周期事件并进输出流【一手，标志存在；行为未跑】。
- dsh 强在**日志 schema 有官方目录**（043 §2）。Claude Code 的会话日志是每项目一目录的只追加 JSONL，本轮对 Alan 迁移过来的 7 份会话做了全量解析：**6600 行、0 行解析失败**，顶层字段含 `type` / `sessionId` / `timestamp` / `uuid` / `parentUuid` / `isSidechain` / `cwd` / `version` / `gitBranch`，另有 `hookCount` / `hookInfos` / `hookErrors` / `preventedContinuation` / `stopReason` / `toolUseID` / `toolDenialKind` / `permissionMode` / `requestId` 等【一手】。形态与 [32](../32-证据与追踪.md) 要的"只追加保存原始记录、导出是派生投影"同构，**但本轮未查到该 schema 的官方文档**【未定】——这是与 dsh 的实质差距：投影脚本要依赖一份没有稳定性承诺的字段集，按判据 C 这是一个新失效面，探测写在 §9。

**可定制——形态不同，边界更清楚。** dsh 用单调守卫做权限、用工具过滤做可见性，官方自己用小节标题"Visibility is not authority"把两者分开（043 §2）。Claude Code 的分法是：**权限规则**（`permissions.allow` / `ask` / `deny`）是硬边界，官方逐字"Deny rules block in every mode, including `bypassPermissions`"【文档】；**hooks** 是可编程层，但官方明写"use the permission system rather than a hook to enforce a hard allow or deny"【文档】。这条分工比 dsh 更明确——dsh 那边要靠读官方小节标题才能推出同一结论。**再往下还有一层 dsh 没有的**：`rm` 与 `rmdir` 命中关键路径时被拒，**即便有 allow 规则匹配、即便 `PreToolUse` 钩子放行**【文档】——这是一条不可被项目配置放宽的地板。

**丢掉的三样，每样一个补法**：

| 丢掉的 | 043 里靠什么 | Claude Code 上的补法 |
|---|---|---|
| 有损压缩的损失信号 | 指令预算超限的点名通告（043 §7 第 0.12 条写着"无备选"） | 自建不变量指纹核对器（041 §6 L3 行原文即如此规定非 dsh 宿主）；`PreCompact` / `PostCompact` 两个钩子做落盘与重锚定 |
| 会话日志 schema 的官方承诺 | dsh 仓库内的持久化事件目录文档 | 投影脚本自带字段存在性断言，字段缺失即整批记未定；§9 加一行探测 |
| 能力位整体替换 | 服务定义加提供者 | 不补。L3 用不到；真需要时的路径是 Agent SDK，不是插件 |

**买到的四样**：

| 买到的 | dsh 侧的状况 | Claude Code 侧 |
|---|---|---|
| 出口网络边界 | 官方明写沙箱不管网络（043 §5 洞 1，靠容器 iptables 加 ipset 补） | 沙箱原生：`sandbox.network.allowedDomains` 加代理，可 `tlsTerminate`，凭据可 `mask` 并按 `injectHosts` 限定注入目标【文档】 |
| 结构化最终裁定 | headless 无 JSON 输出、最终响应官方明写"not a response causally assigned to the prompt"（043 §5 洞 3） | `--json-schema` 原生标志【一手】；`--output-format json` 的结果对象自带三态所需字段 |
| 上限型停机真中止 | 轮次上限映射到阻塞（043 §4） | `--max-budget-usd`【一手】——041 §5 已判定它是各家里唯一到限真中止而非标 partial 的 |
| 遥测处置成本 | 出厂指向厂商端点、无脱敏、配置撤不掉行只能改 mode，要三保险（043 §5 洞 5） | 无同型问题。仍按 [31](../31-守卫与权限边界.md)「未知默认关闭」在 managed settings 里显式关，出口白名单不含遥测域 |

**代价——一条必须写在最上面的风险。** 与 043 那条对称，但内容不同：**Claude Code 的沙箱在原生 Windows 上不支持，官方逐字"Native Windows is not supported. On Windows, run Claude Code inside a WSL2 distribution."**【文档】。043 §7 写的开发机是 Ubuntu 24.04，所以这条不阻塞选型；但它意味着**本轮在 Alan 这台 Windows 机器上取得的【一手】证据里，凡涉及沙箱的一律不成立**，只能在 Ubuntu 或 WSL2 上重取。§7 逐条标了哪些能在 Windows 上先跑、哪些必须等 Linux。

## 3. 拓扑

与 043 §3 的差别只有执行容器那一格，其余逐字不动，故本文只画变化的那一格与它的两条边。**完整拓扑读 [043 §3](043-L3技术选型-DSH宿主.md)，本文不复制**（[08 §7](../08-规范效力元治理.md) 禁止副本）。

```
           │ 起容器：claude -p --output-format json --json-schema ...
           ▼
┌─ 执行容器（Docker）───────────────────────────────────────────────┐
│ 硬边界仍是容器：iptables 出口白名单（沙箱只罩 Bash，罩不住宿主进程）│
│                                                                    │
│ Claude Code：managed settings（不可被项目与用户设置覆盖）           │
│   permissions.deny 硬边界 + defaultMode                            │
│   sandbox.enabled / failIfUnavailable / allowUnsandboxedCommands   │
│   sandbox.network.allowedDomains（第二层出口白名单，与容器互为对账）│
│   启动加 --permission-mode dontAsk --permission-prompts none        │
│   项目侧：hooks（钩子）· agents（子执行者）· skills（方法库）       │
│ 会话日志 JSONL ──► 编排进程定时投影进 PostgreSQL（缺口计数）        │
│ 结果 JSON（含被拒动作清单）──► 编排器直接消费，不解析自由文本       │
└────────────────────────────────────────────────────────────────────┘
```

**两条边的变化**：入边由 dsh 的 headless 入口改为 `claude -p`，且**裁定不再走文件回读、直接走 stdout 的 JSON**（043 §5 洞 3 消失）；出边多一条——沙箱自己的域名白名单与容器 iptables 白名单**互为独立对账**（两层由不同机制实现，符合 [09 §5](../09-跨工具通用性.md#feasibility-test) 的两种机制类型判据），任一层漂移即差集非空。

| 40 人的检查点与授权 | 同 043：五处状态转换全落 GitHub，**不动** | `dontAsk` 之下待批不是挂起而是立刻拒绝——**与 dsh 的确定性拒绝同构，同样满足 [31](../31-守卫与权限边界.md) 而满足不了 [40](../40-人的检查点与授权.md)**；宿主不承担检查点，只负责拒得干净、拒得留痕 | 改写（结论同 043） |

**四点说明**：

- **为什么编排仍不放在宿主里。** 与 043 同理由，且更强：Claude Code 没有编排层，恢复的是会话不是工作流，回退功能官方明确不管 bash 改的文件与子 agent 编辑。[20 §2 P8](../20-状态工件.md) 要的"从上一检查点之后重放、不重复已发生的不可逆副作用"在宿主层没有载体，仍由 DBOS 承担，仍按 043 §4 的口径判"部分（最强）"而非"满足"。
- **为什么裁定不再走文件。** 043 §5 洞 3 的成因是 dsh headless 无 JSON 输出。Claude Code 有 `--output-format json` 与 `--json-schema`【一手】，[21 §2 P7](../21-调度与拆分.md)「上游只消费裁定，不解析自由文本」直接由宿主满足。**但仍要上游校验**：schema 是"请求"不是"保证"，缺字段即记未定（与 041 §5.2 对另一宿主结构化输出的处置口径同）。
- **为什么容器不能撤。** 沙箱原生管网络是真的，但它罩的是 Bash 及其子进程；宿主进程自身、MCP server、hooks 都在罩外【文档】。所以网络与文件的硬边界仍是容器，沙箱是**第二层加对账源**——两层由不同机制实现，正好满足 [09 §5](../09-跨工具通用性.md#feasibility-test) 的两种机制类型判据，比 043 那种"容器是唯一边界、沙箱走回落"的单层加降级更强。
- **为什么人的检查点仍不用宿主。** 结论与 043 逐字相同，只是主语换了：`dontAsk` 之下"auto-denies every tool call that would otherwise prompt"且"the session never waits for input"【文档】——这是拒绝，不是等待。检查点要的是"停下来等人裁"，载体仍是 GitHub。

**五个洞与堵法**（每个都附"它坏了怎么被发现"）：

1. **沙箱只罩 Bash** → 容器仍是唯一硬边界；沙箱作第二层与独立对账源。探测：容器内从**非 Bash 路径**（如让执行者用读文件工具读一个沙箱已拒读的路径）尝试越界，结果应被容器或权限规则拦下而不是被沙箱拦下——**这条探测的意义正是证明"沙箱没罩到那里"，不是证明它罩到了**。
2. **`PreToolUse` 钩子超时不阻断** → 官方逐字"A timed-out `command`, `http`, or `mcp_tool` hook **doesn't block the tool call**… don't count on a stalled hook to act as a gate"【文档】。**处置：钩子只作探测与记账，不作闸门**；闸门一律用 `permissions.deny`（官方自己也这么说：use the permission system rather than a hook to enforce a hard allow or deny）。**另有一条路本轮查到但未采纳**：官方同页逐字"An Agent SDK callback hook that exceeds its timeout **blocks the tool call**"——即走 Agent SDK 而非 CLI 时该洞是关闭的。不采纳的理由是它把编排器与宿主绑进同一进程，与"控制平面独立于执行平面"相悖；**登记为洞 2 的备选路径**，若出现必须靠钩子拦截的需求再评。探测：红队用例——一个故意挂死的钩子加一个应被拦的调用，结果必须仍被 deny 规则拦下。
3. **managed settings 的数组键会被下游放宽** → 官方逐字：布尔键"Claude Code uses the managed value and ignores anything a developer sets locally"，但数组键"merges entries from every scope the session loads, **so a developer can append entries that widen the policy**"【文档】。**这与 043 §5 洞 4 是同型的洞，不是 Claude Code 独有。** 处置同 043：加 `--setting-sources` 收窄来源、容器内不放置用户级与项目级设置文件、**并在宿主之外对账**——从会话 JSONL 读实际生效的模式与被拒事件，与预期比对。探测独立于被探测者：对账脚本不读设置文件，只读日志。
4. **会话日志 schema 无官方承诺** → 投影脚本对每个消费的字段做存在性断言，缺字段整批记未定并停止投影（不猜、不跳过）。探测：每次宿主升级后先跑一次投影的字段断言，断言失败即阻塞升级——**并入 §9 那条"升级前必跑回归集"**，不新增频率。
5. **有损压缩的损失信号无原生载体** → 自建不变量指纹核对器（041 §6 L3 行对非 dsh 宿主的原文规定）：`PreCompact` 落盘活动工作集与一份不变量指纹，`PostCompact` 回读并由程序核对，指纹不符即整次运行记未定。探测：故意撑爆上下文触发一次自动压缩，核对器必须报出差异；**若核对器在真实压缩下从不报差异，先怀疑它没跑起来**（[仓库工作须知 §2](../附录-载体实例/仓库工作须知.md)：空输出一律记未定）。

**另有三条不是洞但要写下的限制**：`--permission-mode` 的取值 `default` 已改名 `manual`，写脚本时用哪个值须按版本标注【一手】；`dontAsk` 之下除 allow 规则外**还自动放行只读 Bash 命令**，这是一处内建的、比显式白名单更宽的放行面【文档】，登记为待观察项；本轮**未查到** Claude Code 实现的 MCP 规范版本号【未定】——与 041 §5.4 对五宿主的同一判定一致，失效形态是"工具静默消失"，§9 沿用 043 那条从宿主外拨测的探测。

## 8. 明确不采纳（本文新增的，041 与 043 已列的不重复）

- **把钩子当权限闸门**：官方逐字超时不阻断，且官方自己指向权限系统。钩子只作探测与记账。
- **走 Agent SDK 把编排器与宿主并进同一进程**（即便它能关掉洞 2）：与"控制平面独立于执行平面"相悖；登记为洞 2 的备选路径，不作正选。
- **撤掉容器、只靠沙箱**：沙箱只罩 Bash，宿主进程与 MCP server 在罩外。
- **用会话内子代理承载结构化裁定**：官方明写返回自由文本（041 §5.2），走进程级 `--json-schema`。
- **依赖会话 JSONL 的字段而不做存在性断言**：schema 无官方承诺，见洞 4。
- **用跳过全部权限检查的模式跑无人值守**：它与 L3 的方向相反——L3 要的是"无人在场也能**拒绝**"，不是"无人在场就**放行**"。容器隔离不是启用它的理由。
- **在原生 Windows 上跑 L3 宿主**：官方明写沙箱不支持；Windows 机器只用于 §7 标 ● 的提前暴露。
