## 0. 这套理论是什么（读完再开工）

Alan 与 Claude 共建了一套「AI 辅助大型项目开发规范」，纯理论、无代码，现要做技术选型以实现它。结构：

**AI 辅助开发系统 = 四个平面 + 一条交付线，14 个部件。**

- 知识平面（**资产**，随项目积累、换工具不丢）：10 意图与验收 / 11 项目知识（代码图谱只是它的派生缓存）/ 12 记忆与知识治理
- 执行平面（**工具**，随时可换）：20 状态工件 / 21 调度与拆分 / 22 上下文装配 / 23 方法库 / 24 工具与执行环境 / 25 执行者与模型
- 控制平面（**纪律**，可以只用文档与人工流程实现）：30 验证与测试 / 31 守卫与权限边界 / 32 证据与追踪 / 33 评估与演进
- 责任平面（**人**，不可转移）：40 人的检查点与授权

交付线：意图确认与冻结 → 从验收条目派生工作项与验证用例 → 每轮先读状态工件 → 派发一个可独立验收的切片 → 装配上下文 → 执行 → 从环境回读事实 → 三态裁定（通过 / 失败 / 未定）→ 证据写回状态 → 状态转换 → 验收。

六条不变量（换任何工具都不变）：① 控制平面独立于执行平面 ② 状态外置且朴素 ③ 知识单一权威 ④ 事实来自回读（不信模型自述）⑤ 责任不可转移 ⑥ 边界外不由我们控制（跨边界读只引用不复制、写限阶段窗口且幂等留回执、结果未知即未定、唤醒不等于授权）。

四档不是阶段而是同一套部件在不同规模下的形态：L0 一人一工具（全部是文档与人工流程）/ L1 一人多会话（跨会话连续性：状态外置、交接、压缩当事件）/ L2 团队（验证者与生成者分开、写入权与生成权分开、事实门禁、记忆治理、成本可观测）/ L3 无人值守（前置条件：有一个不需要人在场就能拒绝坏输出的判定器）。

## 1. 硬约束（选型必须满足）

1. **跨宿主通用（D-020）**：这套规范必须能在 **codex / Claude Code / opencode / DeepSeek Harness (dsh) / VSCode Copilot** 上落地。正文只写语义不变量；具体工具绑定只能放在「效力为零」的附录。**任何推荐都要说明：它是"通用层"（五个宿主都能用）还是"宿主绑定层"（只在某个宿主上有）。**
2. **优先级（Alan 2026-09-04 定）**：**行业标准/规范推荐 > 少就是多（更少的代码/实现/架构达到同样目的）> 好设计避免修修补补**。所以：有开放标准的优先（要给出标准名称、归属组织、当前状态）；同等条件下选组件更少、运维更少的；宁可先用一个静态文本文件，也不上服务。
3. **三条准入判据（仓库 03-通用落地套件 §1 与 §8，逐字）**：
   - 判据 A（必需性）：「没有它，某条规范条文就无法被判定为"已执行"或"已违反"」→ 才是必需；否则属优化。
   - 判据 B（可选性）：「它是否只是把仓库里已有的信息重新组织了一遍」→ 是则可选。仓库已点名落在这里的：**图数据库、向量库、记忆服务、可视化画布**（理由：「依赖关系本来就在代码里，历史决策本来就在 git 里」）。
   - 判据 C（引入门槛）：「它是否引入了新的失效面而没有自带独立探测」→ 引入即须配探测，且探测不能是它自己；**写不出"它坏了怎么被发现"的，不装。** 上游停更也是一个失效面（例：AutoGen 已进维护模式）。
4. **数字只作观察**：任何效果数字（准确率、提升 x%）一律记为「该团队在该条件下报告的观察」，不作论据。
5. **三态**：说不清的记「未定（UNDETERMINED）」，不折算成"满足"或"不满足"。**"部分成立"必须写成"部分成立"**，不得写成"成立"。
6. **证据分级**：每条断言标 **[一手实测]**（你自己跑过/读过源码或官方仓库文件）、**[厂商文档]**（官方文档/README/发布说明）、**[二手]**（博客、综述、媒体）。优先一手与厂商文档。
