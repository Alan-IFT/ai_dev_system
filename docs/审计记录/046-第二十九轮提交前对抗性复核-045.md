### 4.2 证伪（4 条）

**A-01｜§0 Q1 表｜「043 §5 那十五条接触面能力」｜证伪**
现数为 16 行。建议改「十六条」，或按 D-086 的写法改为不写死条数。（并入 §2.1）

**A-02｜§2｜「`--permission-mode` 的取值 `default` 已改名为 `manual`【一手】…本轮就撞到一处」｜证伪**
官方 cli-reference 逐字：「Accepts `default`, `acceptEdits`, `plan`, `auto`, `dontAsk`, `bypassPermissions`, or **`manual` as an alias for `default`**. The `manual` alias selects the permission mode the UI labels Manual and requires Claude Code v2.1.200 or later; `claude --help` lists it in place of `default`, **and both values work**.」官方 permission-modes 逐字：「The mode that reviews every action is named **Manual** in the CLI… **Its config value is `default`, which is what hooks and SDK integrations use.**」实跑 `--permission-mode default` EXIT=0。
即：`default` 仍是权威配置值，`manual` 是后加的别名；不是「改名」，也不存在「旧值」。§2 把这条当作「本轮就撞到一处」的兼容性破坏证据，而官方同一段已明写两值都 work、help 换名是刻意的显示层行为，构不成破坏。**同时是档次误用**：仅凭 `--help` 只列 `manual` 就断定「改名」，属由文档外观推断出的判断，不该标【一手】。
建议：改为「`manual` 是 `default` 的别名（v2.1.200 起），help 只显示 `manual`，两值均可用【文档】」；并删去 §2 里「本轮就撞到一处」那句实例，否则该段没有实例支撑。

**A-03｜§1 结论 3、§3｜「官方逐字"anything that would prompt is denied automatically"且"the session never waits for input"【文档】」｜证伪（档次与拼接）**
(a) 核了 permission-modes 与 cli-reference 两页，**"anything that would prompt is denied automatically" 不出现在任何一页**（cli-reference 的官方说法是「Pass `none` when nobody can answer, and Claude Code denies them instead」）。该句实际来自 `claude --help` 的 `--permission-prompts` 描述——**那是【一手】不是【文档】**。(b) 第二句确在 permission-modes 的 dontAsk 节，但它是 `dontAsk` 模式的描述，**与前一句不同源**；用「且」把两处不同来源的句子并成一句官方逐字，是拼接。
建议：拆开标注。§4「为什么人的检查点仍不用宿主」那条只引 dontAsk 两句，无此问题，可保留。

**A-04｜§10、§5 末段｜「041 §5.4 记…」两处｜证伪（引位错误）**
041 §5.4 是「责任平面／40 人的检查点与授权」，全节无沙箱、无 MCP 内容。两句话都在 **041 §5.2「24 工具与执行环境」**：逐字「**Claude Code 沙箱只罩 Bash 及其子进程**，Read / Edit / Write、MCP server、hooks 在宿主上裸跑」与「**各宿主实际实现的 MCP 版本号全部未查到**」。

引的两句逐字属实，出自 **sandboxing 页**「Enforce sandboxing across your organization」节，官方举的四个例子**全是 sandbox 键**（`enabled`、`failIfUnavailable`、`excludedCommands`、`allowRead`）。045 把它推广成「managed settings 的数组键」，并在 §9 落成「权限策略被下游放宽（数组键）」。而 managed-settings 页开篇逐字是「Claude Code applies them above every other level, so **no user, project, local, or `--settings` value overrides them**, apart from a few security-sensitive exceptions where a **stricter** value from a lower level still counts」，并给出专门关这个洞的锁：**`allowManagedPermissionRulesOnly`**（逐字「Makes managed settings the only settings source of permission rules」）、`sandbox.network.allowManagedDomainsOnly`、`sandbox.filesystem.allowManagedReadPathsOnly`、`allowManagedHooksOnly`、`allowManagedMcpServersOnly`、`strictPluginOnlyCustomization`。**045 全文一个都没提，因此 §7 0.7 的「无备选」不成立——官方现成备选就有六个。**

建议：三条限制那句补第三项，并在洞 2 处置里加一句「钩子不作拦截闸门，但它在 `dontAsk` 下是一条放行通道，须一并收紧或禁用」。
