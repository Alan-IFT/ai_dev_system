# v0.2 理论一致性审计

审计时间：2026-09-01  
审计范围：本仓库 v0.2-draft 的全部 Markdown  
性质：内部反例审计，不是规范接受决策

## 结论

理论方向没有出现根本性冲突，但“提议”已经被写成了类似生效规范的命令语气，而配套状态、模板、Gate 和追踪链尚未闭合。最大风险是 Agent 在理论阶段产生虚假完成、错误阻断或越权执行。

## 最高优先级发现

1. D-001～D-013 全为提议，正文却没有显式效力隔离。
2. 完成定义、生命周期与阶段 Gate 使用了不同状态机。
3. 默认上下文在 README、PROJECT_STATUS、协议和决策中重复，执行者可能取并集。
4. PRD 与工作项模板无法生成规范要求的验收证据绑定。
5. 项目知识与长期记忆、代码定义与运行证据存在术语重叠。
6. WORK_ITEM、SESSION_HANDOFF、PROJECT_STATUS 缺少职责、新鲜度和冲突协议。
7. Gate 只有输入清单，没有 checker、失败回边与限时豁免合同。
8. Harness 实验没有晋升为生效规范的批准与发布链。

## 本轮结构性修订

- 为所有候选规范增加“研究草案/提议无执行效力”声明。
- 建立唯一 Default Context Contract，其他位置只链接。
- 把工作项定义为实时任务源、交接定义为临时快照、项目状态定义为里程碑摘要。
- 把生命周期状态机集中到一处，完成与止损规则只保留一个权威定义。
- 引入 `claim → source of record → observation → validation result → acceptance evidence`。
- 为 Gate 增加 checker、pass condition、failure transition、evidence output 和 waiver 字段。
- 为模板增加验收 ID、revision、环境、时间与证据绑定。
- 将 CoALA 记忆分类明确为概念视角，不直接作为项目治理类别。
- 为 Harness 变更增加 eval manifest 和晋升链。

## 仍未决定

上述修订只是让提议自洽、可讨论，并不表示用户已接受候选规则。仍需按 A0 顺序决定：

1. 规范效力元治理；
2. 唯一上下文合同与状态工件协议；
3. 单一生命周期与最低 Gate；
4. 权威主张和证据最小字段；
5. 记忆权限；
6. Agent 复杂度和 Harness 晋升。

## 复核方式

- 搜索所有命令式规范，确认附近有决策状态与效力说明；
- 检查所有本地链接和 ASCII 片段锚点；
- 用过期 handoff、错误 worktree、发布 N/A、验收失败、Gate 豁免过期和提议误执行 Case 做桌面推演；
- 在任何规则转为`试行`或`已接受`前，补齐批准人、时间、生效范围和验证计划。
