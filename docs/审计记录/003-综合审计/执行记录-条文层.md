2. **把 84 条统一标成「责任结构型」是过度声明，方向反了。** 删减审计 §3.1 的原话是"凡不能归入三类之一的，一律视为**可淘汰性缺失**，按 D-021 处置"——目的是把它们**暴露**出来。我第一轮沿用了删减层 N7 的统一标签，等于给它们发了合法证。改之前是 60 种自造标签（一眼看得出可疑），改之后是整齐划一的"责任结构型"（看起来正当）——**统一标签比杂乱标签更难被后续审计发现问题**。

## 8.1 重判方法

对每条含「写不出」的原则按四步判，顺序固定：

1. 它的章 §4 L0–L3 表里写着某一档才出现吗？→ **起始档**，并在括号里注明 L0/L1 的退化形态。
2. 它以"交付型 / 从头 / 事发当时"为前提吗？→ **运行类型限定**。
3. 能写出一个具体的、可观察的失效条件吗（"当 X 成立时本条可删"）？→ **具体失效条件**。
4. 都不成立，且确实是"谁对结果负责"这一类不因技术进步而消解的安排 → 才是 **写不出（责任结构型：一句话理由）**。

**一条自加的保守规则**：**安全与授权类原则不标起始档**，即使它在低档没有对象。理由是结构审计自己的反方论证 3——"错标成晚生效会放行本该拦住的东西"，这个风险不对称。因此 24-P3（可见性不是安全边界）与 31-P7（被委托者权限是委托者子集）虽然分别在 L0、L1 才有对象，仍按 L0 起适用处理，并在括号里写明"不标起始档"及其理由。31 与 40 两章因此几乎整章留在"写不出"，这是判断结果不是遗漏。

**没有为了压比例而硬填。** 每条要经得起问一句"为什么这条永远不能删"；答不上来的就换轴，答得上来的就把答案写进括号。
