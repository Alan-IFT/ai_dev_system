### 0.1 「历史重放能不能推出未来无用」——不能

030 给了四条独立理由，任一足以否掉那个推论：

1. **历史是被待评估机制自己筛过的。**[仓库工作须知 §2](../附录-载体实例/仓库工作须知.md) 逐字「两项自检（每次改完都要跑，都要 PASS）」——重放量到的是"人工执行率 100% 下的**边际**值"，不是"这两个脚本有没有用"。
2. **仓库已登记过这两个脚本的两条真阳性**（C-008 的 C4、C-010 的 C10），它们在提交前就被修掉了，**任何按提交树做的重放都结构上看不见它们**。
3. n=21 的零事件，三法则上界约 14%/笔，与"每七笔漏一条"完全相容。
4. **D-065 刚砍掉 B-2，理由正是"把尚未证明通过折算成失败"**——027 §0 的判据是同一个折算的镜像。

**外加一条现场证据**：030 写作时自己把一个路径写错，linkcheck 当场报断链、退出 1——**写这份复验的过程中就产生了又一条真阳性**。

> **正确的记法是「未定」，成立条件"人工执行率不下降"。** 这不改变 D-074 的推荐，但**彻底改变它的理由**：不是"价值为零"，是"**价值未定，而代价确定且已知**"。

### 0.2 「六条不变量」这一处比「117」严重（五条判据同向）

- 「117」在同一格里**两次逐字自弃枚举**（"本行给的是判据不是名单""本行不枚举原则编号"，grants 写"任一条"）；**「六条」没有任何判据兜底**，它是那个免于实例判据的例外集合的唯一标识。
- 漂它的动作**被 [D-047](../决策日志.md#effective-register)（已接受）逐字授权**「新增或修改」不变量。
- **它已经实测漂过一次**：决策日志与架构确定两处逐字记着「§5.3 原本就有**五条**不变量」；而 C-039 自认「117 会漂」本轮没有实测支持。
- 加第七条不是"数过期"，是**一条架构级不变量被静默排除出"对一切运行成立"**、落回实例判据。
- **「六条」在正文里另有两处副本**（[00 §3](../00-总览.md#default-scope) 那句、00 §5 标题），落在 [08 §7](../08-规范效力元治理.md#annotation) 的字面射程内，**而「117」不落**——028 自己做的射程分析，量到这一格反向。

> 029 补一刀：**00 §3 那句正是 D-057 明文指名"随本行生效"的正文**，所以只删登记行**只解决一半**。

## 3. 四条的最终推荐

### D-072 · 记忆内容能不能决定控制流 → **推荐：记`已拒绝`＋落地包账面更正**

**裁定：不是真冲突。** 两条独立理由：
- **程序层**：[08 §8](../08-规范效力元治理.md#conflicts) 第 1 条逐字要「两条**生效规则**」。拟加条文在效力为零的落地包里，D-072 记`提议`，而 08 §1 表里`提议`的可阻断/可授权栏都是"否"。**要件不成立，冲突处置不触发。**
- **实体层**：12-P5 的 scope 由三处自证锁定（主语"条目"、防的失败"把'相关'当'可复用'"、删除条件"是否同一问题、是否可迁移"）＝**内容可复用性分级**；31 章的 scope 由章头"什么不许做、能力有多大"＋P6 维度枚举锁定＝**能力面与禁止项**。**两者不重叠。** 字面撞车只发生在提案越出它自己声明的落点的那两句上。
- 另：提案引的原文带 `untrusted` 限定词，**提案正文把它丢了**，泛化成"L2/L3 的内容"。而 12-P5 的置信态"由来源节点与验证证据决定"正是同形状的信任分流——**12-P5 比提案更贴近它自己引的那句**。

| 选项 | 优 | 缺 |
|---|---|---|
| ① 关档，0 改动 | 最少 | 落地包 §7 那格仍写着 `—`（无对应条文），下一轮会复发 |
| ② 收窄 12-P5 加作用域 | 把分界显形 | 12 章无实例；是复述 31 章的话；**无可删项** |
| ③ 31 章新增一条 | 落点对 | 纯增量、无可删项，且**被 D-076 条件阻断**（+1 条原则即让 D-057 行的"117"过期） |
| **④ ①＋落地包 §7/§4.3 零效力账面更正**（推荐） | 正文同样 0 行，**四个选项里唯一自带删除**（把"无可删项"那一格消掉），且堵住复发 | 要动一份效力为零的文件，账面工作 |

### D-073 · 试点判据的「此前」基准与观测窗 → **推荐：两问都裁，但试点本轮仍不跑**

**第一问，「此前」取「本仓库已版本化的书面记录」（`git ls-files` 覆盖的 .md）。** 五种候选里：全称"任何东西"**不是必败而是判不出**（022 这里判错了）；"现有机械检查器"是让试点必胜的作弊读法；"已进 Case 清单"依赖一个读数八自认没定义过的谓词。选中这一个的三条不作弊理由：**它是所有可判定候选里对试点最不利的**（019 点名的"现成材料"全部出局）；它逐字就是 Case 清单 §1 的 A 档定义、C-034/C-041 已按它降过档，**不是为本案新造**；两个结局都可达。

**附一条 026 查出的、比基准更致命的**：这个判据**没有对照臂**——33 §2 P4 要求的"基线"格是空的，成败都归因不到类型头。另：二值判据本身违反 30 §2 P1（"结论 + 成立条件"），不允许"部分成功"是对的，但缺的不是一档、是成立条件。

**第二问，观测窗不会重置。** 现跑：D-057 生效行里"观测窗""重置"两词各 **0** 次，是审议侧造的词。[08 §6](../08-规范效力元治理.md) 逐字「需要继续生效必须**重新批准**并写入新的 approved_at 与 expiry」——全仓无第二条改这两格的路径。014 §7.8(d) **只适用一半**：结论可搬，但它问的是"登记行要不要改"、没谈数据，且其理由逐字有错（D-057 grants 只授权"援引"，不授权"修订"）。**真代价是混样不是清零**，暴露面只有 30-P1/P5 两条。

### D-074 · 要不要挂 pre-commit 钩子 → **推荐：不挂，但换一个理由**

这是四条里唯一被独立复验改过的。**027 的"价值为零"被证伪**（§0.1），所以推荐不变、理由必须换：

| 选项 | 优 | 缺 |
|---|---|---|
| **一 不挂**（推荐） | 代价零 | 两级保持空集；检验① 到期仍缺腿 |
| 二 pre-commit | 唯一能给检验② 造出实例 | 历史真阳 0、**假阳 2**（两次都挡在本仓库自定的"拆四笔"纪律上）；挂上即造出第一个 Gate 实例，31 章十条随即生效，**立刻欠 31-P4 十二项合同 + P9 失效探测 + P10 豁免留痕**——"一行配置"这个标价不成立；脚本文件头自己逐字写着「这是 checker，不是 Gate。把它接成阻断需要单独的 Gate 决策（D-018）」，而 D-018 仍是`提议` |
| 三 pre-push ＋ 版本化钩子目录 | 误伤降到 0 | `git config` 那一步递归回"提醒"级 |
| **四 对抗性复核 +1 分句**（与一同时做） | 提升**他证性**：要求对抗者附脚本输出。跨工具通用，检验①③ 均已兑现 | **不提升"级"，警告级仍空**——不掩饰这一点 |

**推荐一 + 四。** 理由三条：① 收益命题两次不成立（§1）；② 代价确定且四样未付；③ **价值本身是未定而非零**，那就更不该在窗口只剩三个月时用它去换一堆确定的债。

> **人侧排除的处理**：Alan 2026-09-02 那句"先不要考虑 hooks"的**表层理由（"要写代码"）已经过期**——现在只差一行配置。但**它挡住的实质风险今天证据更足**：那一行配置会拉出十二项 Gate 合同。这一条要诚实说清，不替他改主意。

> **一个必须单独拎出来的东西**：**2026-12-04 起，`check_normative_force.py` 的 C3 会报 D-057 过期、退出码 1。** 这与钩子无关——它是 D-057 那一行自己的缺陷，027 把它记进"选项二三的缺点"是记账错位。**从那天起，[仓库工作须知 §2](../附录-载体实例/仓库工作须知.md)「两项自检都要 PASS」这条已写下的纪律永远无法满足。** 复审日 2026-11-19 必须独立处置它。
