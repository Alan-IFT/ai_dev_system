## 1. 三句结论

1. **选型的答案不是"选一个框架"，而是"通用层只有四类机制，其余全是宿主绑定"。** 把 09 §5 的七种机制类型逐一在五个宿主上核对（[A §3.1](041-技术选型/A-通用层与标准.md)），09 §5 那七类里五宿主齐全的只有三类：**外部状态存储（文件 + git）、宿主外检查器（CI / 脚本）、人工检查点**；「条件加载规则」这一类整体只是部分，但它之下有唯一一个五宿主齐全的实现——**Agent Skills 目录**——本文把它单列为第四个可依赖载体。静态指令文件名不统一、条件加载规则的其它形态两家没有、运行时拦截五家形态各异、权限与隔离两家有洞。**D-020 说正文只写语义、载体进附录——这一轮给了它实测支持**：正文各章"必须做到的"里，凡只能靠运行时拦截或权限配置才判得出的，在五宿主上一律是"部分成立"，不能写成"成立"。
2. **L1（Alan 当前档位）的推荐组合里没有任何服务、编排引擎、图库、向量库或记忆库。** 一份唯一的默认加载清单（载体就是 `AGENTS.md`，`CLAUDE.md` 只剩一行 import）、`.agents/skills/` 承载方法库、[03-通用落地套件](../图工程落地包/03-通用落地套件.md)已定的那几份状态文件加一个只追加的事件日志、一个 hook 脚本（所有事件都写同一份日志）加一份 deny 规则、宿主原生的 LSP。**正文要求而市面上无物的东西（§8）——租约、不可逆动作回执、三类停机条件、汇合缺失报告、豁免到期、hook 回执对账、记忆到期扫描——每件都只有几十行且都写得出"坏了怎么被发现"**；六份报告在这一点上完全同向：这些空洞不是"缺一个工具"，而是"任何工具都不做，只能自己写一小段"。
3. **L2 起唯一新增的"服务"是已经在两台机器上跑着的 PostgreSQL。** 持久执行（DBOS 库形态，只要 Postgres）、记忆检索（全文检索表）、遥测落库（OTel collector → Postgres）三件事分别来自 B、D、F 三份互不读对方内容的报告，却都先落到它上面——这是本轮最值得记住的"以少就是多"：**一个已有部件承接三个部件的 L2 需求。** 再往上的东西——Temporal / Restate / Inngest、Graphiti、Sourcegraph、任何图/向量/记忆服务、OPA/Cedar 策略引擎、网关侧上下文改写——全部按判据 B（只是重组已有信息）或判据 C（写不出独立探测）判为不装或暂不装。

## 2. 选型按什么顺序判

本文对每个候选都按下面五步走，顺序即优先级；子报告的 §3～§5 是这五步的逐格展开。

1. **先分层（D-020）**：它是"通用层"（五宿主都能用）还是"宿主绑定层"（只在某个宿主上有）？宿主绑定层的东西只能进附录，且本轮只对 Claude Code 与 dsh 给确定推荐（Alan 2026-09-07 裁）。
2. **有没有开放标准（Alan 的第一优先级）**：标准名称、归属组织、当前状态。**"事实标准"不享受这一分**——五宿主抄了同一套钩子事件名，那是事实收敛，不是标准。
3. **判据 A / B / C**（[03 §1](../图工程落地包/03-通用落地套件.md)，逐字）：没有它某条条文就判不出已执行或已违反（A，必需）；它是否只是把仓库里已有的信息重新组织了一遍（B，可选）；它是否引入了新的失效面而没有自带独立探测（C，写不出即不装）。**判据 C 是本轮砍掉最多候选的一条**。
4. **少就是多**：同等条件下选组件更少、运维更少的；能用一个进 git 的文本文件解决的，不上服务。
5. **按 31 §2 P1 的四级给它定级**：只写在指令里的是提醒；要执行者想起来运行的是工具；自动进入必经路径的才是警告或约束。**定级决定它能承载哪一类条文**——提醒级的载体承载不了 31 章的任何一条。

## 4. 通用层只有四类机制

09 §5 列了七种机制类型。A 报告把它们逐一在五宿主上核对，本文把结果压成一句话再给表。**表有八行不是七行**：Agent Skills 目录不是 09 §5 的一类，是「条件加载规则」类下唯一五宿主齐全的实现，本文把它单列出来（09 §4 末尾写明新取值同样受 §5 检验约束，这套分类不是封闭的；但字面上它仍是七类之外的一行，这里明写）：

| 机制类型 | 五宿主是否齐全 | 通用层的落地形态 |
|---|---|---|
| 按需能力包（Skills）——09 §5「条件加载规则」类下的一种实现 | **齐全**（字段集有差异） | `.agents/skills/<name>/SKILL.md`——Codex / opencode / dsh / Copilot 四家共读此目录，Claude Code 读 `.claude/skills`，一个符号链接即可"一条规则只有一个位置" |
| 外部状态存储 | **齐全**（就是文件与 git，与宿主无关） | 仓库里的状态文件、只追加日志、git 提交 |
| 宿主外检查器 | **齐全**（宿主之外的脚本与 CI） | CI 必需检查、本地脚本 |
| 人工检查点 | **齐全**（各家审批 UI + 代码评审） | 宿主审批、PR 评审、CODEOWNERS |
| 静态指令 | 部分：文件名不统一（`CLAUDE.md` vs `AGENTS.md`），Claude Code 官方明写不读 `AGENTS.md`，须 import 或 symlink | `AGENTS.md` 为原本，`CLAUDE.md` 一行 `@AGENTS.md` |
| 条件加载规则（Skills 之外的其它形态） | 部分：Claude Code 与 Copilot 有按路径触发，opencode 官方明言没有，Codex 只有逐级下沉，dsh 未查到 | 只能作 09 §6 的并列探测提示 |
| 运行时拦截 | 部分：Claude Code 事件最全且 Codex、Copilot 逐字复用其事件名（Copilot 直接读 `.claude/settings.json`），opencode 用插件抛异常，dsh 用瀑布式 `tools/pre-execute` | 一套脚本 + 每宿主一份薄适配；dsh 的 `dsh-hooks-claude-code` / `dsh-hook-protocol` 在 [DSH 载体映射](../附录-载体实例/DSH载体映射.md) 里有 V1 一手证据（读自本机安装的包），**但只读了 README、未经运行验证**；且按该附录 §4，走桥接落地不构成 09 §5 意义上的第二种机制类型 |
| 权限与隔离配置 | 部分：opencode 无原生沙箱；dsh 沙箱官方明写不管网络 | 逐宿主配置，进附录 |

**由此得出的两条硬约束**（六份报告各自独立得出，本文只是把它们并列）：

- **同一条语义要满足 09 §5"两种机制类型不同的载体"，最省力的配对是「Skills 目录 + 宿主外检查器」**，两者天然不同属一个工具。运行时拦截只能作第三个实例逐宿主落地。
- **31 章有两条要求五宿主全体不满足**：没有任何一家为豁免 / 跳过提供失效时间；没有任何一家提供拦截层自身的独立失效探测（dsh 的 `approval/asked` 与 `approval/decided` 成对事件最接近，但两者由同一服务发出，仍是自证）。这两条在任何宿主上都只能由宿主之外的 CI 对账补上——**它们不是选型问题，是必须自建的小件**（§8）。

### 5.1 知识平面

**10 意图与验收。** 最小形态：`ACCEPTANCE.md`，每条带稳定 ID 与可观察结果。**没有任何工具承载这一章**，也不需要——它是人写的清单。L2 起用例覆盖集与条目集由 CI 里一个对账脚本检查（F 报告 §3.1），L3 起 gh-aw 这类"PR 即切片"的形态让条目集合天然成为自动运行的入口与终止判据。不采纳：任何任务系统的字段替代文件（"入口只做地图"的对象在仓库里，不在外部系统）。

**11 项目知识。** 最小形态：入口文件只放"权威源分工表"（决策 → 决策记录；接口 → 类型定义本身；依赖 → lockfile；结构与调用 → 代码 + LSP；历史 → git；验收 → `ACCEPTANCE.md`）加一句摘要，细节就近。**L1 装：宿主原生 LSP**——Claude Code 装对应语言的 code-intelligence 插件（Alan 的栈是 pyright 与 typescript），dsh 用内置 `lsp` 工具；它不落持久产物，因此没有对账义务。**代码图谱是派生缓存，2026 年没有任何现成工具把"声明为缓存 + 绑定源版本 + 与源机械对账 + 差异由人分诊"做全**（C 报告 §3.1 的六条硬要求逐格对照）；最低成本形态不是图数据库，是一个进 git 的文本地图（tree-sitter 或 ctags 抽 def/ref，头部写 `source_rev`，CI 里"重新生成 + `git diff --exit-code`"），C 报告把它列为 L1 的可选项（判据是仓库规模约 200 个源文件以上），并把"LSP 与 grep 都答不出、一周问三次"的跨制品关系问题作为把它移进 CI、再评 SCIP 的升 L2 触发。**装了怎么知道它过期**：版本对账（HEAD 比对，不一致即在返回里带 STALE 标记，**基于它的结论一律裁为未定**）、覆盖率对账（索引文件集 vs `git ls-files`，探测器是 git 不是索引器）、重建对账、抽样回读——向量库只能靠最后一条，前三条对 embedding 无效。明确不采纳：Serena 的 memories（agent 生成、人工与派生同目录同格式、官方文档只写它依赖 human review and agent maintenance、未提供任何过期机制——同时踩 11 与 12）、Copilot 远程语义索引作权威源（对用户完全不可对账）、code-graph-rag（Memgraph + Qdrant + Docker + daemon 四个新失效面，版本仍 0.0.x）、Joern、Sourcegraph 自托管、CodeQL 作日常知识工具、任何 Milvus / Qdrant 类向量方案。未定：SCIP 有格式与治理但未查到轻量本地消费者，若确实不存在则 L2 里给它的位置是虚的。

**12 记忆与知识治理。** 最小形态：**文件。** D 报告逐格核过十四条要求后的结论是——候选的最小身份（来源与产生事件、置信态、适用范围、归属人、时效或派生源版本、冲突、晋升目标、生成与评估它的模型）、双时间轴、来源必填这三样，**没有任何产品的 schema 填得满，而 front-matter 想写几个写几个**；git 还白送记录时间轴（commit 时间不可被写入者篡改）、审批点（权威目录只有人 commit 才能进）、冲突并列（两条矛盾记忆就是两个文件，天然不落入"新的永远赢"）。L0/L1 按套件：候选写在 `WORK.md` 候选区，晋升就是把一句话搬进 `PLAYBOOK.md` 或项目知识；宿主原生的自动记忆（Claude Code auto memory 默认开）**只当草稿本，绝不当权威**——它只有 `type` 与 `modified` 两个字段、直接写权威载体、写前钩子的 feature request 已被官方关闭（closed as not planned）；Codex Memories 官方定位为 generated state 且劝阻手工编辑，写不出探测，按判据 C 保持默认关闭。**dsh 上例外**：`dsh-memory-evolve` 是五宿主里唯一自带写入前确认队列的，可装，但把它写进代码仓库专属分支的记忆内容当普通文件对待，让别的宿主也能直接读。**L2 升级信号不是人数**，是三个可测触发之一：检索误召回可测、同仓库内需按人的读取边界、需要"当时以为是什么 vs 实际是什么"的时间旅行查询——先把 `memory/knowledge/` 的 front-matter 灌进已有的 PostgreSQL 做全文检索（存 commit sha，天然是绑源版本的派生缓存），这条路也失效了才考虑 Graphiti（Apache-2.0；唯一满足双时间轴与"不新的永远赢"的候选，但要图数据库 + 每次摄入调 LLM，且只能是检索侧派生缓存、权威永远在 git）。**proxy 抓会话这种形态（Alan 试过的 TencentDB-Agent-Memory）与 12 §2 P4"模型自身输出与推断不得成为候选"的冲突成立且是形态性的**：proxy 站在模型 API 边界，看得见的只有消息流，看不见交付链的状态转换；其 Chat Memory 是对整段会话做分层蒸馏，assistant 消息必然入池；它又把记忆内容注入系统提示——按落地包 [02 §4.3](../图工程落地包/02-记忆管理落地设计.md) 那条"控制流不得来自记忆内容"的口径（该条已裁不落正文，见 §11）这是它防的那种通道。可用的降级用法是只作会话原始记录的旁路留存（对应 32 章"只追加保存原始记录"），不作候选来源——降到这一步就没必要用记忆产品来做它。它的三级可见性 + User / Role / Agent ACL 是全场最好的治理模型，仅当"同仓库内按人的读取边界"真实出现且两个 git 仓库解决不了时才考虑，且必须关掉 Chat Memory 的自动蒸馏。明确不采纳：mem0（一次 LLM 调用即可 DELETE 一条记忆、无人工环节，与入池/权威正交正面冲突；官方自陈 benchmark 分数来自含专有优化的托管版）、Letta（绑自己的运行时，违反 D-020，但其 git 载体设计值得抄）、Cognee、Basic Memory（用一个 MCP server 做"写 markdown"）、Zep（社区版已停止维护）。**未定：**"注入即记账"的"有用"一维在所有候选里都未查到，记 UNDETERMINED，不折算成"不满足"。

### 5.2 执行平面

**20 状态工件。** 最小形态：套件的三份文件 + 一个只追加的事件日志（每行带 `commit_sha`、工作副本、ISO 时间、`verdict ∈ {通过, 失败, 未定}`）。B 报告 §3.1 的三条硬结论决定了这里"不买宿主的账，买文件系统与 git 的账"：**活性信号（租约 / 心跳）六个候选无一满足**——宿主原生完全没有，持久执行引擎单进程下靠"启动时扫 PENDING"代替，多执行器要额外协调；**"恢复不重复不可逆副作用"上宿主原生是负分**——Claude Code 的 `/rewind` 明确不管 bash 改的文件、不管子 agent 的编辑、不管外部改动，dynamic workflows 官方承认失败点之后已完成的 agent 全部重跑。**git 在这一章是最强的单一部件**：工作副本身份、里程碑摘要、按引用回源三条它同时满足。L2 二选一：**DBOS Transact**（Python / TS 都有，MIT；官方 README 逐字 "there's no additional infrastructure for you to configure or manage"、"no separate queueing service or message broker—just Postgres"；workflow 教程逐字 "Steps are tried at least once but are never re-executed after they complete"——**中断中的那一步仍会重跑**，B 报告据此判"部分（最强）"而非"满足"；多执行器需 Conductor 或手工协调——租约仍要自建）或 **GitHub Agentic Workflows（gh-aw，Public Preview）**——PR 即切片、必需检查即状态机、safe outputs 让生成者无写权限、check conclusion 的 success / failure / neutral 直接就是三态。明确不采纳：Temporal（Server + UI + DB + Elasticsearch）、Restate、Inngest（各需常驻服务，后者官方不保证自托管支持）、LangGraph 作实现依赖（其 checkpoint 三档语义写得最明白，保留作参考语义来源，但它带来的"图"抽象正是不变量②要避免的）、`pg_durable`（方向最对但 Preview 且把失效面放进数据库进程，列观察项）、Claude Code agent teams（实验、默认关、无会话恢复、官方自陈任务状态会滞后）。

**21 调度与拆分。** 最小形态：`PIPELINE.md` 里为每个非验证者阶段写一句存在理由 + 三类停机条件写成三个显式判断 + 收口时打印"预期 / 实收 / 缺失"。B 报告：**三类停机条件各家只做了上限型，且到限的动作多数是错的**（标成 partial 而不是转阻塞并升级；唯一的例外是 Agent SDK 的 `maxBudgetUsd`，到限会以 `error_max_budget_usd` 真中止）；**汇合缺失报告被各家默认做法主动破坏**（官方示例用 `.filter(Boolean)` 把失败分支的 `null` 直接丢掉）。**子执行者只回结构化三态裁定，在 Claude Code 上唯一可靠的落地是进程级契约** `claude -p --output-format json --json-schema`——会话内 subagent 官方明写返回自由文本，社区诉求已 closed as not planned；Codex 是 `codex exec --output-schema`，但有 issue 报告带工具时被静默丢弃，须上游校验、校验失败即未定；opencode / dsh / Copilot 未查到强制 schema 入口，只能"提示词要求 + 上游校验"。**验证者分离是各家都现成的一刀**（Claude Code 的 `disallowedTools: Write, Edit` 即只读验证者）。

**22 上下文装配。** 最小形态：**唯一一份默认加载清单，载体就是 `AGENTS.md`**（它正是五宿主会话开始加载的那份文件；`CLAUDE.md` 只写一行 `@AGENTS.md`）——比套件里"`CONTEXT.md` + 各宿主入口 import 它"再少一个文件；代价是它常驻，所以必须短（11 §2 P7 本来就要求）。E 报告最有价值的发现：**`PreCompact` 在 Claude Code、Codex、VS Code Copilot 三家逐字同名**（`PostCompact` 只有前两家，Copilot 的事件表里没有它），opencode 用 `experimental.session.compacting`（可直接替换压缩提示），dsh 把压缩做成可替换能力位——22 §2 P4 的前半句"压缩可在其前被拦截"接近五宿主齐全（Copilot 的 hooks 仍标 Preview）；**后半句"会话结束与压缩同等对待"只有 Claude Code 与 Codex 满足，dsh / opencode / Copilot 均为部分成立**——这条原则整体在通用层是部分成立，不是成立（E 报告的跨表小结写成了"五宿主全绿"，与它自己的对照表不符，本文按表不按小结）。L1 装两个钩子（`PreCompact` 把活动工作集路径清单落盘、`SessionStart(compact)` 重述不变量并回读该清单）；**Codex 上加一句金丝雀指令**放在指令链最末尾，定期跑，金丝雀不出现即说明被静默截断（判据 C 要的独立探测）。**有损压缩的损失信号只有 dsh 做到**（`dsh-agent-instructions` 先整份丢弃更宽的文件、最后才截最具体的，并发通告点名被省略与被截断的路径——这是唯一确证来自 deepseek-ai 官方仓库的 dsh 一手证据）。**成本三轴只有 Claude Code 原生给出，且并不真正正交**（缓存统计明写不含 subagent），要真三轴只能靠 OTel 属性组合在 collector 侧聚合——这是 L2 推荐 OTel 而不只用 ccusage 的唯一硬理由。明确不采纳：网关侧统一施加 Anthropic Context Editing（会让宿主的 `/context` `/usage` 与真实 prompt 分叉，直接违反不变量④"事实来自回读"）、向量库式上下文检索（装配要的是确定性清单）、LangChain / LlamaIndex 类中间件、proxy 抓会话改写上下文、Copilot 承载任何约束（多指令文件官方明写"不保证顺序"，无加载清单视图，最高只能是提醒级）。

**23 方法库。** 最小形态：**Agent Skills 目录**，每条方法一个目录，`scripts/` 或 `references/` 里放它绑定的失败 Case 的回归用例。这是唯一五宿主齐全的按需加载载体（A 报告判为判据 A 必需：常驻指令文件在机制上做不到"按触发条件加载"）。**规范没有为"分类 / 淘汰条件 / 绑定 Case"定义字段**——`metadata` 能装（自定义 `category` / `expires` / `case` 键），但没有任何宿主会因为它过期而告诉你，得由 CI 里一个 frontmatter 校验（官方 `skills-ref validate` 可做机械部分）加"每个 skill 的绑定用例跑一次"补上。L0 的 `PLAYBOOK.md` 在 L1 变成索引（地图），正文进各 skill 目录——这正是 23 §3 L1"条目按触发条件加载而不是常驻"。明确不采纳：把 `AGENTS.md` 当方法库（常驻、无 frontmatter、Codex 侧 32 KiB 静默截断）；自建 hook 抽象层或统一 harness（五家事件名已同形，抽象层是没有独立探测的新失效面）。

**24 工具与执行环境。** 最小形态：宿主原生工具 + 沙箱（隔离与反馈）+ 一个纯文件的完成标记；只有当"长动作跨会话 / 跨机器"时才需要 MCP 官方 tasks 扩展。**MCP 2026-07-28 没有把"结果未知"提升为协议级第三态**（`resultType` 只有 complete / input_required），三态仍要靠工具自己的返回体表达；删除协议级会话后官方指定的做法是"服务端铸造 handle 作为普通工具参数传递"，MRTR 要求客户端重发原请求——天然要求服务端幂等，方向与 24 §2 P6 一致。**能力目录与权限边界分开维护这一条，Claude Code 是耦合的**（裸工具名 deny 同时把工具移出上下文），MCP 的 `tools/list` 与客户端权限则是分开的。沙箱：Claude Code 与 Codex 都是 OS 级（Seatbelt / bubblewrap + seccomp），但**Claude Code 沙箱只罩 Bash 及其子进程**，Read / Edit / Write、MCP server、hooks 在宿主上裸跑；**dsh 沙箱官方明写不管网络与进程可见性**；opencode 无原生沙箱。**各宿主实际实现的 MCP 版本号全部未查到**——2026-07-28 是破坏性改版，一个宿主升级而 server 没升，表现可能是"工具静默消失"，健康探针必须从宿主外调用。

**25 执行者与模型。** 最小形态：一个 agent 定义文件（输入、权限、模型档、完成条件）+ 一个输出 JSON schema + 一条 allow 列表。Claude Code 的子 agent 定义覆盖了输入、权限、完成条件，**唯独输出契约缺失**（见 21）；按角色选模型档位五家都满足；**子执行者独立计费**在 Claude Code 上由 OTel 的 `query_source`（main / subagent / auxiliary）与 `agent.name` 给出（自定义 agent 名会被脱敏为 `custom`），进程式子执行者直接读 `total_cost_usd`（官方注明是客户端估算）；Codex / opencode / dsh / Copilot 四家均未查到分子代理的用量导出。**委托的治理继承声明在各家都是"文档声明，不是运行时可查的合同"**——Claude Code 文档列了子 agent 不继承什么，dsh 的 `toolFilter` 与 `ctx.tools.restrict` 的关系未定（后者官方确认是可见性过滤，A 报告核实与 [DSH 载体映射](../附录-载体实例/DSH载体映射.md) §5 一致）。

### 5.3 控制平面

**30 验证与测试。** 最小形态：一个读 `git diff --name-only` 映射到验证集的脚本 + 一个 checked-in 的已知失败基线文件 + 每层脚本输出一行 JSON 裁定。**"在独立于生产者的上下文中验证"的通用层落地是 CI**——runner 与开发者会话天然隔离，run id 与 commit sha 可记；GitHub check 的 success / failure / neutral / skipped 天然是三格。判分器自身的已知答案回归集：UK AISI 标准要求提交评估时带 QA 证据，Inspect AI（MIT，0.3.x 仍在快速发版）是它的落点。

**31 守卫与权限边界。** F 报告按四级给每个候选定了级：`CLAUDE.md` / `AGENTS.md` 里的规则 = **提醒**（Claude Code 官方逐字："Instructions in your prompt or CLAUDE.md shape what Claude tries to do, but they don't change what Claude Code allows"）；Makefile / skill 脚本 = **工具**；**git pre-commit hook = 工具，不是约束**（不随 clone 分发、`--no-verify` 可跳过——F 自评这个定级偏保守，但本文采纳它：CI 才是权威，hook 只是提速）；CI 非必需检查 = **警告**；**CI 必需检查 + ruleset（含"不允许绕过"）、CODEOWNERS + 必需 code owner 评审、Claude Code hook 的 deny / exit 2、managed deny 规则、OS 沙箱 = 约束**。**跨五宿主唯一"约束级 + 通用层 + 判据 A"的组合是 git / CI 侧的必经路径**。宿主内守卫全是绑定层且能力差距极大：Claude Code 的 hook 与权限规则是两道独立检查（hook 的 allow 越不过 deny 规则，hook 的 exit 2 先于 allow 规则），Codex 有 hooks 与审批策略，opencode 是配置式三态，dsh 是瀑布式单调守卫 + fail-closed 审批（[DSH 载体映射 §2](../附录-载体实例/DSH载体映射.md)），Copilot 的 hooks 标 Preview。**两处 fail-open 是硬伤，L3 前必须显式关掉**：Claude Code `PreToolUse` 的 command / http / mcp_tool hook **超时不阻断**（官方逐字："don't count on a stalled hook to act as a gate"）；沙箱依赖缺失时**默认降级为不沙箱**，须显式 `sandbox.failIfUnavailable: true`。**"权限只能收窄"这条在五宿主上都不完全成立**：opencode 最后命中者胜、dsh 的 permission preset 官方明示"框架不施加方向性限制"且会话中可切换、Claude Code 的 `/cd` 会加载新目录的 hooks 与权限规则——见 §10 第 2 条。明确不采纳：OPA / Cedar（引擎本身是新单点，"每个宿主的桥接坏了怎么被发现"写不出通用探测，L0–L2 不装）、OWASP ACS v0.1 当守卫、AgentCore Policy（AWS 托管）、E2B（解决"跑不可信生成代码"，不是"罩住本机开发会话"）。

**32 证据与追踪。** 最小形态：**git 就是只追加日志与证据载体**——commit / notes / tag 天然只追加、内容寻址、可交叉核对，"证据有失效条件"绑 commit sha 即天然满足；完成主张的六项字段放 commit trailer。L2 起加 Claude Code 原生 OTel（metrics 与 logs 稳定，traces 仍 beta）做成本记账：`claude_code.cost.usage` 按 model / agent.name / skill.name / mcp_tool.name 打标，**但价表版本未在属性里声明**——32 §2 P8 要的那一格要自己补；轨迹足以还原调用树只在 beta 的 traces 里有（Bash 子进程继承 `TRACEPARENT`、MCP 出站带 `traceparent`）。落库到已有的 PostgreSQL，不上 SaaS。ccusage 是唯一跨宿主的近似成本读数，精度不够时才上 OTel。明确不采纳：Braintrust / LangSmith（SaaS 优先）；把 OTel GenAI 属性名当稳定接口。

**33 评估与演进。** 最小形态：`eval/` 三个子目录（诊断 / 筛选 / 最终验证）+ 每条 Case 带 `added_on` 与来源 + 一个不到 30 行的超龄扫描。**"筛选与最终验证集不得被会修改 harness 的执行者读取"是 33 章唯一一条必须在运行时执行的要求**：目录级 deny 规则（Claude Code `Read(./eval/final/**)`）+ CODEOWNERS 守该目录 + ruleset 限制文件路径——但单人开发下只能做到"同一人不同会话 + deny 规则"的**弱形态，这是部分成立不是满足**（§10 第 5 条）。评估框架 L2 起用 Inspect AI，借 UK AISI 标准的四条纪律；promptfoo 可用但 2026-03 被 OpenAI 收购，治理归属变更本身是判据 C 的一个新失效面。

### 5.4 责任平面

**40 人的检查点与授权。** 最小形态：五处状态转换上的人工确认 + 一份不可逆动作清单。通用层的落地是 **CODEOWNERS + 必需 code owner 评审**（任一列出的 owner 批准即满足，不是全部；语法错误的行被静默跳过——探测是 CI 里跑 `gh api .../codeowners/errors`）；宿主内的审批 UI 各家都有，**dsh 的审批语义最贴 40 与 31 的要求**（`allowed-once` 只对被请求的那一个动作生效，不存在"以后都允许"；应答者缺失、非属主、抛异常一律落 `unavailable` 即拒绝），是五家里唯一把"未知默认关闭"做成结构性保证而非超时约定的。**授权移交的"慢变、可审计、附抽样复核"没有任何宿主原生提供**，逃生口（`bypassPermissions`、`danger-full-access`、`global.autoApprove`）都是无限期的——豁免到期只能自建（§8）。

## 7. 对 Alan 五件套设想的逐项答复

Alan 2026-09-02 设想的系统形态是"agent team 及流水线调度工具 + codegraph 工具 + memory 工具 + 上下文管理工具 + skill 的组合，要简单且灵活"。按本轮审计，五件里在 L1 需要"装一个工具"的只有一件：
