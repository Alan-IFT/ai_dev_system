## 2. 三条需要展开的

### 2.1 卡片 07 §3.2 的初稿判断不成立：「本仓库目前没有这样一条判据」

**这一句被正文逐字驳倒，且不止一处**：

| 卡片的触发 | 正文对应（逐字） |

### 2.2 工作图 / 角色图：正文只有一半，缺的是"对照"不是"规则"

31 章的权限原则**答得了**「哪些权限结构禁止模型现场生成」这个问题，三条各答一面：

- **禁止在运行中生成/扩张**：31 §2 P6「权限边界的维度在创建时固化，执行中只能收窄」，其删除条件逐字「运行中能自行扩权的边界不是边界，单调收窄是"授权不可自我扩张"的形式表达」。
- **禁止模型改写清单**：31 §2 P8「危险动作清单与工具实现分离、按环境配置、版本化慢变，**模型在会话内不可修改**」。
- **禁止模型产生授权**：同条「**授权标记只能由人侧通道写入，模型不能代替人产生授权**」。

**缺的是另一半的显式声明**：「任务如何拆解、合并可以交由模型现场调度」。它在仓库里只以 D-028（`提议`）存在。按 D-057 登记行逐字：「其落进正文的部分随本行生效，**未落进正文的部分不生效**」——所以这半句目前**无效力**。

**这个缺口会漏掉什么失败？本文的判定是：漏不掉。** 反向的失败（模型顺手把权限变更混进一次任务重排里做掉）已被 31 §2 P6 的单调收窄与 P8 的"会话内不可修改"关死。正向的缺失（没人明说模型可以现场重排任务）不产生失败，只产生保守——而 21 §2 P8 的举证责任本来就允许任何一方提出拆分。

**处置建议**：**一句作用域**，落 31 §2 P6，形如「本条约束的是权限维度，不约束任务拆解方案的现场调整（后者的判据见 21 §2 P3、P8）」。这是优先级表里的最高一档（`已被覆盖→加一句作用域`），**+1 个分句、0 条新增**。**可删项：无可删项。** 若不做，正文不产生已知缺陷。

### 2.3 那张模式表：为什么它不能进正文，而它的上位判据已经在

按 [23 方法库](../23-方法库.md) §2 P1 的三分逐条过：

1. **不是执行边界。** 23 §2 P1 逐字「执行边界在模型之外由检查器判定」。这张表没有检查器、没有通过条件、没有失败回边——按 [31](../31-守卫与权限边界.md) §2 P4 逐字「只有材料清单而没有检查器、通过条件与失败回边的，是清单不是 Gate」。
2. **不构成方法约束。** 23 §2 P1 逐字「方法约束是期望被遵守的信息型内容」。这张表不主张任何一种拓扑该被遵守——它的核心原则那一句（「先找最简单的方案，只在真正需要时才增加复杂度」）**才是**约束，而它已经落在 21 §2 P3 且来源已登记为 SRC-ANT-AGENTS。
3. **是样例。** 五模式是三形状的例示，三形状是"多单元怎么连"的例示。

**因此三条挡板同时成立**：23 §2 P3「公开语料里的不写」（Anthropic 博客是公开语料且已是一手来源）、09 §5「判据优先于枚举与样例」、23 §2 P5「每条规则绑定一个已登记的失败 Case」（这张表绑不出）。

**并且仓库已经对同型对象裁过一次**：[架构确定 §7](../架构确定.md)「本次裁决刻意没有采纳的」逐字列着「多阶段流水线（P0–P6、13 棒接力）作为默认形态」。**把三大拓扑写进正文，与那次裁决同型。**

**它该去哪**：作为**可行性证据与反面参照**进[附录·载体实例](../附录-载体实例/README.md)（[09 §8](../09-跨工具通用性.md) 逐字「载体实例的唯一作用是充当**可行性证据**与**反面参照**」），或就留在卡片 07 §2.1 不动。**本文建议后者**——它已经在卡片里，搬一次就是[读数八](../失败Case清单.md)记的"删掉副本又新造一份副本"的形状。

## 5. 「该进正文」与「该留在载体实例 / 卡片」的分界

本文用的分界不是新造的，是把三条已有规定叠起来用；**顺序即判定顺序，前一条判定即停**：

1. **先问它是不是判据。**（[09 §5](../09-跨工具通用性.md#feasibility-test)：「一条规则的本体是它的**判据**；清单、分类与例子是判据的例示，不是穷尽。」）
   - 是判据 → 可以进正文，进的形态是**改已有判据**而不是新增一条并列的。→ 候选 1、2 落在这里。
   - 是清单 / 分类 / 例子 → 不进正文，除非它的上位判据尚不存在。→ 候选 6（四元语）、候选 7（三大拓扑 + 五模式）落在这里，且它们的上位判据都已存在（21 §2 P3/P8、23 §2 P1）。

2. **再问换个载体它还成不成立。**（[D-020](../决策日志.md#effective-register) 判据三：换工具要不要改。）
   - 换掉 LangGraph 换成别的编排器，"节点/边/检查点/时间旅行"这些词就要重写 → 载体，不进正文。→ 候选 6、7、8 的载体侧。
   - "验证者不读生产者的自述""外部写在回读前是未定"换任何工具都成立 → 语义，进正文（且都已经在）。→ 候选 3、4、5。

3. **最后问它绑不绑得出一个已登记的失败 Case。**（[23 方法库](../23-方法库.md) §2 P5：「口头风险不构成登记理由。」）
   - 绑得出 → 有资格进方法库或正文。
   - 绑不出 → 留卡片。→ 候选 9（三条箴言）落在这里：它们是取向，正文侧对应的每一条都已经绑了 Case（21 §2 P3 防"为一次性任务付多份固定开销"、24 §2 P4 防"确定性步骤产生随机错误与无谓消耗"、32 §2 P1 防"把发起当完成"）。

**一句话的分界**：**判据进正文，形状留卡片。** 卡片 07 的价值在它把"一条工作流长什么样"讲得比正文任何一章都完整——但正文管的是"这条工作流的每一步归谁负责、凭什么算数"，两者不是同一个对象（卡片 07 §3.1 自己已经先说了这一点，本文复核该判断成立）。
