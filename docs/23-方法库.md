# 23 方法库

状态：`v0.7-theory-draft`
平面：执行
governed_by：D-008、D-021、D-026、D-055
用途：存放"仍需情境判断的重复方法"——只有本组织知道的做法、内部平台的用法、踩过的坑——并保证每条都登记得住、审计得动、删得掉。

## 1. 它解决什么问题

- **把方法约束当执行边界用。** 这里的规则是信息型的：期望被遵守，但不改变后续状态。高风险要求只写在这里等于没有控制；更强烈的措辞不能替代执行机制，"强制走链"写在方法里，执行者会先答应再绕过。
- **写模型和工具已经能拿到的内容。** 公开语料里的内容写下来只是缩小模型的搜索空间；代码、配置与运行环境里可直接读取的内容写下来会制造第二个事实来源，并且必然先于源过期，执行者照着过期的那份走。
- **只增不减。** 见到一次坏结果就追加一条，库单调膨胀，检索噪声上升；同一条规则出现在多处互相抢注意力并各自漂移；条目数被当成成果，而下游任务结果并没有变好。
- **规则跟着模型代际静默过期。** 为补偿"记不住、不会主动做、容易漏"而写的强调性措辞，在新一代模型上会从"补漏触发"翻转成"过触发"，表现为过度验证、过度触发、过度分析。这种过期不产生误伤信号，靠日常消费观测发不出来。
- **参考材料与规则打架。** 同一套方法配的示例、模板与参考实现和规则本身不一致，执行者照材料走；事后归因时这被记成模型不听话，实际是材料层的失败。

证据强度（数字见[00 总览 §2](00-总览.md#component-evidence)）：这是"被写得多、却被认为可以省"的部件——不可省略票在全表几乎垫底。它有用，但它不是系统可信度的来源；把高风险边界托付给它是最常见的误用。

## 2. 最小职责与接口

- **它必须做到的**
  - 只承载模型与工具拿不到的内容：组织特有的做法、内部平台的用法、踩过的坑。
  - 为每条规则登记分类（能力补偿 / 组织信息 / 责任结构）与相应的淘汰或迁移条件。
  - 为每条规则绑定一个已登记的失败 Case，而不是口头风险。
  - 保证一条规则只有一个位置，规则之间的优先级显式可查。
  - 保证入必有出：删减由结构性机制执行，不依赖策展者自觉（机制形态、健康度口径与候选发现的限流见[33 评估与演进](33-评估与演进.md) §3 P9）。
  - 保证配套参考材料与规则一致。
- **从别的部件拿什么**：从[33 评估与演进](33-评估与演进.md)拿到期审计的判决、消融结论与删减信号；从[32 证据与追踪](32-证据与追踪.md)拿每条规则的消费与误伤记录；从[25 执行者与模型](25-执行者与模型.md)拿模型代际信息与补偿类指令的候选；从[11 项目知识](11-项目知识.md)拿它所引用的权威定义（方法库不复制第二份事实）；从[40 人的检查点与授权](40-人的检查点与授权.md)拿新增、删除与优先级变更的批准。
- **给别的部件什么**：给[22 上下文装配](22-上下文装配.md)按触发条件加载的方法条目及其排除条件；给[31 守卫与权限边界](31-守卫与权限边界.md)"哪些要求不能只靠方法约束"的清单，即需要下沉为执行边界的候选；给[33 评估与演进](33-评估与演进.md)每条规则的分类标签、绑定 Case 与删除条件，作为审计输入。
- **它自己维护什么**：规则条目及其分类、绑定 Case、淘汰或迁移条件、规则之间的优先级关系、最近消费时间与置换记录、候选待审队列、配套参考材料及其与规则的一致性状态。

## 3. 原则

- **P1 方法库承载方法约束，不承载执行边界。** 控制按性质三分：能力目录说明有哪些动作及其副作用（见[24 工具与执行环境](24-工具与执行环境.md)），方法约束是期望被遵守的信息型内容，执行边界在模型之外由检查器判定；只写在这里的要求最多是提醒。高风险边界不得只有信息型控制，须下沉为执行边界；约束力的两个维度、四级分档与下沉的判据和形态见[31 守卫与权限边界](31-守卫与权限边界.md) §3 P1。｜防的失败：高风险动作靠自觉；"强制走链"只在文字里 ｜删除条件：写不出（责任结构型：把高风险边界留在信息型控制里，等于把后果留给没有拦截能力的一侧；控制类型的分工就是责任的分工）｜强度：一手多来源
- **P2 介入强度与人对结果的确定程度匹配。** 完全确定的由系统直接决定；只确定范围的限定候选集或可操作对象；只有倾向的写成指导文本；没有把握的交模型判断。把倾向写成必须会制造误阻断，把确定写成提醒会让它被静默丢弃。｜防的失败：误阻断与静默丢弃两头都出 ｜删除条件：写不出（责任结构型："我们对这件事有多确定"只有人能回答，介入强度是这一判断的编码）｜强度：一手多来源（三个独立团队各自收敛）
- **P3 只写模型和工具拿不到的内容。** 公开语料里的不写；代码、配置与运行环境里可直接读取的不写；只有来自人的头脑与组织结构的内容必须写。"不写"是默认而不是禁令：同一条可推断的事实第二次导致失败时可以写下来，但须绑定删除条件；读取成本过高时允许保留带对账的缓存，缓存不是第二事实来源。｜防的失败：库里塞满通识；方法与代码不一致而执行者照方法走 ｜删除条件：写不出（责任结构型：只有来自人的头脑与组织结构的内容不写就永远不存在，这是[09 §2](09-跨工具通用性.md#criteria-whether)判据在本部件的落点）；单条内容的删除条件随其分类 ｜强度：一手多来源
- **P4 每条规则登记三分类与相应的淘汰或迁移条件。** 能力补偿类须写删除条件，删除条件可以是把触发条件收窄而不是整体移除；组织信息类不因模型变强而过期，但要登记它的迁移形态——从指令形态迁到工具或检查器形态；责任与结构类声明无到期。缺分类或缺条件的新规则不予登记。｜防的失败：规则只增不减；结构性规则被误当补偿性规则删掉 ｜删除条件：起始档——三分类与迁移条件的登记自 L2 起才有对象（L0/L1 的形态是"每条写清它防的是什么"，见 §4）；作用域内写不出（责任结构型：一条规则属于哪一类决定它能不能被删，分类权不能交给要删它的人）｜强度：一手多来源
- **P5 每条规则绑定一个已登记的失败 Case。** 来源可以是已观察的失败（附轨迹）或已构造的失败（附风险来源），两者同等登记并注明来源类型；口头风险不构成登记理由。修复优先改既有规则，新增须附"不存在等价规则"的证据。｜防的失败：说不清防什么的规则无法被淘汰；同一失败在下游被无限追加提示 ｜删除条件：运行类型限定——"已观察的失败附轨迹"以事发当时可采集为前提，接手与追溯运行中轨迹不可得时以可定位的观察与产生事件替代，并按成立条件标注（形式见[30 验证与测试](30-验证与测试.md) §3 P1，作用域轴见[00 总览 §3](00-总览.md#default-scope)）；作用域内写不出（责任结构型：一条规则说不清它防什么就无法被淘汰，绑定 Case 是可淘汰性的前提）｜强度：一手多来源
- **P6 一条规则只有一个位置，优先级显式。** 禁止同一规则的多份副本，低层文档只引用高层、不复述。规则之间谁让谁由显式声明决定，不靠出现次数、措辞强度或所处位置暗示；互斥的红线与操作说明不得并存而无判据。｜防的失败：多副本各自漂移；执行者在两条冲突规则之间自行挑选 ｜删除条件：起始档——"一条规则只有一处、优先级显式"自 L2 起才有对象（L0/L1 规则集小到不产生副本与冲突，见 §4）；作用域内写不出（责任结构型：两条规则谁让谁只能由显式声明决定，不能由执行者现场挑）｜强度：一手多来源
- **P7 强调性措辞是对特定模型代的补偿，随代际审计。** 加重语气不增加约束力，同一句强调在新一代模型上可能翻转为过触发。本部件负责登记分类、绑定 Case 与交出候选；到期审计的三种触发、对照方法与判决见[33 评估与演进](33-评估与演进.md) §3 P8。｜防的失败：过触发；静默过期的规则只产生成本 ｜删除条件：本条自带——去强调版本在其绑定 Case 上不劣于原版时即删该措辞 ｜强度：一手多来源
- **P8 配套参考材料必须与规则一致。** 示例、模板与参考实现和规则不一致时，执行者会照材料走；出现不一致即视为该规则失效，先修材料或先撤下材料，再谈执行者为什么没遵守。｜防的失败：参考材料互相打架，成为违规的独立归因层 ｜删除条件：配套材料与规则由同一来源生成、且不一致可被机械检出并阻断时，本条降为检查器职责；在此之前"先修材料再谈执行者为什么没遵守"的归因顺序不删｜强度：一手单来源

## 4. 从 L0 到 L3

| 档 | 形态 |
|---|---|
| L0 一人一工具 | 几条踩过的坑写在一处，每条写清它防的是什么；没有它也能干活，缺了会重复踩同一个坑。 |
| L1 一人多会话 | 条目按触发条件加载而不是常驻；新增前先问一句"这条模型自己会不会"。 |
| L2 团队 | 条目具名归属，登记分类与绑定 Case；一条规则只有一处、优先级显式；配套材料与规则一并复核。 |
| L3 无人值守 | 缺分类、缺绑定 Case 或缺淘汰条件的条目不进入自动加载；零消费条目按结构性机制自动退出；候选只进待审队列，不自动写入。 |
