# 23 方法库

状态：`v0.7-theory-draft`
平面：执行
governed_by：D-008、D-021、D-026
用途：存放"仍需情境判断的重复方法"——只有本组织知道的做法、内部平台的用法、踩过的坑——并保证每条都登记得住、审计得动、删得掉。

## 1. 它解决什么问题

- **把方法约束当执行边界用。** 这里的规则是信息型的：期望被遵守，但不改变后续状态。高风险要求只写在这里等于没有控制；更强烈的措辞不能替代执行机制，"强制走链"写在方法里，执行者会先答应再绕过。
- **写模型和工具已经能拿到的内容。** 公开语料里的内容写下来只是缩小模型的搜索空间；代码、配置与运行环境里可直接读取的内容写下来会制造第二个事实来源，并且必然先于源过期，执行者照着过期的那份走。
- **只增不减。** 见到一次坏结果就追加一条，库单调膨胀，检索噪声上升；同一条规则出现在多处互相抢注意力并各自漂移；条目数被当成成果，而下游任务结果并没有变好。
- **规则跟着模型代际静默过期。** 为补偿"记不住、不会主动做、容易漏"而写的强调性措辞，在新一代模型上会从"补漏触发"翻转成"过触发"，表现为过度验证、过度触发、过度分析。这种过期不产生误伤信号，靠日常消费观测发不出来。
- **参考材料与规则打架。** 同一套方法配的示例、模板与参考实现和规则本身不一致，执行者照材料走；事后归因时这被记成模型不听话，实际是材料层的失败。

证据强度：频次 41/52，不可省略票只有 3，失败归因 11（架构确定 §5.1）。这是"被写得多、却被认为可以省"的部件：它有用，但它不是系统可信度的来源；把高风险边界托付给它是最常见的误用。

## 2. 最小职责与接口

- **它必须做到的**
  - 只承载模型与工具拿不到的内容：组织特有的做法、内部平台的用法、踩过的坑。
  - 为每条规则登记分类（能力补偿 / 组织信息 / 责任结构）与相应的淘汰或迁移条件。
  - 为每条规则绑定一个已登记的失败 Case，而不是口头风险。
  - 保证一条规则只有一个位置，规则之间的优先级显式可查。
  - 保证入必有出：删减由结构性机制执行，不依赖策展者自觉。
  - 保证配套参考材料与规则一致。
- **从别的部件拿什么**：从[33 评估与演进](33-评估与演进.md)拿到期审计的判决、消融结论与删减信号；从[32 证据与追踪](32-证据与追踪.md)拿每条规则的消费与误伤记录；从[25 执行者与模型](25-执行者与模型.md)拿模型代际信息与补偿类指令的候选；从[11 项目知识](11-项目知识.md)拿它所引用的权威定义（方法库不复制第二份事实）；从[40 人的检查点与授权](40-人的检查点与授权.md)拿新增、删除与优先级变更的批准。
- **给别的部件什么**：给[22 上下文装配](22-上下文装配.md)按触发条件加载的方法条目及其排除条件；给[31 守卫与权限边界](31-守卫与权限边界.md)"哪些要求不能只靠方法约束"的清单，即需要下沉为执行边界的候选；给[33 评估与演进](33-评估与演进.md)每条规则的分类标签、绑定 Case 与删除条件，作为审计输入。
- **它自己维护什么**：规则条目及其分类、绑定 Case、淘汰或迁移条件、规则之间的优先级关系、最近消费时间与置换记录、候选待审队列、配套参考材料及其与规则的一致性状态。

## 3. 原则

- **P1 方法库承载方法约束，不承载执行边界。** 控制按性质三分：能力目录说明有哪些动作及其副作用（见[24 工具与执行环境](24-工具与执行环境.md)），方法约束是期望被遵守的信息型内容，执行边界在模型之外由检查器判定。约束力由两个独立维度决定——检查是否自动进入必经路径、失败是否改变后续状态；只写在这里的要求最多是提醒。高风险边界不得只有信息型控制，须下沉为执行边界，下沉的判据与形态见[31 守卫与权限边界](31-守卫与权限边界.md)。｜防的失败：高风险动作靠自觉；"强制走链"只在文字里 ｜删除条件：写不出（责任判据）｜强度：一手多来源
- **P2 介入强度与人对结果的确定程度匹配。** 完全确定的由系统直接决定；只确定范围的限定候选集或可操作对象；只有倾向的写成指导文本；没有把握的交模型判断。把倾向写成必须会制造误阻断，把确定写成提醒会让它被静默丢弃。｜防的失败：误阻断与静默丢弃两头都出 ｜删除条件：写不出（判断结构型）｜强度：一手多来源（三个独立团队各自收敛）
- **P3 只写模型和工具拿不到的内容。** 公开语料里的不写；代码、配置与运行环境里可直接读取的不写；只有来自人的头脑与组织结构的内容必须写。"不写"是默认而不是禁令：同一条可推断的事实第二次导致失败时可以写下来，但须绑定删除条件；读取成本过高时允许保留带对账的缓存，缓存不是第二事实来源。｜防的失败：库里塞满通识；方法与代码不一致而执行者照方法走 ｜删除条件：写不出（本条是元规则；单条内容的删除条件随其分类）｜强度：一手多来源
- **P4 每条规则登记三分类与相应的淘汰或迁移条件。** 能力补偿类须写删除条件，删除条件可以是把触发条件收窄而不是整体移除；组织信息类不因模型变强而过期，但要登记它的迁移形态——从指令形态迁到工具或检查器形态；责任与结构类声明无到期。缺分类或缺条件的新规则不予登记。｜防的失败：规则只增不减；结构性规则被误当补偿性规则删掉 ｜删除条件：写不出（元规则）｜强度：一手多来源
- **P5 每条规则绑定一个已登记的失败 Case。** 来源可以是已观察的失败（附轨迹）或已构造的失败（附风险来源），两者同等登记并注明来源类型；口头风险不构成登记理由。修复优先改既有规则，新增须附"不存在等价规则"的证据。｜防的失败：说不清防什么的规则无法被淘汰；同一失败在下游被无限追加提示 ｜删除条件：写不出（元规则）｜强度：一手多来源
- **P6 一条规则只有一个位置，优先级显式。** 禁止同一规则的多份副本，低层文档只引用高层、不复述。规则之间谁让谁由显式声明决定，不靠出现次数、措辞强度或所处位置暗示；互斥的红线与操作说明不得并存而无判据。｜防的失败：多副本各自漂移；执行者在两条冲突规则之间自行挑选 ｜删除条件：写不出（唯一位置是结构要求）｜强度：一手多来源
- **P7 强调性措辞是对特定模型代的补偿，随代际审计。** 加重语气不增加约束力，同一句强调在新一代模型上可能翻转为过触发。到期审计有三种触发并存、分工不同：日常的消费与误伤观测发现摆设与误伤，代际更替时的全删对照发现静默过期，周期清扫处理存量；代际审计不可被日常观测替代。本部件负责登记分类、绑定 Case 与交出候选，审计流程、对照方法与判决在[33 评估与演进](33-评估与演进.md)。｜防的失败：过触发；静默过期的规则只产生成本 ｜删除条件：本条自带——去强调版本在其绑定 Case 上不劣于原版时即删该措辞 ｜强度：一手多来源
- **P8 入必有出，删减靠结构性机制而不是策展者自觉。** 结构性机制可并列为容量置换、相似合并加版本、压缩比约束、周期性自动清扫；删除门槛低于新增，绑定 Case 不再复现或持续零消费即可由归属人删除并保留历史。库的健康度按下游任务结果与召回有用率评估，不按条目数；增删的作用域是共享组件，一次性产物只有被重复生成时才成为候选。同源机制在知识与记忆一侧见[12 记忆与知识治理](12-记忆与知识治理.md)。｜防的失败：库只增不减导致检索噪声上升；把条目数当成果 ｜删除条件：写不出 ｜强度：一手多来源
- **P9 候选发现是独立步骤且自带限流。** 任务之后才触发、有信号才输出、单次输出有上限、只建议不写入；候选进入待审队列后才走晋升流程。发现端限流与写入端刹车并行，缺任何一个都会让库单调膨胀。｜防的失败：读到一次坏结果即追加，短期内堆出大量重复条目 ｜删除条件："只建议不写入"部分写不出（责任型）；限流的参数可在写入端刹车被证明足够时放宽 ｜强度：一手单来源（限流形态）+ 一手多来源（膨胀机制）
- **P10 配套参考材料必须与规则一致。** 示例、模板与参考实现和规则不一致时，执行者会照材料走；出现不一致即视为该规则失效，先修材料或先撤下材料，再谈执行者为什么没遵守。｜防的失败：参考材料互相打架，成为违规的独立归因层 ｜删除条件：写不出（材料是人的产出）｜强度：一手单来源

## 4. 从 L0 到 L3

| 档 | 形态 |
|---|---|
| L0 一人一工具 | 几条踩过的坑写在一处，每条写清它防的是什么；没有它也能干活，缺了会重复踩同一个坑。 |
| L1 一人多会话 | 条目按触发条件加载而不是常驻；新增前先问一句"这条模型自己会不会"。 |
| L2 团队 | 条目具名归属，登记分类与绑定 Case；一条规则只有一处、优先级显式；配套材料与规则一并复核。 |
| L3 无人值守 | 缺分类、缺绑定 Case 或缺淘汰条件的条目不进入自动加载；零消费条目按结构性机制自动退出；候选只进待审队列，不自动写入。 |
