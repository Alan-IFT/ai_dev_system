# 22 上下文装配

状态：`v0.7-theory-draft`
平面：执行
governed_by：D-001、D-015、D-030、D-031
用途：决定每一次推理实际看见什么——按唯一一份清单装配，按分层与预算取舍，并在窗口不够时以可拦截的方式把内容移出去而不是丢掉。

## 1. 它解决什么问题

- **取并集与入口分裂。** 项目里存在第二份、第三份默认加载列表，执行者把它们取并集，新会话从携带全部项目历史开始；同一条规则出现在多处互相抢注意力。启动时的固定开销（系统级指令、能力描述、输出格式约束、路由类元机制）在动手之前就占掉一块窗口，长任务因此更早触发压缩。
- **压缩被当成一个静默的技术动作。** 自动压缩在错误时机触发，中间状态没落盘就没了；摘要保住了"发生过什么"却丢了"正在看什么"，恢复后重读错版本或重复审查已审对象；已经失败过的尝试没有转成教训，新会话把同一条死路再走一遍。窗口重建后任务不变量被推进历史中段，遵从率下降，被误判为模型不稳定。
- **工具返回与大工件没有进出策略。** 一次大返回的原文在其后几十轮里重复进入输入，压缩之前就在逐轮计费；反方向上，超出单次输出可靠承载的工件被以"模型完整输出"往返，截断或占位后残缺地写进外部系统。
- **有损压缩滤掉线索，评价口径又看不见。** 对命令输出与检索结果做有损压缩后，关键命中消失，模型用更多命令、更多测试、更多失败去补；而"过滤本身可复现"被误当成"路径中性"，只做组件级对照就下了全流程结论。
- **隔离与拆分的账没算清。** 为减小上下文而隔离出去的执行者把项目规则一并隔了出去，却被派了有副作用的任务；拆分被当成省钱手段，各单元固定开销并行叠加，下游的降幅被读成全流程收益，编排者反向涨上去的成本没人看见。

证据强度：频次 47/52，不可省略票 8，失败归因 29（架构确定 §5.1）。失败归因仅次于验证与测试——它是"做事"那批部件里唯一挤进失败归因前三的。

## 2. 最小职责与接口

- **它必须做到的**
  - 维护唯一一份默认加载清单，可按角色与环境参数化，参数化后仍然唯一，约束之间的优先级显式可查。
  - 分层加载并为启动固定开销留出预算：先索引后正文、先片段后扩展。
  - 把压缩与会话结束当成同等的、可在其前被拦截的生命周期事件，并声明每种策略丢什么、留什么。
  - 规定内容进出窗口的策略：工具返回默认只服务当前决策，读写两侧对称外部化。
  - 提供三类隔离原语，并要求每次委托声明是否继承治理规则。
  - 让上下文成本按三个正交轴可观测。
- **从别的部件拿什么**：从[11 项目知识](11-项目知识.md)拿短入口与就近细节，按需拉取而非全量推送；从[12 记忆与知识治理](12-记忆与知识治理.md)拿带置信态的候选条目及其使用方式；从[10 意图与验收](10-意图与验收.md)拿本次工作项的验收条目与范围；从[20 状态工件](20-状态工件.md)拿每轮的起点、短交接与恢复锚点；从[23 方法库](23-方法库.md)拿按触发条件加载的方法条目及其排除条件；从[31 守卫与权限边界](31-守卫与权限边界.md)拿角色可见的能力集与治理规则的继承边界。
- **给别的部件什么**：给[25 执行者与模型](25-执行者与模型.md)本次推理可见的工作集与隔离原语的选择；给[20 状态工件](20-状态工件.md)压缩前外部化的教训条目与活动工作集引用；给[32 证据与追踪](32-证据与追踪.md)按来源、缓存与执行单元分解的消耗记录和注入条目的消费记录；给[40 人的检查点与授权](40-人的检查点与授权.md)已穷尽可读事实之后剩下的那几类问题。
- **它自己维护什么**：唯一加载清单及其版本与缺失冲突处理、启动固定开销的构成、压缩策略声明与压缩产物的两半、活动工作集引用、隔离原语的选择记录与治理继承声明。

## 3. 原则

- **P1 每个项目只有一份默认加载清单，其它文档只链接不复制。** 清单只做路由，不复制需求、架构、工作项或证据的正文；链接不自动递归展开，加载集合去重。它可以按角色与环境参数化，但参数化产生的是同一份清单的视图而不是新的清单；不同约束集之间的优先级显式声明并可查，权限分档独立于加载分档。｜防的失败：多份默认入口被取并集并持续膨胀；同一规则多副本各自漂移 ｜删除条件：写不出（唯一性是结构要求；参数化的维度可随载体变化）｜强度：一手多来源
- **P2 分层加载，先索引后正文，启动固定开销计入同一预算。** 三层依次是清单列出的入口与当前工作项、当前任务明确引用的对象、只在调查时才读的历史与无关模块。"可能有用"不是加载理由，但给少了也有补偿成本（更多搜索、测试与修复），以当前步骤所需为准。索引只做路由，不具权威，与就近细节冲突时以细节为准（权威归属见[11 项目知识](11-项目知识.md)）。能力描述按需注入，角色可见的能力集作为慢变配置而不是逐轮增删。固定比例与固定条数只是项目参数。｜防的失败：动手前窗口已被占去可观一块；能力集逐轮变动使前缀复用失效 ｜删除条件：能力描述由模型内化或延迟解析成为默认，且索引层可被同等精度的实时检索替代 ｜强度：一手多来源
- **P3 开工前的事实由工件回答，不由聊天回答。** 动手之前执行者应能基于工件说清：目标与非目标、当前工作项与它的状态版本、工作副本身份、事实源、目标环境、验收标识、风险与阻塞、未决策项。答不上来就先补工件，不靠回忆。多个来源冲突时按主张模型分类，不把代码或摘要自动当成产品意图或运行事实。｜防的失败：从聊天里恢复出一个似是而非的任务状态 ｜删除条件：写不出（追溯要求）｜强度：一手多来源
- **P4 压缩与会话结束是同等的、可在其前被拦截的生命周期事件。** 触发条件除窗口余量外必须包含行为信号——重复询问已确认事项、重复同类错误、任务阶段切换——以及单会话历史的增长曲线；阈值只是项目参数。压缩前先把关键状态、活动工作集引用与失败尝试转成的教训条目（假设、证据、为何失败）外部化，原始错误轨迹随后丢弃且不进长期记忆。压缩策略是显式选择（清空 / 确定性截断 / 摘要 / 外部化为交接件 / 主动结构化笔记），每种声明它丢什么、留什么。｜防的失败：自动压缩在错误时机触发丢中间状态；摘要遗漏已失败尝试，新会话重复试错 ｜删除条件：载体可证明压缩不丢状态字段且模型在长任务中不自行提前结束 ｜强度：一手多来源
- **P5 压缩产物分两半，窗口重建后不变量重新锚定。** 叙事摘要（目标与范围、已生效决策、状态身份、未解决错误、验证结果、风险、下一步、原始位置）与活动工作集原文（正在编辑或验证的少量工件按引用原样重载）互不替代。窗口重建后重新核对清单、状态与关键验收记录，并把任务不变量——目标与范围、已生效决策、安全边界、工作副本身份——重新锚定到高注意力位置；规则优先级显式声明，不靠出现次数或措辞强度暗示，具体位置方向只作并列探测提示。压缩产物既不是项目知识也不是长期记忆，不能自证正确。｜防的失败：恢复后重读错版本或重复审查已审对象；规则被推入中段后遵从率下降 ｜删除条件：模型能从摘要引用可靠回源，且位置效应在代表性任务上不可测 ｜强度：一手多来源
- **P6 进出窗口的内容有存活策略，读写两侧对称，失败语义非对称。** 工具返回默认只服务当前决策：决策之后窗口只留结论与回源位置，原文外部化到可回读位置，不随历史逐轮携带；大体量外部数据由短生命周期执行单元消化，进入长生命周期单元的只能是结构化摘要与引用。反方向同样成立：超出单次输出可靠承载的工件不以"模型完整输出"往返，读入只得引用与局部窗口，修改只做局部替换，写回外部系统时内容取自持久工件而不是模型输出。拦截失败按后果非对称——只影响模型所见的读路径可降级放行并留痕，改变外部状态的写路径失败必须关闭并转人工。任务所需的固定观察集可由确定性程序在推理前采集或在执行时过滤后再交模型，程序在动作后触发的盲区检查结果作为带产生时间与触发事件身份的观察推送到下一步，消费后即清理、不累积。｜防的失败：一次大返回在其后数十轮重复计费；残缺工件被写进生产；推送物累积成新的取并集 ｜删除条件：读侧可删于推理成本与注意力不再随历史长度退化；写侧"内容取自持久工件"一半是证据要求，不删 ｜强度：一手多来源
- **P7 有损观察压缩须同时满足三个条件。** 对执行者的观察结果（命令输出、检索结果、日志）做有损压缩时：要有可机械检测的损失信号；命中信号后自动回退无损；验证、审查与验收环节不使用有损输出。采用、跳过与回退可记录，并按整个任务而不是单条输出评估；程序侧的注入与过滤须有大小上限与截断规则。凡改变模型所见信息的机制，组件级对照只能对局部输出层下结论，必须另报路径层指标（口径见[33 评估与演进](33-评估与演进.md)）。｜防的失败：关键线索被滤掉后以更多命令与更多失败去补；把"过滤可复现"误当"路径中性" ｜删除条件：模型能从压缩摘要识别线索缺失并主动回源，且成本不按输入长度计费 ｜强度：一手多来源
- **P8 隔离至少区分三类原语，委托必须声明治理继承。** 委托不继承历史、只回结论；分叉试探继承全部历史、产物不回流主线、用完即弃；压缩外部化让主线自身瘦身。按"任务是否依赖已有上下文"与"产物是否需回流"选择：试探性方案与一次性产出默认走分叉试探，独立的高输出操作默认走委托。委托须声明是否继承治理规则（项目入口指令、权限边界、安全规则），未声明视为不继承，不继承者只授予只读或纯输出型任务；合同字段与子任务原子性见[25 执行者与模型](25-执行者与模型.md)。｜防的失败：试探失败的大段产物污染主线；无规则约束的执行者做出有副作用的动作 ｜删除条件：治理继承部分写不出（责任判据）；原语区分可随载体能力合并 ｜强度：一手单来源 + 厂商产品形态旁证
- **P9 上下文成本按三个正交轴可观测，子执行者独立计费。** 三轴是：来源（系统级指令、能力描述、输出约束、历史、工具返回、人的输入、模型输出）、是否重复携带（缓存命中 / 新输入 / 输出）、执行单元与阶段。子执行者的上下文独立计费，拆分本身不省成本；编排者每站重新理解状态的成本单独计量，可确定的迁移、路由与去重交给程序。成本报告按计费类别加权并声明价表版本；只报总量、或只报原始计数而不分单元与阶段的优化提案不进评审。｜防的失败：总量下降掩盖编排者上升；只知道账单高，不知道该削哪一块 ｜删除条件：执行平台原生给出按当前价表折算的分单元报表且评审默认读它 ｜强度：一手多来源
- **P10 向人提问前先穷尽环境中可直接读取的事实。** 上交给人的问题只应是价值排序、范围边界、权限授予、不可逆选择四类，并附已查证事实与待决选项；面向人的输出先投放少量决策点，确认后再展开；记录选项、取舍、建议、默认影响与决定人。｜防的失败：向人请示本可自查的事实；人面对整篇长文直接放弃审查 ｜删除条件：分流部分可删于模型稳定分流（可查事实的提问率趋零）；投放节奏部分写不出（人侧带宽约束）｜强度：单团队 n=1

## 4. 从 L0 到 L3

| 档 | 形态 |
|---|---|
| L0 一人一工具 | 一份写在纸上的加载清单加一份交接件；先看入口再看正文，压缩前手动把状态与教训写出去。 |
| L1 一人多会话 | 清单按当前工作项参数化；会话结束与压缩同等对待，两半产物是恢复的默认输入；工具返回的原文落在可回读位置。 |
| L2 团队 | 清单按角色与环境参数化且优先级显式；隔离原语具名可选并声明治理继承；成本按来源、缓存与执行单元三轴报告，子执行者独立计费。 |
| L3 无人值守 | 窗口重建后的不变量重锚定与有损压缩的自动回退是运行前提；没有损失信号就不启用有损压缩；分单元成本报表是优化提案的准入条件。 |
