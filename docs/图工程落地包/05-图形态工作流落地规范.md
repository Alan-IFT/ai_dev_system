## 1. 准入：什么时候**不该**建图

**本节是全文最该被执行的一节。** 它把"极简至上：别为了图而图"从一句箴言改写成一组可判定的准入条件。

顺序说明：卡 07 与常见写法都先讲 V/E/S/P 再讲决策树。**本文倒过来**——先判该不该建，再谈建成什么样。理由是[21 §2 P3](../21-调度与拆分.md#complexity-ladder)：复杂度阶梯的升级须**举证**，而举证发生在设计之前。先给形态再给判据，等于先发牌再定规则。

### 1.0 默认值：不建图

> **默认形态是单执行单元（Loop）。建图是一次需要举证的升级，举证责任在提议建图的一方。**

【已有】[21 §2 P3](../21-调度与拆分.md#complexity-ladder)逐字给了升级到多单元结构的前置："**且已有一个跑稳的单一执行单元作为前置**"。本文只把它变成一道必经的准入门。

**"一个目标、一个停止条件"怎么机械判**（这一条是默认值的守门人）：

1. 按 [21 §1](../21-调度与拆分.md#canonical-states)的要求，在起点声明处列出本次运行的**合法停止点**，每个停止点写三栏：`触发条件 | 停下之后去哪 | 谁负责`。
2. 把这张表按"停下之后去哪"与"谁负责"两栏去重。
3. **去重后剩一行 → 一个停止条件 → 不得建图。** 同一个停止条件的多次重试、多轮迭代、多个子步骤都不产生新行（[21 §2 P6](../21-调度与拆分.md#complexity-ladder)：换执行者、改指令或补上下文本身不自动构成新路径）。
4. 去重后剩多行 → 进 §1.2–§1.8 逐条判触发。**注意：多行只是"允许继续判"，不是"应当建图"。**

**判不出（表写不出来、或某行的"去哪"写不出）→ 记未定 → 按不建图处理。** 依据：判不清按更简单的一侧，不是按更宽的一侧——这与[09 §4](../09-跨工具通用性.md#two-axes)"判不清按最宽适用处理"不冲突，那一条说的是**规则的适用范围**（拦住更多），本条说的是**结构的引入**（引入更少），两者同向：都偏向"更多被拦住、更少被建造"。

### 1.1 七条触发的总规则

满足以下任一条 = **允许**建图；**允许不等于应当**。每条触发只授权它自己所必需的最小结构（§1.8）。

七条里**只有一条（§1.8 异构专业化）能纯机械判定**，其余需要他证或一次对照实验。这不是缺陷，是实情：其余六条的判定成本本身就是"别建图"的一部分理由——**当一条触发的他证成本高于建图省下的成本时，按未定处理，即不建图。**

| # | 触发 | 判定方式 | 判定成本 | 单独成立时授权的最小结构 |
|---|---|---|---|---|
| 1.2 | 分支 | 机械（后继路径表去重） | 低 | 一组条件边 + 每条边的失败去向 |
| 1.3 | 并行 | 机械（写范围交集）+ 一条声明 | 低 | 一次扇出 + 一个带缺失报告的汇合点 |
| 1.4 | 跨会话状态 | **多数情况下不构成建图理由**，见该节 | 低 | 通常为零（状态工件即可） |
| 1.5 | 人工审批 | 他证（历史运行里有无真实等待时段） | 中 | 一处可挂起的检查点 |
| 1.6 | 上下文保护 | 他证（一次盲评对照） | **高** | 一个隔离节点 |
| 1.7 | 并发探索 | 他证（判定标准的冻结时间早于探索开始） | 中 | N 条并行分支 + 一个按冻结标准计分的汇合 |
| 1.8 | 异构专业化 | **纯机械**（权限面并集） | 低 | 按权限面切开的节点边界 |

（编号与小节号一一对应，下面逐条展开。）

### 1.2 触发一 · 分支

**判据**：存在两条以上后继路径，其选择依据在运行前不可确定，**且不同路径的失败回边不同**。

**怎么判（机械）**：写一张后继路径表，每行三栏 `触发条件 | 下一步 | 失败去向`。**若所有行的"失败去向"相同，它不是分支，是一次条件判断——留在单执行单元里做。**

依据【已有】[21 §2 P2](../21-调度与拆分.md#complexity-ladder)：阶段独立存在的四项判据里有两项直接可用——"与相邻阶段不同的失败模式"和"失败后的回退目标不同"。分支的本质是回退目标分叉，不是文本上出现了"如果"。

**判不出** → 未定 → 不建图。

### 1.3 触发二 · 并行

**判据（两个条件必须同时满足）**：

1. **写范围不相交**：列出每个子任务将要写的对象集合，取两两交集；**交集非空即不满足**。【已有】[21 §2 P9](../21-调度与拆分.md#complexity-ladder)（并行单元只写自身局部空间，总状态由收口阶段的单一执行者更新）。
2. **汇合的预期分支数写得出**：写不出预期数，就没法执行[21 §2 P10](../21-调度与拆分.md#complexity-ladder)（汇合必须显式报告预期、实收与缺失）→ 不满足。

**并行的收益是墙钟时间，不是成本。**【已有】[25 §2 P5](../25-执行者与模型.md)：各单元固定开销并行叠加，子执行者独立计费。因此本条追加一项声明要求：**提议并行时须声明"墙钟时间是本次运行的一个约束"，并指出该约束的来源（谁在等、等多久算超）。** 说不出谁在等 → 并行不构成建图理由。

### 1.4 触发三 · 跨会话状态 —— 这一条多数情况下**不**构成建图理由

**这是本文对卡 07 决策树的一处【修订】。** 卡 07 把"需要跨天状态留存"列为 Graph 的触发之一。**本仓库在 L1 就用状态工件解决这件事，不需要图。**

依据【已有】：[20 §1](../20-状态工件.md#workspace-identity)的用途逐字是"用少数几份外置工件回答'现在在哪里、下一步做什么、中断后怎么接上'"；[20 §3](../20-状态工件.md#session-end) L1 档的形态逐字是"会话结束与压缩前都生成短交接；新会话先读状态再动手"。**跨会话连续性是 L1 的问题，图是 L2 的东西。**

**只有一种情况下跨会话状态升级为建图理由**：恢复点必须落在**特定节点边界**上，且**不同节点的恢复语义不同**——即某些节点的重放是安全的、某些节点重放会重复不可逆副作用（[20 §2 P8](../20-状态工件.md#state-artifacts)）。

**怎么判（机械）**：列出本次流程里的不可逆动作，标出每一个"从哪个点之后重放会重复它"。若这些点少于两个，恢复语义只有一种，用一份状态工件即可 → 不建图。

【修订】｜防的失败：把"跨天要接着做"读成"需要多节点编排"，于是一个本该由一份状态工件解决的问题，付了一整套图的固定开销，而图的其余部分从第一天起就是空转结构。
｜删除条件：当执行环境对全部外部副作用提供恰好一次语义时（同 [20 §2 P8](../20-状态工件.md#state-artifacts) 的删除条件），"不同节点恢复语义不同"这个例外消失，本条退化为"跨会话状态一律不构成建图理由"。
｜可以删掉现有的什么：**可删任何项目文档里照抄卡 07 决策树"需要跨天状态留存 → 采用 Graph"那一行**——它在本仓库口径下会导致系统性过度建图。

### 1.5 触发四 · 人工审批

**判据**：流程**中途**存在至少一处状态转换，其继续与否只能由人决定，**且等待是异步的**——人不在场时流程必须挂起而不是失败。

**怎么判**：先看[40 §2 P1](../40-人的检查点与授权.md)的五处检查点（确认意图、接受计划、批准集成、授权发布、抽查自动决策）里本次运行覆盖了哪几处。**若只覆盖"确认意图"且它发生在运行开始之前，不构成挂起需求 → 不建图**（那是一次开工前的确认，不是流程中的挂起点）。

**他证**：取一次真实运行的记录，看有没有出现过"等待人"的时段，**且该时段内执行者确实是空闲的**（不是自己接着往下做）。历史上从没出现过这种时段 → 这条触发不成立；此时更可能的实情是**人从来没有被真的等过**，那是[40 §2 P2](../40-人的检查点与授权.md)说的"否决率长期为零说明它已不再产生判断"的形态，先修检查点，别建图。

**判不出（拿不到运行记录）** → 未定 → 不建图，并把"缺运行记录"登记为一处待补的观测能力。

### 1.6 触发五 · 上下文保护 —— 不取阈值，改写为可他证判据

卡 07 给的是"子任务产生超 1000 token 无关信息"。**该来源如此主张；本规范不引为论据，也不取该阈值**（理由见 §0.1）。

**改写后的判据（两级，第一级不满足就到不了第二级）**：

**第一级（机械，且第一处置不是建图）**：某个子任务的工具返回或中间产物，在其决策完成之后**不再被任何后续步骤引用**。
→ 【已有】[22 §2 P6](../22-上下文装配.md#context-levels)已经给了处置，逐字："**决策之后窗口只留结论与回源位置，原文外部化到可回读位置，不随历史逐轮携带**"。
→ **所以第一处置是外部化，不是建节点。** 外部化能解决的，建图是多余的。

**第二级（他证，成本高）**：外部化之后仍不够——即该子任务的**推理过程本身**会改变后续判断，而不只是它的输出体积。

**他证方式（一次盲评对照）**：同一任务跑两次。A 组：同一执行者连着做完。B 组：把该子任务的产物外部化后，由一个未见过该子任务过程的执行者继续。两组产物交给**不知道分组**的第三方判定（判据用已冻结的验收条目，[10 意图与验收](../10-意图与验收.md)）。**差异不可观察 → 这条触发不成立。**

**成本提示（必须写在提案里）**：这次对照本身要跑两遍任务加一次盲评。**当这个成本高于建图省下的成本时，按未定处理，即不建图**——默认站在更简单的一侧。

**为什么不能用"token 数"当判据**：token 阈值是一个**代理指标**。[31 §2 P2](../31-守卫与权限边界.md)逐字："**代理指标只能提醒或产生候选，不得阻断**"。用一个代理指标去阻断"不许用单执行单元"，正是那一条禁止的形态。**这是本文拒绝照抄 1000 token 的仓库内依据，不是口味问题。**

### 1.7 触发六 · 并发探索

**判据（顺序不可颠倒）**：

1. 先看**判定标准是否已冻结**：存在一组在探索开始之前就已冻结的验收条目或评估分区（[10 意图与验收](../10-意图与验收.md)冻结、[03 §4](03-通用落地套件.md) 的 `eval/` 三分区）。**没有冻结标准 → 不满足，先去冻结标准。**
2. 再看**分支是否真互斥**：能不能顺序做完一个再做另一个而不损失信息？能 → **这不是并发探索，是 §1.3 的并行**（墙钟约束），按 §1.3 判。

**他证**：探索结束时，须能指出"被淘汰的分支是按哪条冻结标准淘汰的"，且**该标准的文本版本与探索开始前一致**（用版本控制或冻结记录机械核对）。指不出、或标准在打分之后被改过 → 这次并发探索是一次自证，其结论按[30 §2 P1](../30-验证与测试.md#verification-layers)记未定。

### 1.8 触发七 · 异构专业化 —— 七条里唯一纯机械可判的一条

**判据（机械）**：列出每一步所需的能力（[24 工具与执行环境](../24-工具与执行环境.md#aci)的能力目录）与权限维度取值（[31 §2 P6](../31-守卫与权限边界.md)：可做的动作、可作用的对象、参数范围、环境、可通信主体、能力集合）。

若存在两步 A、B 使得

```
perm(A) ∪ perm(B) ⊋ perm(A)   且   perm(A) ∪ perm(B) ⊋ perm(B)
```

**且该并集包含至少一项不可逆动作** → 触发成立。

**这一条享有特权：满足它就必须拆，不受"极简至上"约束。** 理由是不拆的代价不是复杂度，是权限面扩大——[31 §2 P6](../31-守卫与权限边界.md)要求有效能力沿请求链路**单调收窄**，把两步塞进一个执行者等于让它同时持有两份权限。【已有】，本节只是把它变成一个可算的式子。

**注意它与"专业化"这个词无关。** 按职业名给分身起名字（研究员、写手、审稿人）而不给独立验收，[25 §2 P1](../25-执行者与模型.md)明写不构成一次拆分。**能判的是权限面，不是称呼。**

### 1.9 最小结构授权：每条触发只买它自己那一件

**【新增 N1】每条准入触发只授权它自己所必需的最小结构；结构中的每个节点与每条边都必须能指回准入举证表的某一行，指不回的即为未授权结构。**

｜防的失败：满足了一条触发（例如流程中途需要一次人工审批），于是把整套主管-工作者拓扑连同扇出、汇合、评委一起装上。其余结构从第一天起就是空转的——**它们建的那一刻都是对的，三个月后没有任何东西会发现它们从没被走过**。这正是[失败 Case 清单](../失败Case清单.md)读数六的形状（C-017 `current_work_item` 自基线起从未被填过一次；C-021 `archify visual-check` 自成图起一直 fail 而从没被跑过），只是对象从"一处要求"换成了"一段图结构"。
｜删除条件：当载体让每个节点与每条边自带消费计数、且零消费结构被结构性刹车自动清扫（[33 §2 P9](../33-评估与演进.md#case-registry)的 Thin 在图结构上有对象）时，本条可删——载体已经保证了。
｜可以删掉现有的什么：**项目侧不必再维护任何"工作流模式清单"的副本**（三大拓扑表、Anthropic 五模式表）。有了准入判据加最小结构授权，模式表只是样例；照抄一份进项目文档就是造第二事实来源（[11 §2 P2](../11-项目知识.md#claim-model)），也正是本仓库复发六次以上的那个病（[C-027](../失败Case清单.md)）。本文 §3.3 的表删掉不影响任何一次判定。

**两种机制类型的落法**（[09 §5](../09-跨工具通用性.md#feasibility-test)）：
- **检查器**：扫描图定义，每个节点/边的 `准入依据` 字段必须非空且其值能在举证表里找到；找不到的条数 > 0 即 FAIL。
- **人工检查点**：结构变更走[40 §2 P6](../40-人的检查点与授权.md)的授权变更（慢变、可审计、附抽样复核），提案里没有举证行的结构不予批准。

### 1.10 反向：图什么时候该退回去

【已有】[21 §2 P3](../21-调度与拆分.md#complexity-ladder)逐字："**复杂度阶梯是双向的**……降级同样有判据：同输入多次运行结果一致的步骤转为确定性程序。"按 [D-055](../决策日志.md#decision-index) 判据优先于枚举，这条判据外推到图结构上的形态是：

- **某条准入触发在连续若干次运行中不再出现** → 它授权的结构进入 Thin 候选（[33 §2 P9](../33-评估与演进.md#case-registry)：长期无消费）。"若干次"是项目参数，本文不取值。
- **某个节点的输出同输入多次一致** → 该节点降级为确定性程序（[24 §2 P4](../24-工具与执行环境.md#aci)）。
- **降级与升级同样要举证**，方向相反：升级举证"为什么现在需要"，降级举证"它这段时间没被需要"。

**降级的证据来源不能是提议降级的一方**（[33 §2 P9](../33-评估与演进.md#case-registry)：健康度只能是下游结果与召回有用率，不能是条目数）。

## 2. 图形态工作流的最小定义（V / E / S / P）

**先说这一节不是什么：它不是一个新架构。** [00 §2](../00-总览.md#component-evidence)逐字："**部件清单到此为止**"。V/E/S/P 是执行平面（V、E、S）与控制、责任两个平面（P）的**一个视图**，本文不因它增设第 15 个部件，也不提议任何一章改名。

### 2.1 四元语逐个对齐

| 元语 | 对应本规范的哪个部件与原则 | **语义（必须有）** | **只是命名（可换）** |
|---|---|---|---|
| **V 节点** | [25 §2 P1](../25-执行者与模型.md)执行者是可替换的执行单元；[21 §2 P2](../21-调度与拆分.md#complexity-ladder)阶段独立存在的四项判据 | 每个节点是一份**合同**：输入、非目标、精确事实入口、权限、输出格式、验收，六件缺一即不成立；且满足四项判据（不同失败模式 / 不同回退目标 / 单一责任主体 / 退出条件可观察） | "节点""智能体""工位"；**"单进单出"也是命名**——本仓库的对应约束是四项判据，不是入度出度 |
| **E 边** | [21 §2 P4](../21-调度与拆分.md#complexity-ladder)返工定向与失败去向；[21 §2 P7](../21-调度与拆分.md#complexity-ladder)只消费结构化裁定；[31 §2 P4](../31-守卫与权限边界.md)Gate 是一份合同 | 每条边有**触发条件**与**失败去向**（重试耗尽后去哪，事先声明）；**边的分派函数是确定性的**，它的输入可以来自模型，它本身不是模型 | "边""路由""控制流"；"直通/条件/扇出扇入/回环"这四种形状是样例 |
| **S 状态** | [20 §2 P1/P2/P3/P6](../20-状态工件.md#state-artifacts)；不变量二"状态外置且朴素" | 状态**外置**，任何节点从读状态开始而不是从回放对话开始；每条记录带可交叉核对的工作副本身份与版本；新鲜度冲突失败关闭 | "状态""State""看板" |
| **P 策略** | [31 §2 P6](../31-守卫与权限边界.md)权限创建时固化、只能收窄；[31 §2 P8](../31-守卫与权限边界.md)授权标记只能由人侧通道写入；[40 §2 P5](../40-人的检查点与授权.md)授权是带参数的结构化决定 | 权限的**产生方与执行方分离**；边界在运行创建时固化，执行中只能收窄；不可逆动作的授权只能由人产生 | "策略""Policy""制度" |

### 2.2 一处与卡 07 不一致，明写

卡 07 §2.1 逐字：S 是"**沿着边流动的读写对象**"。

**本仓库的立场不同**：状态不是沿边流动的载荷，而是**外置的、可被任何节点重新读取的工件**。[20 §1](../20-状态工件.md#workspace-identity)逐字的用途是"让每轮推理与每次交接**从读状态开始，而不是回放对话**"。

**差别是实质的，不是措辞**：把状态当 payload 沿边传递，状态的权威就落在**传递链**上——某一跳丢了字段，下游拿到的是一份看起来完整的残缺状态，而没有任何位置可以回读原件。外置之后，权威落在一份可回读的工件上，边只传引用。

【修订】｜防的失败：一条长链上某个节点顺手改写了状态里的一个字段，下游全部按改写值执行，事后无法区分"原本就是这个值"与"被某一跳改过"；[20 §2 P3](../20-状态工件.md#state-artifacts)的新鲜度冲突检测在 payload 形态下没有对象可比。
｜删除条件：当载体保证状态对象在传递中不可被中间节点改写、且每一跳的改写都产生不可伪造的事件时，"外置"与"沿边流动"在可核对性上等价，本条可删。
｜可以删掉现有的什么：**可删任何项目里同时维护"状态工件"与"节点间消息体"两份进度信息的做法**——两份即第二事实来源。

### 2.3 这一节的落法（两种机制类型）

- **外部状态存储**：一份 `graph/nodes.md`，一个节点一个条目，字段即 §2.1 的"语义"列（合同六件 + 四项判据 + 准入依据）。
- **权限与隔离配置**：节点的"权限"一件不写在文档里，而由执行环境按执行身份授予（机制类型清单"权限"维度第 ⑤ 项：执行身份本身不具备该类权限）。**这一种的好处是它不可被文档漂移绕开；代价是它在没有身份隔离能力的工具上不可用**，因此是并列形态之一，不是必填形态（[09 §6](../09-跨工具通用性.md#detection-hints)）。

## 3. 拓扑：上位判据在前，模式表只作样例

### 3.1 为什么不写成一张模式清单

两条仓库内依据：

1. [23 §2 P1](../23-方法库.md)：**方法库承载方法约束，不承载执行边界。** 一张"什么时候用哪种模式"的清单，写在方法库里最多是提醒。
2. [09 §5](../09-跨工具通用性.md#feasibility-test)（D-055 改动 5）逐字：**"判据优先于枚举与样例……遇到不在枚举内的对象，按判据判定，判不出即记未定并升级，不得硬塞进最近的一项。"**

所以本节先给判据，模式表放在 §3.3 且明标为样例。

### 3.2 上位判据：拓扑不是选出来的，是准入结果的形状

> **一条工作流的拓扑，等于 §1 中被判定成立的那些触发所授权的最小结构的并。**

按这条判据，形状是算出来的，不是挑出来的：

| §1 判定成立的触发 | 结构的形状 | 该形状必须同时带的东西 |
|---|---|---|
| 无（默认） | 一条线，单执行单元 | 一处外部锚点（§4.3）+ 一次独立复核（§4.1） |
| 仅分支（§1.2） | 条件边 | 每条边的失败去向（[21 §2 P4](../21-调度与拆分.md#complexity-ladder)） |
| 仅并行（§1.3） | 扇出 + 汇合 | 汇合处的预期 / 实收 / 缺失报告（[21 §2 P10](../21-调度与拆分.md#complexity-ladder)） |
| 仅人工审批（§1.5） | 线 + 一处可挂起的检查点 | 呈现顺序与带宽度量（[40 §2 P4](../40-人的检查点与授权.md)、[31 §2 P3](../31-守卫与权限边界.md)） |
| 仅上下文保护（§1.6） | 一个隔离节点 | 它与上游的上下文来源交集声明（§4.1） |
| 仅并发探索（§1.7） | N 条分支 + 按冻结标准计分的汇合 | 标准的冻结时间早于探索开始，可机械核对 |
| 仅异构专业化（§1.8） | 按权限面切开的节点边界 | 权限沿委托链单调收窄（[31 §2 P7](../31-守卫与权限边界.md)） |
| **分支成立，且分支集合在运行前不可枚举** | **主管模式** | 见 §3.4——它有额外的准入代价 |
| 多条同时成立 | 各自最小结构的并，**不是三大拓扑之一** | 各自的必带项全都要带 |

**最后一行是本节的重点**：真实系统的形状通常不等于任何一个有名字的拓扑。**遇到算出来的形状不在 §3.3 表内，按本节判据判，判不出记未定并升级，不得硬塞进最近的一项。**

### 3.3 样例表（**这是样例，不是清单**）

下表逐字取自卡 07 §2.1（S1 二手，该来源如此主张），本文**只作样例引用，不作论据，也不要求任何项目维护它的副本**（§1.9 已给出它的可删性）。

| 该来源给的模式名 | 该来源给的机制 | **本文的对应**：它是哪些触发的最小结构 |
|---|---|---|
| 提示链 Prompt Chaining | 分解为固定步骤链 | 分支不成立、并行不成立时的**默认线性形态**——它其实是"没有触发成立"的样子 |
| 路由 Routing | 输入分类与分发 | §1.2 分支，且分支集合**可枚举** |
| 并行 Parallelization | 独立分支同步执行 | §1.3 并行（墙钟约束）或 §1.7 并发探索（需冻结标准），两者判法不同，不可混 |
| 主管-工作者 Orchestrator | 动态拆解与汇总 | §1.2 分支 **且分支集合不可枚举**，见 §3.4 |
| 评估-优化 Evaluator-Optimizer | 生成与打分循环迭代 | §4.1 的验证器分离在有冻结标准时的形态；**它是红线一的实现，不是一个可选模式** |
| （该来源的三大拓扑）扇出扇入 / 主管 / 流水线 | — | 分别对应本表第 3、4、1 行，不另立 |

**该来源的核心原则逐字**："先找最简单的方案，只在真正需要时才增加复杂度。拒绝过度设计。"——这与[21 §2 P3](../21-调度与拆分.md#complexity-ladder)同向；本文的 §1 就是把这句话变成可判定的形态，**但立场取自 21-P3，不取自该表**。

### 3.4 主管模式的额外准入代价

主管模式是唯一让**模型在运行时产生控制流**的形态。卡 07 自己写了它的代价（逐字，指 ReAct）："全场临场发挥，控制流全包在模型对话中。极度灵活，但**难复现、难审计、易失控**。"

本文据此给它一道额外的门（不引该句为论据，只作提醒；下面三条各有仓库内依据）：

1. **分派表必须可枚举，否则它是一次授权而不是一次调度**——见 §4.4 的分界判据。
2. **主管的输出必须是结构化裁定，不是自由文本**（[21 §2 P7](../21-调度与拆分.md#complexity-ladder)、[25 §2 P2](../25-执行者与模型.md)）：边按裁定的字段做确定性分派，不解析主管的叙述。
3. **主管每一跳的选择须可复算**：给定同一份状态与同一份分派表，能重算出它选了谁；算不出即该次运行的轨迹不构成[32 §2 P6](../32-证据与追踪.md#evidence-package)要求的调用树（"只有事件流而没有父子与配对关系的记录不构成轨迹"）。

**三条任一不满足 → 不用主管模式，退回可枚举的路由。**

## 4. 四条工程红线

四条各自的结构是一样的：**语义在正文哪一条 → 最小落法 → 怎么他证它真的在生效 → 判不出时怎么办。** 第三栏是本节的重点，因为本仓库最痛的教训是"写着但从没被执行过"（[04 §1](04-接入与验收清单.md)）。

<a id="redline-1"></a>

### 4.1 红线一 · 禁止自证：同一执行者不得规划 + 执行 + 审查

#### 语义已有

【已有】[30 §2 P5](../30-验证与测试.md#verification-layers)逐字："验证在独立上下文或独立模型中进行，**只挂载产出物与验收标准，不读生产者的推理与自述**；结果记录双方身份，**相同即判未定**"，且明写"结构性分离不因模型变强而取消"。
【已有】[30 §2 P1](../30-验证与测试.md#verification-layers)把"生成者与验证者同一"列为未定的四个子原因之一。
【已有】[21 §2 P8](../21-调度与拆分.md#complexity-ladder)："验证者分离是默认允许的拆分，其余拆分须举证。"——**这也是唯一一刀不需要走 §1 准入的拆分。**
【已有】[12 §2 P7](../12-记忆与知识治理.md#memory-retrieval)：权威验证只返回不可逆推的结果。

#### 独立验证器的最小落法

验证器节点的合同按 [25 §2 P1](../25-执行者与模型.md)的六件写：

```
节点：verifier
输入：产物（按引用回源，不含生产者的推理与自述）+ 冻结的验收条目 ID 集合 + 判据
非目标：不改产物、不给修复方案、不读生产者上下文
精确事实入口：ACCEPTANCE.md#<条目 ID>、产物的持久位置
权限：只读；无写权限，无外部动作权限
输出格式：结构化三态裁定（25-P2 字段：产物、三态及子原因、判断依据与定位、
          来源或观察、已验证与未验证项、置信度、风险与依赖），缺字段即拒收
验收：裁定字段完备，且"覆盖了什么 / 没覆盖什么"（30-P2 盲区）非空
准入依据：21-P8（默认允许的拆分，无需 §1 举证）
上下文来源清单：<见下，这是他证的落点>
```

#### 三种验证组织：适用条件与代价

卡 07 给了三种（对抗式 / 多视角 / 评委制）。本文按仓库口径给每种写**准入条件**与**已知失效形态**——**准入条件不满足就不用那一种**，不是"三选一看喜好"。

| 组织 | 适用条件（不满足即不用） | 代价 | 已知失效形态与它的仓库依据 |
|---|---|---|---|
| **对抗式**（多路并行驳斥，少数服从多数） | **必须能写出每一路的盲区，且两两不同。** 写不出 → 不用这一种 | N 倍推理成本；N 份裁定要合并 | 盲区不独立时"并列审查只是重复同一次判断"（[30 §2 P2](../30-验证与测试.md#verification-layers)逐字）。多数票在这种情况下是同一次错误投了 N 遍 |
| **多视角**（正确性 / 安全性 / 复现性分离） | 判据可按维度切开，**且每个维度有各自的确定性检查或独立标准** | 最低——每一路都可以是程序，不必是模型 | 维度之间的空隙无人负责。处置：**必须显式声明"没有任何一路覆盖什么"**（[30 §2 P2](../30-验证与测试.md#verification-layers)：盲区随裁定一起交出，不由下游猜测） |
| **评委制**（多方案并行计分择优并吸收次优） | **存在在打分之前就已冻结的评价标准**（[10 意图与验收](../10-意图与验收.md)冻结 + [03 §4](03-通用落地套件.md) 的 `eval/` 三分区，且筛选与最终验证类不得被会修改 harness 的执行者读取） | 需要评估集治理；评委本身要校准（[33 §2 P10](../33-评估与演进.md#metrics-candidates)） | ① 评委是候选方案的生成者之一 → 自证；② 标准在打分之后被调整 → 用冻结时间机械核对；③ "吸收次优项"这一步由谁做——若由评委做，评委就成了生产者，下一轮它在评自己 |

**三种都不能替代"生产者与验证者身份不同"这条最低要求**：它们是分离之后**怎么组织验证**的三种形态，不是分离的替代品。

#### **"全新上下文"这一半怎么他证**（本节最重点）

先给可判定的门槛，因为"全新"是个形容词，形容词不可判定：

> **门槛**：`来源(验证节点窗口) ∩ 来源(生产节点窗口) ⊆ {产物, 冻结的验收标准, 项目级静态指令}`，此外为空。

**三种他证形态（并列，不得只给一种——[09 §6](../09-跨工具通用性.md#detection-hints)）**：

- **(a) 环境侧清单比对（最强，但多数工具上不可得）**：执行环境为每次调用输出一份**不可由执行者改写**的"本次窗口内容来源清单"，工作流读取两份清单做机械交集。**判定完全客观。**
  → **可得性判未定**：绝大多数 harness 不产生这个值。这与 [04 §8](04-接入与验收清单.md) 指出的"最可能落不了地的一步"是同一个缺口（"这份文件被加载进了上下文"这件事，绝大多数工具不写日志、不写事件、也不暴露给工作流）。
- **(b) 注入探针（可得，但只证伪不证明）**：在生产节点的上下文里放一个**只在那里出现的可识别串**（不影响产物，例如一个随机 token 写在生产者的任务描述里）。若验证器的输出或轨迹中出现该串 → **分离失败，确证**。
  → **这是一个可重复运行的"应被拦截"回归 Case**（[31 §2 P9](../31-守卫与权限边界.md)）。
  → **必须写清它的边界：没出现 ≠ 没继承。** 探针只覆盖"整串被原样带过去"这一种泄漏形态；生产者把自己的推理**改写成摘要**再喂给验证器，探针照不出来。因此 (b) 单独使用时，结论是"未发现分离失败"，**不是"分离成立"**。
- **(c) 人工清点（可得，成本在人）**：由第三方在验证器开始前清点它被喂了什么，按[40 §2 P4](../40-人的检查点与授权.md)的呈现顺序呈现（待裁决项与证据在前，全文作附录）。**清点者不能是生产者，也不能是验证器的设计者。**

**不算他证的**（承 [04 §2.1](04-接入与验收清单.md)）：验证器自己声明"我在干净上下文里跑"；主执行者声明"我没把历史给它"；一次"看起来结论不一样所以应该是独立的"。依据 [31 §2 P9](../31-守卫与权限边界.md)逐字："**机制是否生效以运行时观察为准，不以执行者自报为准**。"

**本仓库自己的读数（为什么这条要写死）**：[C-025](../失败Case清单.md)——本仓库里生产与验证是同一方，而**六份审计记录中 0 处标未定**。**身份这一半（最容易判的那一半）都常年没被执行**，上下文那一半更没有对象。

#### 新增一条

**【新增 N2】验证者与生产者的分离须同时核对两件事：身份不同，且上下文来源集合的交集不超出 {产物, 冻结的验收标准, 项目级静态指令}。**

｜防的失败：两个不同身份的执行者共享同一份历史——最常见的形态是主执行者把自己的推理摘要当作"背景"喂给验证器，或验证器在同一会话内被"换个提示词"当成新执行者。此时[30 §2 P5](../30-验证与测试.md#verification-layers)的身份检查通过、[32 §2 P2](../32-证据与追踪.md#evidence-package)的双方身份字段也填得出，**结构性分离在形式上满足、实质上落空**，而现有条文没有任何一处会发现它。
｜删除条件：当执行环境能为每次调用输出不可由执行者改写的"窗口内容来源清单"、且工作流可读取并机械比对两份清单时，本条的人工核对与探针形态可删；**"两份清单的交集须落在门槛内"这一要求不删**。
｜可以删掉现有的什么：**无。** 理由：身份判据与上下文判据**互不蕴含**——同一身份可以换一个干净窗口（身份相同但上下文不同），不同身份可以共享历史（身份不同但上下文相同）。删掉任何一条，另一条都覆盖不了它。

**两种机制类型的落法**：**运行时拦截**（委托前由钩子剥离生产者的推理与自述，剥离失败即拒绝派发）/ **检查器**（对每次验证的两份来源清单做交集扫描，超门槛即 FAIL；清单不可得时该次裁定记未定）。

#### 判不出时

**该次验证的裁定记未定**，子原因取[30 §2 P1](../30-验证与测试.md#verification-layers)的"生成者与验证者同一"，**不得折算为通过**。含未定层的完成判定为未定，必须停止并报告。

### 4.2 红线二 · 确定性边界：模型判断落节点，代码可靠性落边

#### 语义已有

【已有】[24 §2 P4](../24-工具与执行环境.md#aci)：确定性判断先由程序做，模型只补判残余，且**不得推翻程序已判的项**（该半句标为责任结构型，不删）。
【已有】[21 §2 P7](../21-调度与拆分.md#complexity-ladder)：上游只消费结构化三态裁定，**不解析自由文本**。
【已有】[31 §2 P2](../31-守卫与权限边界.md)：阻断判据必须是可直接观察的确定事实，代理指标只能提醒。
【已有】[25 §2 P2](../25-执行者与模型.md)：子执行者只回结构化裁定，缺字段即拒收。

#### "判断落节点、可靠性落边"在本仓库口径下的准确表达

**不是"边上不许有模型"**——那是错的，一次意图分类本来就是模糊判断。准确的表达是：

> **边的分派函数必须是确定性的；模型只提供它的输入。**

即：模型节点输出一份结构化裁定（字段固定），边读裁定的**字段**做分派。**不允许"模型自己说下一步调用谁"这种形态**，因为那样分派不可复算（§3.4 第 3 条）。

#### 【新增】"哪些事绝不能交给模型节点"的**上位判据**

现有正文给了若干条散落的禁止（授权只能由人产生、确定性问题下沉程序、阻断判据须是确定事实……），但没有一条上位判据能判"表里没有的那件事"。本文补一条：

**【新增 N3】凡其错误不存在一个"不依赖该判断本身"的确定性发现路径的判断，不得由模型节点单独承担。**

判定动作只有一步，可机械执行：对任一交给模型节点的判断，问"**它错了，哪一处会变红**"。指不出那一处，或指出的那一处的输入本身就是这个判断的输出 → 不得单独交给它，须配一个独立的确定性消费者或人工检查点。

｜防的失败：一个模型节点的输出既不被任何回读检验、也不被任何检查器覆盖——它错了，系统没有任何位置会变红。这是[04 §1](04-接入与验收清单.md)记录的"写着但从没被执行过"在图上的对应形态：**结构存在，信号不存在**（[C-021](../失败Case清单.md) 的同型）。
｜删除条件：当载体不允许保存"无独立消费者的模型节点"（保存时强制绑定至少一个确定性消费者）时，本条可删——载体已保证。
｜可以删掉现有的什么：**可删项目侧"哪些动作不许交给模型"的枚举清单。** 按 [09 §5](../09-跨工具通用性.md#feasibility-test)（判据优先于枚举），有了上位判据，清单只是样例；维护一份封闭清单反而会让清单外的新动作被硬塞进最近一项。

**按这条判据算出来的样例**（**样例，不是清单**；不在表内的按判据判）：

| 样例 | 为什么它满足"无独立发现路径" | 已有依据 |
|---|---|---|
| 产生或改变授权 | 授权的正确性没有外部对象可回读；错了只有事后才知道 | [40 §2 P5](../40-人的检查点与授权.md)：不可逆动作的授权只能由人产生，经模型不可写入的通道传递 |
| 计数、比较、去重、格式校验、权限判定 | 同输入同输出且规则可完整表达——它根本不需要模型 | [24 §2 P4](../24-工具与执行环境.md#aci) |
| 判定"本次运行的停止条件是否已满足" | 判断者同时是被判断者 | [21 §2 P5](../21-调度与拆分.md#complexity-ladder)上限型停机由人设定；[30 §2 P1](../30-验证与测试.md#verification-layers)谁有权宣告通过 |
| 判定"这条外部锚点算不算数" | 锚点是模型判断的**校验源**，让模型判它等于取消校验 | [32 §2 P1](../32-证据与追踪.md#evidence-package)：工具副作用由系统直接观察或由工具声明，**不由模型转述** |
| 汇合处判定"是不是全都收到了" | 缺失的那一路正是模型看不到的那一路 | [21 §2 P10](../21-调度与拆分.md#complexity-ladder)：汇合必须显式报告预期、实收与缺失 |

#### 他证探测

- **检查器**：扫描图定义，凡"下一步"字段的取值由模型的自由文本产生（而非取自裁定的枚举字段）的边，一律 FAIL。
- **权限与隔离配置**：模型节点的执行身份**不具备**调用调度接口的能力（机制类型清单"权限"维度第 ⑤ 项：执行身份本身不具备该类权限）。**这一种比检查器强，因为它不可被文档漂移绕开。**
- **空转探测**：某条确定性边的分派结果长期恒为同一个值 → 它可能是一条恒为通过的边，做一次反例注入（构造一个应走另一条路的输入，看它真的走了）。依据 [04 §2.3](04-接入与验收清单.md) 的"恒为通过"形状与 [C-006](../失败Case清单.md)。

#### 判不出时

某个判断说不清它错了哪里会变红 → **该判断不进图**，先补发现路径，或把它交回人工检查点（[40 §2 P3](../40-人的检查点与授权.md)四类问题）。**不得以"暂时先这样"放进去**——它一旦放进去，就是一段没有任何信号的结构。

### 4.3 红线三 · 现实锚点：每条闭环至少接一个外部事实回读

#### 语义已有

【已有】不变量四"**事实来自回读**"（[架构确定 §5.3](../架构确定.md#invariants)）。
【已有】[24 §2 P5](../24-工具与执行环境.md#aci)：执行通道的即时输出只说明动作曾被发起；带任务标识的完成标记或目标状态出现预期变化才是观察。
【已有】[32 §2 P1](../32-证据与追踪.md#evidence-package)：五个概念不可互换；工具副作用由系统直接观察或由工具声明，**不由模型转述**。
【已有】[30 §2 P4](../30-验证与测试.md#verification-layers)：每个改动项要回答"怎么看到它生效"，派生不出可观察终点的直接判未定。

卡 07 的那句"无现实检验的系统只是更有组织的幻觉工厂"与上面同向，**措辞更硬**。本文不引它为论据，但接受它提出的问题：**这句话本身需要一个可执行的检验，否则它也只是一句更有组织的口号。** 下面给的就是那个检验。

#### 锚点的判据（先判它是不是锚点）

> 一个值是本闭环的现实锚点，当且仅当：**它的产生不经过本闭环内任何模型节点**，且它指向本闭环之外的一个可重新读取的状态。

按这条判据，以下**不是**锚点：模型说"测试通过了"；主执行者转述子执行者的返回；一份由本闭环生成的报告；一次"命令返回了 0"而没有回读目标状态（[24 §2 P5](../24-工具与执行环境.md#aci)）。

#### **"这条锚点是真的吗"的四种探测**（本节重点）

这四条要一起做；少任一条，"更有组织的幻觉工厂"这句话在这个项目上就是成立的。

**探测一 · 反向注入（回答"它会不会变红"）**
故意制造一个本该让锚点变红的状态——删掉一个断言、改一个返回值、写一条必然失败的数据——观察闭环是否变红。**不变红 → 该锚点是装饰。**
依据：[30 §2 P7](../30-验证与测试.md#verification-layers)（判分器、验证脚本与检查器自身是被验证对象）按 [D-055](../决策日志.md#decision-index) 判据优先于枚举外推到锚点——**锚点产生判定信号，因此它自身是被判定对象**；操作形态承 [04 §2.3](04-接入与验收清单.md) 的反例测试与 [04 §4](04-接入与验收清单.md) H2 的反例注入。
**安全提示（必须写）**：注入会改文件。[C-012](../失败Case清单.md) 的教训是注入脚本写成先截断再读，**三个文件被清空**（靠备份逐字节复原）。**注入前先备份，注入后先断言待替换串确实变了。**

**探测二 · 执行计数（回答"它最近跑过吗"）**
锚点的"最后一次实际执行时间"必须是一个**被写入的状态字段**，而不是一个可以推断的属性。超过项目声明的窗口未执行 → 该锚点的结论**记未定，不得沿用上次结果**。
依据：[04 §2.3](04-接入与验收清单.md) 第三种形状（"从没被跑过"最难探测，因为它不产生任何输出）；本仓库样本 [C-021](../失败Case清单.md)：`archify visual-check` 自成图起一直 fail 而**从没被跑过一次**。

**探测三 · 来源核对（回答"这个值是谁产生的"）**
按上面的判据核对锚点的产生方。若产生方在本闭环内且是模型 → 它不是锚点，是转述（[32 §2 P1](../32-证据与追踪.md#evidence-package)）。
**这一条可机械扫**：锚点字段的 `产生方` 必填，取值域是 `外部系统 | 确定性程序 | 人`；取值为 `模型` 或为空的，该锚点作废。

**探测四 · 空集合（回答"它覆盖了几个对象"）**
锚点覆盖的对象集合为空时**判未定而非通过**。"全部测试通过"在零测试时不是通过。
依据：[D-014 空集合条款](../08-规范效力元治理.md#empty-set)逐字——"任何形如“全部 X 通过”、“适用的 X 均满足”的条件，当**生效 X 集合为空**时，判定结果是 `UNDETERMINED`，不是 `PASS`。"

#### 落法（两种机制类型）

- **检查器**：图定义里每条闭环必须有 ≥1 个 `anchor` 条目，字段为 `产生方 / 读取方式 / 覆盖对象集合 / 最后执行时间 / 最近一次反向注入的时间与结果`；任一字段为空即 FAIL。
- **外部状态存储**：锚点的每次读取写一条只追加事件（[32 §2 P7](../32-证据与追踪.md#evidence-package)：权威的是本地只追加的原始记录），"最后执行时间"由查询得出而不是由执行者填写（[20 §2 P5](../20-状态工件.md#state-artifacts)：状态由工件事件派生，优先于执行者自报）。

#### 判不出时

拿不到任何外部回读（例如闭环的产物是一份文档，没有可回读的外部状态）→ **该闭环的完成判定记未定**，并按[40 §2 P3](../40-人的检查点与授权.md)上交给人：这属于"范围边界"类问题。**不得用"由模型复核一遍"顶替锚点**——那是把校验源换成被校验者。

### 4.4 红线四 · 工作图 / 角色图隔离

#### 语义已有

【已有】[31 §2 P6](../31-守卫与权限边界.md)：权限边界的维度在**创建时固化，执行中只能收窄**，有效能力沿请求链路单调收窄且至少在两个不同位置检查。
【已有】[31 §2 P8](../31-守卫与权限边界.md)：危险动作清单与工具实现分离、按环境配置、**版本化慢变，模型在会话内不可修改**；授权标记只能由人侧通道写入。
【已有】[31 §2 P7](../31-守卫与权限边界.md)：被委托者的权限严格是委托者的子集；不可逆动作的权限不随委托传递。
【已有】[40 §2 P6](../40-人的检查点与授权.md)：预批准动作集由具名责任人事先枚举并批准，变更是慢变、可审计的授权变更。
【已有】[12 §2 P3](../12-记忆与知识治理.md#memory-retrieval)：全局规则、安全与权限边界、评估集、回滚决策、冷启动种子**必经人审**。
【已有】[02 §4.3](02-记忆管理落地设计.md)：控制流不得来自记忆内容——**同族但更窄**，那一条管的是记忆，这一条管的是调度。

**所以"角色图必须预定义、强约束、可审计，禁止模型现场生成"这句话，在本仓库是已有条文的合取。** 缺的不是这句话，是**分界判据**：在一个允许模型现场调度的系统里，怎么判定某个"调度决定"其实已经越到了角色图那一侧。

#### 【新增】分界判据

**【新增 N4】一次决定属于角色图（必须预定义、不得由模型现场产生），当且仅当它的候选结果集合中存在两个选项，其有效权限面不相等。否则属工作图。**

判定动作可机械执行：把这次决定的候选结果逐个列出，对每个算出 `perm(选项)`（维度取 [31 §2 P6](../31-守卫与权限边界.md) 的六项）。**只要有两个不相等 → 这一步是一次授权，不是一次调度。**

｜防的失败：主管节点在运行时"灵活分配工作"，把一个任务分给了权限面更大的执行者，从而在**没有任何授权动作发生**的情况下扩大了本次运行的有效权限面。[31 §2 P6](../31-守卫与权限边界.md)的"单调收窄"在形式上没有被违反——**没有人改权限配置，改的是"选谁"**；[31 §2 P8](../31-守卫与权限边界.md)的"模型不可修改危险动作清单"同样没有被违反——模型没碰清单，它碰的是分派。现有条文全部通过，权限面照样长大了。
｜删除条件：当每个执行者的有效权限由**任务**而不是由**执行者身份**决定（即任何调度选择都不改变权限面）时，本条可删——分界消失了。
｜可以删掉现有的什么：**无。** 理由：[31 §2 P6/P7](../31-守卫与权限边界.md)约束的是"权限**怎么**变化"，本条约束的是"**什么算**一次权限变化"。前者不蕴含后者：一个从不修改权限配置的系统，可以通过选择执行者把权限面变大，而前者一次都不报。两条都必须在。

**推论**：主管模式下的"分给谁"，若各候选执行者权限面不等，则该步必须走**可枚举的分派表 + 人批准**（[40 §2 P6](../40-人的检查点与授权.md)的预批准动作集形态），不得由模型现场产生。**这就是 §3.4 第 1 条的来源。**

#### 越线探测（三种，他证）

| 探测 | 怎么做 | 依据 | 探测的产出方 |
|---|---|---|---|
| **权限面单调性检查** | 每次调度之后重算本次运行的有效权限并集，与**运行创建时固化的上限**比对；超出即拒绝并留痕 | [31 §2 P6](../31-守卫与权限边界.md)（创建时冻结一次，工具或目标侧再复核一次——**两处**） | 执行环境，非执行者 |
| **角色图指纹比对** | 角色图是慢变可审计工件；运行开始与结束各取一次内容指纹，不一致即报 | [31 §2 P8](../31-守卫与权限边界.md)（模型在会话内不可修改） | 检查器 |
| **应被拒绝的分派回归集** | 保留一组"应被拒绝的分派请求"，角色图每次变更后重跑；有一条被放行即 FAIL | [31 §2 P9](../31-守卫与权限边界.md)（拦截层须有独立于自身的失效探测，保留可重复运行的"应被拦截"回归 Case） | 检查器 + 回归集，回归集由人维护 |

**空转信号**：回归集长期恒为全部拒绝且从未因一次真实变更而被更新 → 它可能已不覆盖当前的分派面，做一次覆盖面审计（列出它的扫描面与"本该覆盖的对象全集"对账，差集 > 0 即报——[04 §2.3](04-接入与验收清单.md) 的"恒不覆盖"形状，样本 [C-022](../失败Case清单.md)）。

#### 判不出时

某次分派算不出各候选的权限面（例如权限维度没有登记）→ **按未知默认关闭**（[31 §2 P5](../31-守卫与权限边界.md)：未登记或未分类的动作默认进入确认档或拒绝，不得"无匹配即放行"），并把"权限维度未登记"作为一处阻塞升级。

### 4.5 四条红线的失效探测总表

**每条探测都写了"产出这个信号的是谁"** —— 承 [04 §6.2](04-接入与验收清单.md)：产出信号的是被探测方，就换一条。

| 红线 | 它失效时的样子 | 他证探测（一句话） | 信号产出方 | 判不出时 |
|---|---|---|---|---|
| **一 · 禁止自证** | 两个不同名字的执行者共享同一份历史，身份检查照样通过 | 两份"窗口内容来源清单"取交集，超门槛即 FAIL；清单不可得时退化为注入探针（**只证伪**）或第三方清点 | 执行环境 / 检查器 / 第三方人 | 该次裁定记未定，子原因"生成者与验证者同一" |
| **二 · 确定性边界** | 某个模型判断错了，系统没有任何位置会变红 | 对每个模型节点问"它错了哪一处会变红"，指不出即 FAIL；再扫"下一步字段由自由文本产生"的边 | 检查器 + 权限配置（模型身份不具备调度能力） | 该判断不进图，退回人工检查点 |
| **三 · 现实锚点** | 锚点恒为绿，因为它根本不检查（[C-006](../失败Case清单.md) 的形状） | **反向注入一次，看到红**；外加最后执行时间、产生方、覆盖集合非空三项 | 注入者（非锚点维护者）+ 只追加事件日志 | 该闭环完成判定记未定，上交人裁决 |
| **四 · 工作图/角色图** | 没人改权限配置，但"选谁"把权限面选大了 | 每次调度后重算有效权限并集与创建时上限比对；角色图指纹比对；应被拒绝的分派回归集 | 执行环境 + 检查器 | 未知默认关闭，登记阻塞 |

## 5. L0–L3 四档：这一档的图长什么样

**这四档不是"图的四种复杂度"，是 §1 准入判据在四种规模下算出来的结果。** 承 [00 §7](../00-总览.md)：四档是同一套部件在不同规模下的形态，升级的唯一条件是上一档的验证能力跟得上。

**本文不给任何档新建文件。** 03 的四档文件表不动；本文只追加**字段**（标【字段级】，由项目自行采纳，不占正文预算）。**如果 L0 就需要新建文件或需要建图，说明 §1 的判据写错了**——这是本节对 §1 的一个自检。

### 5.1 L0 · 一人一工具：**不建图**

**图长什么样**：一条线，三个框，没有分叉、没有汇合、没有主管。餐巾纸上画得下：

```
[ 做 ] ──→ [ 锚点回读 ] ──→ [ 干净会话复核 ]
```

第二个框来自红线三，第三个框来自红线一——**它们不是"图"，是两条红线在最低档的最小形态**。[30 §3](../30-验证与测试.md#verification-layers) L0 档逐字已经写了第三个框："**关键结论换一个干净会话复核一次**。"

**为什么 L0 一定不建图**：按 §1.0，L0 的合法停止点表去重后通常只有一行；即便有两行，§1.2–§1.8 的七条触发在 L0 几乎都判不成立（无并行——只有一个人；无异构权限面——只有一套权限；无中途异步审批——人就在场）。

**需要哪几个文件**：[03 §2](03-通用落地套件.md) 的 L0 最小集不变——`CONTEXT.md`、`ACCEPTANCE.md`、`WORK.md` 三个无条件必需，`PLAYBOOK.md` + `FAILURES.md` 成对条件必需。

**追加的字段**（【字段级】）：

```
ACCEPTANCE.md 的每个条目追加一行：
- 锚点：<这一条的外部事实回读是什么；产生方 ∈ {外部系统|确定性程序|人}>

WORK.md 的状态转换记录表追加一列：
| … | 验证者 | **验证者上下文来源** | 豁免 |
（03 §7.3 已有"执行者/验证者相同 → 该行裁定判未定"；本列承接红线一的另一半）
```

**谁维护**：本人。（L0 没有第二个人，这正是 L0 最难满足红线一的原因，见下。）

**他证验收信号**：

1. **画得出，且别人照着能复述**：把本次工作画成框和线，框数 ≤ 3 且没有回边。**由另一个人照这张图复述一遍流程**，复述与实际执行不一致 → 不合格。（画不出说明它不是 L0；画得出但复述不上说明图和实际是两回事。）
2. **锚点会变红**：做一次反向注入（§4.3 探测一），看到红。**注入者不是锚点的维护者**——L0 只有一个人时，退而求其次：注入与观察之间隔一次会话重启，且注入内容事先写在纸上不凭记忆。**这是一个降级形态，须在项目里标为未定。**
3. **复核在干净会话里**：注入探针（只证伪）或第三方清点，二选一并写明选了哪种。

**空转信号**：`验证者上下文来源` 一栏长期与执行者相同；`锚点` 一行长期为空；锚点的最后执行时间超窗口。

**L0 的诚实边界**：**一个人的项目无法真正满足红线一的他证。** 三种形态里 (a) 需要环境能力、(c) 需要第三方，只剩 (b) 注入探针，而它只证伪不证明。**处置是记未定并写进项目的接入报告，不是假装满足。**

### 5.2 L1 · 一人多会话：仍然不是图，是**带恢复点的线**

**图长什么样**：同 L0 的三个框，中间多一个恢复点。**恢复点不是节点**——它是一次状态外置（[20 §3](../20-状态工件.md#session-end) L1 档："会话结束与压缩前都生成短交接"）。

**这是本文对卡 07 决策树的【修订】落点**（见 §1.4）：**跨会话状态不升级为图。**

**需要哪几个文件**：[03 §3](03-通用落地套件.md) 的 `work/handoff.md` 与 `work/artifacts/`，不变。

**追加的字段**（【字段级】）：`work/handoff.md` 追加一行 `本次未走完的边`——恢复时按它决定重放起点，而不是"从中断行继续"（[20 §2 P8](../20-状态工件.md#state-artifacts)）。

**谁维护**：上一次运行的执行方写，本人核。

**他证验收信号**：另一方（或下一次会话）**只读短交接**能答出"下一原子动作是什么、上一次为什么停"（同 [04 §3](04-接入与验收清单.md) S7）。

**空转信号**：`handoff.md` 的捕获时间长期不变而会话在继续；`本次未走完的边` 恒为空而实际上每次都没跑完。

### 5.3 L2 · 团队：第一次真的有图

**图长什么样**：扇出扇入 + **验证者与生产者分离**。

**为什么图在 L2 才第一次出现**：L2 是"另一个人"第一次存在的档位——[21 §2 P8](../21-调度与拆分.md#complexity-ladder)的验证者分离、[30 §2 P5](../30-验证与测试.md#verification-layers)的双方身份、[31 §2 P7](../31-守卫与权限边界.md)的委托子集，**在 L0/L1 都没有对象**。同时 §1.8（异构专业化）的权限面判据在 L2 第一次可能成立，因为团队里的人权限本来就不一样。

**需要哪几个文件**：[03 §4](03-通用落地套件.md) 的 L2 五件不变（`DECISIONS.md`、`SOURCES.md`、`GATES.md`、`memory/`、`eval/`），**追加两份**（这两份是图特有的，L0/L1 没有对象）：

| 文件 | 承载的最小职责 | 谁维护 |
|---|---|---|
| `graph/nodes.md` | **节点合同登记**：一节点一条，字段即 §2.1 的语义列 + `准入依据`（指回举证表的行号）+ `上下文来源清单` | 节点归属人（具名） |
| `graph/roles.md` | **角色图**：可枚举的分派表 + 每个执行者的权限面六维取值；慢变、版本化、模型不可写 | **具名的授权归属人**；空缺时按 [40 §2 P5](../40-人的检查点与授权.md) 的具名位置空缺语义，依赖它的状态转换记未定并转显式阻塞 |

**边不单独建文件**：边的闸门复用已有的 `GATES.md`（[03 §4](03-通用落地套件.md)），因为[31 §2 P4](../31-守卫与权限边界.md)的 Gate 合同字段已经覆盖边需要的东西（生效范围、触发的动作或状态转换、通过条件与判据类型、失败后的去向与屏障范围、谁能限时豁免、怎样发现误阻断）。**另建一份就是第二事实来源。**

**他证验收信号**（五条，全部要过）：

1. **每个节点/每条边指得回举证表**（§1.9）：指不回的条数 > 0 即 FAIL。
2. **合同完整性的操作化检验**：**把任一节点换成一个只按合同行事的确定性桩程序，图仍能跑通。** 跑不通 → 那个节点的合同不完整（它依赖了合同没写的东西）。依据 [25 §2 P1](../25-执行者与模型.md)逐字："换成另一个执行者甚至一个确定性程序，只要合同不变，系统行为应当不变。"**这是本文认为 L2 最有价值的一条验收信号，因为它是唯一一条能一次性检出"合同写漏"的。**
3. **权限面并集 ≤ 创建时固化的上限**（§4.4 探测一），由执行环境算，不由执行者报。
4. **每条边有失败去向**：扫描，空即 FAIL。
5. **汇合报告非恒真**：汇合处的 `缺失` 恒为 0 且 `实收` 恒等于 `预期` → 疑似恒为通过，**做一次杀分支注入**（故意让一路失败，看汇合是否报缺失）。

**空转信号**：某节点的 `triggered` 计数长期为 0；`graph/roles.md` 的指纹长期不变而执行者清单在变（说明角色图已落后于实际）；`上下文来源清单` 一栏长期为空（说明红线一的他证从没做过）。

### 5.4 L3 · 无人值守：图 + 判定器

**准入条件不是工具，是一句话**（[00 §7](../00-总览.md)、[21 §2 P3](../21-调度与拆分.md#complexity-ladder)）：**有一个不需要人在场就能拒绝坏输出的判定器，且它先于自动触发器就位。** 没有它，图画得再漂亮也上不了 L3。

**图长什么样**：L2 的形状 + **每个节点可独立重试**。卡 07 把这称为"精准容错：仅重试异常节点，保留已成功节点的产出"——本文不引它为论据，但把它变成一条**可他证的验收信号**（见下）。

**需要哪几个文件**：[03 §5](03-通用落地套件.md) 的三件不变（`policy/judges.md`、`policy/budget.md`、`ops/liveness.md`），**只追加字段**（【字段级】）：

```
policy/judges.md 每个判定器追加：
- 上下文来源清单：<红线一的他证落点；与被判定对象的生产者交集须落在门槛内>

policy/budget.md 追加：
- 每节点预算：<按节点分配，不是按运行分配；超预算的节点单独停机而不是整图停机>
- 图结构变更的授权归属：<具名；结构变更是慢变授权变更，40-P6>
```

**他证验收信号**：

1. **部分重试真的发生过**：取一段真实运行日志，重放两次，**成功节点的集合相同**且第二次没有重复执行第一次已成功的不可逆动作（[20 §2 P8](../20-状态工件.md#state-artifacts)）。
   → 这需要一份重放契约（禁随机、禁墙钟、禁框架外 I/O、禁可变全局态），它是 `policy/budget.md` 的一节，**不是新文件**（承 [03 §5](03-通用落地套件.md)）。
2. **判定器自身被判定**：[30 §2 P7](../30-验证与测试.md#verification-layers)——已知答案回归集，变更后重跑历史样本；模型判分器报告与人工判定的一致性。
3. **活性**：进行中的节点绑定可探活的执行者与最后活动时间；失去绑定即转未定或阻塞（[20 §2 P7](../20-状态工件.md#state-artifacts)）。

**空转信号（L3 最重要的一条）**：**从未发生过一次真正的部分重试——每次失败都是整图重跑。** 这说明"精准容错"这段结构从第一天起就没生效过，它是 [C-021](../失败Case清单.md) 形状在图上的直接对应。

## 6. 接入步骤与失效探测

本节只写**图特有的增量**。基础的从零 S0–S8 与从半路接手 H0–H5 在 [04 §3/§4](04-接入与验收清单.md)，不复述。

每步四栏，格式与 [04](04-接入与验收清单.md) 一致：**做什么 / 他证验收信号 / 空转信号 / 判不出时**。**写不出后两栏的步骤不算接入**（[04 §1](04-接入与验收清单.md) 的组织原则）。

### 6.1 从零：G0–G6（前置是 04 的 S0–S4 已完成）

**顺序原则**：先判该不该建（G0），再建被授权的最小结构（G1），**红线先于优化**（G3–G5 在 G6 之前）。

#### G0 · 写准入举证表

- **做什么**：按 §1.0 写合法停止点表并去重；按 §1.2–§1.8 逐条判七条触发，每条写 `判定 / 依据 / 证据位置`。判不出的写**未定**。
- **他证验收信号**：由**未参与写这张表的一方**独立复算至少一条**机械**判据（首选 §1.8 的权限面并集，它是唯一纯机械的）。复算结果不一致 → 表不合格。
- **空转信号**：举证表写完之后再没被复查过，而图结构已经变过（每次结构变更必须回来复查这张表）。
- **判不出时**：全部触发都判不出 → **不建图**，本轮接入到此结束，这是一个合法且常见的结局。

#### G1 · 只建被授权的最小结构

- **做什么**：按 §3.2 算出形状；每个节点、每条边填 `准入依据`（指回 G0 表的行号）。
- **他证验收信号**：检查器扫描，`准入依据` 为空或指向不存在行号的条数 = 0。
- **空转信号**：某个结构的 `准入依据` 指向的那条触发，在最近若干次运行里一次都没成立过。
- **判不出时**：某段结构指不回任何一行 → **删掉它**。这是 `准入依据` 字段存在的全部意义（同 [04 §3](04-接入与验收清单.md) S3 对 `why` 列的处置）。

#### G2 · 给每个节点写合同

- **做什么**：按 §2.1 与 §4.1 的骨架写 `graph/nodes.md`，六件齐全。
- **他证验收信号**：**桩程序检验**——把任一节点换成只按合同行事的确定性桩，图仍能跑通（§5.3 信号 2）。跑不通即合同不完整。
- **空转信号**：合同里的 `非目标` 与 `权限` 两栏长期为空（这两栏最容易被写成占位）。
- **判不出时**：某节点的合同写不全 → 该节点不进图，先把它合回上游节点。

#### G3 · 装验证器，并做一次分离他证（红线一）

- **做什么**：按 §4.1 装一个验证器节点；选一种验证组织（对抗式 / 多视角 / 评委制），**写下选它的准入条件是否满足**；选一种"全新上下文"他证形态并执行一次。
- **他证验收信号**：形态 (a) 两份来源清单交集在门槛内；或形态 (b) 注入探针一次，串未出现在验证器输出与轨迹中（**结论只能写"未发现分离失败"**）；或形态 (c) 第三方清点记录存在且清点人不是生产者。
- **空转信号**：验证器的裁定里 `未定` 与 `失败` 长期均为 0（它可能从没真的挑出过错——**否决率长期为零说明它已不再产生判断**，[40 §2 P2](../40-人的检查点与授权.md)）。
- **判不出时**：三种形态一种都做不了 → 该验证的裁定一律记未定，**不得折算为通过**，并把这一条写进接入报告的未定清单。

#### G4 · 接锚点，并做一次反向注入（红线三）

- **做什么**：每条闭环挂 ≥1 个锚点，填 `产生方 / 读取方式 / 覆盖对象集合 / 最后执行时间`；执行一次反向注入。
- **他证验收信号**：**注入之后看到红**。注入者不是锚点的维护者。
- **空转信号**：`最后执行时间` 超窗口；`覆盖对象集合` 为空（此时按空集合条款判未定，不判通过）。
- **判不出时**：闭环接不出任何外部回读 → 该闭环完成判定记未定，上交人裁决（范围边界类问题）。
- **安全提示**：注入前备份，注入后先断言待替换串确实变了（[C-012](../失败Case清单.md)）。

#### G5 · 固化角色图，并做一次越线注入（红线四）

- **做什么**：写 `graph/roles.md`（可枚举分派表 + 每个执行者的权限面六维）；在运行创建时固化权限上限；建"应被拒绝的分派请求"回归集。
- **他证验收信号**：**故意提交一条应被拒绝的分派，看它被拒绝并留痕**。放行 → FAIL。
- **空转信号**：回归集从未因一次真实变更而更新；角色图指纹长期不变而执行者清单在变。
- **判不出时**：算不出某候选的权限面 → 未知默认关闭（[31 §2 P5](../31-守卫与权限边界.md)），登记"权限维度未登记"为阻塞。

#### G6 · 给每个节点与每条边装消费计数，并声明降级条件

- **做什么**：每个节点/边记 `triggered` 计数与 `最后一次被走的时间`；每条准入触发写下"它不再成立时删哪一段结构"（§1.10）。
- **他证验收信号**：计数由执行环境或只追加日志产生，**不由执行者填写**（[20 §2 P5](../20-状态工件.md#state-artifacts)）。由执行者填写的计数不算数。
- **空转信号**：这一步本身就是空转探测的基础设施；**它自己的空转信号是"计数字段存在但恒为 0 或恒不更新"**。
- **判不出时**：环境拿不到计数 → 退化为定期反例注入（[04 §8](04-接入与验收清单.md) 的降级路径），**成本高、频率低、只覆盖能被机械违反的结构**，并在接入报告里标未定。

### 6.2 从半路接手：GH0–GH4（对象是一个**已经有图**的系统）

**接手与从零的根本差别在这里被放大**：一个已经在跑的多智能体系统，它的多数结构**没有准入证据**——不是因为有人偷懒，而是因为当初根本没有准入这道门。

#### GH0 · 声明运行类型：`事实型 × 接手`，出口是测绘不是变更

同 [04 §4](04-接入与验收清单.md) H0。**他证验收信号**：这次运行结束时没有产生任何结构变更；产生了 → 运行类型声明错了。

#### GH1 · 反向测绘：不问"这张图长什么样"，问"哪些部分从来没被走过"

- **做什么**：对每个节点、每条边填一行 `最后一次被走的时间 | 依据 | 判定（活 / 疑似空转 / 不可得）`。
- **他证验收信号**：每行的时间值能被第二个人独立复算；复算不出的改记"不可得"。
- **判不出时**：记"不可得"，**不推断，也不因为"它看起来很重要"就判它是活的**（同 [04 §4](04-接入与验收清单.md) H1）。
- **诚实提示**：这一步在多数系统上会大面积返回"不可得"。[04 §8](04-接入与验收清单.md) 已把这一环判为整套方案最薄的一环，本文不改那个判定。

#### GH2 · 对准入判据倒查 —— **本路径的核心价值**

- **做什么**：现有的每个节点、每条边，指回它满足 §1 的哪一条触发。**指不回的进 Thin 候选。**
- **他证验收信号**：倒查表的每一行由一个未参与该结构设计的一方复核；**分歧行数 > 0 时以"指不回"为准**（举证责任在主张它该存在的一方，§1.0）。
- **空转信号**：倒查做完之后，Thin 候选一条都没被处置（既没删也没写"判为取舍不修 + 判据"）。
- **判不出时**：三个出口选一个并记录理由（承 [04 §4](04-接入与验收清单.md) H2）：① 删掉；② 补一条真实的准入触发（并补它的证据）；③ 判为取舍不修，**但必须写下判据**。"以后再说"不是出口。

#### GH3 · 四条红线各做一次探测，**红线先于优化**

- **做什么**：按 §4.5 总表逐条探测一次。
- **他证验收信号**：四条各有一条记录在案的探测结论（通过 / 失败 / 未定），且每条注明信号产出方是谁。
- **判不出时**：任一条判未定 → **先修红线，不谈拓扑优化**。理由：红线管的是"错了会不会被发现"，优化管的是"跑得快不快"；发现能力未知时，跑得快只是错得快。

#### GH4 · 降级：能删的边先删

- **做什么**：把 GH2 的 Thin 候选与 GH1 的"疑似空转"取并集，按 §1.10 降级。
- **他证验收信号**：删除前后跑同一组代表性任务，**产物的三态裁定不变**（由不知道删了什么的一方判定）。
- **空转信号**：降级提案连续多轮只增不减（[33 §2 P9](../33-评估与演进.md#case-registry)：删除门槛低于新增；健康度不能是条目数）。
- **判不出时**：删了之后判不出有没有变差 → **保留，并登记为未定**；不得以"看起来没问题"作为删除依据，也不得以"看起来有用"作为保留依据。

### 6.3 每一步"怎么知道它真的生效了"的共同形状

承 [04 §1](04-接入与验收清单.md) 的组织原则，本节的每一步都配了两样东西，缺一不算接入：

> **一个他证的验收信号**（装的那一刻它对不对）**和一个空转信号**（三个月后它还活着吗）。

**图特有的空转形态有三种**，各配一条探测：

| 空转形态 | 它在图上的样子 | 探测 |
|---|---|---|
| **从没被走过的结构** | 某条边的 `triggered` 恒为 0 | 计数由环境产生；恒 0 且该触发在举证表里还在 → 复查举证表那一行是不是当初就判错了 |
| **恒为通过的汇合** | `缺失` 恒为 0、`实收` 恒等于 `预期` | 杀分支注入：故意让一路失败，看汇合是否报缺失（[21 §2 P10](../21-调度与拆分.md#complexity-ladder)） |
| **形式上分离、实质上共享** | 身份不同但上下文相同 | 两份来源清单取交集；不可得时退化为注入探针（只证伪）+ 第三方清点 |

## 7. 两种机制类型的落法汇总（[09 §5](../09-跨工具通用性.md#feasibility-test) 检验）

**每一项给两种机制类型不同的落法，且两种实例不同属一个工具。**

| 落地项 | 机制类型 A | 机制类型 B | 说明 |
|---|---|---|---|
| 准入举证与最小结构授权（§1.9） | **检查器**：扫 `准入依据` 字段，空或悬空即 FAIL | **人工检查点**：结构变更走慢变可审计的授权变更，无举证行不批准 | A 覆盖已有结构，B 拦住新增结构；**两者配套而非二选一**（同 [03 §7.7](03-通用落地套件.md) 的理由：只认一种形态会漏，[C-022](../失败Case清单.md)） |
| 节点合同（§2.1） | **外部状态存储**：`graph/nodes.md`，一节点一条目 | **权限与隔离配置**：合同的"权限"一件由执行身份授予，文档不承载 | B 更强（不可被文档漂移绕开），但需要身份隔离能力；无此能力的工具上只能用 A |
| 边的确定性分派（§4.2） | **检查器**：扫"下一步"字段是否取自裁定的枚举字段 | **权限与隔离配置**：模型节点的执行身份不具备调用调度接口的能力 | — |
| "全新上下文"他证（§4.1） | **运行时拦截**：委托前剥离生产者的推理与自述，剥离失败即拒绝派发 | **人工检查点**：第三方在验证器开始前清点它被喂了什么 | 第三种（环境侧来源清单比对）最强但**多数工具不可得**，见 §8 |
| 现实锚点（§4.3） | **检查器**：`anchor` 五字段任一为空即 FAIL | **外部状态存储**：每次读取写一条只追加事件，"最后执行时间"由查询得出 | B 满足 [20 §2 P5](../20-状态工件.md#state-artifacts)（不由执行者填写） |
| 角色图与越线探测（§4.4） | **权限与隔离配置**：运行创建时固化上限，两处校验 | **检查器**：角色图指纹比对 + 应被拒绝的分派回归集 | A 是拦截，B 是探测；[31 §2 P9](../31-守卫与权限边界.md)要求拦截层有独立于自身的探测，所以两者都要 |
| 节点/边消费计数（§6.1 G6） | **外部状态存储**：只追加事件日志，查询得出计数 | **运行时拦截**：宿主在每次节点调用前后发出事件 | 两者都不能是"执行者自己填" |
| 图结构的降级（§1.10） | **检查器**：零消费结构自动进入 Thin 候选队列 | **人工检查点**：定期由具名维护者处置候选队列 | [33 §2 P9](../33-评估与演进.md#case-registry)：删减须有结构性刹车，不依赖策展者自觉 |

**同属一个工具的组合不算数。** 上表 A/B 两列在任何 harness 上都至少有一列可实现；两列都不可实现的项，在该项目上按未定处理。

## 9. 本文未做的事，与最可能落不了地的一步

- **没有在任何真实的多智能体系统上跑过一次。** §1 的七条准入判据、§4 的四条红线探测、§6 的 G0–G6 与 GH0–GH4，全部是设计出来的，不是实测出来的。
- **没有给任何数量阈值**：连续多少次不成立才降级、多久未执行算超窗口、并行几路、验证几路——全部是项目参数（[21 §1](../21-调度与拆分.md#canonical-states)、[22 §1](../22-上下文装配.md#context-levels)、[23 §1](../23-方法库.md) 已声明这类取值不在本规范内）。
- **卡 07 的三处数字一处都没引为论据**（§0.1），包括那个被广泛照抄的 1000 token。
- **§1.6（上下文保护）的他证是一次盲评对照，成本可能高于它要省下的东西。** 本文对此的处置是"成本付不起就按未定、即不建图"，但**这个处置本身没有被验证过**：它可能导致一类本该隔离的场景被系统性地判为不建图。**记未定。**
- **§5.1 的 L0 无法真正满足红线一的他证**（只有一个人，(a) 需环境能力、(c) 需第三方，只剩 (b) 而它只证伪）。本文给的降级形态（隔一次会话重启 + 注入内容事先写在纸上）**是一个降级，不是一个满足**，须在项目里标未定。
- **§5.3 的"桩程序检验"没有在真实项目上做过。** 它是本文最看重的一条验收信号，但它假定图可以在不改结构的情况下替换单个节点——**在没有节点抽象的载体上这一条不可执行**，此时无替代信号，记未定。

### 最可能落不了地的一步

**是红线一形态 (a) 依赖的"窗口内容来源清单"。**

理由与 [04 §8](04-接入与验收清单.md) 判定的"最可能落不了地的一步"是同一个缺口：绝大多数 harness 不产生"这份内容进入了本次窗口"这个事实——不写日志、不写事件、也不暴露给工作流。于是：

- 形态 (a) 在多数项目上**取不到值**；
- 形态 (b) 注入探针可得，但**只证伪不证明**——它只覆盖"整串被原样带过去"这一种泄漏，生产者把推理改写成摘要再喂给验证器，探针照不出来；
- 形态 (c) 人工清点可得，但**成本在人身上**，按 [40 §2 P2](../40-人的检查点与授权.md)受判断带宽约束，做不了几次。

**因此本文对红线一他证的判定是「未定」**：在能拿到上下文来源事件的执行环境上，N2 成立且可机械执行；拿不到的环境上，**红线一退化为"身份不同 + 未发现分离失败"**——这比现状强（现状是本仓库 [C-025](../失败Case清单.md)：身份这一半都常年不执行），但**不构成"分离成立"的证明**，接入报告里必须这样写，不得写成"已满足"。
