### 1.2 更正一处：L1 append-only 不是新增

卡片 03 §5.1 第 2 行写"本规范目前**没有**这一条，建议新增"。**这是不准确的。** [32 §2 P7](../32-证据与追踪.md) 已经写了三件事：权威是本地只追加的原始记录、丢失必须显式可见、验收证据须能回读原始记录。它的删除条件是"写不出（责任结构型）"。

**卡片说对的那半句是**：现有条文写在**证据与追踪**平面，措辞的对象是"记录"与"导出通道"，而不是"记忆"。所以在记忆语境里它需要一个**指针**，不需要一条新条文。

【已有】L1 = [32 §2 P7](../32-证据与追踪.md) 的那份只追加原始记录，在记忆治理里就是"事件日志层"。**记忆治理不另建一份日志。** 另建就是第二事实来源（[11 §2 P2](../11-项目知识.md#claim-model)），也正是本仓库复发六次以上的那个病（[C-027](../失败Case清单.md) 逐字："**这是同一个病的第六次**"）。

### 1.3 三条属性作为验收条件——新增，但不进正文

The Log is the Agent 的三条属性逐字：

> "deterministic replay of any run from its log, cheap forking that branches a run at any event without re-executing the shared prefix, and end-to-end lineage from a high-level goal down to the individual model call that produced each artifact."

卡片自己划的边界必须一起记（逐字）：作者自陈 "We discuss--without claiming to demonstrate--why this substrate is unusually well suited to self-improving agents"。**这是一个架构主张，不是一个实验结论。**

【新增】但**本文判定它不进正文**，理由是仓库规矩：

- **可以删掉现有的什么：指不出。** 三条属性都是纯增量的验收信号，删不掉任何现有条文。按 [33 §2 P9](../33-评估与演进.md) Add 与 Thin 的口径，指不出可删项的 Add 是配额外的膨胀。
- **因此处置是**：登记为 **L3 档的载体验收信号**（[33 §2 P4](../33-评估与演进.md) 的"先写成功与失败标准"意义上的标准），不写成原则。L0–L2 的项目不需要它；L3 的项目在"有一个不需要人在场就能拒绝坏输出的判定器"之外，再加一句"日志可确定性重放"。
- **它的价值在于可判定性**：卡片的读数（逐字）——"它提出的三条属性（确定性重放、廉价分叉、端到端血缘）是**可判定的验收条件**，比'记忆质量更好'这类说法硬得多。"

【字段级】确定性重放的前置条件是一份**重放契约**：禁随机、禁墙钟、禁框架外 I/O、禁可变全局态（来自[卡片 02](../参考资料/15-图工程/02-系统智能层.md) 的记录）。没有这份契约，重放不 sound，"日志是真值"这句话就落空。

### 1.4 一处必须裁决的冲突：L2 的"谁写"

卡片草案写 L2 是"**agent 提议**，证据门放行"。现有 [12 §2 P4](../12-记忆与知识治理.md#memory-retrieval)写的是"**模型自身输出与推断不得成为候选**"。**两者直接冲突。**

**本文按现有正文裁决，理由有三，其中两条来自卡片自己：**

1. 卡片 §5.2 第 3 条已经拒绝"完全自主记忆管理"，理由逐字："MemGPT 自曝在 GPT-3.5 上'unable to complete'；AgeMem 需三阶段 RL 专门训练。**这条能力随模型塌缩**，把它作为规范默认值等于引入一个未申明的模型下限。"
2. 卡片 §3.5 引名单外材料记录的"Silent Failure"：弱模型下"memory becomes corrupted due to failed write operations"。**写入失败不报错，只安静地存进一条坏记录。**
3. 现有 12-P4 的删除条件是"运行类型限定 + 作用域内组织信息型，不因模型代际而过期"——它已经考虑过模型变强这一轴，且判定为不因此过期。

**裁决**：L2 的写入方是**提取器**（绑定在交付链的状态转换上），不是 agent。提取器可以由模型实现，但它的**触发**不由模型决定，它的**输入**只取人的自述或可定位的观察。这与卡片的"证据门"不矛盾——证据门是第二道，第一道是"谁有资格提议"。

【已有】不新增。本文只把这条的落地形态写清（§2.1）。

## 2. 四件现有正文缺的：谁有权写 / 什么时候写 / 怎么防污染与漂移 / 怎么淘汰

### 2.1 谁有权写：按层给一张写入权表

**这张表的组织原则来自 CaMeL（卡片 03 §3.2 答案四）逐字：**

> "CaMeL explicitly extracts the control and data flows from the (trusted) query; therefore, the untrusted data retrieved by the LLM can never impact the program flow."

**代价被明写**（该团队在 AgentDojo 上报告的观察）："solving 77% of tasks with provable security (compared to 84% with an undefended system)"。卡片的读数（逐字）：**"7 个百分点买'不可信内容永远不能影响控制流'。"**

另一条形状要求来自 MemGPT（卡片称"本卡最可直接落地的一句"），逐字：

> working context 是 "a fixed-size read/write block of unstructured text, **writeable only via MemGPT function calls**"

卡片读数（逐字）：**"记忆的可写性不是靠约定，是靠接口形状限制的。"**

| 层 | 内容 | **写入方** | 写入通道（接口形状） | 可变性 | 现有条文 |
|---|---|---|---|---|---|
| **L0 活跃上下文** | 本阶段正在用的内容 | 装配器 | 每轮重建 | 每轮弃 | [22 整章](../22-上下文装配.md) |
| **L1 事件日志** | 原始交互、工具调用与**回执原文** | **只有执行环境／harness**，只能追加 | 只有"追加"一个动作，**没有改写与删除的接口**（不是"约定不改"，是"没有改的入口"） | append-only | [32 §2 P7](../32-证据与追踪.md)【已有】 |
| **L2 事实层** | 从 L1 提取的、跨阶段仍为真的事实 | **提取器**（绑定状态转换）；模型自身输出与推断不得成为候选 | 提议 → 证据门 → 入池 → 归属人批准才成为权威 | 只能作废，不删除 | [12 §2 P2/P3/P4/P5](../12-记忆与知识治理.md#memory-retrieval)【已有】 |
| **L3 方法层（＝方法库）** | 可复用的**约束与规程** | **只有人** | 新增须带分类 + 绑定 Case + 淘汰条件，缺一不予登记 | 版本化 | [23 §2 P1/P4/P5](../23-方法库.md)【已有】 |

**支撑 L3「只有人能写」的一份新证据**（卡片 03 §4.2，Demystifying Agent Skills，仅读摘要，逐字）：

> "skills work when noisy trajectories become procedural anchors that stabilize execution."
> "Procedural anchoring accounts for 65.7% of skill cases, versus 4.5% for explicit knowledge injection, showing that skills stabilize action rather than inject missing facts."

卡片读数（逐字）：**"方法库的作用是稳住执行的形状，不是补知识、更不是替执行"** —— 而"能被 agent 自己改写的锚不是锚"。

### 2.2 什么时候写：三条触发判据

**判据 W1（已有）：写入发生在交付链的状态转换上，不发生在轮次上。**
[12 §2 P4](../12-记忆与知识治理.md#memory-retrieval) 已有。卡片给它补了一个此前没有的成本理由（LycheeMemory V2，仅读摘要，逐字）：

> "Existing memory systems typically rely on eager consolidation, invoking LLMs after each interaction to extract, summarize, or update memories. This design makes memory construction increasingly costly as conversations grow."

以及那句可以直接进落地包的总结（逐字）：

> "our results suggest that the accuracy--cost trade-off of long-term agent memory depends not only on what information is retained, but also on **the granularity at which it is consolidated**."

**判据 W2（已有）：只写"跨阶段仍为真"的东西。** 本阶段内用完即弃的留在 L0。这是 [12 §2 P1](../12-记忆与知识治理.md#operational-separation)"上下文是当次可见的工作集"的直接推论。

**判据 W3（已有）：提取器可以输出"无可沉淀"。** [12 §1](../12-记忆与知识治理.md#operational-separation) 已明写。**这一条与 [01 §3.4](01-上下文管理落地设计.md) 的"允许什么都不加载"同源**：都是"空是合法输出"，且都必须与"采集没跑起来"可区分。

### 2.3 一条被卡片当成新发现、其实已有的：语义段 vs 轮

卡片把 LycheeMemory 的"segment-level batching"当成新的工程判断。**在本规范里它已经被更强的形式表达了**：状态转换是比"语义段"更硬的边界，因为它有工件事件绑定（[20 §2 P5](../20-状态工件.md#state-artifacts)"状态由工件事件派生，优先于执行者自报"），而"语义边界检测"是一个模型判断。

【已有】不新增。**但本文取用卡片的一句作为落地时的自检**：如果一个项目发现自己在按轮写记忆，那说明它的状态转换定义得太粗——**该修的是状态机，不是记忆策略**。

### 2.4 lineage：本文的第一条真新增

【新增】**L2 的每一条记录必须绑定至少一个 L1 事件标识；绑不出的一律拒收。**

来源是 Proof-or-Stop 的口径（卡片 03 §3.6，逐字）："treats agent outputs as claims rather than lifecycle state"，以及（§4.6 逐字）"lifecycle states such as reviewed, tested, DONE, and ready-to-merge remain claims unless supported by current evidence."

卡片的平移（逐字）：**"agent 说'我记住了 X'只是一个 claim。"** 以及："拒收比写错便宜：污染进了 L2 会被后续检索反复放大，而拒收只是丢一条。"

｜**防的失败**：一条无法回指任何原始事件的"事实"进入检索池，之后每次被召回都在为自己背书，而没有任何一处可以核对它当初凭什么成立。这正是[卡片 03 §3.5](../参考资料/15-图工程/03-个体智能层与记忆.md) 记录的静默损坏的传播路径：抽取错了不会报错，只会安静地存进一条假事实。
｜**删除条件**：当载体对每条记忆记录自动绑定不可伪造的产生事件标识、且该标识可与实际事件日志机械交叉核对时，"须自行带上标识"的记录动作可删；"绑不出即拒收"写不出（责任结构型：一条无法回指证据的事实，它错了之后的后果由引用它的一方承担，而引用方没有可核对的东西——这与 [20 §2 P2](../20-状态工件.md#state-artifacts)"仅凭记录自称不算"同型）。
｜**可以删掉现有的什么**：**可删 [12 §2 P5](../12-记忆与知识治理.md#memory-retrieval) 里"来源不清"这一项的人工判断**。现文是"敏感、**来源不清**或与现有知识冲突的候选隔离，不参与默认检索"——本条成立后，"来源不清"从一个需要人判断的形容变成一个机械判定（无 lineage 即拒收，根本不进候选池），该项在 P5 里可以删掉，P5 只留"敏感"与"与现有知识冲突"两类。**净效果是 P5 变短，且它的三项里有一项从人工判断降为机械判断。**

### 2.5 context-independent：字段级形状规则

LycheeMemory V2 的 "context-independent typed memory records"（逐字）。卡片读数（逐字）：**"这是一条可机械校验的形状规则：把记录单独拿出来，读不懂就不合格。"**

【字段级】每条 L2 记录在**脱离写入时的上下文**后仍须可读：主语不得是代词、不得出现"这个/上面提到的/当前"之类的指代、不得引用未在本条内定义的缩写。

**不进正文的理由**：它是零成本的形状校验，落在载体的字段校验层即可，不占正文预算，因此不触发 Add/Thin 配额。**指不出可删项，所以也不该进正文**——这是本文对"每个新增必须能删掉点什么"这条仓库规矩的一致执行：删不掉的就别进正文，降级为字段。

## 3. 时间语义与冲突裁决

### 3.1 四个时间戳：为什么必须分成两条轴

Zep 的两条时间线（卡片 03 §3.4，读全文，逐字）：

> "Timeline represents the chronological ordering of events, and timeline T′ represents the transactional order of Zep's data ingestion."

四个时间戳的分工（逐字）：

> "t′ created and t′ expired ∈ T′ monitor when facts are created or invalidated"
> "t_valid and t_invalid ∈ T track the temporal range during which facts held true."

卡片读数（逐字）：**"'事实何时被系统知道' 与 '事实何时为真' 是两件事，必须分开存。"** 以及它解决的问题：**"漂移发生时，你能区分是'世界变了'还是'我们当时就记错了'。"**

【新增，字段级为主】L2 每条记录存四个时间戳：

| 字段 | 语义 | 谁写 | 缺失时 |
|---|---|---|---|
| `t_created` | 系统何时知道这条事实（入池时间） | 提取器，自动 | 不可缺（入池即产生） |
| `t_expired` | 系统何时把它标为作废 | 作废动作，自动 | 空表示未作废 |
| `t_valid` | 这条事实**何时开始为真** | 提取器从 L1 事件推；推不出记 `未定` | 记 `未定`，该条按弱置信登记，不得单独驱动执行 |
| `t_invalid` | 这条事实**何时不再为真** | 作废裁决写入 | 空表示据现有证据仍为真 |

**注意 `t_valid` 与 `t_created` 经常不同，且它们的差就是本项目的"发现延迟"。** 这个差本身是一个可观测量：如果一个项目的 `t_created - t_valid` 中位数在增长，说明它发现事实变化的能力在退化。**这是一条不需要任何新机制就能得到的健康度信号。**

｜**防的失败**：一条记忆过期时无法判断是"世界变了"（该更新）还是"我们当初就记错了"（该复盘提取器）。两者的处置完全不同，混在一起时两种都做不好。
｜**删除条件**：当载体对每条记录自动维护双时间轴时，"须自行填写"的动作可删；四个时间戳的**区分**写不出（责任结构型：`t_created` 是系统的账，`t_valid` 是事实的账，合并即取消了"我们记错了"这一类的可归因性）。
｜**可以删掉现有的什么**：**可删 [12 §1](../12-记忆与知识治理.md#operational-separation) 最小职责里"时效或派生源版本"中的"时效"一词**——那是一个说不清的词（是"什么时候过期"还是"什么时候写的"？），四时间戳把它拆成了两条轴，这个词失去对象。同时**可删 [32 §2 P3](../32-证据与追踪.md) 第三组"结论会随时间失效时加首次观察与最近复核时间"**中的"首次观察"（= `t_valid` 的起点）与"最近复核时间"（= 一次重新确认，属 `t_valid` 区间的再断言）——**这一处删得比较紧，须经审议**：32-P3 的对象是证据字段组，12 章的对象是记忆条目，两者是否可以共用同一组时间字段，本文判**未定**。

### 3.2 明确不采纳"新的永远赢"

Zep 的矛盾处置机制（逐字）：

> "When the system identifies temporally overlapping contradictions, it invalidates the affected edges by setting their t_invalid to the t_valid of the invalidating edge."

它的策略选择（逐字）：

> "Graphiti consistently prioritizes new information when determining edge invalidation."

卡片的判断（逐字）：**"注意第二句是一条未加论证的策略选择——'新信息永远优先'在对话记忆里合理，在工程记忆里未必（一条新的错误观察不该推翻一条经过验证的旧结论）。本规范取'作废不删除'，不取'新的永远赢'。"**

**取的那一半【已有】**：[12 §2 P5](../12-记忆与知识治理.md#memory-retrieval)"过期或零消费的条目默认退出检索但不删，被引用或被标有用时恢复"。
**不取的那一半**：本文给出替代规则，见 §3.3。

### 3.3 可操作的裁决规则：证据等级阶梯

当两条 L2 记录在同一 `t_valid` 区间内对同一主张给出不同取值时，按下列阶梯裁决。**阶梯逐级下降，第一级能判出就停。**

| 级 | 判据 | 依据 |
|---|---|---|
| **E1** | **主张类型不同的不构成冲突。** 先按 [11 §2 P1](../11-项目知识.md#claim-model) 分类：意图 / 源定义 / 部署状态 / 运行现场可以同时正确。**分类之后不同类的两条各自成立，不裁决** | [11 §2 P1](../11-项目知识.md#claim-model)【已有】 |
| **E2** | **范围不重叠的不构成冲突。** 比较各自的范围、版本、环境；不重叠即各自在自己范围内成立 | [11 §2 P1](../11-项目知识.md#claim-model)【已有】 |
| **E3** | **按 lineage 的证据类型裁决。** 顺序（高 → 低）：<br>① 对环境的直接回读（[32 §2 P1](../32-证据与追踪.md)"观察"）<br>② 指定过程的执行结果（"验证结果"）<br>③ 权威记录源的声明（"源定义"或"意图"）<br>④ 人的自述<br>⑤ 未经验证的单次观察<br>**高级别胜低级别，与新旧无关** | 卡片 §3.6 的修改（"经环境回读验证过的旧事实 > 未经验证的新观察"）+ [32 §2 P1](../32-证据与追踪.md) 的五概念【修订】 |
| **E4** | **同级别时才比时间**，`t_valid` 晚者胜，且旧者被作废而非删除（`t_invalid ← 新条的 t_valid`） | Zep 机制 + [12 §2 P5](../12-记忆与知识治理.md#memory-retrieval)【已有】 |
| **E5** | **同级别、同时间、或证据等级判不出**：**不裁决**。按 [11 §2 P1](../11-项目知识.md#claim-model) 登记为一处主张冲突，列出双方与各自的范围、版本、环境，两条都退出默认检索，进人工队列 | [11 §2 P1](../11-项目知识.md#claim-model)【已有】 |

**E5 是这套规则的承重墙。** 没有 E5，E3 就会被迫在判不出的时候硬判——那正是 [09 §5](../09-跨工具通用性.md#feasibility-test)"遇到不在枚举内的对象，按判据判定，**判不出即记未定并升级，不得硬塞进最近的一项**"要防的事。

【修订】E3 是对 [11 §2 P1](../11-项目知识.md#claim-model)"不静默挑一个"的一处**收窄**，不是推翻：现有条文要求一律登记交人，本文允许在证据类型可机械比较时自动裁决，**比不出时退回登记路径**。
｜**防的失败**：一条经过环境回读验证的结论，被一条未经验证的新观察静默覆盖（Zep 的默认策略在工程记忆里的后果）；反向地，全部冲突都交人导致人被打断到麻木（[00 §6](../00-总览.md) 已列此症状，归因 [40 人的检查点与授权](../40-人的检查点与授权.md)）。
｜**删除条件**：当证据类型的判定不再可机械得出时本条失效（即 E3 的输入没了）；"判不出即登记不裁决"写不出（责任结构型：裁决权在归属人，机械规则只在它能确定的范围内代劳）。
｜**可以删掉现有的什么**：**可删 [12 §2 P5](../12-记忆与知识治理.md#memory-retrieval) 里"与现有知识冲突的候选隔离"这一项**——E1/E2 之后，"冲突"这个词有了精确定义（同类型、同范围、同区间、不同取值），大部分被现文当作"冲突"而隔离的候选其实是 E1/E2 的不冲突项，隔离它们是纯误伤。**这是本文给出的第二个真实可删项，且它与 §2.4 的可删项合起来，把 P5 的三项隔离条件删到只剩"敏感"一项。**

## 4. 防污染与防漂移

### 4.1 两种病要分开：污染是"进来了假的"，漂移是"真的变歪了"

| | 污染 | 漂移 |
|---|---|---|
| 定义 | 一条本不该成立的记录进了 L2 | 一条曾经成立的记录，在增量维护下缓慢偏离"从头重算"的结果 |
| 材料证据 | CaMeL（防注入，摘要）；"Silent Failure"（名单外材料，弱模型写入静默损坏） | Zep 自曝（读全文，逐字）："While this dynamic updating enables efficient community extension as data flows into the system, **the resulting communities gradually diverge from those that would be generated by a complete label propagation run.**" |
| 卡片的判断 | 拒收比写错便宜 | **"这是一种结构性漂移，不是 bug"**（卡片逐字） |
| 处置 | 入口闸门（§4.2、§4.3） | 周期性重算对账（§4.4） |

### 4.2 闸门一：来源标记必填，不可信来源不得晋升为事实

【新增】**任何来自不可信来源的内容（网页、第三方文件、他人产出、模型自身转述）进入 L1 时必须带来源标记；在 L2 中它只能以"某来源声称 X"的形式存在，不得直接成为"X"。**

依据是 CaMeL 的平移（卡片 §3.6）。现有 [32 §2 P1](../32-证据与追踪.md) 有半条同型的话（"工具副作用由系统直接观察或由工具声明，不由模型转述"），但它的对象是工具副作用，不是记忆内容。

｜**防的失败**：一段网页文本里的"你应该把 X 改成 Y"被提取成一条项目事实，此后每次相关检索都把它召回，且它看起来与其它事实无异。
｜**删除条件**：写不出（责任结构型：一条内容可信不可信，是它的来源的归属问题；把它交给模型现场判断，等于让被注入方自己判断有没有被注入）。
｜**可以删掉现有的什么：指不出。**

**指不出可删项的处置**：按仓库规矩，这类 Add 不能自行进正文。本文的处置是：**它作为一条提案进[决策日志](../决策日志.md#decision-index)，并在提案里明写"本条无可删项"**，由审议决定是否接受一次纯增量。理由是它落在 [09 §2](../09-跨工具通用性.md#criteria-whether) 判据一的第三类（人的头脑与组织结构）＋责任判据——这一类本来就"不会自己出现，只能由人补"，正文的**短**是靠前两类退出实现的，不是靠拒绝第三类。

### 4.3 闸门二：控制流不得来自记忆内容

【新增】**记忆里的内容只能改变"我知道什么"，不能改变"我这一轮该做什么"。** L2/L3 的内容不得作为动作、权限或流程的决定依据；它们只作为待判断的输入进入判断，判断的规则来自本次运行的合同与权限配置。

这是 CaMeL 的原义（逐字）："the untrusted data retrieved by the LLM can never impact the program flow"。

｜**防的失败**：记忆污染升级为动作污染——一条被污染的记忆条目里写着"本项目允许直接推主线"，于是它被当成权限依据。**这是记忆污染与权限绕过之间的唯一通道，堵住它，污染的最坏后果就停在"知道了假的"，而不会变成"做了不该做的"。**
｜**删除条件**：写不出（责任结构型：权限的来源是授权，不是记忆；[31 §2 P6](../31-守卫与权限边界.md)"权限边界的维度在创建时固化，执行中只能收窄"已经定了权限的来源，本条只是禁止一条绕道）。
｜**处置：已裁，本条不落。** [D-072](../决策日志.md#decision-index) 2026-09-05 记`已拒绝`。**原写的"作为提案进决策日志，明写无可删项"由本裁定取代，"无可删项"一栏随之消。** 两条独立理由（见 [031 §3](../审计记录/031-四条待裁的整合与推荐.md)）：**程序层**——[08 §8](../08-规范效力元治理.md#conflicts) 第 1 条逐字要「两条**生效规则**」，而本文效力为零、本项记`提议`，按 [08 §1](../08-规范效力元治理.md#force-states) 表`提议`的可阻断与可授权皆为"否"，要件一不成立，冲突处置不触发，按 [08 §1](../08-规范效力元治理.md#force-states) 与 [08 §3](../08-规范效力元治理.md#unmarked-default) 处置；**实体层**——[12 §2 P5](../12-记忆与知识治理.md#memory-retrieval) 的 scope 是内容可复用性分级，[31 章](../31-守卫与权限边界.md) 的 scope 是能力面与禁止项，两者不重叠。**另记一处本节自身的缺陷**：上引 CaMeL 原文带 `untrusted` 限定词，而本节第一段把它丢了，泛化成"L2/L3 的内容"——12-P5 的置信态"由来源节点与验证证据决定"反而比本节更贴近所引那句。

### 4.4 防漂移：三条对账

| # | 对账 | 频率 | 判定 | 依据 |
|---|---|---|---|---|
| D1 | **抽取层 vs 原始层**：抽样 N 条 L2 记录，回到它 lineage 指向的 L1 事件，重新判断该记录是否仍能被推出 | 项目参数 | 推不出的条数 > 0 即报，逐条进人工队列 | 卡片 §3.5 读数（逐字）："**图层可以错，前提是原始层没丢，可以重抽。没有无损原始层的图记忆，是不可回滚的。**" |
| D2 | **增量维护 vs 从头重算**：对聚合类产物（社区、摘要、索引）周期性做一次全量重算，与增量结果比对 | 项目参数 | 差异超出项目声明的范围即判派生物过期 | Zep 自曝的结构性漂移；[11 §2 P4](../11-项目知识.md#claim-model)（派生缓存须与源机械对账）【已有】 |
| D3 | **`t_created − t_valid` 的分布**：见 §3.1 | 每次策展复查 | 中位数增长即为发现能力退化信号 | 本文提出，无外部依据，标**未定** |

**D2 是【已有】的**：[11 §2 P4](../11-项目知识.md#claim-model) 已经要求派生缓存"变更进入主线前与源机械对账、差异由人分诊"。卡片给它补的是一个**新的适用对象**：图/聚合类记忆产物也是派生缓存，同样受 P4 约束。**这条不是新增，是把已有条文的适用面写清。**

**关于图记忆本身：** 卡片 §5.2 第 8 条明确拒绝"任何'图记忆更好'的一般性断言"，理由是"Mem0 自报图变体仅高约 2 个百分点；Zep 自报 single-session-assistant 一类反而下降 17.7%/9.06%"。本落地包据此**不推荐**任何 L0–L2 项目引入图数据库形态的记忆；L3 项目引入时须按卡 05 判据 C 自带独立探测（图库的限流、抽取失败率、延迟），否则不装。

## 5. 淘汰

### 5.1 三层三种淘汰机制，不能共用一套

| 层 | 淘汰机制 | 判据 | 现有条文 |
|---|---|---|---|
| **L1** | **不淘汰，只冷归档** | 永久 | [32 §2 P7](../32-证据与追踪.md)【已有】 |
| **L2** | **使用即强化的自然沉底** | 被检索并**实际用于产出**的记录强化；长期零消费的自然退出检索但不删 | [12 §2 P5](../12-记忆与知识治理.md#memory-retrieval) + [12 §2 P6](../12-记忆与知识治理.md#memory-retrieval)【已有】 |
| **L3** | **按"被触发但未被遵守"计数** | 见 §5.3 | 【新增】 |

### 5.2 L2：公式是载体参数，不是语义

MemoryBank 的遗忘曲线（读全文，逐字）："R=e^{-t/S}"，变量逐字：R 是 "memory retention, or what fraction of the information can be retained"；t 是 "time elapsed since learning the information"；S 是 "memory strength"。强化规则逐字：

> "When a memory item is recalled during conversations, it will persist longer in memory. We increase S by 1 and reset t to 0, hence forget it with a lower probability."

卡片读数（逐字）：**"使用本身就是投票，不需要额外的判官。"** 并明确取机制不取理由——MemoryBank 给的是产品理由（"make the AI companion more natural"），本规范要遗忘是为了控制检索池规模。

**本文的判定**：`S += 1, t ← 0` 是**载体参数**，不是语义。语义已经在 [12 §2 P5](../12-记忆与知识治理.md#memory-retrieval)（"被引用或被标有用时恢复"）与 [12 §2 P6](../12-记忆与知识治理.md#memory-retrieval)（两维记账）里了。**项目可以照抄这个公式，也可以用别的衰减形态——本规范不取值。**

【字段级】L2 记录需要两个可机械维护的字段：`recall_count`（被检索并实际用于产出的次数）与 `last_recalled`。**注意"被检索"与"实际用于产出"是两件事**——这正是 [12 §2 P6](../12-记忆与知识治理.md#memory-retrieval)"指标分'到达'与'有用'两维"的字段落点，**只记到达就是反馈环缺失**（该条原文如此）。

### 5.3 L3：第三种 Thin 信号

现有 [33 §2 P9](../33-评估与演进.md) 的 Thin 信号是**长期无消费**与**频繁误伤**。

【新增】**第三种信号：被触发但未被遵守的计数。** 一条方法条目被加载进上下文（触发发生），而本次产出没有遵守它（遵从缺席），且没有被登记为一次有理由的豁免。

依据是 Skill-Use 把 Trigger 与 Compliance 分开度量的做法（卡片 §5.1 第 12 条，标注为"我的引申，需另行论证"——本文保留这个标注）。

**它与前两种不同在哪**：长期无消费的条目是"没人看"，频繁误伤的条目是"看了但拦错"，而这一种是"**看了、没拦错、但也没被照做**"。三者的处置完全不同：第一种删，第二种收窄触发条件，第三种**改写或删除**——卡片的读数（逐字）：**"一条方法总被命中却总不被遵守，说明它写得不可执行，该改或该删——不是该更用力地提醒。"**

｜**防的失败**：一条不可执行的规则被反复加载、反复不被遵守，处置却是"加重语气"，于是它既占预算又不起作用，还制造了"我们有规则"的假象。
｜**删除条件**：当"遵不遵守"不再可从产出机械判定时本信号失效（它的输入没了）；"不得以加重语气作为处置"写不出（责任结构型：[23 §2 P7](../23-方法库.md) 已有"加重语气不增加约束力"，本条是它在淘汰侧的落点）。
｜**可以删掉现有的什么**：**可删 [23 §2 P7](../23-方法库.md) 对"代际审计"的等待**。现文把强调性措辞的处置全部交给到期审计（三种触发见 [33 §2 P8](../33-评估与演进.md)），而本信号可以在日常观测里直接给出"这条不可执行"的判决，不必等代际。**净效果是 P7 的处置路径从一条（等审计）变成两条（日常信号 + 代际审计），且日常这条更快。**

**一条必须一起记的容量约束**（卡片 §3.6，Demystifying Agent Skills 报告的观察）：候选池从 5 涨到 100，实际使用精度从 29.6% 掉到 3.3%。卡片推论（逐字）：**"L3 方法库不是越全越好，检索池规模本身就是失效变量。"** 本规范[已有登记](../23-方法库.md)：单次候选输出的上限与库的规模预算为项目参数。**本文不取值，只补一句判据**：规模预算的上限应当由"单次可见候选数"倒推，而不是由"库里有多少条"正推——因为失效变量是前者。

## 6. 记忆 / 项目知识 / 代码的边界：三问判据

**给判据不给清单**（[09 §5](../09-跨工具通用性.md#feasibility-test)：判据优先于枚举）。对任何一条待安置的内容，按顺序问：

**问一：它能从代码、配置或运行环境里直接读到吗？**
能 → **留在代码里，不写。** 这是 [09 §2](../09-跨工具通用性.md#criteria-whether) 判据一，也是 [11 §2 P8](../11-项目知识.md#claim-model)"'代码里能读到就不写'是默认方向，不是禁令"。
**已知间隙（[11 §2 P8](../11-项目知识.md#claim-model) 已写）**：读取成本高到不得不缓存时可缓存，但缓存须按 [11 §2 P4](../11-项目知识.md#claim-model) 声明为缓存、绑源版本、机械对账；同一条可推断的事实**第二次**导致失败时可以写下来，但须绑删除条件。

**问二：它是"应该怎样"，还是"曾经怎样"？**

- **"应该怎样"**（意图、约定、权威定义）→ **项目知识**。它需要一个具名的权威记录源（[11 §2 P1](../11-项目知识.md#claim-model)），需要不过期（[11 §2 P5](../11-项目知识.md#claim-model)），且它的变更受同一次评审（[11 §3](../11-项目知识.md) L2 形态）。
- **"曾经怎样"**（观察、经历、试过什么失败了）→ **记忆**。它带范围、产生事件与产生时版本，被引用才强化，不被引用就沉底。

**这一刀的命名依据**来自卡片 §3.1 记录的综述口径（arXiv 2602.05665，仅读摘要，逐字三组正交二分之一）：

> "knowledge vs. experience memory"

卡片读数（逐字）：**"这一刀是名单里唯一直接对应本规范'项目知识 / 长期记忆'分离的划分。它比'情节/语义/程序性'那套心理学移植更实用，因为它问的是这条记忆的权威来源是谁，而不是它长什么样。"**

**问三：它是"下次遇到 X 应当怎么做"这种可复用的规程吗？**
是 → **方法库（L3）**，且必须能登记分类 + 绑定一个已登记的失败 Case + 淘汰条件，缺一不予登记（[23 §2 P4/P5](../23-方法库.md)）。
**注意与"记忆"的分界不在内容而在形态**：同一段经历，作为"某年某月某次运行观察到 Y"是记忆，作为"下次遇到 X 先做 Z"是方法。**前者可以自动沉淀，后者只有人能写。**

**判不出时**：记**未定**，暂放候选区，不硬塞进最近一格。候选区本身就是 [12 §1](../12-记忆与知识治理.md#operational-separation) 的最小职责之一，它存在的意义正是承接判不出的东西。

**一条反向的边界（本文认为最容易被违反的）**：[11 §2 P6](../11-项目知识.md#claim-model)"不为执行者维护与人读版本分离的第二副本"。**记忆层不得成为"给模型看的项目知识"。** 一旦某个项目开始往记忆里塞项目事实的副本，它就有了两份权威，而记忆侧那份没有归属人、不受评审、也不会过期复核。

## 8. 两种机制类型的落法（D-020 §5 检验）

| 落地项 | 机制类型 A：**外部状态存储**（仓库内纯文本） | 机制类型 B：**运行时拦截 / 检查器** | 机制类型 C（备选）：**权限与隔离配置** |
|---|---|---|---|
| L1 append-only | 仓库内 `memory/events/` 下一行一条的 JSONL；文件权限只读追加 | 检查器：对该目录做历史比对，已存在行的内容变化 > 0 即 FAIL | 文件系统 ACL / 对象存储的 WORM 桶：**没有改写接口** |
| L2 事实条目 | `memory/facts/*.md`，每条一份，front matter 放七个字段 | 检查器：`lineage` 为空、`t_valid` 为空且未标 `未定`、正文含指代词 → FAIL | 任务系统的一张自定义对象表，字段即 schema，写入走 API 且必填校验在服务端 |
| lineage 必填 | front matter `lineage: [ev-0001, ev-0007]` | 检查器：每个 lineage 值必须能在 `memory/events/` 里找到 | 数据库外键约束 |
| 四时间戳 | front matter 四个字段 | 检查器：`t_invalid` 非空时必须存在一条指向它的作废记录 | 双时序图数据库（如卡 05 记录的 Graphiti，逐字："Each fact in a context graph has a validity window: when it became true, and when (if ever) it was superseded."）。**按卡 05 判据 C，这条落法引入图库运维与抽取失败两个新失效面，须自带独立探测，否则不装** |
| 来源标记 | front matter `source_trust: trusted \| untrusted`，`untrusted` 的正文必须以"某来源声称"开头 | 检查器：`untrusted` 且正文不以声称句式开头 → FAIL | 装配器在注入时对 `untrusted` 条目自动加壳，模型看到的永远是带声称前缀的形态 |
| 控制流隔离 | 约定：记忆目录下的内容不出现在任何权限或流程配置的引用路径上 | 运行时拦截：权限判定器的输入源白名单里不含记忆目录，读到即拒 | 权限配置与记忆存储在不同的授权域，记忆域对权限域无读取权 |
| Thin 第三信号 | `PLAYBOOK.md` 每条附 `triggered` / `complied` 两个计数 | 检查器/统计器：从轨迹里数触发次数，从产出里数遵从次数，两数之差入报表 | 平台原生的规则命中与规则遵从两项统计（若平台提供，则本落法退化为一次查询） |

**同属一个工具的组合不算数。** A 列与 B 列在任意 harness 上都可实现且互不依赖；C 列在多数 harness 上需要平台支持，按 [09 §6](../09-跨工具通用性.md#detection-hints) 只作**并列探测提示**，不作必填。
