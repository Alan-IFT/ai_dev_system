# 12 记忆与知识治理

平面：知识
governed_by：D-006、D-033、D-034、D-055
用途：经验怎样成为候选、怎样被分级、怎样晋升为知识、怎样退场——记忆的准入与退出制度。

<a id="operational-separation"></a>

## 1. 最小职责与接口

- **它必须做到的**
  - 在运营上把上下文、任务状态、项目知识、长期记忆、验收证据五类分开，存放位置相同不改变治理身份。
  - 维护候选区与候选的最小身份：身份与标题、类型、状态、来源与产生事件、置信态与使用方式、适用范围、归属人、时效或派生源版本、冲突、晋升目标、待补齐项，以及生成与评估它的模型。
  - 按入池条件 × 权威性 × 影响面三维决定晋升方式，并保证晋升是一次原子完成的事务。
  - 在项目声明的状态转换子集上提取候选，不依赖人自觉；提取器可以输出"无可沉淀"。
  - 记录注入与使用，并有结构性删减机制：入必有出（机制形态与健康度口径见[33 评估与演进](33-评估与演进.md) §2 P9）。
- **从别的部件拿什么**：从[30 验证与测试](30-验证与测试.md)拿判定器结论与保留样本上的验证结果；从[32 证据与追踪](32-证据与追踪.md)拿状态转换事件、消费记录与轨迹；从[40 人的检查点与授权](40-人的检查点与授权.md)拿晋升批准与事后否决；从[11 项目知识](11-项目知识.md)拿当前权威项，用于冲突核对与确定晋升落点。
- **给别的部件什么**：给[11 项目知识](11-项目知识.md)晋升后的唯一权威项与替代关系；给[22 上下文装配](22-上下文装配.md)带置信态与使用方式的可召回条目；给[33 评估与演进](33-评估与演进.md)策展自身的失败 Case、指标与验证分歧样本；给责任平面待人审队列。
- **它自己维护什么**：候选池与其状态机（候选 → 隔离 / 影子 / 待审 → 已晋升 | 已拒绝 | 已过期 | 已归档）、置信态标注、晋升与否决记录、退场与复活记录、个人与团队记忆的归属划分。
- **未决**：判定器由谁登记、如何声明覆盖域；隐私标记升级为加载前过滤的触发条件。

<a id="memory-retrieval"></a>

## 2. 原则

- **P1 知识与记忆在运营上严格分开。** 上下文是当次可见的工作集，任务状态只对声明范围内的进度有效，项目知识经治理且有归属，长期记忆不因"被记住"而权威，验收证据只支持它声明的范围。放进同一个存储不改变这五类的治理身份。｜防的失败：摘要、旧记忆或状态书签被当成事实 ｜删除条件：写不出（责任结构型：五类的区别是治理身份——谁批准、有效范围归谁；放进同一个存储不改变归属）
- **P2 入池与权威是两个正交维度。** 进入默认可见范围由客观交付信号满足（如关联到已生效的验收或工作区）；成为权威由归属人批准。审批点在进入权威载体或默认可见范围之前，不在写入候选区之前；归档与晋升是两个动作。｜防的失败：评审通过未生效的方案被当生效事实引用；反向地，全量人审导致沉淀停滞与审核疲劳 ｜删除条件：起始档——本条自 L2 起才有对象（L0/L1 单用户没有"归属人批准"这一侧，形态见 §3）；作用域内写不出（责任结构型：入池由客观信号推进、权威由归属人批准，是两种权限的分离）
- **P3 自动晋升的允许域是"已登记判定器覆盖"且"影响面局部可撤回"。** 判定器须独立于生成者、带保留样本、声明覆盖域与归属人；自动晋升须可追溯并留事后否决入口。全局规则、安全与权限边界、评估集、回滚决策、冷启动种子必经人审。｜防的失败：模型自评"有用"的错误资产入库并被后续检索；错误的全局规则被无条件遵循 ｜删除条件：起始档——自动晋升自 L3 起才有对象（L0–L2 的晋升本来就经人审，本条无对象，形态见 §3）；作用域内的"全局规则、安全与权限边界、评估集、回滚决策、冷启动种子必经人审"写不出（责任结构型：这几类的后果不可局部撤回）；判定器覆盖域可随判定器增多而扩大
- **P4 候选由交付链的状态转换自动提取，模型自身输出与推断不得成为候选。** 提取作为评审通过、审查完成、发布生效、任务失败等既有转换的副产品发生；来源只取人的自述或可定位的观察，模型自己的产出不进候选，只进本次运行的证据与轨迹（见[32 证据与追踪](32-证据与追踪.md) §2 P1）；被排除项与理由要记录；提取器可以输出"无可沉淀"。｜防的失败：靠人主动写则不写；模型推断自我强化；有价值信号被静默丢弃且无法审计 ｜删除条件：运行类型限定——"由交付链状态转换自动提取"以事发当时可采集为前提，只对从头的交付型运行无条件成立；接手与追溯运行按成立条件降级（形式见[30 验证与测试](30-验证与测试.md) §2 P1），来源判不出时记未定并按弱置信登记，不得硬塞进最近一类（见[00 总览 §3](00-总览.md#default-scope)）；作用域内组织信息型，不因模型代际而过期
- **P5 条目携带置信态与使用方式，而不只是优先级。** 强可驱动执行，弱只提示风险，影子只助发现与背景召回、不得单独作为执行依据；敏感、来源不清或与现有知识冲突的候选隔离，不参与默认检索；偏好只影响形式不覆盖事实；召回为空须声明"无历史经验"，不得以旧个案替代新问题的排查。过期或零消费的条目默认退出检索但不删，被引用或被标有用时恢复。｜防的失败：把"相关"当"可复用"驱动错误流程；有价值的条目被一次性误杀 ｜删除条件：模型判断"是否同一问题、是否可迁移"的精度经评估稳定达标时可删分级；"偏好不覆盖事实"与复活语义为责任结构型不删
- **P6 注入即记账，指标分"到达"与"有用"两维。** 装配时留下消费记录（条目、任务、时间），输出中引用所用条目的标识，使人能分辨模型判断与团队事实；使用后记录有帮助或误导。只报到达率视为反馈环缺失。｜防的失败：无人消费的条目无法识别，库只增不减；命中率被满足而知识无用 ｜删除条件：记账部分可删于平台原生提供消费记录（能力补偿类）；"有用"一维的人工标注可删于下游结果能机械回归到条目消费；"两维不得合并为一维"写不出（责任结构型：到达率是注入方的自证，有用率是消费方的判断，合并即取消反馈环）
- **P7 权威验证只返回不可逆推的结果。** 验证者与生成者的信息隔离是结构要求，见[30 验证与测试](30-验证与测试.md) §2 P5 与第一条不变量；代理验证与权威验证的分歧要记录，分歧时先强化验证器再改候选。｜防的失败：自证偏差、对验证器过拟合、假通过入库 ｜删除条件：模型自评与独立评估在代表性集合上不再有系统偏差时可放宽隔离
- **P8 个人与团队的边界在读取前生效。** 个人偏好、原则与身份由本人确认即对本人生效、不要求外部证据，但进入项目会话时效力低于项目规则、生效决策与事实性主张；描述性经验无论归属都要证据；项目事实不复制进个人记忆；团队记忆按身份与作用域过滤后再检索，一旦被非本人发起的流程或含他人可见输出的会话读取即升级为加载前过滤。｜防的失败：个人偏好压过项目规则；他人范围的资产被流畅执行；靠模型自觉过滤而泄漏 ｜删除条件：起始档——本条自 L2 起才有对象（L0/L1 单用户无他人范围，形态见 §3）；作用域内写不出（责任结构型：可见范围的归属是授权问题，不能交给模型自觉）

<a id="coala-lens"></a>

## 3. 从 L0 到 L3

| 档 | 形态 |
|---|---|
| L0 一人一工具 | 一个候选区加自己定期过一遍；置信态靠标注；晋升就是把一句话搬进项目知识；个人与团队的边界降级为标注（L0–L1 单用户）。 |
| L1 一人多会话 | 提取绑定任务收尾与会话结束；候选带产生事件与范围；跨会话只读晋升后的条目。 |
| L2 团队 | 入池由交付事件推进、权威由归属人批准；个人与团队记忆分源挂载并按身份过滤；策展有自己的指标与复查节奏。 |
| L3 无人值守 | 只有判定器覆盖且影响面局部的条目可自动晋升；全局规则与安全边界的候选进入人工队列，并阻塞依赖它的自动路径。 |
