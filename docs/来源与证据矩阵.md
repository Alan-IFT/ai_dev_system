## 1. 研究支撑类型

| 代码 | 类型 | 能说明 | 不能直接说明 |
|---|---|---|---|
| A1 | 同行评审受控实验 | 给定模型、任务、指标下的观察 | 新模型、新任务和真实项目的普适效果 |
| A2 | 同行评审概念框架 | 分类和设计语言 | 某个实现必然更优 |
| V1 | 厂商一手工程报告/指南 | 一手实践、产品机制、失败模式 | 独立复现、跨厂商普适性、完整因果 |
| P1 | 实践者案例/访谈 | 真实问题与候选机制 | 无对照条件下的普遍效果 |
| S1 | 二手综合材料 | 概念地图和待核实主张 | 替代原始论文、官方资料或公开数据 |

### 2.3 本仓库的引用纪律（D-042，提议）

- 进入决策"原因"栏的引用须登记证据等级三态：实测报告 / 具名二手转述 / 说明性示例；说明性示例不得作为原因栏证据。
- 数字须标评价层（局部输出 / 行动路径 / 整体结果）与测量条件；概念出处与数字出处分列；口径标签（预估、n=1、价格换算、工具估算）随摘要与转载不得剥离。
- 材料入库按内容级去重（段落级相似度），同源材料只登记一次。
- 效力元信息（状态值、分向降级说明）只暴露给需要判定效力的执行路径，不进入模型的常驻指令。

`validation_status` 变为“通过”也不会自动使规范生效；仍需 D-019 的批准与发布链。

<a id="conflict-reconciliation"></a>

## 5. 表面冲突的处理

1. **Lost in the Middle 与新模型能力增强**：不预设必然失忆或必然可靠；把长度、位置、噪声和冲突纳入所选模型 eval。
2. **CoALA 架构与 Harness 删减**：删减无边际价值的文字脚手架，不等于删除权限、可恢复状态和验证；每项机制分别评估。
3. **记忆便利与知识权威**：记忆只提供线索，知识晋升需 owner/source/scope 和事务化更新。
4. **换模型再试与两次止损**：只有形成新假设、观察或对照才算新路径。

<a id="not-universal-rules"></a>

## 6. 暂不采纳为通用硬规则

- 固定文件行数、目录两层、Token 百分比、Top-K 或 TTL；
- 每次会话加载全部核心文档；
- 所有任务默认多 Agent；
- 固定周期无条件删除全部 Prompt/Skill/规则；
- 单纯换模型或改措辞视为新增证据；
- 用代码行、PR 或 Token 单独衡量价值；
- 让 AI 自动把对话晋升为权威知识；
- 任何具体阈值（打断秒数、笔记行数、上下文利用率、验证评分线、单轮增量行数、Skill 行数区间、skill 数量退化点、压缩率、入口文件行数）；
- 任何具体角色数量、分工命名、目录结构、文件名约定或具名工具产品；
- Prompt / Harness / 模型的固定影响力排序；
- 把 Prompt → Context → Harness → Loop → Graph 之类的演进序列当作必经路径或分期标准；
- 把"删除而非改写"当作跨模型代际的通用处置；
- 第三轮与第四轮材料中的全部效果数字与标题数字；
- 第四轮新增项见[输入材料 004 §5](输入材料/004-第四轮公众号文章综合记录.md#not-universal)。
