## 0. 这是什么，为什么第十一轮才有

[33 评估与演进](33-评估与演进.md) §2 **P2** 规定："Case 注册表接受两种来源……已观察的失败附轨迹，已构造的失败附风险来源，两者同等登记并注明来源类型"，其 L0 形态是"一份不分区的失败 Case 清单"。**本仓库写下这条规定十轮，从未建过这份清单。** 本文是它的第一次落地，不是新机制。

这件事有后果，而且是硬的：

- [D-021](决策日志.md#decision-index) 要求每条规则绑定它防御的**可复现失败**。没有清单，当时已记的决策绝大多数绑不出来——这就是[自指风险一](../PROJECT_STATUS.md)。
- [33 §2 P9](33-评估与演进.md) 的 Thin 信号里，"长期无消费"是删除的主要正当依据。没有清单就没有消费计数，**Thin 判据在本仓库一直不可执行**——这就是自指风险二"只能删却不知道删什么"的直接原因。

## 1. 来源与证据等级

本清单前 12 条来自第九～十一轮在本仓库上的真实运行（提交 `9acf832`、`c1793e7`、`fdcd177`、`ff75b26`、`5ab136d`），C-013 起来自第十二轮的[事实型运行](审计记录/004-接手场景事实型运行.md)。**除 C-043 与 C-047 外全部非构造**——C-043 是第一条按 [33 §2 P2](33-评估与演进.md)「已构造的失败附风险来源，两者同等登记并注明来源类型」登记的构造型条目，它的风险来源是两处现存事实、触发条件是日历时间；**C-047 是第二条，2026-09-05 立，同一形态、同一触发日期**（风险来源是检查器的 `EFFECTIVE_STATES` 判定不含时间条件与 D-057 的 expiry 格，触发条件同为日历时间）。但它们的可核性分两档，必须分开写——[自指风险三](../PROJECT_STATUS.md)登记过本规范前三轮有约 20 处转述失真，这里不能再犯：

| 等级 | 含义 | 条数 |
|---|---|---|
| **A｜仓库可复核** | 从 git 历史或当前文件即可独立复算，不依赖任何人的叙述 | 跑脚本现取 |
| **B｜仅会话记录** | 失败在同一轮内被当场修掉未进入任何提交、或承重句在 git 里零书证（C-034 立的降档先例） | 跑脚本现取 |

**B 档的存在本身是一条发现**，见 §3 第 2 条。

## 3. 从这批 Case 读出什么

**一、`提议`期内，拦住东西的全部是机械检查器，正文原则拦住 0 条——而这两个前提在 D-057 与 C-038 之后都变了。**

**2026-09-04 再补一条**：本读数里"拦住东西的全是程序"这半句也不再成立了。C-038 是本清单第一条**被非机械手段当场拦住**的——一个独立执行者只读 diff，把一条正要提交的新规则的论据拆了八处，而两项自检当时照常 PASS。**"被拦住了吗"这一列此前只有程序能填是，现在有了第二类填法。** 被当场拦住的只有极少数（编号与分档跑 [`repo_counts.py`](附录-载体实例/repo_counts.py) 现取，不在此抄）；**在 C-038 之前无一例外是程序，C-038 起不再是**。这不是因为原则写得不好——是因为它们当时全部是`提议`，没有任何执行点，按 [D-014](08-规范效力元治理.md) 的效力语义本就不阻断。**2026-09-04 更正——本读数的前半句已不成立。** 它写于第十一轮，当时 117 条全部是`提议`；D-057 让它们整套进入`试行`之后，独立核查查出**至少四次由正文原则拒绝或停止了具体改动**：① [30 §2 P1](30-验证与测试.md)「缺成立条件即记未定」→ [D-059](决策日志.md#decision-index) 记`已拒绝`、不改 33 §2 P9；② [22 §2 P2](22-上下文装配.md) → D-058 第 ② 项记`已拒绝`、22 与 09 两处都不改；③ [11 §2 P1/P2](11-项目知识.md) → D-058 第 ① 项记`已拒绝`、00 §3 那句不加；④ [33 §2 P9](33-评估与演进.md) 的删除门槛 → 第二十轮放弃删除上下文合同第 5 项。另有两条改变了做法而非阻断：33 §2 P4 使审计记录多出"开工前写下的判据"一节，30 §2 P1/P5 使结论分两类写、并促成第一次独立核查。

**注意一处口径陷阱**：这四次拦住的是**提案**不是**失败**，所以清单里没有对应行；若照 D-057 后续验证栏说的"对账「当时被拦住了吗」那一列"，会得出"仍然拦住 0 条"的错误结论。**这一列在 C-038 之前全是机械检查器，是因为它只登记失败，不登记生效。****这是 [D-008](决策日志.md#decision-index)「可确定的规则下沉到程序、测试、权限或 Gate」的第一份非构造证据**，也是 [23 §2 P1](23-方法库.md)「高风险动作靠自觉；"强制走链"只在文字里」的第一份。

**二、当场修掉的失败不留痕，于是"这条规则拦住过东西吗"永远无法回答。** B 档里按 §1 第一支收入的条目都是在同一轮内被修掉、从未进入提交的，失败稿本身在仓库里零书证（C-012 甚至一度清空了三个文件，复原后 git 里同样毫无痕迹）；按第二支「承重句在 git 里零书证」收入的条目，失败本身至少部分可从 git 复算、只是承重句不可复算，不在本读数之内（**原写"B 档 4 条都是在同一轮内被修掉、从未进入提交的，仓库里查不到它们存在过"，已被推翻**：条数写下时属实（`5ab136d` 的等级列可复算），此后随 §1 拓宽为两支（`a282e31`）而漂，第二支条目不满足本句谓语；"仓库里查不到"对 C-048 也不成立——016 在 git 里逐字保存了它的失败原句（查得到描述，查不到失败稿本身）；故删条数、把谓语收窄到第一支、把"查不到"改为"失败稿本身零书证"。哪些行属哪一支照 §1 的两支定义判：行内点名"在 git 里零书证"的属第二支，其余按第一支读。2026-09-11 核查指出）。[33 §2 P2](33-评估与演进.md) 要求"已观察的失败附轨迹"、[32 §2 P6](32-证据与追踪.md) 要求轨迹能还原调用与重试——两条在本仓库都没有实例——**但那不是欠账**：它们的删除条件都是起始档 L2（33-P2 明写"L0/L1 的形态是一份不分区的失败 Case 清单"，而本清单正是它），本仓库是 L0/L1，按 D-057 的作用域判据这两条在此不被触发。后果是 [33 §2 P9](33-评估与演进.md) 的 Thin 信号"长期无消费"**在本仓库不可执行**：不是没有消费，是从来没测过。本清单是这条链路的起点。

**三、写检查器本身出缺陷的频率高于写规则，而且缺陷形态是"能通过但不检查"。** 本仓库自写的检查（"几条"这个数取决于算不算重写与算不算 `linkcheck.py`，口径没定死，故不写数），出了 **3 处缺陷**：C7 的正则混进不可见退格符导致恒不匹配（C-006）、C10 只认裸写形态认不出链接形态（发现于反例测试）、C10 对举例误伤（C-011，发现于实际运行）。**前两处"跑一遍看到 PASS"完全察觉不到**——这直接支持 [30 §2 P1](30-验证与测试.md)：未执行不得折算为通过，而"看起来通过"和"确实执行了"是两回事。第三处是相反方向的教训：检查一旦上线就会误伤合法写法，[33 §2 P9](33-评估与演进.md) 把误伤列为 Thin 信号是对的。

**四、第一次有了非"改条文"类运行的 Case，而它们的形状不同。** C-013 与 C-014 来自一次[事实型运行](审计记录/004-接手场景事实型运行.md)，两条都不是"某条规则失守"，而是**规则之间对不上**：一条是合同的视图边界没覆盖到真实用法，一条是正文把作用域写在了 09 §4 指定的字段之外——**后半句已于 2026-09-04 由 [D-058](决策日志.md#decision-index) 第 ② 项撤回**（那句是判据说明，不是作用域声明），故这一读数现在只剩 C-013 一个样本。前 12 条几乎全是"该拦没拦住"，这两条是"规则本身互相不一致"。**这类缺陷机械检查抓不到**，只有真跑一次不同类型的运行才会撞上——这是继续攒 Case 时应当刻意换运行类型的理由。

**五、本仓库最看重的那条原则，第一次有了自己的真实样本。** [D-014 的空集合条款](08-规范效力元治理.md#empty-set)说"全部 X 通过"在 X 为空时应判 UNDETERMINED——C-012 是它的精确实例：我两次拿到空输出，两次都差点读成结论，而两次空输出的真实原因都是**采集根本没跑起来**（grep 语法错、注入脚本截断文件），与"检查失效"或"检查通过"都无关。**这条原则此前只有推理支撑，现在有观测了。**

**推论（本轮唯一的新做法，不是新规则）**：新增检查的验收不是"跑一遍 PASS"，而是四步——① 验字节（控制字符会隐身）；② 注入前断言待替换串存在；③ 反例测试确认它真报；④ 跑全仓看误伤。**任一步得到空输出即记未定，不得读作通过。** 四步写在[仓库工作须知 §2](附录-载体实例/仓库工作须知.md)。

**十、本清单自己的数量型断言，经不起复算的占相当比例——而它是全部读数的地基。**

2026-09-04 把三份活文档交给五组独立执行者重算：**139 条断言，56 条非"属实"**。

**注意口径**：这里的"非属实"把 `已过期`（写下时对）与 `不可判定`（从未被证伪）也算了进去。按 [30 §2 P1](30-验证与测试.md)「未定不得折算」，**写下时就错的是 24/139 与 23/112**；余下的 32 条与 17 条分别是 `已过期` 或 `不可判定`。（2026-09-04 diff 对抗者指出，C-038）

其中最该记住的不是任何单条错，是三件事：

1. **"本节刻意不写任何计数字面值"这句话，写在同一节的 8 个计数字面值中间**——它在写下的那一刻就被自己所在的段落证伪，而此后九轮无人发现。
2. **分工按投影切，源表无人查**（C-032）。五组查的全是本清单 §2 那张表的投影，表本身落在每一格外面；抽查两行即得两处错。**与本清单反复登记的那个病同形：每次都去查副本，不去查源。**
3. **独立核查以自家手写数为基准就会退化成对账**（C-033）。两组因此把对的判成了错的。第二十轮把教训记成"量错了口径"，**真正的教训是"不要拿自家的数当基准"**。

**处置遵循一条判据，不是逐条改数**：一个数若同时满足 (a) 是仓库当前状态的函数、(b) 有唯一可机械解析的权威载体、(c) 却出现在权威之外的散文里——就交给 [`repo_counts.py`](附录-载体实例/repo_counts.py) 导出；若口径写不死、权威在仓库之外、带相对时间锚、或数字不承重——就删掉字面量改定性表述；只有被已生效决策冻结的结构常量与对已完成事件的量度才留字面量。**脚本本轮新增了 Case 表的五个分组数导出，一次性覆盖三份文件里十余处手写投影。**

**十一、这一批待裁用的那把优先级尺，自己就有取向——所以"三路一致"不等于三次独立确认。**

**先写这一条为什么记在读数里，不记成一条 Case，判据是本文件自己的体例**：§2 那张表的每一行要填「观察到的失败」「本该防住它的规则」「当时被拦住了吗」，即**要有一个已经发生的失败事件**；而按 [33 §2 P2](33-评估与演进.md) 以**已构造**形态登记的两条（C-043、C-047）都还要有**确定的触发条件**——两条的触发条件都是日历时间，触发日期都实测得出。**本条两样都没有**：[审计 036 §4.6](审计记录/036-三条待裁的独立复验.md) 的裁定逐字是「**判「未固化」**」，即它明确拒绝断言这个失败已经发生；而它的触发条件是"下一轮的观测结果"，**今天取不到值**。把一个作者自己判为未发生、且触发条件未定的东西登记成 Case，就是本清单反复登记的那种"把未定折算成一个方向"（C-038 那条被违反的 [30 §2 P1](30-验证与测试.md)）。**而它属于§3 这一节**：读数九、读数十说的都是"这批 Case 与它们的结论是怎么被生产出来的、那个生产过程可不可靠"，本条是同一类。

**尺是什么，现跑**：`grep -n "已被覆盖 > 加一句作用域 > 改判据 > 改结构 > 新增" docs/审计记录/03[4-7]-*.md` 现取 **5 处**（034 一处、035 两处、036 一处、037 一处）；033 用的是同一把尺、写法略异，`grep -n "已被覆盖 → 加一句作用域" docs/审计记录/033-*.md` 现跑 **1 处**，逐字是「档次按仓库优先级是最优的一档：**已被覆盖 → 加一句作用域**（`> 改判据 > 改结构 > 新增`）」。**三路用的是同一把尺，这一点复核属实。**

**取向在哪**：这把尺**按构造就把"不动"排在最高档**，外加"提新增必须指出可删项，指不出就明写无可删项"。任何一路只要走这把尺，输出偏向「已被覆盖」是**先验的**，不是那一轮的证据挣来的。**所以"三路全部推荐不做"这件事本身的证据价值被稀释了**——它不是三次独立的判断，是三次同一把尺的应用。同型判据本仓库早有：[40 §2 P2](40-人的检查点与授权.md) 逐字「否决率长期为零……都说明它已不再产生判断」——**一把永远输出同一档的尺，与一个否决率为零的检查点，是同一句话的两侧。**

**但必须同时写下反方向的证据，否则本条自己就在折算**：这一批**不是**"证据被尺牵着走"。三份深挖各自都写下了对自己不利的东西——035 主动构造两个能满足 B-1 的机制来拆自己最省事的论据（逐字「**这两句差得很远**」），又主动放弃"用 D-020 挡住 B-1"这条现成的路（逐字「**所以不能用 D-020 §5 把 B-1 挡在正文外——这条路走不通，本文不用它。**」）；033 更主动推翻了仓库里两句**对"不做"有利的现成话**（「三项检验一项也答不出」与「到期时读数仍将是"拦住 0 条"」），而更正的方向是给"续期"那一侧递论据。[审计 036 §4.6](审计记录/036-三条待裁的独立复验.md) 据此判「未固化」。**同时，036 自己查出的三处实质性错误里有两处方向偏保守**（把一个看得见的输出误判成 C-006 那种察觉不到的红灯、用换了对象的反驳去支持"零改动"），第三处偏向反面且是那一路**自愿**写下的。**n=3，太小，不足以下"取向"的结论**——方向分布记下来，不折算。

**这一格不能靠再多写一轮论证解决，只能靠观测。可复跑的证伪信号（036 §4.6 给的，照录）**：**下一轮若仍是三路全部落在「已被覆盖」档，且三份里没有任何一份因证据改变了自己开工时的方向，"固化"才有观测支持**，在此之前记未定。**这条信号的价值正在于它可复跑**：它不问任何人的态度，只问下一轮的两个可数事实——档位分布，以及有没有一份改过方向。

## 4. 本轮刻意没有做的

**没有产生任何 Thin。** 按 [33 §2 P9](33-评估与演进.md)，Thin 的主要信号是"长期无消费"。本仓库的消费计数从今天才开始，**没测量不等于无消费**；用"没有数据"反推"可以删"，恰好是该条禁止的方向（"删除门槛低于新增"是给有数据的情形定的，不是给没数据的）。

因此第十一轮只做两件事：建立清单、把已发生的失败绑上去。删减要等这份清单有足够条数、且能看出哪些规则从没出现在任何一条 Case 的"本该防住它的规则"列里。
