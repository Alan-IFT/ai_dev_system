# 11 项目知识

状态：`v0.7-theory-draft`
平面：知识
governed_by：D-005、D-020、D-032、D-040、D-047、D-055
用途：项目特有、代码里读不到或读取成本过高的事实，按问题指定唯一权威记录源并保持不过期。

## 1. 最小职责与接口

- **它必须做到的**
  - 按问题类型指定唯一权威记录源，并声明它对哪一类主张有权威。
  - 保持入口只做地图（去哪找 + 一句摘要），细节放在它所描述的对象旁边。
  - 声明哪些工件是派生缓存，为它们绑定源版本并保持对账。
  - 为经验知识记录适用范围、产生事件与产生时的版本。
  - 冲突时列出互相冲突的主张与各自范围、版本、环境，不静默挑一个。
  - 同一条知识只有一个载体，人与执行者共读。
  - 为每个权威记录源标注内部或外部；标为外部的适用第六条不变量（读只引用不复制），判据与推论见[架构确定 §5.3](架构确定.md#invariants)。
- **从别的部件拿什么**：从[10 意图与验收](10-意图与验收.md)拿已确认的意图（"产品应该怎样工作"的权威记录源）；从[12 记忆与知识治理](12-记忆与知识治理.md)拿晋升后的唯一权威项与到期复核结论；从[32 证据与追踪](32-证据与追踪.md)拿观察与验证结果作为主张的支撑；从[33 评估与演进](33-评估与演进.md)拿失败驱动的增删。
- **给别的部件什么**：给[22 上下文装配](22-上下文装配.md)短入口与就近细节，供按需拉取而不是全量推送；给[30 验证与测试](30-验证与测试.md)契约与源定义作为对照基准；给全平面统一的冲突处理口径。
- **它自己维护什么**：权威记录源的指派、我方在每段跨边界关系中的角色与该关系的三项可执行前提（见[架构确定 §5.3](架构确定.md#invariants)）、入口地图、派生缓存的源版本与对账状态、待复核与已过期清单、知识变更的追加记录。
- **未决**：D-040 是对判据一的修正案，需宪法性批准；派生缓存的对账时机与漂移处置（阻断还是记待复核）留作项目参数。

## 2. 原则

- **P1 权威按主张指定，不设全局最高文档。** 先写清要证明什么主张，再决定谁有权定义、哪些观察能支持：主张 → 权威记录源 → 观察 → 验证结果 → 验收证据，五者不可互换；每条主张带范围、版本、环境、观察时间与限制。同一主题的意图、源定义、部署状态与运行现场可以同时正确。｜防的失败：用实现把意图改掉；拿引用当交付证明 ｜删除条件：写不出（责任结构型：谁有权定义某类主张是治理权的指派，同一主题的意图、源定义、部署状态可以同时正确，选哪一个只能由人按主张裁定）
- **P2 每类工件在任一时刻只有一个权威记录系统。** 存在副本时声明主从或至少互链；新摘要不能覆盖原始来源，也不能靠复制旧内容制造"新权威"。归属优先由可推导属性确定，与生成者的自我声明冲突时以推导为准。｜防的失败：第二事实来源腐败，两处记录各自演化 ｜删除条件：写不出（责任结构型："哪一份说了算"是治理权的指派；载体能自动对账只消掉人工核对，消不掉两份都自称权威时的裁决）
- **P3 入口只做地图，细节就近，索引不具权威。** 索引与细节冲突以细节为准；索引失配应当可检测，而不是靠提醒执行者自觉更新。｜防的失败：入口膨胀成百科全书；按过期索引定位错对象 ｜删除条件：检索能在可接受成本内实时建立同等精度的导航时，索引层可删
- **P4 派生的导航、摘要与地图只能作为声明的缓存存在。** 允许存在的条件同时成立：声明为缓存而非权威记录源；记录派生来源与源版本；变更进入主线前与源机械对账、差异由人分诊；人工写入区受保护并对自动区有覆盖权；再生成只追加不可覆盖的变更记录。｜防的失败：自动内容复活已下线接口；人工批注被覆盖且无法回滚；派生摘要被当原文引用 ｜删除条件：读取工具能在读取时自动对照源并标出差异时可删对账；人工覆盖权写不出（责任结构型：人工写入区不被自动区覆盖，是写入权的归属）
- **P5 两类知识两种过期机制。** 派生知识绑定源版本，差异超出项目声明的范围即机械判过期，过期后默认不作事实，只可带"待核实"标签引用；经验知识带范围、产生事件与产生时版本，范围内的源发生变化触发复核，而不是机械判过期或静默沿用。｜防的失败：调已废弃接口链路全通结果错；沿用已失效的排障结论 ｜删除条件：派生一侧可删于工具读取时自动对照源；经验一侧写不出（责任结构型：结论在何范围成立来自人的判断）
- **P6 不为执行者维护与人读版本分离的第二副本。** 派生缓存供人与执行者共读；只给执行者看的摘要是新的腐化点，人看不懂的知识没人维护。｜防的失败：副本漂移；同一事实在不同读者处不同 ｜删除条件：写不出（责任结构型：维护责任落在人身上，人看不懂的副本没有维护者；这不是模型能力问题）
- **P7 入口与状态保持短小，超预算先归档历史。** 压缩时不压掉风险、身份与下一步；架构正文只留当前生效设计，历史取舍进入决策记录。固定行数、比例或层级深度不作跨项目硬规则，只能是可评估的项目参数。｜防的失败：入口越长越没人读，关键项被淹没 ｜删除条件：加载成本不再是约束时可放宽长度，但"不压掉风险、身份与下一步"为责任结构型不删
- **P8 "代码里能读到就不写"是默认方向，不是禁令。** 读取成本高到不得不缓存时，可按 P4 的条件缓存；由运行观察提炼的经验既不在公开语料也读不出来，应当写下来，并绑定它防的失败与删除条件。这是判据一的已知间隙。｜防的失败：判据被读成禁令，二次失败仍不许写；反向地，副本无对账成第二事实来源 ｜删除条件：模型对"可读但需跨文件综合"的事实推断可靠时，兜底句可删

## 3. 从 L0 到 L3

| 档 | 形态 |
|---|---|
| L0 一人一工具 | 一份短入口加就近说明；权威记录源主要在人的头脑里，靠本人记得。 |
| L1 一人多会话 | 入口是每次开工的唯一起点；一旦出现派生索引，立刻声明它是缓存并记下源版本。 |
| L2 团队 | 权威记录源的指派具名到人；知识变更与代码变更受同一次评审；对账与过期报告进入流程。 |
| L3 无人值守 | 入口与对账结果是自动运行的可读前置条件；过期或未对账的派生知识默认不进入自动决策。 |
