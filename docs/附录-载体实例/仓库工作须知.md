## 1. 动手前先读什么

入口是 [Default Context Contract](../../CONTEXT_MANIFEST.md)，它列了必读的六项。**不要一上来全量读 `docs/`**——正文 15 个文件约 807 行，加上研究材料仓库有 195+ 个 md，全量加载正是本规范要解决的那个问题。


本机只有 `python`（3.12），**没有 `python3`**；PowerShell 下先 `$env:PYTHONIOENCODING='utf-8'` 否则中文输出乱码。检查器含 C1～C7，其中 **C7 校验正文每条原则在追溯账本中有且只有一条对应记录**（编号一致）——这是正文与账本分处两份文件后唯一的硬约束，改原则编号或增删原则时必然触发。

第二项是链接与锚点全解析，**没有现成脚本，每次现写**；判据是：全部 markdown 行内链接里，相对路径指向的文件（或目录）存在，且井号后的锚点在目标文件里能找到（`<a id="...">` 或标题转 slug）。当前基线是 **196 个 md、1,636 条本地链接、0 断链**。注意目录型链接（如 `../参考资料-公众号文章/`）指向的目录没有 README.md 也算通过，否则会误报一条。

## 3. 五个会咬人的地方

1. **文件头格式**：每章的 `平面：X` 与 `governed_by：D-xxx` **必须各占一行**。合并成一行会让检查器的 C6 判不合规。
2. **检查器的 ROOT**：`check_normative_force.py` 里 `ROOT = ...parent.parent.parent`（脚本在两层子目录下）。移动脚本要同步改。
3. **状态值只有一处副本**：一条决策的状态值只允许出现在生效登记表与决策索引状态列。写第三处是缺陷（08 §7）。
4. **正文不许出现的东西**（D-020）：具名工具、产品名、文件名、目录名、字段名、钩子事件名、效果数字、阈值。研究卡片目录（`docs/参考资料*/`）效力为零，那里可以写。
5. **git 在本会话里是能跑的**（此前记载相反，已更正）：2026-09-03 本会话直接完成了第九轮提交 `9acf832`。唯一的坑是 `.git/index.lock` 会残留零字节文件，提交前若报锁冲突，先确认没有 git 进程在跑再删它。首个提交是 `78664b0`。

## 4. 新增内容时的三条硬规矩

- **不新增部件、不新增章节**（D-043、D-047）。新内容要么归入现有 14 个部件之一，要么是"架构级内容"（不变量与平面接口，与部件并列）。
- **新原则的「删除条件」按四类取值**：`{具体失效条件 | 起始档 | 运行类型限定 | 写不出（仅责任结构型，且必须写一句为什么）}`。**不要默认写"写不出"**——那正是上一轮花力气清理掉的（永久豁免从 72% 降到 35%）。
