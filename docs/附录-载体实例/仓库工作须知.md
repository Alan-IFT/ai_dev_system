**新增检查的验收是四步，不是"跑一遍 PASS"**：① 验字节（控制字符在 `grep` 里隐身）；② **注入前先断言待替换串存在**；③ 反例测试确认它真报；④ 跑全仓看误伤。**任一步拿到空输出一律记未定**——空输出最常见的原因是采集没跑起来（`grep` 基本正则不认「括号加竖线」分组、注入脚本 `open(f,"w")` 先截断了文件），与"通过"和"失效"都无关（Case C-012）。 迄今写过的 4 条检查里有 **2 条**（C7、C10）在反例测试中被发现"恒为通过、其实不检查"——C7 的正则里混进过一个 `grep` 显示不出的退格符，C10 起初只认裸写形态、认不出链接形态（`[21 调度与拆分](…21-调度与拆分.md) §6` 这种）。**前两处"跑一遍看到 PASS"完全察觉不到**（Case C-006、C-010）。第三步是因为 C10 上线后误伤了"举例中的引用"（Case C-011）——检查与链接自检现在都跳过围栏代码块与行内代码。

第二项判据是：全部 markdown 行内链接里，相对路径指向的文件（或目录）存在，且井号后的锚点在目标文件里能找到（`<a id="...">` 或标题转 slug）；目录型链接指向的目录没有 README.md 也算通过，否则会误报一条。**基线数字不在这里抄**——跑 `repo_counts.py` 现取。这一项此前写的是"没有现成脚本，每次现写"；2026-09-03 现写的那一版忘了排除 `.staging/`（冻结快照），报出 40 条假断链、结论 FAIL，而真实断链是 0（Case C-016）。判据本身只有两句，但"排除哪些目录""代码块内的链接不算数"这类前提每次重写都会丢一两条，所以固化成脚本。**三个脚本的 `SKIP` 与 `mask_code` 必须同步**，否则计数与判定会互相对不上。

## 3. 六个会咬人的地方

1. **文件头格式**：每章的 `平面：X` 与 `governed_by：D-xxx` **必须各占一行**。合并成一行会让检查器的 C6 判不合规。
2. **检查器的 ROOT**：`check_normative_force.py` 里 `ROOT = ...parent.parent.parent`（脚本在两层子目录下）。移动脚本要同步改。
3. **状态值与版本号都只有一处副本**（08 §7）：决策状态值只在生效登记表与决策索引状态列；**语料版本号只在 PROJECT_STATUS 的 `corpus_version`**——不要在新文件头写 `状态：`v0.x-theory-draft``，C8 会报。`docs/历史/`、研究材料与 `.staging/` 是冻结快照，保留各自的版本号，已在 C8 中豁免。
4. **正文不许出现的东西**（D-020）：具名工具、产品名、文件名、目录名、字段名、钩子事件名、效果数字、阈值。研究卡片目录（`docs/参考资料*/`）效力为零，那里可以写。
5. **架构图重出 PNG 的做法**（此前没写下来，两次都是现摸索的）：成品页右上角「导出 → PNG（无损图像）」，深浅主题各一张。浏览器沙箱里下载不生效，做法是钩住页面自己的 `URL.createObjectURL` 拿到 Blob，再同源 POST 回一个本地小服务落盘——**跨端口会被 CORS 预检挡住，服务与页面必须同端口**。导出前先确认 `data-theme` 是想要的那个：2026-09-03 有一次点了主题按钮没生效，深色那张被浅色覆盖了一遍。完整说明在[架构图 README](../架构图/README.md)。**另注**：`archify visual-check` 会在图旁边写下一批 `*.visual-check.*` 副产物（html、json、四张视口截图），已加进 `.gitignore`——2026-09-03 有一次 `git add -A` 把它们连同一个 `out.png` 一起提交了，**提交前扫一眼 `git status` 的新增项**。
6. **git 在本会话里是能跑的**（此前记载相反，已更正）：2026-09-03 本会话直接完成了第九轮提交 `9acf832`。唯一的坑是 `.git/index.lock` 会残留零字节文件，提交前若报锁冲突，先确认没有 git 进程在跑再删它。首个提交是 `78664b0`。

## 4. 新增内容时的三条硬规矩

- **不新增部件、不新增章节**（D-043、D-047）。新内容要么归入现有 14 个部件之一，要么是"架构级内容"（不变量与平面接口，与部件并列）。
- **新原则的「删除条件」按四类取值**：`{具体失效条件 | 起始档 | 运行类型限定 | 写不出（仅责任结构型，且必须写一句为什么）}`。**不要默认写"写不出"**——那正是上一轮花力气清理掉的（永久豁免从 72% 降到 35%）。
- **架构图改 JSON，不改 HTML**：图源是 `docs/架构图/four-planes.architecture.json`，改完跑 `archify validate` 再 `archify deliver`（showcase 档须 0 错 0 警），PNG 预览用成品页的「导出 → PNG」重出。archify 需从其仓库的 `archify/` 子目录安装，根目录没有 package.json。
- **判据优先于枚举**（D-055 改动 5）：写清单时上位判据必须写在同一处；遇到不在枚举内的对象按判据判，判不出记未定并升级，不得硬塞进最近一项。
