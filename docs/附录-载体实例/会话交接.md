## 在本机继续

1. 本机没有系统级 git 与 python，**钩子与脚本只需要 Node**：
   - Node：`%USERPROFILE%\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe`
   - git：便携 MinGit，解压在 `%LOCALAPPDATA%\dsh-std-tools\mingit\`；用时把 `mingit\cmd` 与 `mingit\usr\bin` 放进当次进程的 PATH，没有改系统 PATH
   - TypeScript 构建：`node node_modules\typescript\bin\tsc -p tsconfig.json`；构建前先删 `lib/`，再跑 `scripts/check-lib-sync.mjs` 核对
2. 开工先跑，全绿再动手（读数不抄，现跑）：
   ```text
   node lib/cli.js . --no-scope
   node lib/cli.js --selftest
   node scripts/check-normative-force.mjs
   node --test "test/*.test.mjs"
   ```
3. 本机 `core.hooksPath` 是 `.githooks`，钩子是**五道全 Node**：std-check（含链接与锚点）、check-normative-force、check-lib-sync、check-py-semantics、check-residue（废弃技术栈字样白名单）。它自己找 node（`$DSH_HOME` → `$USERPROFILE/.dsh` → PATH，都没有就拒绝提交）。**验证钩子要用使用者真实终端的环境**（无 `DSH_HOME`、PATH 里没有 node），不要用自己会话的环境——这条错已经犯过三次。
4. **Ubuntu 在本机 Docker 里验证**：`pwsh scripts/verify-ubuntu.ps1`（可加 `-Mutations <名>` 跑某份变异清单、`-Overlay "<文件…>"` 覆盖未提交的文件）。脚本只看**已提交**的内容，所以先本地提交、再跑 Ubuntu、再推送。
5. 变异验证：`node scripts/mutate.mjs test/mutations/<名>.json --tests "<测试文件>"`。同一时刻只能跑一个（它们会重建 `lib/`）。每份清单首轮常有漏网的，**补测试直到全抓住，不是调清单**；平台相关的变异标 `winOnly`／`posixOnly`，跳过不算通过。
6. **发版**：版本号只有一处权威——`package.json` 的 `version`（semver），标签是 `v` 加它。打标签前先跑 `node scripts/check-release-tag.mjs v<版本>`（只读）；**打标签与推送由 Alan 在终端执行**（对外可见、难以撤回，且批量／不可逆的 git 动作在 DSH 的 `pwsh` 里会被工具层拦下，他明确授权也一样；不要换方式绕过）。
7. **Windows PowerShell 5 的中文路径陷阱**：`git ls-files` 的中文输出被按本地代码页解码，与脚本里的中文字面量静默对不上。给 Alan 的命令先 `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8`，并在批量操作前核对计数是否等于预期；写路径清单用无 BOM 的 `WriteAllLines`。
