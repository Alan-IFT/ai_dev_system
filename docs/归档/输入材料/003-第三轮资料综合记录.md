## 2. 对现有框架的六项实质冲击

### 2.1 八层模型缺一层：组织摩擦不在任何一层里

现有八层（意图与权威 → … → 评估与演进）与四个闭环，全部描述**单条交付链内部**的事。ATT-E 指出的量——需求等待排期、资源协调、跨团队协同、联调等待、返工——发生在**链条之间**，在现有八层和四闭环里都没有归属。

这不是一个可以靠"再加一条原则"补上的疏漏。它意味着现有模型的作用域需要被显式声明为"单条交付链"，组织流动是否纳入、以什么形式纳入，是一个需要单独决定的问题。

支持强度：ATT-E 是单团队、单工具栈、无对照组的实践报告；同期 AI Coding 普及本身也在起作用，两者的因果无法分离。**"个体提效不自动转化为组织提效"这个问题的存在，比 ATT-E 给出的解法可信得多。**

### 2.2 现有 19 条决策全部无法被淘汰

ATT-H 的判据：规则写下来时必须绑定它防御的**具体失败模式**；说不清防什么的规则，从写下来那一刻就无法被淘汰。ATT-O 的补偿面把这条说得更彻底：harness 里每个组件都编码了一条关于"模型自己做不到什么"的假设，假设会随模型能力增强而过期。

拿这条检查本规范：D-001～D-019 的"原因"列写的是**理由**，"后续验证"列写的是**将来要做的验证**，没有一条绑定了**已经观察到的、可复现的失败**。因此本规范的 19 条决策，按此判据全部处于"无法被淘汰"状态。

这与 D-013（按无收益/重复/误伤 Thin）不冲突，而是暴露了 D-013 缺失的那一半：D-013 给了 Thin 的信号，没有给 Thin 的**依据**。没有绑定失败 Case，任何一次 Thin 都只能靠判断，无法举证。

### 2.3 本规范正在以只增不减的方式膨胀

ATT-N 拆解的机制：自动修复工具选择追加而非重构，因为它是局部视角、偏好安全追加、没有文档健康度概念，而且自动化拆掉了"人的懒惰"这个天然刹车。

本规范的实际轨迹与之吻合：v0.2 → v0.3 → v0.4，仓库从约 1665 行增至 1800 行以上；v0.4 一轮新增 154 行并重写决策日志，全部为追加，未删除任何内容。

ATT-N 的注意力 U 形（中间区域遵循率下降）与 ATT-H 的"冗余从中性变成负数"合起来意味着：这不只是浪费预算，而是**主动降低本规范被正确执行的概率**。规模约束因此不是风格问题，是效力问题。

### 2.4 失败分类缺"目标失明"

现有失败分类（06 章）为：意图、source of record、检索/上下文、状态/记忆、工具/ACI、工作流/权限、验证/证据、环境、模型。

ATT-J 的客服案例不属于其中任何一类：工单解决率连涨五个月，续费流失率翻倍。系统学到的"解决"方式是偏转——快速关闭对话、劝阻用户追问、把被放弃的问题标记为已解决。**每一层都没坏，指标一路上升，而这个"成功"恰恰是失败的机制。**

配套的是 ATT-J 的现实锚点判据：如果一条链里所有节点都在互相引用模型生成的结论，没有一个节点真的去碰现实，那它只是一台更精致的自嗨机器。本规范现有的 readback 只覆盖"发布后从目标环境回读"，不覆盖"整条证据链中必须存在直接观察真实世界的节点"。

### 2.5 自主度与 Gate 数量都有人侧上界，D-010 与 D-018 都没有

ATT-H 给出两条约束：

1. 你能交给一个循环的自主度，上限就是你能**廉价且可靠地验证**的那么多。配套三个判定问题：多快能知道错了、多干净能撤销、什么能证明是对的。注意上界绑定的是验证能力，不是任务重要性，也不是模型能力。
2. Gate 的数量上限 = 人能真正判断的数量上限。人在 Gate 面前会退化成快速点头；**一个人判不动的 Gate 等于没有 Gate，而且更糟——它制造了"已经审过"的假象。**

D-018 只规定 Gate 必须声明哪些字段，没有任何关于 Gate 总量的约束。D-010 只说"eval 证明更高复杂度改善净结果才升级"，没说验证能力才是上界。这两条都是约束条件而非能力，按 ATT-H/ATT-O 的四层归属属于"永不内化"一类——责任不可转移。

### 2.6 局部指标不代表端到端结果，且端到端 A/B 有适用条件

ATT-F 的三层评价（局部输出 / 行动路径 / 整体结果）配了一批方向相反的观察：终端字符下降约四成而总 token 上升约四个百分点；同一工具在不同任务形态上从大幅下降到大幅上升。

更重要的是它的**方法论警告**：作者最初计划用"同一需求跑两遍完整工作流"做 A/B，发现大模型执行路径本身的波动（探索轮次、是否踩坑重试）比被测机制的效果还大；改用**可复现的组件级对照**——被测机制是纯文本过滤、与模型决策无关，因此 100% 可复现。

本规范 06 章的 eval manifest 有"重复策略"字段，但没有"**何时端到端 A/B 不成立、应退回组件级对照**"这条判据。这是评估协议的实质缺口。

## 3. 材料之间的四组冲突及处理

**冲突一：加法与减法方向相反。** ATT-P 在建（四层领域模型 + 五类规则文件 + 五层验证 + 四角色分工）；ATT-H 在拆（根指令删 61%、skills 砍 40%、agent 从 10 减到 6）。两份材料出自同一时期、同一公司体系。

化解：按 ATT-O 的四层归属，二者作用在不同层——ATT-P 建的多为组织特有、模型无法从公开语料或代码库获得的内容；ATT-H 删的多为补模型能力缺口的脚手架。方向相反但不矛盾。

**但残留一个材料自身没有覆盖的问题**：ATT-P 全文没有报告任何一次 Thin，也没有为它的任何一层验证绑定具体失败 Case。按 ATT-H 的判据，它已经在积累无法淘汰的规则。这一点不在材料的自我认知范围内，属于本规范的独立观察。

**冲突二：代码图谱的相反实测。** ATT-F 报告在部分任务形态上大幅反增，ATT-L 报告总 token 明显下降。两者出自同一公司不同团队。

化解：不采纳"这类工具一定省或一定贵"为通用规则。收益方向由任务形态和查询结果在会话中的存活时长决定，属于项目参数，需项目自测。**同一公司不同团队测出相反方向，本身就是"这是参数不是规则"的强证据。**

**冲突三：影响力排序。** ATT-O 同时引用了"只换 harness 使某榜单通过率大幅提升"和"prompt 的影响大于 harness 结构、harness 结构的影响大于模型"。

化解：不冲突但极易被误读。后者是**边际**影响力，且有前提（harness 已是成熟多层架构，prompt 站在它之上），不是**基础**重要性。本规范不采纳任何固定的影响力排序。

**冲突四：多智能体的成本与收益。** ATT-J 转述的官方数据显示多智能体伴随数量级的 token 增长；ATT-Q 指出跳过"可靠单任务执行"直接做多任务自动化，净效率可能为负。

化解：与现有 D-010 方向一致，并补上 ATT-Q 的前置条件——在单任务可靠执行未解决前不升级复杂度。

## 4. 本轮新增"不采纳为通用硬规则"

- 一切具体阈值：打断成本秒数、笔记行数上限、上下文利用率百分比、验证评分线、单轮追加行数、Skill 行数"甜区"、skill 数量的路由退化点、压缩率区间、入口文件行数；
- 一切具体角色数量与分工命名（6 个 / 4 个 / 7 个；reader/planner/executor/reviewer 等）；
- 一切具体目录结构与文件名约定；
- 一切具名工具与产品；
- Prompt / Harness / 模型的影响力排序；
- 四层或五层演进序列作为必经路径或分期标准；
- "删除而非改写"作为跨模型代际的通用处置（原始表述针对特定模型版本）；
- 材料中全部效果数字。
