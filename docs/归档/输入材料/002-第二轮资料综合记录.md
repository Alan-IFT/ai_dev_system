# 输入材料 002：第二轮资料与实践观察

日期：2026-09-01  
性质：用户提供的参考材料和观点摘要，**不代表已经接受的决策**。详细证据边界见[来源与证据矩阵](../../来源与证据矩阵.md)。

## 1. 四份附件的共同问题意识

四份材料从软件交付、上下文工程、个人记忆和业务分类四个场景，共同提出一个待验证假设：随着单次生成能力增强，项目失败的相对瓶颈可能转向事实、边界、状态、权限、验证和长期维护。材料本身不足以证明该趋势对所有模型和项目成立。

本项目综合出的七层候选结构（不是附件作者共同结论，也尚未通过项目 eval）：

1. 按范围和现场声明的权威事实；
2. 经治理、可过期的长期记忆；
3. 按任务动态组装的上下文；
4. 可跨会话恢复的任务状态；
5. 有输入输出合同的工作流；
6. 可执行的权限和质量 Gate；
7. 与 revision、环境和时间绑定的验收证据。

## 2. 附件 A：交付链

贡献：

- 代码不是交付；可信上下文、可执行约束、可恢复流程共同构成 Harness；
- 同一主题存在代码、契约、部署和运行现场，结论必须携带来源、revision、scope、环境和时间；
- 文档/Rule 讲意图，脚本判断事实，Gate 阻断阶段或危险动作；
- State 是书签，文档是任务正文，Workflow 是阶段交接协议；
- 从真实任务建立基线，按证据 Add/Thin。

保留为待验证：私有项目案例、具体目录和脚本只能作为示例。

## 3. 附件 B：Context Engineering

贡献：

- 区分 Prompt、行动循环和 Context Engineering；
- 上下文不仅包含提示词，还包含历史、状态、记忆、检索、工具和输出约束；
- 提出 compaction、结构化笔记和子 Agent 三类长任务方法；
- 强调 JIT、渐进披露、工具边界和工具返回治理；
- 汇总“全量加载、工具过多、规则枚举、原始输出常驻”等反模式。

修正：不采用固定压缩百分比、固定文件数量、字符/Token 估算和泛化的准确率数字；不把标准自注意力复杂度直接等同于所有现代实现的实际成本。

## 4. 附件 C：个人记忆

贡献：

- 记忆应由用户拥有，避免绑定单一 AI 工具；
- 稳定身份/原则与动态偏好/上下文/知识分开；
- 短索引路由正文；条目携带状态、隐私、标签和时间；
- 经验可以晋升为技能，但写入和晋升需要本人确认；
- 记忆需要冲突、过期、归档和跨工具同步。

修正：两级目录、目录权重和每条独立提交仅作为个人实现候选；项目事实不能复制到个人记忆形成第二权威版本。

## 5. 附件 D：业务规则与模型分工

贡献：

- 当多个答案语义上都合理时，业务目标决定“正确方向”；
- 确定规则、范围限制、优先推荐、语义判断形成控制强度梯度；
- 业务定义方向，Harness 稳定执行，模型处理剩余语义不确定性；
- taxonomy、规则、Few-shot、评测数据必须绑定版本；
- 变更需离线回归、灰度、线上观察和回滚。

修正：材料中的准确率提升缺少公开数据和消融，不能据此证明因果；规则必须保留“不确定/人工升级”，避免错误范围限制排除正确答案。

## 6. 用户提供的 12 条一线观察

| 观察 | 在本规范中的处理 |
|---|---|
| 做事前先考虑 AI | 作为探索习惯，不作为“必须使用 AI”的强制规则 |
| 意愿会放大个人产出 | 组织假设，暂不转为工程规范 |
| 外行 + AI 可提出跨域质疑 | 鼓励证据化异议，但专业责任和权限不随之转移 |
| 没有判断力会被 AI 忽悠 | 引入风险分级 Review、独立证据和人工责任 |
| 问题定义与验收仍是瓶颈 | 加强 PRD、非目标、验收和认知覆盖 |
| Prompt 仍重要 | 保留最小充分指令，用失败和 eval 驱动增删 |
| 不要为了 AI 而 AI | 确定性任务优先普通程序，复杂度需证明收益 |
| 老员工优势是隐性知识和判断 | 把知识显式化，但保留来源、所有者和审核 |
| 个人、团队、业务提效不同 | 评估分层，不用单一吞吐指标替代价值 |
| AI 可能制造产能过剩 | 优先优化价值链和瓶颈，不以产出数量为目标 |
| 团队资产应 Bottom-up 积累 | Harness 从真实任务和失败中生长 |
| 知识库重点是知识质量 | 优先治理内容、来源和更新，不先沉迷检索参数 |

## 7. 一个需要化解的表面矛盾

“一次搞不定就换模型、补上下文再试”与“两次无新证据就停”并不冲突：前者只有在形成了新假设、新上下文来源或新的对照实验时才是有效尝试；仅换措辞重复同一推断仍属于无证据循环。

## 8. 本轮形成的候选决策

- 区分上下文、任务状态、知识、记忆和证据；
- 按主张的范围、版本、环境和时间指定权威来源并绑定支持证据；
- 项目事实写入与记忆晋升需要所有者审核；
- 阶段推进与完成判定绑定可验证工件；
- 使用确定性 → Workflow → Agent → 多 Agent 的复杂度阶梯；
- 模型升级对 Prompt、工具、Skill 做受控消融；
- 建立轨迹、任务 Case 和项目结果三层以上评估；
- 所有固定数值和目录约束都由项目实验决定。
