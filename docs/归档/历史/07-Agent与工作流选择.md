<a id="complexity-ladder"></a>

## 1. 候选复杂度阶梯

| 任务特征 | 优先验证的最低机制 |
|---|---|
| 同输入应同输出、规则可完整定义 | 普通程序、lint、CI |
| 单步且资料明确 | 单次模型调用 + 检索 + 验证 |
| 路径固定、可清晰分段 | 预定义 Workflow + Gate |
| 子任务事先可知且独立 | 并行处理 |
| 子任务需动态发现 | Orchestrator–Workers |
| 评价标准清楚且迭代可测 | Evaluator–Optimizer |
| 步骤不可预写、需连续环境反馈 | 有边界的自治 Agent |

阶梯是双向的（D-010）。升级须代表性任务 eval 证明净收益；升级到多单元结构还应满足：任务重复频次足以摊销结构成本；预期跨会话或需中途审批（须有可恢复状态）；单元间的边只在下游消费上游数据处存在；每个单元声明失败去向；同步点只在某步必须看到全集时设置。降级：同输入多次运行结果一致的步骤转为确定性程序。验证器先于自动触发器就位。

多单元与单单元的比较须等 token 预算；子执行者的上下文独立计费，编排者重新理解的成本单独计量（见 [03](03-上下文与会话协议.md)）。

<a id="workflow-agent"></a>

## 2. Workflow 与 Agent

Workflow 的路径由系统预定义，适合可预测、合规、可审计流程；Agent 根据环境反馈动态选择行动，适合开放且步骤未知的问题。可以外层 Workflow、局部 Agent，确定性检查仍交给程序。

<a id="multi-agent-conditions"></a>

## 3. 多 Agent 条件

验证者分离是默认允许的拆分：它只需工件与验收标准，不需生成过程（见 [05 §6](05-质量闸门与交付证据.md#verification-layers)，D-037）。其他按工作类型的拆分须证明：子任务相对独立；输入、输出与完成条件清楚；上下文可真正隔离且隔离有收益；有独立验收；汇总者能核查来源与冲突；并行收益大于协调、Token 和合并成本。

并行单元只写自身局部记录、只改自身可写空间；总状态由收口阶段的单一执行者更新；共享入口与全局契约/存储变更不进入并行期。汇合输出必须报告预期 / 实收 / 缺失。

不适合：高度耦合取舍、同一热点竞争修改、边界不清、没有合并验收、只为形式上的“Agent 化”。

<a id="worker-contract"></a>

## 4. Worker 交接合同

输入至少含目标、非目标、精确事实入口、权限、是否继承治理规则、输出格式和验收。委托须声明是否继承治理规则（项目入口指令、权限边界、安全规则）；未声明视为不继承，不继承者只可授予只读或纯输出任务；子任务须原子方可交给低能力执行者（D-031）。隔离原语（委托 / 分叉试探 / 压缩外部化）的选择见 [03 §8](03-上下文与会话协议.md#compaction)。

返回是与执行者无关的结构化裁定（D-029）：产物、三态结果（通过 / 失败 / 未定（UNDETERMINED：阻塞、未核验））、判断依据与定位信息、来源/观察、已验证/未验证、置信度、风险和依赖；缺字段即拒收，主 Agent 只消费裁定，不解析自由文本。每类工件只有一个可写角色，下游对上游工件的异议只能以阻塞项回流（D-037）。主 Agent 不只接收无来源摘要，也不把全部原始探索塞回主上下文。

<a id="autonomy-boundary"></a>

## 5. 自治边界

自治需要：受限工作区/工具与通信对象（权限边界应含可与哪些主体通信，Agent 间协作走可记录、可归因的渠道）；沿链路单调收窄且至少在两个不同位置检查的能力范围，被委托者权限 ⊆ 委托者，不可逆动作权限不随委托传递；创建时固化、运行中不可放宽的时间/成本/迭代/并发上限；可观察环境反馈；一个不需要人在场即可拒绝坏输出的判定器（没有则不应自动触发）；活性不变量——进行中的单元绑定可探活执行者与新鲜度信号，失去绑定即转未定/阻塞并通知，未到合法停止点不得静默停止（D-036）；集中在少数状态转换处的人工判断检查点（记录耗时、频率、否决率与队列，后台单元不得发起需人响应的等待）；可恢复状态与幂等/回滚；独立于自我陈述的完成判定。

并行自主流的上限是人能认真审查的数量；验收队列时长是检查点有效性的必测量。预批准动作集（具名批准、触发条件满足即可机械触发）与仍需判断的 Runbook 分开声明，交互式审批不得沉淀为永久授权（D-028）。三个判定问题：多快知道错、多干净撤销、什么能证明对。自治等级应随项目可读性、测试、权限和恢复能力提升，而不只随模型能力提升。

<a id="aci"></a>

## 6. Agent-Computer Interface

工具名称和参数应直接表达用途、副作用和不适用场景；相似工具边界清楚；目标绝对可校验；工具自身输出最小、结构化、高信号，对工具输出的事后有损压缩另受 [03 §8](03-上下文与会话协议.md#compaction) 有损观察压缩条款约束；错误含下一步诊断。用真实任务测试模型能否正确选择和调用。更多工具会增加选择与维护成本，不等于能力更强。
