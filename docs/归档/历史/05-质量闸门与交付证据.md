# 质量闸门与交付证据

状态：`v0.6-theory-draft`  
governed_by：D-005、D-008、D-009、D-017、D-018、D-020、D-029、D-035、D-037、D-038
效力查询：[决策日志 · 生效登记表](../../决策日志.md#effective-register)

> 决策效力：本文规则的效力由上方 `governed_by` 所列决策在[生效登记表](../../决策日志.md#effective-register)中的状态决定，本文不复制状态值。未登记的决策为`提议`：不阻断、不授权。未标注规则按[分向降级](../../08-规范效力元治理.md#unmarked-default)处理——可作为拒绝理由，不可作为授权理由。

<a id="mechanism-placement"></a>

## 1. 规则放到产生约束力的位置

| 要求类型 | 性质 | 候选载体 |
|---|---|---|
| 价值取舍与设计原则 | 方法约束（信息型：期望被遵守） | PRD、架构、ADR |
| 仍需情境判断的重复方法 | 方法约束（信息型） | Runbook、Skill、Checklist |
| Agent 可调用的动作及其副作用声明 | 能力目录 | 工具接口描述、可见性过滤 |
| 可确定判断的正确性要求 | 执行边界（验证型：应用前由模型之外的检查器判定） | 测试、lint、schema、静态检查 |
| 高风险动作限制 | 执行边界 | 权限、沙箱、allowlist、动作前 Gate |
| 状态转换条件 | 执行边界 | 阶段 Gate |
| 已发布和已生效声明 | 执行边界（以回读观察为判据） | 发布记录、目标系统 readback、监控观察 |

更强烈的措辞不能替代执行机制。约束力由两个独立维度决定：检查是否自动进入必经路径；失败是否改变后续状态。据此分四级：只写在指令里的是提醒；写成脚本但要执行者想起来运行的是工具；自动运行但失败仍可继续的是警告——警告必须留下被下游必然消费的痕迹，跳过须可见；只有自动运行且失败使下一步无法进行的才是约束。

阻断的判据必须是可直接观察的确定事实；代理指标（"已读""已声明""看起来合规"）只能提醒或产生候选，下沉时机由观察到的违规触发（D-008）。介入强度应与人对结果的确定程度匹配：完全确定→由系统直接决定；确定范围→限定候选集或可操作对象；只有倾向→指导文本；无把握→交模型判断。高风险边界不得只有信息型控制。

<a id="gate-contract"></a>

## 2. Gate 合同

每个可执行 Gate 至少声明：

| 字段 | 含义 |
|---|---|
| gate_id / decision_id / status | 唯一身份、来源决策和效力状态；status 只从[生效登记表](../../决策日志.md#effective-register)读取，不在 Gate 定义处复制 |
| effective_scope / trigger | 生效模块、环境、动作或状态转换 |
| owner | 维护规则和处理误伤的人 |
| checker | 程序、服务或有资格的人工检查者；须声明自检语义——其结构假设（路径、格式、粒度）与被检对象不一致时判为检查器故障并阻断，不得降级为警告或"已有问题" |
| inputs | 需要的工件、revision、环境和权限 |
| pass_condition | 可判定的通过条件，并标注判据类型（确定事实 / 代理指标）；含未执行项的判定为未定（UNDETERMINED）；对未登记动作、应答缺席、超时的默认判定 |
| failure_transition | 失败后进入 BLOCKED、回到哪个状态或执行何种回滚；上游失败后同一任务的后续写入是否停止（屏障）；重试预算按失败所在层分配 |
| evidence_output | 生成何种 validation result/acceptance evidence；数字由程序重算，摘要只作索引 |
| waiver_owner / waiver_expiry | 谁能限时豁免、何时自动失效 |
| observability / rollback | 怎样发现误阻断与拦截层静默失效（下游防御性断言、可重复运行的"应被拦截"回归 Case、消费 / 拦截 / 误伤计数）、怎样撤回 Gate |
| 呈现与带宽 | 呈现给人的内容顺序（裁决项、证据、推荐前置；目标环境与受影响对象来自可观察事实；全文与 diff 为附录）；预期耗时、触发频率、否决率与队列长度的记录方式 |

只有材料清单而没有 checker、通过条件和失败回边的内容是 Checklist，不是 Gate。

检查器、拦截层与判分器自身是被验证对象（D-038）：机制生效以运行时观察为准，不以执行者自报为准；每项机制须能回答是否被本次运行消费、拦住的是真实问题还是误伤，没有计数不得判定其有效。

<a id="gate-types"></a>

## 3. 两类 Gate

- 动作前 Gate：在数据离开系统或状态不可逆之前（发布、对外写入、付款、删除、覆盖、迁移、权限/密钥变更、保护分支修改、成本越界）判断是否允许。不可逆动作的授权只能由人产生、经模型不可写入的通道传递、由非模型组件核验；授权是带参数的结构化决定（方式、范围、批准人、时间窗），人确认的入参与实际执行的入参必须一致；自动修复路径不继承人工豁免。
- 状态转换 Gate：对[唯一状态机](02-全生命周期工作流.md#canonical-states)的相邻转换检查输入、结果与证据。

按判据性质再分（D-024）：事实门禁的判据是可从工件或环境直接观察的确定事实，可阻断、不耗人注意力、只递例外，数量上限由误报率约束；人工判断检查点集中在少数状态转换处，数量上限由判断带宽约束，须记录耗时、频率、否决率与队列，判不动的合并或移除；判据为代理指标的检查只能提醒或产生候选，不得阻断。对未知默认关闭：未登记或未分类的动作默认进入确认档或拒绝，应答缺席、出错或超时等于拒绝，不得"无匹配即放行"；失败处置按后果非对称——只影响模型所见的读路径可降级放行并留痕，导致外部状态改变的写路径失败必须关闭。

外部写入结果允许未定（结果未知）态，不得记为成功或失败；解除只能靠回读，重试须有幂等标识；写操作只在声明的阶段窗口内允许并留痕；未成功写入进入待补偿记录，依赖它的状态在补偿完成前不得宣告（D-029、D-036）。

所有项目的最低 Gate 仍在待决策。当生效 Gate 集合为空时，"全部 Gate 通过"判定为未定（UNDETERMINED）而非 `PASS`，执行者必须停止并报告，见[空集合条款](../../08-规范效力元治理.md#empty-set)（D-014）。风险分级只用于在已确定最低基线上增配检查，不能用来把空集解释成已通过。

<a id="evidence-package"></a>

## 4. 验收证据包

一条完成主张至少绑定六项：断言；原始证据（报告、日志、截图、trace 或回执的位置）；精确版本与[工作区身份](03-上下文与会话协议.md#workspace-identity)；适用范围；观察时间；确认方法（含检查器及版本、执行者与验证者身份——二者相同判无效）。

以下字段只在项目观察到对应复杂度信号时追加，并登记触发信号：多来源冲突→权威归属与 owner；多环境→环境与关键数据/权限/feature flag；结论随时间失效→首次观察与最近复核时间；存在派生投影→派生来源与内容指纹；新旧替代→状态与替代关系。

变更验证另附：变更前失败集合及其版本（验证基线，语义见 [02 §1](02-全生命周期工作流.md#canonical-states)）、运行实际消费的输入版本、每层三态（通过 / 失败 / 未定）与盲区、验证者身份。阻断只对变更引入的新增失败成立；存量失败显式登记，不得掩盖新增失败。

认知覆盖：审查人声明实际理解和审查的范围与未审范围，绑定到被审版本；高风险变更必填，其余可选；未覆盖部分不得被"已审过"掩盖。

这些字段是 D-009 的候选底线。概念关系以[主张模型](01-工作原则与事实来源.md#claim-model)为准。

<a id="evidence-freshness"></a>

## 5. 证据新鲜度

代码、依赖、生成物、配置、测试、工作区、环境、数据集、浏览器、权限、feature flag 或验收标准变化时，旧结果可能失效。报告来源不明或无法绑定当前工件时不能证明当前交付。工作副本领先于运行实际消费的输入时，"修复已生效"不成立；验证现场与代码现场不一致时同样不能证明当前交付。

“测试曾经绿过”不等于当前 revision 在目标环境满足验收。

<a id="verification-layers"></a>

## 6. 验证层级

按风险组合：静态检查 → 局部行为 → 边界/契约/迁移 → 用户旅程 → 发布 readback → 运行日志/指标/trace/业务结果 → 人工体验和剩余风险判断。每一层输出三态——通过 / 失败 / 未定（UNDETERMINED，含未执行、无法核验、结果未知）——只证明其覆盖范围并声明盲区，端到端测试也不能宣称完全覆盖视觉、真实依赖或数据分布；含未定层的完成判定为未定，聚合分数不得把未定折算为部分通过（D-029）。可被无断言刷满的指标不得单独作 Gate 输入。验证计划从本次改动集派生出可观察终点；多个审查者的盲区应彼此独立。

验证者独立于生产者是结构要求，不随模型能力消解（D-037）：验证在独立上下文或独立模型中进行，只挂载产出物与验收标准，不读生产者的推理与自述；验证结果记录生产者与验证者身份，相同判无效；执行事实由独立于生产者的环境重新取得，生产者自报只作候选。客观可机械判定的项无需独立审查者，但验收标准本身须有独立来源、确认后冻结；证明修复的测试不得被修复者修改；实现 Agent 不能通过弱化验收或测试使自己通过。安全和重大架构由有资格的人类审查。

"要求模型自我验证"的指令属能力补偿类，随模型代际审计（见 [06 §6](06-评估与演进.md#ablation)）；评审类 Agent 的效果指标须锚定下游真实行为（被指出的问题是否真的被修复、被阻断的动作是否真的有害），不得只统计标记数（D-035）。

<a id="waiver-risk-acceptance"></a>

## 7. 豁免与风险接受

豁免不是永久关闭 Gate。记录 `waiver_id`、gate/finding、理由、范围、批准人、批准时间、失效时间、补偿控制、复查日期和关闭证据。超期自动失效。跳过检查也是豁免，须留同样字段；交互式确认中的"始终允许"不是豁免机制——累积的免审批集合须可枚举、可机械扫描、有复审周期，不可逆动作的确认不得提供"始终允许"（D-028）。

风险接受记录风险描述、可能性/影响、受影响用户或数据、替代方案、补偿控制、剩余风险、owner 和期限。实现者不能自行接受其产生的重大风险。

## 8. 完成与故障
