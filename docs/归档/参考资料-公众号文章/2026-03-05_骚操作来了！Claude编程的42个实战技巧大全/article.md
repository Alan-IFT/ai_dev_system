# Datawhale干货 ******作者：Nav Toor，整理：Claude Code技巧******

Claude Code 11 个月硬核实战总结来了！

来自一位 X 博主、Claude/GPT 的深度使用者 Nav Toor，他用了十一个月，踩了无数坑，也从社区里挖到了不少宝贝——这份清单就是这些经验的结晶。

不管你是刚上手，还是已经用了一段时间想再往上走一层，这 40+ 个技巧都能帮到你。从最基础的操作习惯，到只有顶尖用户才知道的骚操作，全在这里了。

基础技巧：01–10

*从这里开始。打好地基，之后每一次 Claude Code 会话都会更顺。*

## 01 定制你的状态栏

把当前模型、工作目录、Git 分支、未提交文件数、同步状态、token 用量全塞进状态栏。不用开口问 Claude，一眼就知道自己在哪、用了多少。

## 02 把斜杠命令背熟

几个必会的：/usage 查 token 消耗，`/mcp` 管理 Model Context Protocol 服务器，`/stats` 看会话统计，`/clear` 清空重来。这些命令用熟了，效率直接上一个台阶。

## 03 用语音跟 Claude 说话

试试 SuperWhisper、MacWhisper 这类语音转文字工具。很多开发者发现，口述需求比打字快得多——尤其是描述复杂逻辑的时候。

## 04 把大问题拆小

复杂任务别一股脑丢给 Claude，拆成小块逐步推进。更聚焦的请求比模糊的大问题准确率高得多，迭代起来也更可控。

## 05 把 Git 和 GitHub CLI 用起来

提交、建分支、开 PR，都可以让 Claude 来。配合 `gh` CLI 做进阶查询，说一句“帮我开个 PR”，Claude 会把整个流程都搞定。

## 06 上下文就像牛奶，要喝新鲜的

换话题就开新对话。长对话会拖累输出质量，切换任务时直接开一个干净的会话，别恋战。

## 07 把输出搬出终端

用 `/copy` 复制回复，用 `pbcopy` 等剪贴板命令，或者直接写文件、在 VS Code 里打开、把链接扔进浏览器。别让有价值的内容困在终端里。

## 08 设好终端别名

给常用操作起个短名字：`c` 打开 Claude，`ch` 开 Chrome，`gb` 启动 GitHub Desktop，`co` 打开 VS Code。每天省下的那些击键次数，积累起来相当可观。

## 09 主动压缩上下文

在开新对话前，用 `/compact` 或 `/handoff` 生成一份摘要文档。重要上下文留住了，Claude 又能从一个干净的起点出发。

## 10 写代码→跑代码→验结果，循环起来

写完就跑，跑完就验，验完继续写。用 tmux 做交互式终端测试。这个快速迭代的节奏，正是 Claude Code 最能发挥价值的地方。

进阶技巧： 11–25

*工作流升级。这些技巧是普通用户和高手之间的分水岭。*

## 11 Cmd+A / Ctrl+A 全选大法

遇到 Claude 无法直接访问的页面，全选内容粘贴进来就行。这招能绕过很多访问限制。

## 12 用 Gemini CLI 作为备用方案

做一个调用 Gemini CLI 的 skill，专门用来抓取 Claude 访问不了的内容——比如某些 Reddit 帖子或被屏蔽的网站。

## 13 在自己的工作流上投资

花时间定制你的工具：做个自定义状态栏，搭好语音转文字，精简系统提示词。前期投入的时间，会以每天的效率红利回报你。

## 14 搜索历史对话

历史对话存在 `~/.claude/projects/` 里，可以自己翻，也可以让 Claude 帮你搜。这是一个被严重低估的知识库。

## 15 多开终端标签页，并行推进

用“瀑布式”多标签页的方法，同时跟进三到四个任务，每个标签页对应一个独立的 Claude 会话。

## 16 给系统提示词瘦身

进阶用户可以直接 patch Claude CLI 的 bundle，把系统提示词从约 19K token 压到 9K——省了一半，留给实际工作的上下文空间就更多了。

## 17 用 Git Worktrees 多线并行

用 `git worktrees` 在不同目录同时操作多个分支，不用来回切换，并行开发不打架。

## 18 等待长任务时用指数退避

跑 CI 构建或 Docker 操作这类耗时任务，让 Claude 按递增间隔检查状态（1 分钟、2 分钟、4 分钟、8 分钟……），而不是一直轮询。

## 19 把 Claude 当写作搭档

用语音口述初稿，然后和 Claude 逐行过一遍。这个组合能把 Claude 变成一个很顺手的编辑伙伴。

## 20 拥抱 Markdown

用 Markdown 写文档、和 Claude 对话、保存成 Markdown，需要时再转成其他格式。Markdown 就是现代文档的母语。

## 21 用 Notion 保留链接

从 Slack 或其他会剥离格式的应用复制内容时，先粘到 Notion 再转存，链接就不会丢了。

## 22 用容器跑高风险任务

用 `--dangerously-skip-permissions` 参数在容器里跑 Claude Code，处理无人值守的任务。危险操作隔离起来，出了问题也不会殃及本机。

## 23 克隆和半克隆对话

`/clone` 可以分叉当前对话，`/half-clone` 在保留近期工作的同时缩减上下文。这两个是会话管理的利器。

## 24 用 realpath 给出绝对路径

涉及不同目录下的文件时，用 `realpath` 命令生成完整绝对路径，消除歧义，省去不必要的麻烦。

## 25 搞清楚工具的层级关系

`CLAUDE.md` 每次都加载，Skills 按需加载，斜杠命令手动触发，Plugins 是内置工具。搞清楚各自的定位，用对地方。

高阶技巧：26–42

*用了这些，你就和普通用户不在一个段位了。顶尖 1% 的玩法，全在这里。*

## 26 把 PR Review 变成对话

让 Claude 陪你一起做 PR Review：逐文件过，自己控制节奏和细节深度。代码审查从此不再是批量走流程，而是一场有来有往的对话。

## 27 把 Claude 当研究工具

调试 GitHub Actions、分析 Reddit 讨论、摸清一个陌生代码库——Claude 在信息综合和深度调查上出奇地好用。

## 28 认真对待输出验证

用测试、可视化 Git 客户端、草稿 PR，让 Claude 自己检查自己的输出。生成和验证同样重要，别只盯着生成。

## 29 把 Claude 当 DevOps 工程师用

用 `/gha` 斜杠命令排查 GitHub Actions 失败，找根因，出修复方案。Claude 在基础设施调试上的能力，会让你惊喜。

## 30 `CLAUDE.md` 越简单越好

从零开始，只把反复出现的指令加进去，定期清理过时内容。少即是多。

## 31 选对抽象层级

“氛围编程”和深度钻研之间找好平衡，根据任务的重要程度来决定投入多少注意力。不是每个功能都值得精雕细琢。

## 32 审查你批准过的命令

用 `cc-safe` CLI 扫描有风险的已批准命令，比如 `rm -rf` 或 `sudo`。用了 AI 助手，安全意识也不能松。

## 33 多写测试

用测试驱动开发（TDD）：先写会失败的测试，再写代码让它通过。Claude 在 TDD 流程里表现特别稳。

## 34 在陌生领域大胆一点

遇到不熟悉的技术领域，让 Claude 带着你一步步探索。它能在你还不懂的地方给你指路。

## 35 跑后台进程

用 `Ctrl+B` 把进程放到后台，让子 agent 在后台并行工作。Claude Code 本来就支持多任务，好好利用起来。

## 36 个性化软件的时代来了

给自己做专属工具：小脚本、小项目、小工具，有 Claude 帮忙，这些现在人人都能搞定。

## 37 高效操作输入框

记住这些终端快捷键：`Ctrl+A/E` 跳到行首/行尾，`Option+左右方向键` 按词跳转，`Ctrl+W/U/K` 删词/删到行首/删到行尾，`Ctrl+G` 打开外部编辑器。

## 38 规划和原型都要做

高层决策要早规划，技术选型要快验证，两者各有各的价值，不要偏废。

## 39 对过度复杂的代码动刀

定期让 Claude 帮你审查并简化那些绕弯子的实现，或者删掉多余的改动。重构是持续的事，不是一次性的。

## 40 把自动化本身自动化

把常用命令放进 skills、脚本或 `CLAUDE.md`。目标是把重复劳动压缩到零。

## 41 装上 DX Plugin

这个内置插件提供了 `/dx: gha`、`/dx: handoff`、`/dx: clone`、`/dx: half-clone`、`/dx: reddit-fetch`、`/dx: review-claudemd` 等命令，都是日常必备的工具。

## 42 保持学习

问 Claude 关于它自己的事，查 `/release-notes`，逛 r/ClaudeAI，关注官方账号。Claude Code 迭代很快，跟上节奏很重要。
