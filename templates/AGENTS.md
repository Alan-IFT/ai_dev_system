# AGENTS.md — Agent 开发工作规范

> **用法**：整份复制到项目根目录，命名 `AGENTS.md`。DSH 的 `dsh-agent-instructions` 会自动加载（`$DSH_HOME/AGENTS.md` → 项目根 → 工作目录，广到具体）；Claude Code 读同名或 `CLAUDE.md`；Codex 读 `AGENTS.md`。**只需填 §0，其余不改。**
> 本文件在本仓库内是载体实例、效力为零（D-020）；复制到目标项目后，它在那个项目里就是生效规范。删掉本引用块再用。

---

## 0. 项目专属（唯一需要填的地方）

```yaml
项目名：
一句话目标：
技术栈：                      # 例：TypeScript / Node 22 / Postgres
运行方式：                    # 例：pnpm dev；测试 pnpm test；构建 pnpm build
生产环境是否存在：             # 是 / 否。否 → §10 SLO 与 §9 供应链整节不适用
数据是否含个人信息或凭据：      # 是 / 否。是 → §9 全节强制
团队规模：                    # 1 人 / 多人。1 人 → §11 评审降级为"独立会话自审"
不可逆动作补充：               # 本项目特有的，追加到 §3 清单
```

**填不出的字段写 `未定`，不要留空。** 按 §4，留空与"未定"不是一回事。

## 1. 权威位置：一次定死，此后不改

**每类事实只有一处权威记录。第二处副本一律视为过期源。**

| 事实类别 | 唯一权威位置 | 禁止 |
|---|---|---|
| 意图与验收 | `ACCEPTANCE.md`（带稳定 ID） | 不在 issue、聊天记录、代码注释里另存一份 |
| 任务状态 | `WORK.md` | 不抄进 README、不抄进提交信息 |
| 项目知识与踩坑 | `PLAYBOOK.md` | 不散落在各文件头注释 |
| 失败记录 | `FAILURES.md` | 不只存在于聊天历史 |
| 证据（测试、构建、部署结果） | CI 产物 + `WORK.md` 引用 | 不手抄结论，只写指针 |
| 代码结构、依赖、配置 | 代码本身 | **不写进本文件**——会先于代码过期 |
| 决策 | `docs/adr/NNNN-*.md` | 不在 PR 描述里另述 |

**判据**：任何一个数字或状态值，在仓库里出现第二次，就是缺陷。需要引用时写链接，不抄值。

## 2. 开工前必须确认的八项事实

新会话开始、或压缩之后，先回答，答不出就停：

1. 当前工作项是什么，状态版本是多少（`WORK.md`）
2. 工作副本身份：仓库 / 分支 / 提交
3. 本次是交付型还是事实型运行（改东西 vs 查东西）
4. 起点是从头还是接手
5. 本次可触的范围（哪些目录、哪些环境）
6. 本次禁止的动作（§3）
7. 完成判据是什么（`ACCEPTANCE.md` 的哪几个 ID）
8. 上一次运行留下的未完成项（`WORK.md`）

**任何一项答不出，先补齐再动手。不许"边做边看"。**

---

## 3. 不可逆动作：必须先问人

以下动作**一律先停下来问，得到明确同意才执行**。同意只对本次有效，不延伸到下一次。

- 删除文件、分支、表、桶、卷；`git push --force`；`git reset --hard`（有未提交改动时）
- 任何写生产环境的操作：迁移、部署、回滚、改配置、改 DNS、改 IAM
- 数据库 schema 变更；批量 UPDATE / DELETE（不带精确 WHERE 或影响 > 1 行）
- 发布：npm publish、镜像推送、tag、release
- 对外通信：发邮件、发消息、提 issue/PR 到外部仓库、调用会产生费用的 API
- 安装新依赖、改锁文件、改 CI 配置、改权限文件
- 改 `ACCEPTANCE.md` 中已冻结的条目
- 覆盖或删除本文件、`WORK.md`、`FAILURES.md`

**§0 里补充的项目特有动作同样适用。**

**列表之外但你觉得"可能不可逆"的，按不可逆处理。** 判据：撤销它需不需要人工介入、需不需要恢复备份、会不会被别人看见。三个中任一为是，就问。

## 4. 三态纪律：PASS / FAIL / UNDETERMINED

**这是全文最硬的一条。**

- 每个结论都是**「结论 + 其成立条件」的一对**。写不出成立条件，记 `UNDETERMINED`。
- 以下情形**一律** `UNDETERMINED`，**不得折算为通过**：
  - 检查没跑、跑失败、或超时
  - 输出为空——**空输出永远不是"通过"**，先断言目标存在
  - 生成者与验证者是同一方，且判断涉及解释而非机械测量
  - 依赖的外部写入结果未知
  - 需要人应答而人没答
- **形如"全部 X 通过"的条件，在 X 为空集时判 `UNDETERMINED`，不判 `PASS`。**
- 聚合时 `UNDETERMINED` 不得被平均掉、不得计入通过率分子分母。

**报告格式**：`PASS 3 / FAIL 1 / UNDETERMINED 2`，三个数分列，永不合并。

## 5. 交付门：全部必过，无例外

每次声明"做完了"之前，按顺序跑完并贴结果：

| # | 门 | 通过条件 | 失败去向 |
|---|---|---|---|
| G1 | 格式化 | formatter 无 diff | 自动修，重跑 |
| G2 | 静态检查 | linter + 类型检查 0 error | 修，不许加 ignore 注释绕过（要加须在 PR 里说明理由） |
| G3 | 单元测试 | 全绿 | 修代码，**不许改测试让它变绿**（见 §8） |
| G4 | 集成测试 | 全绿 | 同上 |
| G5 | 构建 | 成功，无新告警 | 修 |
| G6 | 依赖审计 | 无 high/critical 漏洞 | 升级或明确接受风险并记 ADR |
| G7 | 密钥扫描 | 0 命中 | 立即停止，撤销泄露的凭据 |
| G8 | 验收对账 | `ACCEPTANCE.md` 里本次声明的 ID 全部有对应证据 | 补证据或降低声明 |

**没有配置某个门的项目，该门记 `UNDETERMINED`，不记跳过、不记通过。** §0 里"生产环境=否"时 G6/G7 仍然要跑。

## 6. 证据六字段

任何"做完了 / 测过了 / 部署好了"的声明，必须同时给出六项。**缺一项，声明无效。**

1. **断言**：具体说了什么（"登录接口的速率限制生效"，不是"改好了"）
2. **原始证据**：命令 + 完整输出，或 CI 运行链接。**不许只写结论**
3. **精确版本与工作区身份**：仓库 / 分支 / 提交 SHA / 环境
4. **适用范围**：在什么条件下成立（哪个环境、哪组输入）
5. **观察时间**：什么时候测的
6. **确认方法**：怎么知道它成立的（跑了哪条命令、看了哪个面板）

**当时没记，事后补不出来。** 这是全套里唯一"漏了就永久缺失"的东西。

## 7. 变更与提交

- **Conventional Commits**：`type(scope): subject`。type ∈ `feat|fix|docs|refactor|test|chore|perf|build|ci|revert`
- **一个提交一件事。** 重构与功能改动**不许**混在同一提交
- **SemVer**：破坏性变更进 MAJOR，提交体里写 `BREAKING CHANGE:`
- 分支短命：从主干切出，**不超过两天**合回。长期分支是缺陷
- **不许**：`--no-verify`、跳过 hook、绕过签名、直接推主干（多人项目）
- 提交信息写**为什么**，不写**改了什么**（改了什么看 diff）

---

## 8. 测试

- **测试金字塔**：单元 > 集成 > 端到端。端到端只覆盖关键路径
- **测试描述行为，不描述实现。** 测试名是一句话事实，不是函数名
- **证明修复的测试，不得由修复者修改。** 先写会失败的测试，看它红，再修代码，看它绿
- 新代码带测试。**修 bug 必须先有一个复现它的失败测试**
- 覆盖率是**信号不是门**——不设百分比阈值当 Gate（会奖励无断言的测试）
- 测试必须确定性。有 flaky 测试，**修它或删它，不许重跑到绿**

---

## 9. 安全

- **最小权限**：agent、CI、服务各自只拿本次需要的权限。默认只读
- **凭据永不进仓库**：不进代码、不进配置、不进提交信息、不进日志。用环境变量或密钥管理
- **输入即不可信**：所有外部输入（用户、API、文件、模型输出）先校验再用。参数化查询，不拼 SQL
- **OWASP Top 10** 作为代码评审清单；对外服务另加 **ASVS L1**
- **供应链**：锁文件必须提交；新依赖须说明为什么不用现有的；定期跑依赖审计
- **不许**由 agent 处理：真实凭据、支付信息、生产数据库的写操作、绕过验证码

---

## 10. 可观测性与运维

> §0 中"生产环境=否"时，本节整节记 `UNDETERMINED`（不适用），不删。

- **结构化日志**：JSON，带 trace id。**不许** `print` 调试后留在代码里
- **OpenTelemetry** 埋点：请求、外部调用、错误
- **SLO + 错误预算**：先定"多少算坏"，再谈优化。没有 SLO 时性能改动无判据
- **变更失败率与恢复时间**（DORA 四指标里的后两个）是发布质量的判据
- **事后复盘不追责**：写清时间线、触发条件、为什么没被拦住、加了什么机制

---

## 11. 代码评审：生产者 ≠ 验证者

- **结构性要求，不因模型变强而消解。** 写代码的和判它对不对的，必须是两个上下文
- 多人项目：至少一名他人评审，**不许自合**
- 单人项目：**开独立会话评审**——新上下文，只给 diff 与验收标准，任务是"试图证伪"，不是"看看还行吗"
- 评审者只看 diff 与验收条目，不看作者的解释
- **评审意见转成 `ACCEPTANCE.md` 的 ID 或 `FAILURES.md` 的条目**，不停留在对话里

## 12. 决策记录（ADR）

以下情况写一份 ADR 到 `docs/adr/NNNN-短标题.md`：

- 选了一个技术/库/架构，且存在真实备选
- 做了一个后面很难改的决定
- 拒绝了一个看起来很对的方案

格式（Nygard）：`## 背景` / `## 决策` / `## 考虑过的备选与为什么不选` / `## 后果（含代价）`。

**"考虑过的备选"不许留空。** 没有备选说明没在做决策，那就不需要 ADR。

---

## 13. 失败登记

任何一次"本来不该发生"的事，当场追加到 `FAILURES.md`：

```
| id | 观察到的失败 | 本该防住它的规则 | 当时被拦住了吗 | 处置 |
```

- **"当时被拦住了吗"只填 是 / 否**，不填解释
- 连续三条同形状的失败 → 把它下沉成一条机械检查（G1–G8 加一门）
- **一条规则连续失效两次仍拦不住 → 删掉它**，别加第三层补丁

---

## 14. 停机条件

命中任一即停下来报告，不许继续试：

- **同一故障连续两次修复无效，且没有新证据** → 停。重试前必须改变一个输入变量并写下改了什么
- 修改范围超出 §2 第 5 项声明的范围
- 需要执行 §3 的动作而没得到同意
- 出现 `UNDETERMINED` 且它挡在完成判据上
- 连续三次工具调用失败
- 发现自己在改测试而不是改代码

**停机不是失败。** 带着"我知道什么、不知道什么、下一步需要什么"停下来，比猜着往下做便宜得多。

---

## 15. 本文件自身

- 本文件是**语义规则**，不写目录结构、不写文件清单、不写依赖版本——那些读代码
- 新增一条规则时，必须同时写清**它防的是哪个具体失败**与**什么条件下删掉它**。两样写不出，不许加
- **本文件只增不减是缺陷。** 每次新增，先问能不能删掉一条
- DSH 的加载预算是 65536 字节，超了会**整份丢弃更宽泛的文件**——保持精简是硬要求，不是风格偏好
