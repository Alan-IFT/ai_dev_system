# 交付门与证据

## 八道门：逐道跑完、逐道贴三态，一道红了也不停

| # | 门 | 通过条件 | 失败去向 |
|---|---|---|---|
| G1 | 格式化 | formatter 无 diff | 自动修，重跑 |
| G2 | 静态检查 | linter + 类型检查 0 error | 修；加 ignore 绕过须在 PR 说明理由 |
| G3 | 单元测试 | 全绿 | 修代码，**不许改测试让它变绿** |
| G4 | 集成测试 | 全绿 | 同上 |
| G5 | 构建 | 成功且无新告警 | 修 |
| G6 | 依赖审计 | 按项目的依赖风险处置约定完成适用风险判定及处置，无未解决的阻断风险或过期例外 | 补证、修复/缓解；有权人限时接受风险，不能将接受写为漏洞消失 |
| G7 | 密钥扫描 | 0 命中 | **立即停止，撤销泄露的凭据** |
| G8 | 验收对账 | 本次声明的 `ACCEPTANCE.md` ID 全部有证据 | 补证据，或降低声明 |

**没配置或没跑成的门记 `UNDETERMINED`**（由跑门的那一层记，写明原因），不记跳过、不记通过。没有生产环境时 G6/G7 照跑。

## 证据六字段：缺一项，声明无效

1. **断言**——具体说了什么（"登录接口速率限制生效"，不是"改好了"）
2. **原始证据**——命令 + 完整输出，或 CI 链接。**不许只写结论**
3. **精确版本与工作区身份**——仓库 / 分支 / 提交 SHA / 环境
4. **适用范围**——在什么条件下成立（哪个环境、哪组输入）
5. **观察时间**
6. **确认方法**——跑了哪条命令、看了哪个面板

**当时没记，事后补不出来。** 这是全套里唯一"漏了就永久缺失"的东西——其余规则违反了还能补救，证据不能。
