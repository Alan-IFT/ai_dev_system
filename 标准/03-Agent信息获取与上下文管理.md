# 03 Agent 信息获取与上下文管理

候选实现修订见 [README](README.md)。配合 [01 项目管理标准](01-项目管理标准.md) 与 [02 项目架构描述规范](02-项目架构描述规范.md) 使用。

每个小节标题下有一行 `**执行点**`，登记这一条今天由谁或由什么在执行；取值三种：**具名角色**（链到 [01 §6 角色与写入权](01-项目管理标准.md#roles)）、**无**（链到 [01 §4.7 执行点复审队列](01-项目管理标准.md#enforcement-queue)）、**非条款**（序言、纯标题、定义或复述，本就不承担执行点）。这是登记现状、不新增义务；`无` 不是失败，是把 01 §2 N1 的未定从“没人问过”变成当场可见。

---

## 0. 目标
**执行点**：非条款（本节是序言，不承担执行点）

让每一次推理获得当前判断所需的信息，并使关键事实可从工件核查。本文处理无关信息过载、过期信息误用与跨会话状态丢失；任务失败也可能来自模型能力、工具或验收设计，须通过评估定位，不能只归因于上下文。

本文是候选实现，效力为零；不改变 `docs/` 正文与生效登记。研究依据分别链接到本轮独立研究卡。

---

## 1. 五条原则
**执行点**：[无](01-项目管理标准.md#enforcement-queue)

1. **拉取不推送。** 入口只给地图与"何时读什么"，不把可能用到的规范塞进常驻上下文。能力描述常驻，内容命中才加载。
2. **先地图后正文，先片段后整份。** 三层：清单列的入口与当前工作项 → 当前任务明确引用的对象 → 只在调查时才读的历史与无关模块。"可能有用"不是加载理由；但给少了也有补偿成本（更多搜索、测试、修复）。分层依据是**与当前判断的相关性**，不是与当前任务的距离——任务对象本身是历史时，历史就是第一层。
3. **开工前的事实由工件回答，不由聊天回答。** 目标与非目标、工作项与状态版本、工作区身份、事实源、目标环境、验收 ID、风险与阻塞、未决项——答不出先补工件。**反向同理**：工件与环境能回读的问题自己读，只把需要人裁的判断（范围、取舍、授权、验收口径）交给人；发现不确定却按自己的理解跳过，与把可自查的问题抛给人，是同一条规则的两种违反。[依据与限制：C-15](参考资料/C-15-两份技巧清单中的两条语义.md)。
4. **只有一份默认加载清单。** 可按运行类型参数化出视图，视图是同一份清单的投影；出现第二份加载列表即缺陷。
5. **进出窗口的内容有存活策略。** 工具返回默认只服务当前决策，之后窗口只留结论与回源位置；大产物不以"模型完整输出"往返，写回外部的内容取自持久工件。

## 2. 信息层级：agent 找信息的标准路径
**执行点**：[无](01-项目管理标准.md#enforcement-queue)

按"我要回答什么问题"选路，而不是按目录遍历：

| 我要回答 | 先看 | 再看 | 不要看 |
|---|---|---|---|
| 我这次该做什么、做到什么算完 | 当前工作项或等价轻量记录的目标/范围/验收映射 | `acceptance/` 里被引用的那几条 | 整份验收清单；其他工作项 |
| 现在项目什么状态、有什么卡着 | `STATUS.md` | `handoff/` 最新一份（接手时） | 历史发布记录 |
| 这个模块是干什么的、边界在哪、谁依赖它 | `INDEX.md` → `modules/<m>.md` | 该模块的契约文件 | 该模块的全部源码 |
| 这个接口/事件能不能改、改了影响谁 | `contracts/README.md` 的消费者列 | 该契约文件；相关 ADR | 消费者的实现代码（先看登记，再抽查） |
| 为什么当初这样设计 | `decisions/README.md` | 对应 ADR | 聊天记录；旧版本文档 |
| 以前踩过这个坑吗 | `PLAYBOOK.md`（按触发条件） | `FAILURES.md`（按关键词） | — |
| 出了故障怎么办 | `runbooks/` | 模块文档的可观测性节 | — |
| 怎么跑、怎么测、怎么构建 | `governance/project.yaml` | — | README 里的过期命令 |
| 这个动作能不能做 | 当前宿主权限与用户授权；项目治理入口及 `GATES.md` 中的适用限制 | 经确认有效的例外记录 | 不把检查通过或委托目的当授权 |
| 代码在哪 | `modules/<m>.md` 的入口指针；`codemap.md`（若有，注意 `source_rev`） | 定向 grep | 全仓 grep 后逐个打开 |

**路径规则**：读模块代码之前先读模块文档；改契约之前先读登记表；grep 之前先读 INDEX 与模块文档的入口指针。**文档与代码不符时登记冲突，不静默以任一方为准**（[01 §3.6](01-项目管理标准.md)）。

## 3. 默认加载合同
**执行点**：[无](01-项目管理标准.md#enforcement-queue)

可写在 `AGENTS.md` 的"加载"一节（示例见[示例项目 AGENTS.md](示例项目-连锁零售中台/AGENTS.md)）；项目已有唯一清单时只路由到该清单。下表为装配结构，不能另建成第二份清单；入口是否实际加载须按 §12 验收。

### 3.1 结构
**执行点**：[无](01-项目管理标准.md#enforcement-queue)

| 顺序 | 精确路径#片段 | 交付型·从头 | 交付型·接手 | 事实型 | 用途 | 缺失时 |
|---|---|:---:|:---:|:---:|---|---|
| 1 | `AGENTS.md`（整份） | ● | ● | ● | 规则与本合同 | 停 |
| 2 | `governance/project.yaml` | ● | ● | ● | 命令与栈 | 停 |
| 3 | `docs/state/STATUS.md` | ● | ● | ○ | 当前重点与阻塞 | 停，请求恢复状态 |
| 4 | 当前工作项 `docs/state/work/WI-*.md` 或可定位的等价轻量记录 | ● | ● | △ 请求者给定时 | 本次目标、范围、验收、上下文清单 | 关键字段缺失先补；不因未单建文件而停 |
| 5 | 最新交接 `docs/state/handoff/*` | ○ | ● | △ | 恢复凭据 | 接手无交接：先做测绘（§8.4） |
| 6 | `docs/INDEX.md` | ● | ● | ● | 地图 | 可继续，但不得猜路径 |
| 7 | 工作项上下文清单列出的对象 | ● | ● | ● | 模块文档、契约、ADR、验收条目 | 缺一项即记未定 |

● 必读　○ 不读　△ 条件读（写出条件）

表中是示例路径；采用时映射到项目既有的权威载体，允许命令、地图与入口合并。停机条件针对所需事实或约束缺失，不针对示例文件名不存在；事实型未给工作项时，由请求者问题及已确认的精确资料路径形成当前调查输入。

**运行类型两轴**：产出类型（交付型 / 事实型）× 起点（从头 / 接手）。事实型的出口是一份带成立条件的事实，不是变更，所以不读议程类内容（STATUS 的下一优先级、其他工作项）；接手比从头多一个**空转探测集**——对每个必读项问"上次被写、上次被读是什么时候"。判不清按交付型·接手处理（最宽）。

### 3.2 解析规则
**执行点**：[无](01-项目管理标准.md#enforcement-queue)

1. 路径用仓库相对 canonical path；同一 `path#片段` 只加载一次。
2. `#片段` 的外延由唯一合同规定；本实现沿用本仓库合同的“该锚点起至下一个锚点前”，不得改读成下一个同级标题前。需要跨片段逐个列出，文件头需读时明确列整份。
3. 链接不递归展开；通配符与"相关""对应""最新""当前"这类动态描述不由 agent 猜测——工作项里必须写精确路径，实际加载前解析为明确工件。
4. 合同、工作项、工作区身份（分支/HEAD）冲突时失败关闭：先核对 ID、版本、`updated_at`、HEAD，再继续。
5. 切换工作项时递增合同版本；历史版本归档不进默认上下文。
6. 视图不得增生：需要第三个视图先证明它不是已有视图的子集。

### 3.3 排除项（默认不加载）
**执行点**：[无](01-项目管理标准.md#enforcement-queue)

全部规范全文；全部模块文档；`docs/归档/历史`/已取代文档；`FAILURES.md`（只在做删减、审计、补绑定时读）；`releases/`（只在回溯时）；`artifacts/`（按引用回源）；聊天历史、旧工作项、废弃 ADR、完整日志、大段工具输出；**仅因链接可达但不在清单中的文档**。

## 4. 工作项级上下文清单
**执行点**：[无](01-项目管理标准.md#enforcement-queue)

每个工作项有一节"上下文"，是合同第 7 项的内容。轻量任务可沿用 [01 项目管理标准](01-项目管理标准.md) 的裁剪：在已有任务／变更记录中写目标、范围、责任人、验收与证据指针、上下文引用及恢复所需状态即可，不强制新建 `WI-*` 文件；记录必须持久可定位，不能只存在于聊天中。缺项时只补与本次判断有关的字段。

```markdown
## 上下文
### 必读（精确到片段）
- docs/architecture/modules/inventory.md#公开接口
- docs/architecture/contracts/EVT-inventory-stock-changed.md
- docs/decisions/ADR-0007-库存事件契约v2.md
- docs/product/acceptance/INV-库存.md#INV-014
### 条件读
- docs/runbooks/RB-03-POS流水回传中断.md — 只在联调 POS 回传失败时
- .agents/skills/inventory-migration/SKILL.md — 动手写迁移脚本前
### 明确不读
- services/pos_gateway/**（本次不碰）
### 本次不变量（压缩后重新锚定）
- 目标与范围：…；生效决策：ADR-0007；安全边界：不写 prod；工作区：main @ a3f9c21
```

**写清单的人是开工作项的人**（人或上一次运行的 agent），清单本身是可评审对象：评审看它有没有漏掉被依赖列表里的模块。清单里每一项都要能在 `INDEX.md` 里找到——找不到说明 INDEX 过期或路径错。

**"明确不读"与"本次不变量"里的禁止项与安全边界写成对执行者的指令，不写成关于环境的事实断言。** 写"不得访问互联网／不得触碰 services/pos_gateway／未授权不得对外写"，不写"你没有互联网／该服务不存在／当前是仿真"；后者一旦被环境证伪（真出现了本以为不存在或不可达的系统），执行者会据此推断该系统属于任务或演练的一部分而继续操作，安全边界随环境假设失真而整体失效。措辞是否为指令式属清单可评审项；能否真正阻断该动作另见 §12。[依据与限制：C-20](参考资料/C-20-禁止项写成指令而非环境断言.md)。

## 5. 按需层：skills、模块文档、runbook 的触发
**执行点**：[方法库归属人](01-项目管理标准.md#roles)

- **skills**（示例位置 `.agents/skills/<name>/SKILL.md`）：装配目标是让简介可发现（一句话说清"什么时候读我"），正文命中才读；宿主能否发现该目录按 §12 核验。**简介之间职责不重叠**：同一任务落到两份简介都自称适用即缺陷，由方法库归属人合并或补写"不适用场景"，触发时机是新增或修改简介、以及观察到触发错项时；工具定义同理，名称与参数须能区分适用与不适用场景。切分判据：这条规则在它该生效那一刻**必须已在上下文里**吗？是 → 进唯一治理入口；否 → 进按需方法文档。skill 可带 `scripts/` 与 `references/`，把"绑定的失败 Case"放在 `references/`。
- **模块文档**：由工作项的影响清单触发——碰哪个模块读哪份；被依赖列表里的模块读"公开接口"与"不变量"两节。
- **runbook**：由故障或联调失败触发；事故处置时是第一读。
- **PLAYBOOK**：按条目的触发条件读（每条规则写明"做 X 时"）；不整份常驻。skills 数量多时 PLAYBOOK 退化为索引，正文进 skills。

**拿不准时先查触发条件与目录说明。** 涉及当前动作的授权、安全边界或验收前提，先补读再行动；仍与本次判断无关的内容不加载。必要约束在动作完成前保留，消费后留结论与回源引用。[依据与限制：C-01](参考资料/C-01-Anthropic上下文工程.md)。

## 6. 检索纪律
**执行点**：[无](01-项目管理标准.md#enforcement-queue)

- 定向检索：先从模块文档的入口指针定位目录，再在目录内 grep；不做全仓 grep 后逐个打开。
- 大输出（测试日志、grep 结果、长文件）落到 `artifacts/`，窗口只留结论 + 路径 + 行号范围。
- 读文件优先按锚点或行号定位，但须覆盖定义、例外和相邻约束；合同要求整读、片段不足或需核对整体矛盾时读全文。行数仅用于估算成本，不能证明语义完整。
- 派生文档（codemap）先看 `source_rev`，落后即只作线索不作事实。
- 遇到与工作项无关但明显的问题：登记为候选工作项，不顺手修。
- 检索结果为空不是"不存在"，先确认检索本身跑起来了（N1）。
- 命中多条时按相关性取舍，写下取用项与被舍弃项；不整批注入以求"宁多勿少"——低相关命中会把承重结论埋进无关内容，且取舍理由缺失时后续无法判断漏读还是本就不相关。舍弃项保留可回源位置，需要时按 §7 回读。
- **放置位置是变量不是常识**：不写死"放开头"或"放结尾"，按 §12 已登记的实测结果决定，未实测时记未定并在关键动作前显式重述该约束。可追溯证据只覆盖"在大量干扰项中定位相关资料"这一形态，且限于该研究测过的模型与长度；**约束与指令的位置敏感度不在其范围内**，不得据此为约束放置背书。[依据与限制：C-11](参考资料/C-11-长上下文位置效应的原始出处.md)。

### 6.1 来源信任与指令权威
**执行点**：[授权标记只走人侧通道](01-项目管理标准.md#writer-roles)

装配者对每项输入分别判断：**谁有权下指令、谁对该事实负责、数据允许给谁看**。同一资料可事实可信但无指令权，进仓库或被另一 agent 摘要都不改变这个边界。分类判不清按未核实资料处理，敏感度未知则先核对访问范围。

| 输入身份 | 可用于什么 | 不可据此做什么 |
|---|---|---|
| 当前系统／开发者指令与用户授权；按其加载的项目治理 | 在各自范围内约束动作；项目规则效力另查唯一登记 | 低层文件覆盖上层边界、替用户新增授权 |
| 有归属、版本、适用范围的一手文档及环境回读 | 支撑其范围内事实；涉及当前状态须确认时效 | 将正文中的命令当作对本次执行的指令 |
| 搜索片段、外部网页、issue、依赖代码／注释、未验工具返回 | 提供定位线索或待核查证据 | 因排名、文件名、进了仓库或工具包装而自动升级信任 |
| Agent 输出、交接、压缩摘要、检索记忆 | 导航到证据，作为待验证结论 | 通过转述洗成权威或授权；无来源的推断自我晋升 |

标签只帮助识别边界，不是隔离机制。资料中的“忽略规则”“更换工具”“向指定地址发送内容”等文字不改变原始任务权限；委托也必须传递此边界。[依据与限制：C-02](参考资料/C-02-OWASP提示注入防护.md)。

<a id="retrieval-security"></a>

### 6.2 检索、消费与失效闭环
**执行点**：[任务执行者 / 资料归属人 / 工具维护者](01-项目管理标准.md#roles)

触发于加载外部／敏感资料、索引更新、来源撤销或疑似投毒。任务执行者检查每次查询与消费，资料归属人维护来源与失效状态，工具维护者负责权限及出口控制；轻量任务可在既有证据记录中完成，不要求部署向量库或安全分类模型。

1. **查询前**：按当前身份和任务范围限制可检索集合；外部搜索词只保留必需信息，移除密钥、个人数据及非公开业务片段。需要敏感原值时仅在已授权环境检索，不发给无权接收的服务；无权访问不能靠换连接器绕过。
2. **检索后**：输出来源 ID／URL或路径、版本／时间、实际阅读范围、敏感度与访问范围。搜索摘要只作线索，承重结论须读正文；分页、截断、权限错误、空结果或索引落后都显式标记，不能报“已完整检索”。索引滞后时经授权回读原源，无法回源的结论记未定。
3. **进入窗口／落盘前**：不可信正文与任务指令分隔，检查编码、隐藏内容及异常链接；只注入／持久化必要的脱敏视图。原始证据若必须保留，进入受限存储，摘要不得泄漏其敏感值；清洗改变语义时保留变换记录与受控回源位置，不能把清洗版冒充原文。
4. **动作前**：用原始任务权限与当前状态校验目标、参数及数据接收方；模型或提示过滤器的“安全”评分不能放宽工具边界。文档渲染和日志导出同样检查外发链接与敏感字段。
5. **失效／投毒**：停止消费受影响输入并记录来源、受影响动作与责任人；从检索候选中隔离原条目、缓存及可追溯的摘要／记忆。回到未受影响的权威源，重新验证依赖结论；疑似已发生外泄或越权交由项目安全处置流程。保留必要受限证据，不能通过删日志掩盖问题。找不到衍生链时，该范围内结论先记未定，不静默复用。

验收用虚构敏感标记和恶意／正常资料成对测试：检查越权读取、外发、工具动作是否实际发生，以及正常任务误拦；来源被更新或撤销后，旧版本不能继续充当当前事实。失败时暂停相应数据源或工具写能力、修复后重测；未部署的防护明确记未定，不写“已防住注入”。

## 7. 工具返回外部化
**执行点**：[无](01-项目管理标准.md#enforcement-queue)

- `docs/state/artifacts/<WI>/<序号>-<描述>.txt`（或项目约定的位置）；不进版本控制或只提交索引，由项目参数决定。
- 落盘工件记录来源版本／采集时间、命令及退出状态、完整或截断、敏感度、允许访问者与保留／失效条件；无退出码的接口记录完成／错误状态。窗口保留结论、成立条件、路径与实际用到的范围，沿用 §6 的信任身份。
- 后续优先回读该文件的**局部**；需核对完整语义或整体证据时按 §6 扩读，不为节省长度漏掉约束。
- 由确定性程序在推理前采集的固定观察集（测试结果摘要、依赖检查结果）作为带时间戳的观察推送到下一步，消费后即清理，不累积。
- **工具与窗口之间的有损压缩／摘要组件按场景启用，不做必经之路。** 触发于接入或扩大此类组件的适用范围。工具维护者登记允许压缩的命令类别、旁路类别（写操作、状态查询、输出还要被脚本解析的命令）与回退条件；组件缺失、拒绝处理、超时或输出异常为空时自动回原始命令。执行者设熔断：预期线索未出现即用原始输出复核，同一任务再次需要宽泛检索时后续检索与读取全部切回原始输出；证据核对与最终验收始终用原始输出。每次运行记录哪些命令走了压缩、哪些被跳过、哪些回退，作为 §11 的度量输入。**这类组件的失败方式是静默丢线索而不报错**，因此不得以"输出变短"验收，须按 §11 端到端对照；未做对照即记未定，不升为默认。[依据与限制：C-06](参考资料/C-06-上下文给对而非少给.md)。

清理指退出窗口；外部工件按保留策略处置。路径可访问不等于有权外传；输出再次交给 Agent、报告或日志平台前，重新核对接收方与脱敏范围。

<a id="recovery"></a>

## 8. 压缩与会话结束
**执行点**：[执行者写 / 接手者核验 / 项目负责人定可接受丢失量](01-项目管理标准.md#roles)

**结束前回调只作补充，不能作为恢复的唯一保障。** 正常结束、压缩、取消、崩溃与宿主强制终止的通知能力须分别验收；未知能力不得依赖。执行者在阶段完成、关键事实变化、交接前保存检查点，不等窗口耗尽；重复询问、同类错误、阶段切换也是检查信号。检查点由执行者写、接手者核验，项目负责人负责确定可接受的丢失工作量。[依据与设计推导：C-01](参考资料/C-01-Anthropic上下文工程.md)。

### 8.1 压缩/结束前
**执行点**：[无](01-项目管理标准.md#enforcement-queue)

将最近检查点更新为交接（`docs/state/handoff/<WI>-<日期>.md`，或等价轻量记录），两半；写入失败应报告，不声称已交接，停止会扩大恢复缺口的后续写操作：

- **叙事摘要**：目标与范围、已生效决策、工作区身份与状态版本、已完成项与证据位置、未完成原因、未解决错误、风险、**下一个原子动作**、失败尝试的假设及证据；原始轨迹退出窗口但按保留策略外部保存，不因压缩删除审计证据。
- **活动工作集引用**：正在编辑或验证的少量文件按路径列出，重建后按引用原样重载，不摘要。

### 8.2 重建后
**执行点**：[接手者](01-项目管理标准.md#roles)

重新核对合同、工作项状态版本、HEAD；把**本次不变量**（目标与范围、生效决策、安全边界、工作区身份）重新放到高注意力位置（工作项"上下文"节末尾那段）。压缩产物**不是**项目知识也不是长期记忆，不能自证正确——摘要里的每个结论仍是"结论 + 成立条件"。

重建验收由接手者按原工件逐项检查目标、禁止项、未解决错误、活动引用与下一动作；关键项丢失先补读，不能靠摘要猜。强制终止且没有最终交接时，从最近检查点及环境回读恢复；检查点之后的动作状态先记未知，再按 §9.5 对账，不能整段盲重跑。

### 8.3 交接的接收方
**执行点**：[交接接收方](01-项目管理标准.md#roles)

先核对身份与状态版本（不一致失败关闭），再核对已执行的不可逆动作清单，再把有效变化合并回工作项、递增状态版本、归档交接。**旧交接不直接覆盖工作项。**

### 8.4 无交接的接手（测绘）
**执行点**：[接手者](01-项目管理标准.md#roles)

先声明运行类型；把出口定为"一份带成立条件的事实"；核对工作区、现有检查点与动作证据，登记哪些状态可证、哪些未知。没有读取日志时不能以文件访问时间证明“被读”。需要反例注入时只在隔离副本或获准测试环境执行；按缺口补恢复记录，由接手者做照单加载演练再继续交付。轻量任务允许使用同一等价记录，不另建测绘文档；独立复核缺席的判断记未定。

## 9. 子执行者与委托
**执行点**：非条款（本节是纯标题，条款在 §9.1–§9.5，不承担执行点）

### 9.1 何时委托
**执行点**：[委托授权只走人侧通道](01-项目管理标准.md#writer-roles)

验证者分离有助于发现生成者盲区，**不是自动授权委托的理由**。能否创建或调用子执行者、提供哪些数据与工具，仍由当前宿主和用户授权决定；未获相应权限时保留可评审工件、声明独立验证未完成，不能以质量要求绕过限制。获准后给验证者产出物、验收标准及必要原始证据，不能只给生成者的成功摘要。其他拆分须举证：子任务相对独立、输入输出与完成条件清楚、上下文隔离有收益、有独立验收、汇总者能核查来源与冲突、预期并行收益大于协调成本。高度耦合的取舍、同一热点的竞争修改、边界不清、没有合并验收的场景**不拆**。成本账按**复用次数**算：固定编排的开销（多份输入约定、状态结构、以及合并漏项、路由死循环、状态跨执行者泄漏这些新增失败模式）在反复运行的任务上摊销，在只跑一次的任务上无处摊销——同一笔开销在两类任务上结论相反。首次采用时以代表任务验证收益，不把研究任务收益外推到编码任务。[依据与限制：C-03](参考资料/C-03-Anthropic多Agent研究系统.md)；[复用次数判据：C-10](参考资料/C-10-图编排与循环编排的取舍.md)。

### 9.2 委托合同
**执行点**：[无](01-项目管理标准.md#enforcement-queue)

每次委托写下（可以很短）：

| 字段 | 内容 |
|---|---|
| 身份与责任 | 委托 ID、尝试 ID、父工作项、派发者／执行者／收口者、状态版本 |
| 目标与完成条件 | 一句话 + 验收 ID；证据要求及接收方 |
| 输入工件 | 精确路径或受控引用、来源版本／敏感度／信任身份、基线 HEAD 与相关文件内容摘要值；只给必要历史。上游已确认的定位结果（文件、符号、调用关系、已排除项）随委托传下去，下游先复用再按缺口补查，不各自从零测绘 |
| 允许的动作 / 禁止的动作 | 读集、独占写集、工具与数据接收方；子任务默认不执行不可逆动作；已有明确授权也须逐项传递，不能由“委托”推导授权 |
| 治理继承 | 必须继承主线适用的治理与权限边界，权限只能收窄；派发者确认子执行者实际收到必要约束。无法确认时只给受控的只读／纯输出任务，敏感输入仍须访问授权 |
| 返回格式 | `{委托ID, 尝试ID, 基线版本, 结论, 三态, 成立条件, 证据位置, 变更清单, 动作回执, 盲区}`；格式不符先补齐，不能因 JSON 合法就当结论可信 |
| 预算与停机 | 时间／轮次／费用上限、检查点位置、超时／取消通道；**带重试或多轮发现的委托另登记证据型停机**——连续若干轮没有新的环境回读、新的失败定位或新的可核对事实即停并上报，其去重基线取全部已见候选（含已被否决项）而非仅已确认项，否则被否候选每轮重现、循环只能耗尽资源上限才退出；完成、预算到限、无新证据、边界或证据异常分别收口为待验收、交接、停止依赖动作并报告（[停机判据：C-16](参考资料/C-16-Loop家族三篇的失败模式核对.md)） |

### 9.3 三类隔离原语
**执行点**：非条款（本节是定义，不承担执行点）

- **委托**：只装配必要输入，返回结论与持久工件引用——独立的高输出操作可采用。
- **分叉试探**：宿主若支持选择性或完整历史复制，按敏感度与任务需要核验后使用；试探产物不自动回流主线，要采用须经过同样验收。
- **压缩外部化**：主线自身瘦身——§8。

### 9.4 并行纪律
**执行点**：[无](01-项目管理标准.md#enforcement-queue)

派发者先检查写集重叠。共享仓库可用不重叠文件写集或隔离工作树；同文件交给单一写入者，其他任务只给补丁提案。独占声明不等于机械锁：收口者在应用前比较输入基线、当前文件内容和补丁前提；当前内容已变化先重读、协调冲突并重验，不整文件覆盖或回滚别人的修改。未提交变化也须纳入比较，HEAD 相同不足以证明基线相同。

总状态（工作项、STATUS、共享入口、契约）由指定收口者更新；汇合报告 `expected / received / missing`，逐路核对身份、版本、写集、来源、验收证据及总成本。缺一路或证据不可核记未定；确定违反验收记失败；完整且满足标准才通过。**承重结论要能追到环境锚点**：沿委托链向上追溯，直到遇到环境回读、程序断言或人的确认；每层都只消费上一层的结论、全链没有一次触及环境时记未定——单跳合规（§6.1）不保证整条链有依据。自由文本可作解释，承重字段先规范化并核验；不因某一路自称完成而更新总状态。编排、汇总、重试成本与子执行者消耗一起计量。**编排者自身的上下文随阶段增长同样计入预算**：固定的状态迁移、路由、去重与格式化汇总交由确定性程序执行，编排者只在需要判断时加载该阶段的交接与产物路径，不在每一站重新加载全部产物。

### 9.5 超时、恢复与重放副作用
**执行点**：[派发者 / 执行者 / 收口者](01-项目管理标准.md#roles)

派发者维护委托记录，执行者写阶段检查点，收口者核验实际动作。单人低风险任务可用一个文件的串行记录；有并发重试或外部写时，必须具备下列同等保障，不能用约定冒充锁或恰好执行一次。

1. **状态与恢复**：记录待派发、运行、待验收、完成或已停止，另记超时／取消／错误原因。恢复读取委托 ID、最新尝试、输入版本、检查点和动作账；模型／工具／合同版本改变时先判断检查点兼容性，不混用两版假设。
2. **超时与撤销**：超时不是“未执行”。先撤销旧执行者的写资格并确认停止，才能重派同一写集；自动编排可用递增隔离令牌在写入端拒绝旧尝试，单机则串行核对进程终止。只靠租约到期而未阻止旧写者不算隔离。无法确认停止时保持隔离空间，不启用第二个共享写者。
3. **迟到结果**：已撤销或旧版本结果仅进隔离证据区；由收口者判定是否可重验采用，不直接覆盖新工作项或触发后续动作。接收消息去重与工具副作用去重分别处理。
4. **动作账**：有副作用的调用前持久记录跨重试稳定的动作 ID、目标、参数摘要、授权依据与“待执行”；返回后记回执及环境回读。尝试 ID 可变，动作 ID 不随重试改变；敏感参数按 §6 脱敏。
5. **未知结果**：调用超时、进程崩溃或回执丢失先查接收方状态。支持幂等键且仍在有效去重期限内时，以原键核对／重试；否则必须证明未生效才重放。查不清保留未知，停止依赖写动作并交责任人对账，禁止从头重跑整个任务。补偿操作也要有授权和回执，不能假定撤销无副作用。

验收在隔离环境模拟写冲突、旧执行者迟到、调用成功后丢回执、合并前终止；须能恢复最新可证状态且没有重复副作用，正常不重叠任务可合并。仅完成文档协议或本地格式检查时，运行保障仍记未定。

## 10. 记忆与沉淀
**执行点**：非条款（本节是引子与判据陈述，不承担执行点）

记忆的目的是让下一次任务少走弯路，不是保存历史。条目数量不是成功指标；**判据是它能否降低下一次任务的不确定性**。记忆提供背景、已排除路径与方法，确定性验证仍由测试与检查项承担：**记忆不替代测试，测试也不解释历史原因**，两者缺一都不能声称"这个坑已经堵上"。

### 10.1 候选、入池与批准
**执行点**：[记忆归属人（批准）](01-项目管理标准.md#roles)

- **候选从哪来**：交付链的状态转换（评审通过、验证完成、发布、任务失败）作为副产品提取；来源只取人的输入或可定位的观察（命令输出、日志、diff）。**模型自己的推断与输出不作候选**——它进本次运行的证据与轨迹，不进记忆。批量从历史轨迹自动抽取会把未验证推断送进池子，采用前须先有本节的验证升级与置信分级。另有一类候选**只在跨任务回看时才出现**：单次看是偶发个例、若干次任务合起来看是同一处系统性短板；周期维护时回看跨任务轨迹提出候选，仍由人裁，不自动升级。
- **候选放哪**：工作项的"候选沉淀"节。周维护时由人裁：进 PLAYBOOK（规则，带失败绑定与删除条件）、进 skills（细则）、进 FAILURES（失败）、进模块文档"已知坑"、或丢弃。**归类判据写在唯一的路由文档里**（同一条同时像两处时按什么裁），灰色地带按该判据裁，不逐次临场决定；判据不足时补判据，不靠个人记忆维持一致。裁决同时记不采纳的去向与理由。**§10.2～§10.4 的条目要求随条目走**：落到哪个载体都要带作用域、验证状态与复核／删除条件，不因进了 PLAYBOOK 或 skills 而豁免（[核对：C-12](参考资料/C-12-CoALA记忆分类学核对.md)）。
- **权威怎么来**：入池由客观信号（关联到已验收的工作项）；成为权威由归属人批准。两个动作分开。
- **权威载体跟项目走，不跟宿主或账号走。** 记忆的权威位置是项目的持久工件；宿主、账号、模型或框架更换不得导致项目记忆丢失，也不得因此产生第二份权威。**工具自带的自动记忆**只当草稿本：默认关闭或限定为个人偏好；项目事实不复制进个人记忆；个人偏好进入项目会话时效力低于项目规则。反方向同样受限：个人记忆中含他人、组织关系或职责分工的条目，进入项目会话、共享上下文或委托输入前按 §6.1 核对可见范围、按 §6.2 脱敏，不因"是我自己的记忆"跳过。

### 10.2 条目结构
**执行点**：[无](01-项目管理标准.md#enforcement-queue)

每条记忆是**抽象 + 证据 + 作用域 + 验证状态**的组合，缺任一项不得晋升为可驱动动作的条目。

| 组成 | 至少写什么 | 缺失后果 |
|---|---|---|
| 抽象 | 结论或步骤，以及**适用条件、已排除的路径与理由、验证方式**；只有结论没有适用条件即退回候选 | 找得到相关内容仍重复同样的推理错误；已被否决的路径被重新尝试 |
| 证据 | 可定位的原始锚点（任务／工作项 ID、命令输出或日志路径与行号范围、提交或 diff、验收 ID） | 抽象在多轮摘要后失真且无法核对，摘要自证（§8.2） |
| 作用域 | 归属人、适用仓库／**分支／路径／环境**、版本区间、生效与失效时间、敏感度与访问范围 | 正文高度相似而实际路径或环境不同的两条被按相似度择一，动作落到错误目标上 |
| 验证状态 | 由什么证据支持（测试、提交、人工评审），以及三态判定 | 未验证内容与已验证内容同权进入决策 |

上层抽象负责减少阅读量，原始证据负责防止失真；**上层不取代下层**，抽象条目必须能沿锚点回到原文。

条目另分**稳定**与**动态**两类：动态条目（当前阶段的状态、组织关系、环境配置）登记复核周期，到期未复核即降为待核查——事件触发的复核（§10.4）抓不到没有触发事件的过期，把阶段性状态当成长期规则是一种典型的静默失效。

### 10.3 置信分级与召回
**执行点**：[无](01-项目管理标准.md#enforcement-queue)

条目分三级，不是"保留／删除"两态：

| 级别 | 成立条件 | 允许用于 | 不允许 |
|---|---|---|---|
| 强 | 作用域匹配、有验证证据、归属人批准 | 进入计划、动作与验收依据 | — |
| 弱 | 作用域部分匹配或验证不完整 | 作为风险提示与待核查线索 | 直接作为动作依据 |
| 背景 | 只有相关性信号，无验证 | 帮助发现候选、扩大检索 | 进入计划或动作；作为结论引用 |

- **召回顺序**：先按身份、权限与作用域缩小候选集（§6.2 第 1 步），再做相关性判断；无权访问的条目不进候选池，而不是召回后再删。
- **召回不得挤占合同。** §3 合同的必读项与工作项明确绑定的约束不参与相似度竞争，也不因记忆召回被替换或截断；记忆只在必读项之外补充。
- **召回时机**：任务开始时只装配入口——条目名称、触发条件、作用域与摘要；确认适用后才展开细则与原始证据（§5、§6）。入口来自记忆索引，**索引与条目同批更新**：写入或修改条目而未同步索引的那次变更即缺陷，索引落后会让渐进召回的第一层本身不可信。
- **同一任务内锁定版本**：任务期间对已召回条目锁定版本，前后两次读到的同一条规则必须一致；期间发生变更时显式报告并由执行者决定是否重启该判断，不静默换版本。

### 10.4 冲突、过期与撤销
**执行点**：[无](01-项目管理标准.md#enforcement-queue)

- **冲突**：作用域相同而结论相反的两条同时命中即失败关闭，先按作用域与版本优先级过滤，仍冲突交归属人裁并登记（§2 路径规则）。相似度不作为裁决依据。
- **过期与撤销**：条目带来源 ID、版本、敏感度及失效条件；源变化触发归属人复核，源撤销／投毒按 §6.2 隔离原条目及衍生摘要。零消费条目可退出检索但不删；再次引用时先核版本、授权与有效性，通过后才恢复，不能因"被引用"自动复活。
- **降级路径**：证据失效、作用域收窄或出现反例时降级或撤回，不是只能删除；降级须记录原因、版本与复查时机。**删除与降级要有结构性触发**（§10.2 的复核到期、容量上限置换或项目选定的等价约束），不依赖归属人或提取环节自行想起——只设入库闸而无触发时，库只增不减是可观察的常态。[依据与限制：C-14](参考资料/C-14-自进化回路的两类退化.md)。
- **回退粒度到条**：记忆变更逐条可单独撤销。批量写入且只能整批回滚时，一条被污染的条目会连带撤掉同批的正确条目，处置成本反过来抑制处置。

### 10.5 注入记账与负反馈
**执行点**：[无](01-项目管理标准.md#enforcement-queue)

装配时记下注入了哪些条目（到达）；使用后记有帮助或误导（有用）。只报到达率视为反馈环缺失。**负反馈必须实际改变后续路由**：被标记为误召回或过期的条目，后续同类任务的召回结果须可观察地变化（降权、撤回或收窄触发条件）；只记录而路由不变，等同于没有反馈环，不能指望下一次由模型自己重新判断。

[依据与限制：C-07](参考资料/C-07-团队记忆工程实践.md)、[C-09](参考资料/C-09-个人记忆库的归类与维护.md)。

按需走查：[反馈跨任务生效演练](示例项目-连锁零售中台/反馈跨任务生效演练.md)将本节与 §11.1 接成一次可取证流程，覆盖重复提醒、独立复现、误归类和撤销后的新任务；是待执行示例，不是效果证明。来源取舍见 [C-19](参考资料/C-19-CyberneticAgent反馈闭环的取舍.md)。

## 11. 预算与度量
**执行点**：[无](01-项目管理标准.md#enforcement-queue)

**预算由项目校准。** 不设跨模型通用的行数、skill 数或 token 安全线。负责人为任务类型登记模型／宿主版本、上下文上限、输出与工具预算预留、告警值、依据和复查条件；无数据时先采用显式标为试验值的预算，在代表任务上测量后调整。超预算先去冗余，必要约束仍放不下时拆阶段或交接，不以删验收／权限内容换达标。

**怎么量**：宿主的上下文视图或 token 计数；每任务按来源（系统指令、能力描述、历史、工具返回、人的输入、模型输出）× 是否重复携带（缓存/新输入/输出）× 执行单元分解——只报总量的优化提案不进评审。

**调查信号**：入口挤占任务及输出预算；重复读同一版本而没有新问题；已装入的约束被遗漏；新会话长篇复述历史。这些是定位线索，不是失效证明；文件已变化或验证需要回读时，重复读取可能合理。**信号从哪读**：AI 运行的留存记录与其字段见 [04 §6.1](04-可靠性安全与运行维护.md#agent-run-observability)，本节不重复其口径；没有留存记录时这些信号只能靠回忆，按未定处理。

**处置顺序**：先去无关与重复信息，再按需外部化，最后压缩。分别计量文档库存、每轮输入和整任务成本；外部化可能减少重复携带，但也可能增加回源，不能只看某一轮变短就宣布节省。优化以同任务完成质量与总成本比较验收。

**三层验收，缺一层不算证据**：局部（该次返回缩短多少）、**行动路径**（步骤数、补偿性检索、修改与测试轮次、测试失败次数）、整任务（总输入输出、成本、延迟与验收结果）。每轮更短而总量更高是常见形态——被裁掉的线索由后续搜索、修改和测试补回来，所以行动路径的变化必须单列计量，不能由局部与总量倒推。优化手段按**任务形态**登记适用与不适用范围（如"目标符号明确"与"需逐点核对具体位置"结果可能相反），至少在两类形态上各取样；方向不一致时分形态登记，不做跨形态外推，也不因一类任务的收益把该手段设为默认。[依据与限制：C-06](参考资料/C-06-上下文给对而非少给.md)。

### 11.1 能力、上下文与回归评估
**执行点**：[维护者 / 任务负责人 / 验证者](01-项目管理标准.md#roles)

模型、提示、检索／压缩策略、方法库、工具或委托编排变化时，由维护者组织受影响用例；任务负责人事先定义成功／失败与允许变化，验证者检查环境结果与证据。输入记录任务 ID、来源快照、模型／宿主／工具／合同版本、权限、上下文配置、初始环境、预算、判定器版本与重复次数。轻量项目可从已有人工验收和少量真实失败开始，用文件与脚本保留记录；次数和样本量按风险与波动决定，不设通用达标数字。[依据与限制：C-04](参考资料/C-04-Anthropic-Agent评估.md)。

**判据未稳定时不先建用例集与评分器。** 触发于新任务类型首次纳入评估、或既有成功判据被一次评估结果推翻。此阶段任务负责人先看真实运行轨迹，出口是一份可判定的成功／失败描述；判据稳定后维护者才构造可重复用例集与评分器。判据仍不可判定时该轮记未定，不出比较结论——在标准变动期构造的用例集会把当时的错误目标固化，此后每次门控都通过而比较全部落在错目标上。项目已有稳定人工验收判据可直接复用时跳过本步并记理由。[依据与限制：C-13](参考资料/C-13-轨迹先于用例集的评估次序.md)。

| 评估对象 | 成对用例与观察 | 验收重点 |
|---|---|---|
| 任务能力 | 真实困难任务及可解的参考任务；新能力与既有回归分开 | 成果满足验收、原文支撑结论、覆盖所需事实；不以任务结束自报为准 |
| 上下文选择 | 同任务基线与候选；该检索／不必检索、最新／过期、相关／干扰资料 | 必要事实与约束保留，过期事实不误用；同时报漏项、误触发、回源及总成本 |
| 记忆与沉淀 | 同类前后任务成对；强／弱／背景条目、作用域相符与不符、条目被撤销后；**同一批轨迹由不同提取或归类方式产出的两组条目**（提取环节本身也是被评估对象，不默认可靠） | **禁止未来信息泄漏**：只允许使用被评估任务发生前已存在的条目，目标任务之后产生的结论不得充当它的历史经验，否则该组结果无效；另查弱／背景条目是否被当作动作依据 |
| 压缩与恢复 | 未压缩／压缩后；正常交接／强制终止／缺失检查点；**有损裁剪或缓存驱逐后思考／推理历史被静默丢弃**（含陈旧会话、工具调用中途追加等角落触发） | 下一动作可恢复、未解决错误和禁止项未丢；对副作用未知状态不盲重放；**静默丢弃会穿透常规评审／单测／端测，须有专门探测其发生的回归用例**（表现为重复动作、乱选工具、无法解释先前决策），并按 §7 端到端对照、不以"输出变短"验收 |
| 注入与权限 | 恶意与正常输入、允许与禁止动作、来源有效与撤销 | 检查实际读取、外发和工具副作用；既要拒绝越权也要能完成正常任务 |
| 并行委托 | 串行基线／独立并行；写集冲突、迟到、缺路与正常汇合 | 正确收口、无越界覆盖／重复副作用，完整计算协调成本 |

**用于挑选改动的用例集与最终验证用例集分离**，挑选集不暴露给产出改动的一方；只在同一批用例上反复迭代会得到该批上的高分与新问题上的失效，两集有交集时该轮验证结果无效。**比较须预算对等**：上下文、工具调用与总成本对齐后再比较，靠多花预算换来的提升在预算收回后消失，不算改进。**新增规则或方法须证明增量**：跑有／无两组，用例要有难度梯度，并在轨迹中检索该规则要求的关键步骤；两组结果无差异，或轨迹显示该步骤未被执行、关键校验被绕过，则不新增或按规则减法删除——结果正确而路径错误只说明这次碰巧。**改动须拆到可单独回退的最小单位跑有／无两组**（逐行或逐块）：多行或多块一起改会得到"整体退化却说不清是哪一条"、无法做规则减法；模型专属的改动绑定到目标模型，一条改动不得无区分地同时命中多个模型（[依据与限制：C-21](参考资料/C-21-系统提示变更的回归门槛与逐行消融.md)）。**同一方法也是版本变更后的减法触发**：模型或宿主版本变更时，为旧版本新增的入口条目、工具说明与临时补丁按同一有／无两组复查，无增量即删除并记版本与理由；未复查的记未定，不以“当初新增时有理由”长期保留（§12 的升级复验只验能力，不回答冗余）。[依据与限制：C-18](参考资料/C-18-ClaudeCode作者访谈的二次利用.md)。

**用例与其答案不得同源。** 触发于用例或期望结果由模型生成时。参考答案与判定须能追到环境回读、程序断言或人的确认（§9.4 同一判据的评估侧落点）；由出题方自己给出答案时，得分只证明解题方与出题方的猜测对齐，回路会在未经外部证实的目标上收敛且每轮都显示提升。追不到锚点的，该组结果只作线索，不作改进依据、不进回归集。[依据与限制：C-14](参考资料/C-14-自进化回路的两类退化.md)。

**引入外部或第三方用例集作能力或回归基准前，先审计其坏例并分类、带审计版本。** 触发于采用外部基准、外部基准被推荐或被作为对外结论引用、以及定期复核在用外部基准时。坏例分四类：过严测试锁死提示未要求的实现细节、提示欠定（隐藏测试强制的条件无法从提示合理推断）、低覆盖（不完整的修复也能通过）、提示误导（把模型指向错误行为或与测试相悖）。坏例比例高的基准只作线索、不作承重结论（不据其单独下能力、发布或回归判定）。基准还会随时间失效——同一基准的通过率在数月内大幅变化，既可能是能力提升也可能是基准饱和或污染，须结合坏例审计判断，不以通过率单独下承重结论；审计版本失效（基准更新、模型代际跨越）后重审，不把旧审计带入新版本。坏例比例与通过率数字只作观察，不作规则论据与达标线。[依据与限制：C-22](参考资料/C-22-引入外部评测集前先审计坏例.md)。

每次试验从干净且等价的初始环境启动，隔离缓存、历史、记忆与其他试验产物；被测执行者不得修改评分器或答案。先用已知正确结果与故意缺证／错误结果检验评分器，避免恒通过或恒拒绝。确定性结果优先用环境回读／程序断言；开放结论采用清楚的评分准则与独立复核，模型判定器须与人校准，证据不足允许返回未定。除权限与必要状态顺序外，不强制唯一工具调用路径。

输出逐例记录通过／失败／未定及原因、证据、工具调用、成本与延迟，并保留任务数、尝试数和配置；不能删除失败或把未定计入通过。多次尝试至少一次成功（`pass@k`）与全部成功（`pass^k`）回答不同问题，不能用挑最佳一次证明持续可靠；有环境共因的试验不能假装独立。局部分数用于诊断，不能抵消越权、证据缺失等必要条件。

回归或安全用例失败时暂停相应升级，恢复已验证配置或收窄能力；先从轨迹区分模型、检索、工具、编排及评分器问题，修复后复跑受影响用例。未运行／环境失败记未定并交责任人处置。已稳定的能力用例进入回归集，饱和的能力集补更有区分度的真实任务；退役用例记录原因与版本，不能为提分静默删失败。生产观察与反馈继续补充离线评估盲区。

**结果回流。** 评估的出口是工件变更或一条明确的"不处理"记录，只进报告即缺陷。按根因分路：跨用例复现的系统性模式改规则或方法文档；孤立个例按 §10 进记忆并标为反例与适用条件；缺工具或缺能力按 §12 登记，不在规则层反复打转；回归回滚并冻结相应升级；通过的进回归集。由此产生的每次变更记版本、改了什么、**由哪次评估触发**、在什么用例上验证过，供后续排查沿"异常→版本→变更→验证证据"回溯。批准环节须能被抽查证明实际发生，逐条走过场记未定不记通过。

**回路自身的边界与方向。** 自动改进回路不得修改评估集、评分器、安全边界与权限配置——改自己的判分与自己的权限即回路失效（§6.1、§12）。逐次门控只判断"这次有没有引入回归"，不判断"若干次之后整体是否还朝原定目标"；因此另登记少量方向性观察量（如输出长度、工具调用次数、拒绝率等由项目选定的量）与阈值，并周期回看规则库与记忆库的构成变化是否仍与原定目标一致。每步都通过门控而整体偏移，是这条回路的特有失效方式，只有回看能发现。[依据与限制：C-08](参考资料/C-08-评估回流与自进化回路.md)。

## 12. 按版本登记的能力验收
**执行点**：[无](01-项目管理标准.md#enforcement-queue)

本文不维护宿主支持矩阵。项目工具维护者在自己的接入记录中登记**产品／宿主版本、运行模式、操作系统、模型、配置摘要、资料 URL 与核验日、测试用例、实际结果与证据、归属人、复验条件**。文档声称与本地实测分列；没有证据的格记未定，不能推成“不支持”或“已经可靠”。升级或影响能力的配置变化后复验，不把旧版本结果直接带入新版本。

| 能力 | 最小验收及证据 | 失败／未定时的降级 |
|---|---|---|
| 唯一入口与按需方法 | 核对真实加载路径、优先级、子目录与子任务继承、实际长度限制、**同层级冲突指令的处置（报错还是静默择一）**；含头／中／尾不同约束的正反任务均需观察，单句复述不证明完整遵从 | 显式装配必要约束并记录；不能确认关键边界到达时停止依赖动作 |
| 权限与隔离 | 在获准测试环境运行允许／禁止的文件、网络和工具操作；确认低层项目文件不能放宽上层限制，回读实际副作用 | 收窄到可验证的只读／隔离输出；CI 守住的是其覆盖的提交或发布环节，不能代替执行时隔离 |
| 检查点与结束通知 | 分别测正常结束、压缩、取消、超时、崩溃、强制终止后的恢复；保存检查点与回读证据 | 依靠阶段落盘及人工接手，不依赖结束回调 |
| 拦截与故障行为 | 实测超时、异常退出、缺配置时动作是否仍发生；区分只记录的探测和能阻断的边界 | 仅把日志当观察；未证实能阻断时不授予相应自动写能力 |
| 委托及并发控制 | 验证治理／敏感度继承、写集、取消、旧尝试隔离、结构化结果及 §9.5 重放对账 | 串行、只读子任务或补丁提案，由单一写入者收口 |
| 长时程守规与持续性 | 在允许的长序列任务上验证守卫是否仍拦得住：能力更强的模型会持续尝试绕过（拆分凭据、嵌套子会话、寻找出口），旧模型碰到沙箱／边界即停不代表新模型也停；单步审批通过不代表整段轨迹合规，证据取一次长序列运行的轨迹级观察（[04 §6.5](04-可靠性安全与运行维护.md#unattended-operation)）。同一守卫在旧版本成立不自动带入新版本 | 收窄到单步可判定的动作或人盯着的短序列；轨迹级监测未验证前不授予长时无人值守（依据：[O-19](参考资料/O-19-长时程模型的轨迹级监测.md)） |
| 状态与证据接口 | 验证落盘持久性、版本、截断／字段变化检测与重启可读性，记录接口实际返回字段 | 使用可核查外部工件；解析失败记未定，不跳过证据 |
| 检索与自动记忆 | 验证访问范围、来源可追溯、敏感字段处理、撤销／到期后的索引与记忆失效 | 停用受影响来源或自动记忆，转受控的按需回源 |
| 输出可重复性 | 按 [04 §6.2](04-可靠性安全与运行维护.md#agent-run-observability) 声明的档次（逐字一致／产物等价／多次采样落在区间）分别实测，同一输入在有并发负载与无并发负载下各取样比较；标注该档属接口契约保证、本地实测还是间接推断 | 只承诺产物等价或区间，并在验收记录的 `limitation` 写明；托管或闭源服务上不声称逐字可重复 |

低风险单人任务可从文件、现有检查脚本与人工检查点起步；只有这些手段不能满足已出现的恢复、并发、权限或观测需求时才增设机制。升级按具体失败或验收缺口决定，不以人数、Agent 数或固定目录作为充分条件；首次启用高风险能力前同样须验收，不能等事故发生才验证。能力测试通过只是适用证据，**不产生用户授权，也不改变宿主权限**。[评估依据：C-04](参考资料/C-04-Anthropic-Agent评估.md)。

## 13. 反模式
**执行点**：非条款（本节是 §1–§12 的复述，不新增条款，不承担执行点）

| 反模式 | 为什么坏 | 改成 |
|---|---|---|
| 入口里堆全部规则 | 可能掩盖当前必要约束，不能只靠长度判断 | 按任务校准；细则按触发条件加载，保留必要边界 |
| 新会话先读全部文档"熟悉一下" | 动手前窗口已满；读的多数与本次无关 | 按合同与工作项清单 |
| 从聊天记录恢复状态 | 似是而非 | 从工作项与交接恢复 |
| 工具输出留在窗口里 | 每轮重复计费，注意力稀释 | 落盘，留结论与指针 |
| 摘要当事实 | 摘要不能自证 | 摘要里每个结论带成立条件，关键工件按引用重载 |
| 让 agent 自己决定记什么 | 自我强化的推断进库 | 提取绑定状态转换；人批准晋升 |
| 给子执行者整段历史 | 试探失败的产物污染主线 | 委托只给工件与验收标准 |
| 文档与代码不符时以代码为准 | 代码可能是错的实现 | 登记冲突，归属人裁 |
| 用"相关文档"这类动态描述 | agent 只能猜 | 精确路径#片段 |
| 第二份加载清单（README 里再列一遍） | 两份被取并集，各自漂移 | 只维护项目选定的唯一合同，其余入口引用它 |
| 用更大的上下文窗口代替上下文管理 | 窗口容量不解决信噪比与遵从度，只推迟观察到问题的时点（扩窗变体未必更会用输入：[C-11](参考资料/C-11-长上下文位置效应的原始出处.md)） | 按 §11 校准预算并按 §12 实测遵从度，容量变化后重验不重设 |
| 工具与技能清单只增不减 | 边界重叠使触发条件不可判定，且描述本身常驻计费 | 新增前证明不与现有项重叠；重叠即合并或补"不适用场景" |
