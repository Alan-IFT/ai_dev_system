# 03 Agent 信息获取与上下文管理

版本 1.0 · 配合 [01 项目管理标准](01-项目管理标准.md) 与 [02 项目架构描述规范](02-项目架构描述规范.md) 使用

---

## 0. 目标

让每一次推理**只看见当前判断需要的东西**，并且开工前的一切事实都能由工件回答。大型项目里 agent 变笨的主因不是模型，是三件事：一开始就把不相关的东西读进来、读了过期的东西当事实、该记住的东西没落盘于是下次重来。本文管这三件事。

---

## 1. 五条原则

1. **拉取不推送。** 入口只给地图与"何时读什么"，不把可能用到的规范塞进常驻上下文。能力描述常驻，内容命中才加载。
2. **先地图后正文，先片段后整份。** 三层：清单列的入口与当前工作项 → 当前任务明确引用的对象 → 只在调查时才读的历史与无关模块。"可能有用"不是加载理由；但给少了也有补偿成本（更多搜索、测试、修复）。分层依据是**与当前判断的相关性**，不是与当前任务的距离——任务对象本身是历史时，历史就是第一层。
3. **开工前的事实由工件回答，不由聊天回答。** 目标与非目标、工作项与状态版本、工作区身份、事实源、目标环境、验收 ID、风险与阻塞、未决项——答不出先补工件。
4. **只有一份默认加载清单。** 可按运行类型参数化出视图，视图是同一份清单的投影；出现第二份加载列表即缺陷。
5. **进出窗口的内容有存活策略。** 工具返回默认只服务当前决策，之后窗口只留结论与回源位置；大产物不以"模型完整输出"往返，写回外部的内容取自持久工件。

## 2. 信息层级：agent 找信息的标准路径

按"我要回答什么问题"选路，而不是按目录遍历：

| 我要回答 | 先看 | 再看 | 不要看 |
|---|---|---|---|
| 我这次该做什么、做到什么算完 | 当前 `WI-*` 的目标/范围/验收映射 | `acceptance/` 里被引用的那几条 | 整份验收清单；其他工作项 |
| 现在项目什么状态、有什么卡着 | `STATUS.md` | `handoff/` 最新一份（接手时） | 历史发布记录 |
| 这个模块是干什么的、边界在哪、谁依赖它 | `INDEX.md` → `modules/<m>.md` | 该模块的契约文件 | 该模块的全部源码 |
| 这个接口/事件能不能改、改了影响谁 | `contracts/README.md` 的消费者列 | 该契约文件；相关 ADR | 消费者的实现代码（先看登记，再抽查） |
| 为什么当初这样设计 | `decisions/README.md` | 对应 ADR | 聊天记录；旧版本文档 |
| 以前踩过这个坑吗 | `PLAYBOOK.md`（按触发条件） | `FAILURES.md`（按关键词） | — |
| 出了故障怎么办 | `runbooks/` | 模块文档的可观测性节 | — |
| 怎么跑、怎么测、怎么构建 | `governance/project.yaml` | — | README 里的过期命令 |
| 这个动作能不能做 | `AGENTS.md` 不可逆清单 + `GATES.md` | `exceptions.md` | — |
| 代码在哪 | `modules/<m>.md` 的入口指针；`codemap.md`（若有，注意 `source_rev`） | 定向 grep | 全仓 grep 后逐个打开 |

**路径规则**：读模块代码之前先读模块文档；改契约之前先读登记表；grep 之前先读 INDEX 与模块文档的入口指针。**文档与代码不符时登记冲突，不静默以任一方为准**（[01 §3.6](01-项目管理标准.md)）。

## 3. 默认加载合同

写在 `AGENTS.md` 的"加载"一节（示例见[示例项目 AGENTS.md](示例项目-连锁零售中台/AGENTS.md)）。

### 3.1 结构

| 顺序 | 精确路径#片段 | 交付型·从头 | 交付型·接手 | 事实型 | 用途 | 缺失时 |
|---|---|:---:|:---:|:---:|---|---|
| 1 | `AGENTS.md`（整份） | ● | ● | ● | 规则与本合同 | 停 |
| 2 | `governance/project.yaml` | ● | ● | ● | 命令与栈 | 停 |
| 3 | `docs/state/STATUS.md` | ● | ● | ○ | 当前重点与阻塞 | 停，请求恢复状态 |
| 4 | 当前工作项 `docs/state/work/WI-*.md` | ● | ● | △ 请求者给定时 | 本次目标、范围、验收、上下文清单 | 停：没有工作项不开工 |
| 5 | 最新交接 `docs/state/handoff/*` | ○ | ● | △ | 恢复凭据 | 接手无交接：先做测绘（§8.4） |
| 6 | `docs/INDEX.md` | ● | ● | ● | 地图 | 可继续，但不得猜路径 |
| 7 | 工作项上下文清单列出的对象 | ● | ● | ● | 模块文档、契约、ADR、验收条目 | 缺一项即记未定 |

● 必读　○ 不读　△ 条件读（写出条件）

**运行类型两轴**：产出类型（交付型 / 事实型）× 起点（从头 / 接手）。事实型的出口是一份带成立条件的事实，不是变更，所以不读议程类内容（STATUS 的下一优先级、其他工作项）；接手比从头多一个**空转探测集**——对每个必读项问"上次被写、上次被读是什么时候"。判不清按交付型·接手处理（最宽）。

### 3.2 解析规则

1. 路径用仓库相对 canonical path；同一 `path#片段` 只加载一次。
2. `#片段` 的外延是"该锚点起至下一个同级锚点前"，不默读到文件尾；需要跨片段逐个列出。
3. 链接不递归展开；"相关""对应""当前"这类动态描述不由 agent 猜测——工作项里必须写精确路径。
4. 合同、工作项、工作区身份（分支/HEAD）冲突时失败关闭：先核对 ID、版本、`updated_at`、HEAD，再继续。
5. 切换工作项时递增合同版本；历史版本归档不进默认上下文。
6. 视图不得增生：需要第三个视图先证明它不是已有视图的子集。

### 3.3 排除项（默认不加载）

全部规范全文；全部模块文档；`docs/历史`/已取代文档；`FAILURES.md`（只在做删减、审计、补绑定时读）；`releases/`（只在回溯时）；`artifacts/`（按引用回源）；聊天历史、旧工作项、废弃 ADR、完整日志、大段工具输出；**仅因链接可达但不在清单中的文档**。

## 4. 工作项级上下文清单

每个工作项有一节"上下文"，是合同第 7 项的内容：

```markdown
## 上下文
### 必读（精确到片段）
- docs/architecture/modules/inventory.md#公开接口
- docs/architecture/contracts/EVT-inventory-stock-changed.md
- docs/decisions/ADR-0007-库存事件契约v2.md
- docs/product/acceptance/INV-库存.md#INV-014
### 条件读
- docs/runbooks/RB-03-POS流水回传中断.md — 只在联调 POS 回传失败时
- .agents/skills/inventory-migration/SKILL.md — 动手写迁移脚本前
### 明确不读
- services/pos_gateway/**（本次不碰）
### 本次不变量（压缩后重新锚定）
- 目标与范围：…；生效决策：ADR-0007；安全边界：不写 prod；工作区：main @ a3f9c21
```

**写清单的人是开工作项的人**（人或上一次运行的 agent），清单本身是可评审对象：评审看它有没有漏掉被依赖列表里的模块。清单里每一项都要能在 `INDEX.md` 里找到——找不到说明 INDEX 过期或路径错。

## 5. 按需层：skills、模块文档、runbook 的触发

- **skills**（`.agents/skills/<name>/SKILL.md`）：`description` 常驻（一句话说清"什么时候读我"），正文命中才读。切分判据：这条规则在它该生效那一刻**必须已在上下文里**吗？是 → 进 `AGENTS.md`；否 → 进 skill。skill 可带 `scripts/` 与 `references/`，把"绑定的失败 Case"放在 `references/`。
- **模块文档**：由工作项的影响清单触发——碰哪个模块读哪份；被依赖列表里的模块读"公开接口"与"不变量"两节。
- **runbook**：由故障或联调失败触发；事故处置时是第一读。
- **PLAYBOOK**：按条目的触发条件读（每条规则写明"做 X 时"）；不整份常驻。skills 数量多时 PLAYBOOK 退化为索引，正文进 skills。

**不确定要不要读，就读**——读一份 skill 的代价远小于漏一道门。但读完在窗口里只留"读了、结论是什么"。

---

## 6. 检索纪律

- 定向检索：先从模块文档的入口指针定位目录，再在目录内 grep；不做全仓 grep 后逐个打开。
- 大输出（测试日志、grep 结果、长文件）落到 `artifacts/`，窗口只留结论 + 路径 + 行号范围。
- 读文件优先读片段（按锚点或行号）；整份读取只用于 ≤ 200 行的文件。
- 派生文档（codemap）先看 `source_rev`，落后即只作线索不作事实。
- 遇到与工作项无关但明显的问题：登记为候选工作项，不顺手修。
- 检索结果为空不是"不存在"，先确认检索本身跑起来了（N1）。

---

## 7. 工具返回外部化

- `docs/state/artifacts/<WI>/<序号>-<描述>.txt`（或项目约定的位置）；不进版本控制或只提交索引，由项目参数决定。
- 落盘后窗口只保留：一句结论、文件路径、用到的行号范围。
- 后续需要再回读该文件的**局部**，不整份重载。
- 由确定性程序在推理前采集的固定观察集（测试结果摘要、依赖检查结果）作为带时间戳的观察推送到下一步，消费后即清理，不累积。

## 8. 压缩与会话结束

**会话结束与上下文压缩是同等的、可在其前被拦截的事件。** 触发不只看窗口余量，还看行为信号：重复询问已确认的事、重复同类错误、任务阶段切换。

### 8.1 压缩/结束前

写一份交接（`docs/state/handoff/<WI>-<日期>.md`），两半：

- **叙事摘要**：目标与范围、已生效决策、工作区身份与状态版本、已完成项与证据位置、未完成原因、未解决错误、风险、**下一个原子动作**、失败尝试转成的教训（假设、证据、为何失败——原始错误轨迹随后丢弃，不进长期记忆）。
- **活动工作集引用**：正在编辑或验证的少量文件按路径列出，重建后按引用原样重载，不摘要。

### 8.2 重建后

重新核对合同、工作项状态版本、HEAD；把**本次不变量**（目标与范围、生效决策、安全边界、工作区身份）重新放到高注意力位置（工作项"上下文"节末尾那段）。压缩产物**不是**项目知识也不是长期记忆，不能自证正确——摘要里的每个结论仍是"结论 + 成立条件"。

### 8.3 交接的接收方

先核对身份与状态版本（不一致失败关闭），再核对已执行的不可逆动作清单，再把有效变化合并回工作项、递增状态版本、归档交接。**旧交接不直接覆盖工作项。**

### 8.4 无交接的接手（测绘）

先声明运行类型；把出口定为"一份带成立条件的事实"；测绘：这个项目现在有什么、哪些文件是活的（最近被写/被读）、哪些疑似空转；对疑似空转项做一次反例注入（改一处看有没有东西发现）；只补测绘判为缺失的；由**没参与测绘的一方**做一次照单加载演练；才转入交付型运行。

## 9. 子执行者与委托

### 9.1 何时委托

验证者分离总是合法（验证只需要产出物与验收标准，不需要生成过程）。其他拆分须举证：子任务相对独立、输入输出与完成条件清楚、上下文能真正隔离且隔离有收益、有独立验收、汇总者能核查来源与冲突、并行收益大于协调成本。高度耦合的取舍、同一热点的竞争修改、边界不清、没有合并验收的场景**不拆**。

### 9.2 委托合同

每次委托写下（可以很短）：

| 字段 | 内容 |
|---|---|
| 目标与完成条件 | 一句话 + 验收 ID |
| 输入工件 | 精确路径；不给历史，不给主线的推理 |
| 允许的动作 / 禁止的动作 | 只读 / 可写哪些路径；不可逆动作一律禁止 |
| 治理继承 | 是否继承 `AGENTS.md` 规则与权限边界；**未声明视为不继承，不继承者只给只读或纯输出任务** |
| 返回格式 | 结构化：`{结论, 三态, 成立条件, 证据位置, 盲区}`；自由文本不作为上游输入 |
| 预算与停机 | 轮次/时间/费用上限；三类停机条件 |

### 9.3 三类隔离原语

- **委托**：不继承历史，只回结论——独立的高输出操作默认走这里。
- **分叉试探**：继承全部历史，产物不回流主线，用完即弃——试探性方案默认走这里。
- **压缩外部化**：主线自身瘦身——§8。

### 9.4 并行纪律

并行单元只写自身局部空间；总状态（工作项、STATUS、共享入口、契约）由收口阶段的单一执行者更新；汇合时显式报告 `expected / received / missing`，不许静默少一路。被委托者的权限严格是委托者的子集；子执行者独立计费，编排成本单列——拆分本身不省钱。

## 10. 记忆与沉淀

- **候选从哪来**：交付链的状态转换（评审通过、验证完成、发布、任务失败）作为副产品提取；来源只取人的输入或可定位的观察（命令输出、日志、diff）。**模型自己的推断与输出不作候选**——它进本次运行的证据与轨迹，不进记忆。
- **候选放哪**：工作项的"候选沉淀"节。周维护时由人裁：进 PLAYBOOK（规则，带失败绑定与删除条件）、进 skills（细则）、进 FAILURES（失败）、进模块文档"已知坑"、或丢弃。
- **权威怎么来**：入池由客观信号（关联到已验收的工作项）；成为权威由归属人批准。两个动作分开。
- **工具自带的自动记忆**只当草稿本：默认关闭或限定为个人偏好；项目事实不复制进个人记忆；个人偏好进入项目会话时效力低于项目规则。
- **过期**：条目带来源版本或失效条件；范围内的源变化触发复核；零消费的条目默认退出检索但不删，被引用时恢复。
- **注入记账**：装配时记下注入了哪些条目（到达）；使用后记有帮助或误导（有用）。只报到达率视为反馈环缺失。

## 11. 预算与度量

**默认值（参数）**：入口层三份合计 ≤ 300 行；单个工作项 ≤ 150 行；交接 ≤ 60 行；skills 总数 ≤ 20；PLAYBOOK 条目 ≤ 40；默认加载集（合同 1–6 项）≤ 12k tokens。

**怎么量**：宿主的上下文视图或 token 计数；每任务按来源（系统指令、能力描述、历史、工具返回、人的输入、模型输出）× 是否重复携带（缓存/新输入/输出）× 执行单元分解——只报总量的优化提案不进评审。

**膨胀信号**：动手前已用超过窗口三成；同一文件在一个会话里被整份读两次以上；规则被违反且事后发现它在窗口里但位置靠中段；新会话第一轮就在复述历史。

**处置顺序**：先删（排除项、历史、重复副本），再移（细则进 skills、过程进 artifacts），最后才压缩。**移位只改善单次阅读量，只有删除才降总量。**

## 12. 工具落地对照

跨工具可依赖的机制只有四类：**Agent Skills 目录、外部状态存储（文件 + git）、宿主外检查器（CI 与脚本）、人工检查点**。本标准的每条要求都落在这四类上；其余（静态指令文件名、条件加载、运行时钩子、权限配置）逐工具不同，只做薄适配。

| 语义 | 通用落地 | Claude Code | Codex | Cursor |
|---|---|---|---|---|
| 常驻入口 | `AGENTS.md` 为原本 | `CLAUDE.md` 一行 `@AGENTS.md`（官方不读 `AGENTS.md`） | 读 `AGENTS.md`；**有静默截断**，末尾放金丝雀句定期验 | 未定：本标准未核对其入口文件名与截断行为，按 [02 §5.2](02-项目架构描述规范.md) 同样的登记纪律先核再写 |
| 方法库 | `.agents/skills/<name>/SKILL.md` | 读 `.claude/skills`，用符号链接指向同一目录 | 读 `.agents/skills` | 未定 |
| 压缩前外部化 | 人工纪律 + 交接文件 | `PreCompact` / `PostCompact` 钩子落盘与重锚定 | 未定 | 未定 |
| 硬边界（deny） | 宿主外：CI、仓库保护规则、CODEOWNERS | `permissions.deny`（全模式生效）；沙箱（只罩 Bash） | 权限配置 | 未定 |
| 钩子作探测不作闸门 | 钩子只写日志；闸门用权限规则与 CI | 钩子超时不阻断，官方明写"硬 allow/deny 用权限系统而非钩子" | 事件名与 Claude Code 同型 | 未定 |
| 子执行者结构化返回 | 非交互进程 + 强制 schema | `claude -p --output-format json --json-schema` | 非交互模式 | 未定 |
| 状态与证据 | 文件 + git；只追加日志 | 会话 JSONL 可投影，但 schema 无官方承诺，投影脚本做字段断言 | 同左 | 同左 |
| 自动记忆 | 关闭或限定为个人草稿 | auto memory 默认开，显式关或 `--bare` | — | 未定 |

**什么不装**（一人多会话档）：agent team 编排引擎、代码图谱服务、记忆服务、向量库、上下文管理工具——四件事在这一档全部"文件 + git + 你自己的脚本"就够；唯一要装的是 skills 目录。升级信号：出现过"重放导致不可逆副作用重复"、并行单元常态超过五个、说不清一次任务的钱花在哪个单元、出现第二个人。

**未定不是不支持**：表里的"未定"表示本标准没有核过；接入前按同一判据自己核（常驻入口是什么、有没有按需能力包目录、有没有能阻断的拦截点、权限能否被项目文件放宽），核不出的格记未定。工具的标志名与配置键会漂，项目在自己的附录里写映射并标注取得日期，本标准不维护。

## 13. 反模式

| 反模式 | 为什么坏 | 改成 |
|---|---|---|
| 入口里堆全部规则 | 规则越多每条被遵守的概率越低；中段遵从率下降 | 入口 ≤ 150 行；细则进 skills |
| 新会话先读全部文档"熟悉一下" | 动手前窗口已满；读的多数与本次无关 | 按合同与工作项清单 |
| 从聊天记录恢复状态 | 似是而非 | 从工作项与交接恢复 |
| 工具输出留在窗口里 | 每轮重复计费，注意力稀释 | 落盘，留结论与指针 |
| 摘要当事实 | 摘要不能自证 | 摘要里每个结论带成立条件，关键工件按引用重载 |
| 让 agent 自己决定记什么 | 自我强化的推断进库 | 提取绑定状态转换；人批准晋升 |
| 给子执行者整段历史 | 试探失败的产物污染主线 | 委托只给工件与验收标准 |
| 文档与代码不符时以代码为准 | 代码可能是错的实现 | 登记冲突，归属人裁 |
| 用"相关文档"这类动态描述 | agent 只能猜 | 精确路径#片段 |
| 第二份加载清单（README 里再列一遍） | 两份被取并集，各自漂移 | 只有 `AGENTS.md` 那一份 |
