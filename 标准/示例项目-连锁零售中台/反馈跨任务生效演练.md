# 反馈怎样在下一次任务中生效

**这是待执行的虚构演练，不是运行报告。** 本文的事件编号、样本及角色安排仅用于教学；所有实际结果初始为未定。它不改写示例项目的历史工作项、现行 PLAYBOOK 或授权记录。采用时将计划放入自己的工作项，绑定真实工件与环境，再由执行者和验证者分别留证。

演练依据是 [03 记忆治理](../03-Agent信息获取与上下文管理.md#memory-governance)、[03 评估](../03-Agent信息获取与上下文管理.md#context-evals)与 [01 闸门](../01-项目管理标准.md#gates)。来源取舍见 [C-19](../参考资料/C-19-CyberneticAgent反馈闭环的取舍.md)；本文不另设加载合同或通用晋升次数。

<a id="setup"></a>

## 1. 场景与准备

商品部会用宏处理导出文件。现有 [IMP-007](docs/product/acceptance/IMP-导入导出.md)、[PB-14](docs/knowledge/PLAYBOOK.md)及 [F-015](docs/knowledge/FAILURES.md) 已说明模板兼容要求。**本题的起点是已有要求再次失守**；不能把它改写成“没有规则，所以再加一条”。

教学样本只比较表头：模板为 `SKU、名称、规格、条码`，错误导出为 `SKU、名称、条码、规格`。这些列是隔离样本，不替换业务模板。表头一致只证明本项检查，不能证明文件内容、宏或整个 IMP-007 已验收。

撤销用例 T7 另在隔离副本设置模板事实条目：`MEM-TPL@1 → 模板 S1`（上述原顺序），替代版本 `MEM-TPL@2 → 模板 S2`（`SKU、条码、名称、规格`）。条目带模板来源、适用消费者和生效/失效边界；S2 未经该消费者确认前不得生效。它们是教学版本，不是本项目新增的有效记忆。**T7 撤销的是绑定 S1 的事实条目版本及其衍生内容，PB-14“匹配现用模板”的要求继续有效。**

采用项目开跑前，在工作项登记以下输入；原始文件缺失时相应验证记未定，不以模型描述补齐。

| 输入 | 本例的安排 | 实际执行前补什么 |
|---|---|---|
| 目标与范围 | 商品部导出文件的模板兼容；只在隔离目录或测试环境操作 | 验收引用、仓库/分支/HEAD、允许写入的精确路径、禁止动作 |
| 责任与授权 | Li 生成修订；Zhao 裁定业务范围与条目晋升；由另一执行者验证 | 具名责任人、现有授权记录及范围；演练人名不构成授权 |
| 来源与版本 | 当前模板、实际导出、PB-14 及其来源 | 各工件路径、版本/摘要、可见范围；敏感业务样本先脱敏 |
| 初始状态 | 从未修改的基线开始，当前任务只能使用此前存在的条目 | 规则、索引、缓存和检查器快照；预留逐条回退方式 |
| 判定与成本 | 以实际导出和模板逐列比对；记录准备、执行、复核开销 | 确认方法、预先冻结的判据、预算；回归用例与最终验证用例分开 |

规则与条目正文仍在原权威位置；本工作项只存引用、候选及变更证据。下面 A～D 是执行顺序，E 系列是本演练内的事件编号，不是项目新增的工作项或事故编号。

## 2. 从纠正到后续使用

| 阶段 | 输入与动作 | 责任及预期落点 | 需要的证据 |
|---|---|---|---|
| A：修正本次 | 任务 A 的导出列序错误，收到反馈 E-01。按已存在的 PB-14 修本次产物；核对规则是否加载、是否有执行点、检查器是否工作 | Li 更新任务 A 的产物与问题记录；归因按 01 §5.6，不先追加规则 | 原始反馈锚点、修改前后文件、模板版本、实际比对结果；有检查器时回读其执行记录 |
| A：重复提醒 | E-01a 是对同一产物、同一次缺陷的再次提醒 | 指回 E-01，保留提醒记录；不得算作新的独立复现或自动晋升依据 | 两次反馈与同一任务/产物/缺陷的对应关系 |
| B：独立复现 | 新任务 B 中另一份导出发生同类列序错误 E-02；先核实消费者和模板范围相同，再核对是否同一根因 | 证据显示原条目缺少可执行验证方式时，Li 在任务 B 候选区提出补足；已有检查器故障则转修复与回归。无法判定同类时待核查，不硬合并 | 两项任务的来源、不同产物与发生顺序、归因依据；不是只看关键词或反馈条数 |
| B：审定与更新 | 对候选做范围和反例验证，确认是否需要修改原条目；重复出现只触发审查，不自动批准 | Zhao 决定采纳、收窄或不采纳并记理由；按已有写入授权执行。采纳时修改原 PB-14 的验证方式及版本范围，同批更新其索引 | 候选验证结果、裁定记录、授权依据、逐条 diff 和可回退版本；缺任一必要条件不能声明晋升完成 |
| C：下一任务使用 | 在新任务 C 启动时按现有合同匹配 PB-14，锁定其版本；将相关教训转换为本次动作，执行后回读导出 | 执行者记录条目到达、实际使用；独立验证者裁定本项效果 | 条目引用 → 本次比对动作 → 原始返回/产物 → 判定；仅能复述规则不算使用 |
| D：反例与撤销 | 测试消费者变更、误归类、到期和撤销后的任务，见 §4 | 归属人收窄、降级或撤销条目；维护者同步索引与衍生摘要/缓存，验证者另开任务检查 | 反例来源、变更与失效处理记录、变更后新任务的实际召回及动作；旧版本残留仍可驱动动作即失败 |

仅在上述验证方式缺口成立的分支中，候选拟补：**在 PB-14 适用的导出任务中，锁定消费者确认的模板版本，并逐列核对实际输出**。若原条目与检查器已覆盖而只是执行故障，修执行链并回归，不改条目文本。不另建同义 PB 条目，不复制整个反馈表到长期记忆；未证明步骤稳定、高频前，不直接包装成技能，更不能仅写“必须检查”就宣称已有硬闸门。

任务 C 的启动记录可以短到一行：`PB-14@本次锁定版本 → 本次商品部导出 → 回读实际表头并与该模板逐列比对 → 证据入口`。这是工作项中的使用记录，不要求每项日常任务额外等待确认；授权仍按已有记录判断。

## 3. 将记录放进已有工作项

下表是一组字段示意，不要求另建数据库或新的权威台账。沿用项目已有候选、评估和证据字段，避免同一事实多处维护。

| 记录位置 | 至少能回答的问题 |
|---|---|
| 反馈原始记录 | 谁在何时针对哪个任务、产物版本说了什么？是新事件还是已有事件的再次提醒？ |
| 工作项候选区 | 人的要求或可定位观察是什么？依据和作用域是什么？原有条目为何不足？模型推断只留运行轨迹，不作为候选入池 |
| 原条目及裁定记录 | 采纳/收窄/不采纳的理由；归属人、验证状态、版本范围、复核/失效条件、授权与来源引用 |
| 后续任务证据段 | 召回了什么版本，实际改变了哪个动作，结果是否有帮助或误导；按 [01 证据六字段](../01-项目管理标准.md#session-protocol) 保存原始证据与确认方法 |
| 变更与撤销记录 | 哪个反例触发了变更，哪些索引/摘要/缓存受影响，谁处置，后续任务怎样证明旧条目不再误用 |

明确的要求按其有效范围处理，不等待“再提一次”；是否写成长效条目仍按已有候选治理与授权办理。事故级反馈立即走事故处置，不能等累计次数。两者都不能被“尚不足以推断长期偏好”拖延。

## 4. 成对演练及故障分支

采用方在隔离环境先冻结判据，再执行。下表“预期”是待检验的要求，**不是实际通过记录**。实际结果分别填通过/失败/未定，附证据；故意放入的坏样本被检查正确拒绝时，该验证用例通过，但坏产物仍不合格。

本表是公开教学用例，可用于调试；最终验证另选未用于修订的任务和样本。实际判定仍须回读工件或有人的确认，不能把模型照抄本表预期当作验证结果。

| 用例 | 输入与预期 | 失败信号 | 初始实际结果 |
|---|---|---|---|
| T1：首次明确要求 / 一次性调整 | 前者在声明范围内本次执行；“仅本次调整说明文字”不泛化为长期偏好 | 要求必须说两次才处理；或把临时要求写成永久规则 | 未定：未运行 |
| T2：重复提醒 / 独立复现 | E-01a 关联 E-01；E-02 经根因及范围核对后才能成为独立重复信号，仍需审定 | 将消息数当事件数，或达到固定次数自动晋升 | 未定：未运行 |
| T3：同词异因 / 同因同范围 | “规格不对”可能是列序错，也可能是商品匹配错；后者核对 PB-12 的范围，不归入 PB-14 | 仅凭“规格”合并反馈，导致错误规则被召回 | 未定：未运行 |
| T4：适用 / 不适用 | 商品部导出采用其模板；供应商有不同契约时使用供应商模板，不能沿用商品部列序 | 全局套用 PB-14；为少读上下文漏掉本任务契约 | 未定：未运行 |
| T5：正常检查 / 检查器停跑 | 正常样本通过、交换两列表头的样本被发现；在副本中停用检查器时运行覆盖须能显示缺口 | 停跑后仍报“零拦截，质量提高”或宣称受控 | 未定：未运行 |
| T6：误召回修复后的双向复测 | PB-14 已限定商品部，先查索引、摘要是否丢了范围或过滤是否未执行，据根因修复。分别新开供应商和商品部任务：前者不误用 PB-14，后者仍正确召回 | 只改文字未修实际路由；供应商仍误用；或商品部正常任务失去约束 | 未定：未运行 |
| T7：撤销 / 有效条目保留 | 模拟商品部确认 S1 停用、S2 生效；撤销 MEM-TPL@1 及其摘要/缓存，启用有依据的 MEM-TPL@2。新任务继续执行 PB-14，回读 S2 并验证导出列序；无关有效条目继续可用 | 旧摘要/缓存复活 S1；把 PB-14 一并撤销；仍按 S1 导出；整库回滚连带丢失无关条目 | 未定：未运行 |
| T8：证据缺失 / 可回读 | 缺原始产物或检查回执时记未定；补齐后按实际结果重判 | 把模型的“已经检查”计为通过；用未来任务的结论伪造历史经验 | 未定：未运行 |

T5 只在隔离副本中故障注入，不停用真实生产检查；没有可执行检查器时该分支记未定，并保留人工比对的实际覆盖。T7 不通过删除历史来实现撤销：先隔离旧版本及其衍生项，当前任务若已锁定 MEM-TPL@1，显式报告变化并重启受影响判断，记录转用 MEM-TPL@2/S2 的依据、版本与导出比对结果；不能静默换版本后接着宣称通过。

## 5. 怎样判断它有没有帮助

先分清三个问题：条目是否到达、到达后是否改变动作、动作是否改善结果。记录到达率或产出更多规则，均不足以回答后两项。

观察窗口和分类口径由采用项目预先登记。若计算复发率，分母是同一作用域与口径下可判定的适用任务数，分子是其中发生该类问题的任务数；未知样本另列，分母为零记不可计算。同一任务多次提醒不膨胀任务数。模板、模型、检查器或分类版本变化时分组观察，不直接比较混杂的前后总数。

对改进候选按 [03 §11.1](../03-Agent信息获取与上下文管理.md#context-evals) 做预算对等的基线/候选比较，两组都保留业务验收、安全边界与既有授权；只改变待评估的记忆或验证方式。用例至少包含适用任务与不适用任务，核对原始结果、误触发、漏检、总成本及维护开销。独立验证任务不提前暴露给修订方，次数由风险与波动决定。

**零拦截先核对检查覆盖与已知错误样本，不能直接判成改善；不采纳候选允许是正确结果，不设沉淀转化率满额目标。** 样本不足只能说明本次发生了什么，不能宣称“从此不再犯”。

完成演练后，在采用工作项中给出逐例判定、实际工件变更及未解决限制，并由验证者签明证据范围。未完成演练的维度保留未定；不因本文件写齐而把[试点通过条件](../覆盖与采用检查.md#pilot-exit)判为通过。
