# 一次任务的完整走法：WI-0142 库存事件契约 v2 迁移

下文保留初版虚构任务的过程、数值与当时规则，不构成真实执行证据。当前契约迁移应按[02 的阶段退出与恢复边界](../02-项目架构描述规范.md#contract-migration)核验；“登记为零”“回退代码”不能单独证明可清理或已恢复。当前运行工件见[演练包](docs/operations/README.md)。

高影响变更（契约破坏性 + 三个消费者 + 生产数据），2025-12-08 → 2026-02-20，跨 11 个会话、5 次发布。**每一步写清：读了什么、写了什么、谁做的、哪道门。** 工作项全文在 [WI-0142](docs/state/work/WI-0142-库存事件契约v2迁移.md)。

2025-12-02 一次急躁的尝试：直接在 v1 上加字段（F-019），两个消费者崩，回滚。**这次失败让 ADR-0007 的备选方案 1 有了实测依据**，不再是推测。

## 这条走法里，标准在哪些点上真的起了作用

| 点 | 没有它会怎样 |
|---|---|
| 验收 ID 在动手前冻结（第 1 步） | 实现者会把"每消费者只处理一次"改成"大多数情况只处理一次" |
| 工作项上下文清单被评审（第 2 步） | 漏读 `pos-gateway.md#已知坑`，死信重投被当成普通重试直接执行 |
| 三阶段各自可发布可回滚（第 3–5 步） | F-019 重演 |
| 停机条件（第 4 步 pos-gateway） | agent 硬套 `{vendor}:{ref}`，跨日撞键 |
| 生产者 ≠ 验证者（每阶段） | 自评"测过了"，盲区不写 |
| 回执对账在 staging 与 prod 都跑、且跑在宿主之外（第 4 步） | F-023 那一笔在 prod 丢失而无人知道 |
| 候选沉淀由人裁（第 6 步） | 四条全进 PLAYBOOK，其中一条一次性的永远占位 |
| 复查日写在 ADR 里（第 7 步） | 决策做完就没人再看 |
