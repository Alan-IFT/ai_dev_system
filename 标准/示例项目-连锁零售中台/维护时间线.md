这是初版示例的虚构历史叙事，不是实测结果或当前规则清单。其中固定观察时长、篇幅参数和早期“禁止改测试”等做法保留作背景；当前采用以[标准入口](../README.md)及本示例活入口为准，2026-09-08 的运行补充见[演练包](docs/operations/README.md)。

2025-03 → 2026-09。每月：发生了什么、按标准做了什么、文档树怎么变、**如果按"旧做法"会怎样**（旧做法 = 规则堆在一个大 README 里、状态靠聊天记录、没有验收 ID、没有契约登记、没有检查器——也就是让上一套系统无法维护的那套做法）。

## 从这 18 个月读出的四件事

1. **被拦住的全是检查器和停机条件，文档里的规则单独从没拦住过任何事**（FAILURES 读数）。规则的价值是让检查器有出处，不是让 agent 自觉。
2. **同一形状复发最多的是"写了、没人再看"**（F-013、F-020、F-021、F-032）。处置永远是"配一个会发信号的检查"，不是"再写一遍"。
3. **膨胀在第五个月就来了**（F-009），不是第二年。没有预算和减法，入口在半年内就会长到没人读。
4. **检查器自己坏比规则被违反更难发现**（F-026 恒 PASS 半年）。四步验收和月度反例是唯一有效的探测——"CI 是绿的"什么也不说明。
