# 检查器

每引入一个新失效面配一个检查器；每个检查器上线时做四步验收并记在这里（PB-18；F-026 是 `check_deps` 曾恒 PASS 半年的记录）。检查器自身的结构假设过期时判故障并阻断，不降级为警告。

| 脚本 | 判定什么 | 闸门 | 运行位置 | 四步验收 | 反例测试 |
|---|---|---|---|---|---|
| `check_deps.py` | 允许依赖矩阵之外的 import；跨模块写（`--writes`）；模块清单 vs 目录（`--list-modules`） | G9 | CI 每次提交 | 2025-09-12 首次（**漏了步骤 ③**）；2026-04-08 补做（F-026） | 月度：故意加一条 `reporting → inventory` ORM import，须 FAIL；最近 2026-09-01 FAIL ✓ |

## 四步验收（每个新检查器）

① 验字节（控制字符在 grep 里隐身，先 `xxd | head`）② 注入前断言待替换串存在 ③ 反例测试确认它真报 ④ 跑全仓看误伤。**任一步空输出记未定。**

月度反例（上表末列）跑在 CI 之外的 cron；反例不 FAIL 即检查器故障，当天转事故。F-026 之后加的。
