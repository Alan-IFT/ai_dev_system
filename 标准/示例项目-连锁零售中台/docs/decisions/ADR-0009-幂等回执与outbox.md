# ADR-0009：幂等回执表与 outbox 作为全部外部写的基础设施

状态：active　日期：2025-11-24　决策人：Zhao　批准人：Zhao
取代：无　被取代：无　重评条件：消息平台原生提供恰好一次语义且可回读回执

## 背景与约束

F-017（库存双扣）复盘的根因有两层：契约层无幂等键（→ ADR-0007），基础设施层**每个模块各自处理"发消息"与"写外部系统"**，有的在事务内发、有的在事务外发、没有一处记回执。事故当天无法回答"到底重复执行了哪些"。

## 备选方案

1. 各模块自己加去重——不选：14 处实现，14 种漏法。
2. 消息平台开启去重插件——不选：只管消息，管不了 POS 推送、短信这类 HTTP 外部写。
3. **platform 提供两样东西：`outbox`（事务内写、投递器异步发）与 `idempotency_receipt`（每笔外部写先写回执，含幂等键、目标、状态、回执原文）；所有模块必须经它们**——选。

## 决定与适用边界

- 任何对 RabbitMQ 的发送经 `outbox`；任何对外部系统（POS、短信、财务导出）的写经 `idempotency_receipt`：写前登记 `pending`，成功写 `done` + 回执原文，失败写 `failed` 进待补偿清单。
- 消费者按幂等键查回执表去重。
- **对账**：`check_receipts` 每日比对外部系统写入数与回执数（INV-04）；差集非空转事故。
- 重放与恢复：先读回执表，已 `done` 的跳过。

## 代价与风险

- 每笔外部写多一次 DB 写；`idempotency_receipt` 增长快，90 天归档。
- 回执表本身成为单点——它的失效探测是对账脚本跑在宿主之外（cron），不依赖应用自报。

## 验证方式

INV-04 每日对账连续 30 天差集为零（2025-12-24 达成）；INV-016 重放测试。
