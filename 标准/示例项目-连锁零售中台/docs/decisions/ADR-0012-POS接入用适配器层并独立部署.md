# ADR-0012：POS 接入用适配器层并独立部署

状态：active　日期：2025-09-01　决策人：Zhao　批准人：Zhao
取代：ADR-0011（轮询推送）；局部取代 ADR-0001（pos-gateway 独立部署那一条）　被取代：无　重评条件：第三家厂商的协议无法用现有适配器接口表达

## 背景与约束

- 首发（2025-06）只接厂商 A，推送逻辑与厂商协议混写在 `core` 里。
- 2025-08 集团并购 18 家店，用厂商 B；协议不同（回调式回传、跨日流水号重置、证书由厂商签发）。
- 厂商回调需要公网入口；`core` 此前不暴露公网。
- 营业时间 POS 链路可用性要求高于后台（99.9% vs 99.5%）。

## 备选方案

1. 在 `core` 里加 `if vendor == B`——不选：两家已经难看，三家不可维护；且把公网入口开到 `core` 违反信任边界。
2. 每家厂商一个独立服务——不选：一人维护成本；两家厂商 80% 逻辑相同。
3. **一个 `pos-gateway` 模块，内部适配器接口 `VendorAdapter`（push、pull_sales、health、identity_of_sale），每家厂商一个实现；模块作为独立部署单元，独立公网入口 + mTLS + 独立伸缩**——选。这是 ADR-0001 允许的唯一拆出条件（独立安全边界 + 独立可用性），且 `API-pos-push`/`API-pos-sales` 已有契约测试。

## 决定与适用边界

- `pos-gateway` 与 `core` 通过公开 API 与事件通信，不共享数据库事务；`pos.*` schema 归它。
- 新增厂商 = 新增一个适配器实现 + 一份 skill（`pos-adapter`）+ 契约测试；不改 `core`。
- 幂等键由适配器给出（`identity_of_sale`），因为只有它知道厂商流水号的语义（F-023 跨日重置）。

## 代价与风险

- 多一个部署单元、一套证书、一份运维；用 runbook RB-03/RB-04 补偿。
- 适配器接口一旦定了，第三家厂商可能不合——写在重评条件。

## 验证方式

POS-006（厂商 B 满足 POS-001/POS-003，差异只在适配器）：2025-10-20 验收通过，`core` 零改动。
