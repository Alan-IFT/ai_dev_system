## 一次走查

情境：POS 回传正常，库存投影发生积压；新版本准备上线，同时备份任务显示成功。依次检查：

1. 从责任卡的 SLI 确认“收到请求”和“库存已反映”是否分开；仅返回成功不能关闭事件。
2. 从发布计划找到放量前提。演示样本不足时应停在未定；不能填写虚假的线上证据。
3. 从恢复计划找业务对账。即使表恢复成功，重复库存扣减或遗漏事件仍不满足恢复判据。
4. 从风险记录查未完成项及负责人。恢复能力未测不能因为发布计划完整就被关闭。

走查检查的是工件之间能否接上；实际部署、安全扫描、容量测试和恢复演练仍需在真实项目中分别执行。
