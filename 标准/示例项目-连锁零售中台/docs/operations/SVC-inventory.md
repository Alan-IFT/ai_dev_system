# SVC-inventory · 库存运行责任卡

类型：虚构示例；设计目标待真实采用项目确认；运行验证 `UNDETERMINED`。

| 字段 | 示例内容 |
|---|---|
| 对象 | 库存变更到门店可查询库存；目标环境为示例 prod |
| 业务/决策责任 | Zhao；确认体验、风险取舍和恢复目标 |
| 运行责任 | Li；无人响应升级 Zhao；数据恢复协作 Wang |
| 架构 | [库存模块](../architecture/modules/inventory.md)、[数据所有权](../architecture/data-ownership.md)、[事件契约](../architecture/contracts/EVT-inventory-stock-changed.md) |
| SLI-INV-FRESH | 在约定时限内反映到查询视图的合法库存变更数 / 同窗口应反映的合法变更数；按门店和来源分层，排除项须先确定 |
| 演示目标 | 以 28 天为观察窗口，99% 的合法变更在 60 秒内可查询；仅示范目标表达，不是推荐阈值 |
| 测量来源 | 候选：事件接收账与投影完成账按事件 ID 对账；查询实现尚未提供，因此不能出通过结果 |
| 盲区 | 未进入接收账的上游丢失需要上游序列/对账发现；采集断档与无流量分别标注 |
| 预算动作 | 演示策略：确认体验目标不达标时暂停普通功能放量，Li 建恢复工作项；安全修复和恢复动作由 Zhao 按范围决定；稳定且补救证据核验后恢复放量 |
| 恢复目标 | 演示 RTO 2 小时：从业务中断到关键旅程及对账恢复；RPO 15 分钟：从故障点向前容许丢失的数据时间范围；未实测 |
| 操作入口 | [POS 回传手册](../runbooks/RB-03-POS流水回传中断.md)、[库存恢复计划](DR-inventory.md) |
| 变更入口 | [待执行发布计划](REL-inventory-next.md)、[维护风险](RISK-maintenance.md) |

告警演示：积压导致关键旅程持续不达标时通知 Li；无人响应按项目实际通讯和值班安排升级 Zhao。投递/应答时限待项目确认，不把这里的人名当成真实可联系的值班系统。事故处理按[04 事故响应](../../../04-可靠性安全与运行维护.md#incident-response)。
