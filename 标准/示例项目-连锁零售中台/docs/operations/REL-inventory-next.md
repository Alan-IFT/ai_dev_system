# REL-inventory-next · 库存变更渐进发布计划

状态：虚构候选计划，尚无发布授权、实际制品或线上观测。验收 `UNDETERMINED`。

## 发布前

发布负责人 Li，风险决定与运行接收 Zhao；场景为库存投影逻辑优化，不改变[现有事件契约](../architecture/contracts/EVT-inventory-stock-changed.md)。若实际变更涉及 schema 或事件语义，先转入[架构迁移流程](../../../02-项目架构描述规范.md#contract-migration)。

必填但当前未提供：工作项/验收 ID、候选与现网制品摘要、代码修订、配置差异、构建验证、受影响门店/消费者、灰度路由实现、实际操作授权、放量阈值及观察时段。缺任一适用前提不开始执行。

## 分批、观察与停止

1. 首批选择能代表本次业务路径的门店和流量，记录选择理由；无法隔离消费者时改用项目批准的替代发布方式。
2. 观察[责任卡的 SLI](SVC-inventory.md)、对账差异、积压与资源变化；比较前先核对共同数据库与队列造成的互相影响。
3. 样本不足、营业周期未覆盖或采集失效时保持未定；延长观察或补等价验证，不自动放量。
4. 达到预定停止条件，由发布负责人停止扩展并按已授权范围恢复；情况超出授权则找有权人，其他调查可继续。

## 恢复与不可逆点

回退前核对旧制品能读取当前数据及队列；关闭开关不能撤销已发出的事件或 POS 副作用。发现数据损坏时转[恢复计划](DR-inventory.md)，不能仅回退代码就声明恢复。

当前未执行任何数据收缩步骤。以后若清除旧字段/旧数据，应在消费者退出、共存验证和恢复前提满足后另行记录不可逆点及授权。发布完成后回读实际运行制品、配置和业务体验；临时开关在稳定后进入清理工作项。
