# 无交接的接手

**第一步不是建东西。** 先声明运行类型为"事实型·接手"，出口是"一份带成立条件的事实"。

## 1. 测绘（只读）

对 `AGENTS.md` 加载合同里的每一项与 `INDEX.md` 里的每一份，答两问：**上次被写是什么时候（git log -1）、上次被读是什么时候（有没有别的文件/工作项引用它、CI 有没有消费它）。** 两问都答不出的记"疑似空转"。

产出一张表：路径 / 上次写 / 上次读 / 判定（活 / 疑似空转 / 缺失）/ 依据。

## 2. 反例注入（对疑似空转项）

改一处看有没有东西发现：在疑似空转的检查器里放一个必失败的样例；在疑似没人读的文档里改一个会影响行为的值，跑一次相关任务。**没有任何东西发现 → 确认空转**，登记 F-。

## 3. 只补缺失

按 01 §3.1 的 ★ 顺序补：入口 → 验收 → 状态。不补"应该有"的，只补测绘判为缺失且当前任务需要的。

## 4. 照单演练

由**没参与测绘的一方**（另一个会话或另一个人）只按 `AGENTS.md` 合同加载，尝试回答八问。答不出的项回到 §3。

## 5. 转交付型

演练通过后开工作项，转"交付型·接手"。

## 本项目的坑

- 2026-03 新成员接手时 `.claude/rules/` 有一份旧规则副本（F-024），测绘表把它判为"活"（最近有写）但没人读——**"最近有写"不等于活**，读的一侧要单独答。
