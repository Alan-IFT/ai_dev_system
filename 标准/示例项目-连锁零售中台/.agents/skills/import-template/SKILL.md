# 导入模板与四类拆分

来源：CAT-011/012、IMP-001/002/006/007；绑 F-012、F-015、F-029。删除条件：商品部改为在系统内直接维护，不再用 Excel。

## 模板版本

- 首行 `TEMPLATE_VERSION=n`；未知版本拒绝并列出支持的版本（IMP-001）。
- 新版本 = 新文件契约版本（`contracts/FILE-新品导入模板.md` 变更历史）+ 契约测试含旧版本降级路径。
- 合并单元格读为 None：逐行报"第 N 行第 M 列为空"，不整体拒绝（F-012）。

## 四类拆分判据（`catalog.classify_row`）

1. 条码精确命中已有 SKU → 看售价/经营范围差异：有差 → **调价** 或 **编辑经营范围**（可同时）；无差 → 跳过（预览标"无变化"）。
2. 条码未命中，`item_key(名称, 规格)` 命中已有 SKU → **一品多码**（追加副条码，≤ 8，CAT-012）。
3. 都未命中 → **新品**。
4. 名称相似但规格缺失或相似度在阈值带内 → **待确认**，给出候选 SKU（IMP-006）。
5. **规格必须参与比对**（PB-12；F-029）；批内分组键与归类键必须是同一个 `item_key`（WI-0151 当前失败用例的教训）。

## 导出四份文件（IMP-007）

- 列顺序与商品部现用模板**逐列一致**（PB-14；F-015 他们的宏跑坏过）；模板样本在 `packages/contracts/files/export_samples/`。
- 附一份"待确认说明"：行号、原因、候选 SKU。
- 不写任何数据：导出只是文件；写入由用户在预览确认后提交（IMP-002 两阶段）。

## 失败重跑

只重跑 `failed` 行，用原 `import_job_id`（PB-09）。
