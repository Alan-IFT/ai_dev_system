# 项目管理标准（AI 协作开发 · 大型项目长期维护）

版本：1.0　整理日期：2026-09-07

这套标准回答一件事：**一个由人和 AI 编程工具（Claude Code、Codex、Cursor 等）共同开发的大型软件项目，怎样在十八个月、三十六个月之后仍然能被继续维护。** 它管的是"AI 参与的开发过程"，不管代码风格，不绑定任何一个工具。

## 先记住的四句话

1. **项目的真相存在于仓库里可被机器和人重新读到的工件中**，不在任何人的记忆或任何工具的聊天记录里。
2. **每类事实只有一处权威位置**；第二处是副本，副本必然漂移。
3. **每个结论都是"结论 + 成立条件"**；没跑、跑空、自己验自己，一律记未定，不折算成通过。
4. **每条规则写下时就绑定它防的失败和删掉它的条件**；只增不减是缺陷。

## 采用顺序（新项目约一天，存量项目约一周）

1. 读 01 §3 建文档树，只建三个无条件文件（入口、验收、状态）与文档地图。
2. 按 02 写系统全景、模块清单与依赖规则；契约登记表先登已有的。
3. 按 03 配工具入口与默认加载合同；第一次真实运行只用这几份文件。
4. 第一次踩坑后成对建 PLAYBOOK 与 FAILURES；第一次发现"写了没人遵守"时装第一个检查器。
5. 每季度按 01 §4.7 做一次减法。

## 与本仓库正文的关系

这套标准是本仓库正文（四平面十四部件）在"文档 + 目录 + 检查脚本"这一种载体上的一次装配，取的是今天就能装进真实项目的那一面。正文是语义依据，本标准是实现；措辞不同处以正文为准，但本标准不做逐字同步。效力零：它不阻断也不授权本仓库的任何决策。
