## 原文结论与适用限制

作者把对话式开发的瓶颈归为四点（上下文膨胀、缺业务知识、无自动化闭环、无法并行），做法是知识库工程加端到端开发工程。与 01 有关的：

- **并行的冲突治理：能事前隔离的就事前隔离，必须共享的就串行收口**。四类分别处置：普通合并冲突由拆解阶段标注每个任务预期触及的文件做事前隔离，真冲突正常解决、绝不用跳过校验的方式绕过；共享入口文件不在并行阶段修改，统一收敛到集成阶段由单个执行者处理；协议变更前置且串行，先统一改协议、生成桩代码，下游基于桩代码开发；数据库与配置变更在拆解阶段一次性前置确认，由专门执行者落地。
- **过期知识比没有知识更危险**，且失败不表现为报错。作者给的具体事故：知识库未更新，AI 调了一个老接口，整条链路都通了，但一直拿不到预期结果，排查很久才定位到调用了老接口。
- **自动生成文档与人工沉淀文档地位等同**，增量更新时把 diff 喂给模型改已有文档，并识别人工添加的业务背景与示例予以保留，以避免"每次更新都要重新补充上下文"。新鲜度检测比较两个 git hash（生成文档时记录的与仓库当前 HEAD），差异超阈值即标记过期并派发增量更新；每次生成向变更日志追加一条，严禁覆盖历史条目。
- **执行者职责隔离**：一个执行者只干一件事（评审的只评不改、验证的只诊断不改、修复的收到问题清单才动手），上下文隔离，工具按职责裁剪（审查类不给写文件权限，规划类不给发布权限），执行者之间靠结构化状态文件而非对话传递。作者给的动因是"角色频繁切换时行为不稳定——可能在开发步骤里越权改协议，也可能在审查步骤里顺手改了代码"。
- **长链路必须状态化**：进度与产出持久化到文件，主调度器读状态文件而不依赖对话记忆，流程可中断、可恢复、可观测。
- **两处方案回退**（负结果，值得记）：弃用主子 Agent 模式改由外部程序编排，原因是指令依从性不足与子执行者越界接管主链路；弃用 shell 驱动层改强类型语言，原因是生成的 shell 常有隐性语法错误且在长链路末端才抛异常。另有"严格禁用项目级记忆"一条，理由是全局记忆引入不可控的上下文串扰，破坏单个子任务的幂等性与可复现性。
- **代码质量边界**：看板这类"结果导向、容错率高、无强一致性要求"的系统适合黑盒化（其看板代码全部由对话生成、无人评审）；核心在线业务系统现阶段仍需人守住架构，理由是代码腐化快、高质量架构反哺生成质量、失去掌控后线上问题只能靠 AI 排查。

**适用限制**：单团队一次重构中的自述，无对照组、无消融、无前后对比；作者自评这套工程"仅仅处于能跑的刚起步状况"，并明确列出缺自我复盘迭代能力、缺评估体系、重度依赖某个 CLI 工具而未与工具解耦。规模数字（4 个业务域、90 多个微服务、800+ 份结构化文档）是仓库计数，只说明覆盖面，不说明效果。大量机制绑定其内部平台（需求管理、协议、发布、配置、监控各一套），不可移植。文中对某商用模型代际行为的判断（"哪怕是现在某某模型，放任迭代会很快偏离既定规范"）是使用体感，无测量，本卡不采纳。

## 缺口、采纳与不采纳

01 §4.4 要求交付负责人把需求拆为各自可评审、可验证的变更，每片说明前置关系、验收与恢复方式；**没有一处约束并行片之间的工件重叠**——按现有文字，两片可以各自"可评审、可验证"却同时改同一个共享文件或同一份契约。§4.5 已经规定了发布侧"共享迁移或无法隔离时串行"，开发侧没有对应条款。这是本篇能补的第一处。第二处：01 §3.4 的"派生"关系核对方式是"CI 重建 + diff"，**没有说派生文档里能不能有人工内容**；一旦混入，重建要么覆盖人工内容，要么使 diff 恒不为零而让人关掉这项对账，两条路都让派生核对失效。

**采纳**

- [01 §4.4](../01-项目管理标准.md#review-flow)：拆分并行片时标注每片预期触及的工件；共享工件与契约、schema、配置变更不进并行片，前置串行处理后再分发。触发条件为一个需求被拆为可并行的多片；责任角色为交付负责人；工件是拆分记录里的触及清单；失败处置是重叠无法消除时该片改串行。风险依据与失效路径：多个执行方同时改同一共享工件，后写的覆盖先写的且不产生冲突提示，或在集成时才暴露为编译失败。复查条件：该项目不再并行执行时删除本句。
- [01 §3.4](../01-项目管理标准.md#doc-tree)："派生"一行的核对方式补：派生文档不得混入人工内容；确需人工补充的另置一文件由引用关联，否则重建会覆盖它、或使对账恒不为零而被关掉（表格单元内改写，不新增行）。风险依据与失效路径如上。注意：原文的处置与此相反——它让增量生成识别并保留人工批注；本卡不采纳该处置，理由是它把"重建是否等价"这一机械判据换成了模型的识别能力，判据从确定事实退为代理指标（[M-07](M-07-人退到判据上.md)），与 01 §5.6 冲突。

**不采纳**

- 状态文件是流程唯一真相源、脱离对话窗口独立存在、可中断可恢复可观测：01 §4.1"工作项是实时状态源"、§4.2 交接、§7"状态丢失"行**已覆盖**；具体的状态文件格式与调度器读取方式属 **03**。
- 执行者职责隔离（只评不改、只诊断不改、按职责裁剪工具权限）、上下文隔离、模型可插拔：01 §4.4"生产者 ≠ 验证者"、§5.7"最小权限：agent、CI、服务各自只拿本次需要的；默认只读"、§6.1 写入角色表**已覆盖**；子执行者的委托与汇合属 **03**。
- 三层知识库、渐进式分层加载加检索替代向量检索、四种查询模式：对象是上下文获取方式，属 **03**，**落点不在 01**。
- 新鲜度检测比较记录的 git hash 与当前 HEAD、超阈值标记过期：01 §3.5 的 `source_rev`、§7"文档过期"行的 `check_docs_fresh`（`source_rev` 落后 N 次提交即报）**已覆盖**，且 01 的表述已是同一机制。本篇的价值是补了一个具体失败依据——过期知识导致的失败不表现为报错而表现为"链路全通但结果不对"，记录在此，正文不改。
- 变更日志每次追加、严禁覆盖历史条目：01 §3.2 验收条目"留痕不覆盖"与 §4.1 的转换记录**已覆盖**同一原则。
- 用接口调用量判断接口是否活跃并在文档中标注：01 §5.3"观察期无请求仅在采集可靠且覆盖使用周期时才有意义，未知消费者或缺测记未定"**已覆盖**，且 01 的表述更严——本篇未说明其调用量采集的覆盖窗口，直接据此标注废弃有漏判风险。
- "AI 负责认知，脚本负责执行""执行步骤必须脚本化"：其可检查的实质由 01 §5.6"判据是确定事实才做硬拦截"（[M-07](M-07-人退到判据上.md)）与 [M-12](M-12-输入归宿与落盘证据.md) 本轮的证据载体条款**已覆盖**；作为工程分工原则属 **03**。
- 冲突时"绝不用跳过校验的方式绕过"：01 §5.6"豁免与主动跳过留同样的记录（门、理由、范围、批准人、到期、补偿控制）"**已覆盖**。
- 需求级测试用例（方案设计阶段产出含输入输出预期的用例，验证阶段据其构造请求判断）：01 §5.2"测试从验收条目派生"与 §4.1 `in_validation` 的"从改动集派生的可观察终点"**已覆盖**。
- "看板类系统适合黑盒化、核心在线业务仍需人守架构"：其判据实质是流程强度随失败可观察性与后果可逆性变化，已由 [M-11](M-11-脚手架的到期与保值.md) 本轮采纳的 §5.5"授权范围上限由验证能力决定"与 01 §1 G8"流程按风险增减"**覆盖**，不重复采纳；"忘记代码的存在"是观点性表述，无可检查判据。
- 弃用主子执行者模式改外部程序编排、弃用 shell 驱动层改强类型语言、严格禁用项目级记忆：均属 **03** 与采用项目自己的技术决策，**落点不在 01**；但作为负结果材料有价值，见跨方向建议。
- 平台集成（需求管理、协议、发布、配置、监控）、内网网关、外部评审工具集成：**场景不适用**，绑定其内部系统。
- 全部规模数字。

## 跨方向建议（不由本执行者落地）

- 给 **03**：① 三层知识库 + 分层加载加精确检索替代向量检索的四条理由，是 03 上下文获取一节的一手实践论证；② 状态文件驱动 + 会话开始/结束/停止三个事件上的钩子（防提前停止、跨会话断点恢复、会话结束清理残留状态），与 03 的检查点与恢复直接对应；③ **两处负结果值得单列**——主子执行者模式因"指令依从性不足与子执行者越界接管主链路"被弃用，改由外部程序编排；生成的 shell 驱动层因隐性语法错误在长链路末端才抛异常被改为强类型实现；④ "严格禁用项目级记忆"及其理由（全局记忆引入上下文串扰，破坏单个子任务的幂等性与可复现性）与 03 的记忆沉淀条款存在张力，值得在 03 中给出适用边界。本卡不改 03。
- 给 **02**：① 每个服务八类自动生成文档的切分（定位与能力、接口、架构与数据流、上游依赖、存储、配置、坑点、变更日志）可与 02 的模块文档职责对照；② 协议变更前置且串行、下游基于已生成桩代码开发，是 02 契约迁移的一手实践形态。本卡不改 02。
- 给 **04**：无建议。

## 验证办法

在采用项目取近三个月并行执行过的需求，核对每片是否有触及工件清单，统计实际发生的工件重叠数与它们在哪个阶段暴露（并行中、集成时、还是运行时）。派生文档那条：列出全部标为派生的文档，检查其中是否含人工撰写段落，以及机械重建的 diff 是否长期不为零、该项对账是否已被停用。本仓库无并行执行记录，派生文档只有示例项目中的示意，上述验证**未定**（生成者与验证者同一）。
