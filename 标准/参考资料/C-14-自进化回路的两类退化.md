## 原文结论与适用限制

作者按"是否更新权重 × 是否依赖人工数据"把自进化 Agent 分三类：经验／Skill 存储型（模型冻结、经验落成可检索文件）、RL 训练型（把经验训进权重）、零数据自学型（Agent 互相出题解题）。逐篇拆解后给出三个观察：几乎所有工作把"总结／策展经验"这一步外包给冻结的大模型或闭源 API，而唯一专门训练策展者的工作显示该环节本身影响很大；第一类"看似不训练其实仍要训练数据"；"自动出题 + 训练总结者"这一象限尚无工作。作者另点出零数据路线的隐患：题目的答案是出题方自己多次采样投票产生的（作者称 sliver answer），可靠性存疑，最好有代码执行器这类客观判定。

适用限制（本轮的核心）：

1. **全部论文结果来自封闭任务域**——ALFWorld、WebShop、SWE-bench Verified、SkillsBench、OfficeQA、数学与代码 benchmark，即**存在标注答案或可执行判定器**的任务。本标准面向的是开放的、多年期的软件维护，不存在这样的 Oracle。因此本卡**只取失败模式，不取任何机制设计、不取任何效果结论**。
2. 作者对第二类与第三类的关注点在训练侧（更新权重），与本标准"模型是可替换组件、规则跨宿主通用"的立场不在同一层；本卡只把它们当作对"自动经验提取能力边界"的旁证。
3. 作者自述"评估很混乱"，各工作基准几乎无重叠、可比性差。本卡不引用任何完成率、提升幅度、条目数量与压缩比。

## 缺口、采纳与不采纳

**采纳一：自动生成的评估用例，其参考答案或判定不得与出题方同源。** 落点 [03 §11.1](../03-Agent信息获取与上下文管理.md#context-evals)。作者在三处独立点出同一隐患（第三类两篇的 PS，以及 §4.4 核心点 2）：出题方自己给出"正确答案"，解题方的得分就是在跟出题方的猜测对齐，回路会在一个未经外部证实的目标上收敛且每轮都显示提升。03 §11.1 现有的约束挡不住这一形态——"被测执行者不得修改评分器或答案"挡的是篡改，"禁止未来信息泄漏"挡的是时序，都不涉及**答案的来源**。与 03 已有机制同源：§9.4"承重结论要能追到环境锚点"讲的正是同一件事在委托链上的版本，本条是它在评估侧的落点。触发条件：用例或其期望结果由模型生成时。责任角色：任务负责人（判定来源）、维护者（用例集）。工件：用例的答案来源登记。失败处置：无法追到环境回读、程序断言或人的确认时，该组结果只作线索，不作改进依据、不进回归集。删除条件：项目全部评估用例均为人工编写或由环境直接判定时本条无对象。

**采纳二：删除与降级需要结构性触发，不依赖策展环节自觉。** 落点 [03 §10.4](../03-Agent信息获取与上下文管理.md#memory-governance)。转引 WX-20 §3 与 §4：其中一项工作在训练全程"插入为主、后期转向更新，**删除操作全程很少**"，另一项工作改用固定容量的置换（新条目入库必须挤掉旧条目），第三项工作用合并加版本号处理近似条目。三种机制不同，指向同一个可追溯风险：把"该删了"交给策展环节自行判断时，删除在实践中系统性缺席。03 §10.4 已有降级路径与零消费条目退出检索，§10.2 已有动态条目的到期降级，§13 已有"新增前证明不与现有项重叠"的入库闸——都在，但都没有说清删除由什么触发。本轮只补触发形态（复核到期、容量置换或等价的结构性约束由项目选一），不引入任何具体机制与容量数字。失败绑定：库只增不减，边界重叠使触发条件不可判定（§13 已登记）。删除条件：项目已能证明其删除动作按周期实际发生时，本句可退为提示。

**采纳三：提取与归类环节本身是评估对象，不是默认可靠的能力。** 落点 [03 §11.1](../03-Agent信息获取与上下文管理.md#context-evals) 表格"记忆与沉淀"行。转引 WX-20 §3 图 016／017 与 §4：唯一把策展者（增／改／删记忆库的角色）单列并单独评估的工作显示，**换策展方式对结果的影响可以大于换执行者**，且冻结的大模型策展未必优于小模型策展。本标准 §10.1 规定了候选来源与人裁路由，但 §11.1 的"记忆与沉淀"行只评估**召回与使用**（强／弱／背景条目、作用域相符与不符、撤销后），不评估**提取与归类本身提对了没有**。本轮只在该行的成对用例列补一项对照，不新增行、不引入策展者角色。失败绑定：归类判据存在而提取质量无人核查时，错误归类沿 §10.3 的召回路径一路进入动作依据。

**已由 C-08 覆盖，不重复采纳**：
- 回路红线（自动改进回路不得改评估集、评分器、安全边界与权限）——C-08 采纳五，已在 §11.1。本文的"出题者冻住再训解题者"等编排不另写。
- 方向性回看（逐次门控查不出累积漂移）——C-08 采纳六，已在 §11.1。本文"库从任务专属演化到元策略"属同一类观察，不重复。
- 结果按根因分路回流、挑选集与验证集分离、预算对等、新增规则须证明增量——C-08 采纳一至四，均已在 §11.1。
- 跨任务复现的模式作为记忆候选——C-08 采纳七，已在 §10.1。本文的"失败轨迹→根因→技能提案"是同一动作，不重复。
- 条目数量不是成功指标——03 §10 开头已有（本文报告某工作"只看抽出的 Skill 数量、无下游性能"，是该条的又一份佐证，不新增文字）。
- 技能／工具清单只增不减的反模式——[C-05](C-05-上下文工程范式综述.md) 采纳四，已在 §13。本轮只补触发形态（采纳二），不改该行。

**不采纳一：三大技术路线分类、三角色（出题者／解题者／总结者）框架与二维空间图。** 属论文综述的组织方式，不产生带触发条件与验收的规则；且 03 §10 已有自己的路由判据，引入第二套角色命名会造成同一事实两处定义。

**不采纳二：全部具体机制**——Pareto 前沿精英池、双环增删改查、代理验证器加权威 Oracle 两阶段、跨轨迹重组（Crossover／Transfer／Restructure）、Sequential Rollout、课程式撤回、压缩奖励。它们都绑定"存在自动 Oracle 的封闭任务域"这一前提，本标准面向的场景没有该前提；写进正文即为无依据的机制外推。其中"验证者对生成者信息隔离"与 03 §9.1"验证者分离有助于发现生成者盲区"方向一致但更强，本轮不加强——03 §9.1 已明确验证者分离不自动授权委托，加强隔离要求需要本项目自己的失败依据。

**不采纳三：训练侧的一切结论**——训练策展者优于冻结大模型、强模型 Skill 迁移到弱模型的效果、内化进权重。属模型供应商侧工作，与本标准"宿主能力按版本实测登记"（§12）不在同一层；且 WX-20 卡片已核出其中一处结论"无实验支撑"。

**不采纳四：全部数字。** 准确率、提升点数、Skill 条数增长、压缩比、迭代轮次一律不进 03 正文，也不作任何规则成立的理由；本卡引用处只说明"该文转述的观察"。

## 验证办法

- 答案同源：在评估集中放入一组"答案由模型生成、无环境判定"的用例，检查它们是否被用作改进依据或进入回归集；被采用即判失败。
- 删除触发：连续观察若干个维护周期，统计记忆库与规则库的新增／修改／删除条数；删除长期为零而条目持续增长即判为触发缺失，须补结构性触发。
- 提取质量：取同一批轨迹，由两种提取或归类方式各产出一组条目，比较它们在同一组后续任务上的召回正确性与误召回；两组差异显著而项目从未评估过提取环节，说明该环节被默认可靠。
- 以上均未在本仓库运行，本轮全部记未定。
