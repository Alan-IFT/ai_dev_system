# 逐篇资料与标准落地索引

本目录记录两轮阅读与采用及后续专项。**一张卡对应一篇文章、一份文档，或明确声明的同源关联章节组**，不是把同一个站点的多个页面当成独立研究证据。文章数量不等于证据强度；工程博客、方法说明、产品政策、机构框架和真实项目的规范原文各有边界。

每个方向按下表顺序逐篇完成"原文 → 研究卡 → 标准修改"，再继续下一篇；方向之间并行。阅读范围和未读部分在各卡中明确，本文只做索引。卡片中可回到具体落点。

**卡内出现的"标准仓 `docs/…`"是私有脚手架的路径**——原文抓取、审计记录与完善记录留在标准仓私有主干，**未随发布分发**，采用项目的 `.std/` 里没有这些文件；公开可核的出处以各卡自己登记的 URL 与访问日期为准，指向 `docs/` 的那部分按不可第三方复核处理。

## 类型与证据强度

后面几张表的"类型"列按转述层数与可核对性分档。**排在前面的不自动更可信，但转述层数越多，可核对性越低**：

| 记号 | 含义 | 能说明什么 | 不能说明什么 |
|---|---|---|---|
| 真0 | 真实项目公开出来的工程文档原文 | 该项目的规范或审计文本长什么样；其中记录的已定责缺陷是已观察失败 | 该规范是否被执行、检查是否真在跑、在别处是否有效 |
| V1 | 厂商一手 | 一手实践、产品机制、失败模式 | 独立复现、跨厂商普适性 |
| P1 | 实践报告（作者即实施方） | 该团队在其条件下做了什么、遇到什么 | 因果与可迁移性；样本常为一个团队或一个人 |
| S1 | 二手综述（转述他人） | 有哪些说法在流传 | 被转述内容的真伪——**未核对原始出处的转述不作证据** |
| 论文 | 同行评审论文，经本仓库既有阅读卡二次利用 | 论文实测范围内的效应 | 超出其任务、模型与长度的外推 |
| O1／T1 | 观点评论／技巧清单 | 基本不作规则依据：判断不是证据，操作细节是载体 | — |
| 内部 | 本仓库自己的研究或实践材料 | 本项目自己的设计选择，以及本仓库自己发生过的事 | 不得转述为外部来源的结论 |

**效果数字一律只记为"该团队在该条件下报告的观察"，不作为任何规则成立的论据，不进标准正文。**

## 二次利用与断点

标注"二次利用"的卡，实际输入是**本仓库自己写的既有阅读卡**而非原文重读，各卡的"实际阅读范围"逐条写明了这一点。本轮对其中数份做过抓取核对，**抓取工具常返回模型摘要而不是原文正文**；凡只拿到摘要的，只用于核对与收紧，不用于新增条款。以下断点保留：

- 论文卡 C-11、C-12 与指南卡 C-13 未做原文逐节通读；CoALA 的四类记忆命名未在原文核实。
- O-13 只取到摘要，故全卡无逐字引用。
- 公众号文章的图未逐张查看，按第四轮 标准仓 `docs/参考资料/11-公众号文章卡片/` 各卡的"图片信息"节转引；该节未记录的图内容一律按未读处理，未读的不采纳。
- 真实项目文档取自固定 commit 的公开快照，是**规范文本，不是该规范被执行的证据**；其公开集经过筛选与脱敏，不能据此确认其私有实现与检查的实际运行。

## 继续调研的记录方式

新资料先对照[覆盖与采用检查](../覆盖与采用检查.md)找具体问题，再选择原作者或机构材料。每卡保留原题、机构／作者、类型与转述层数、URL 或本地路径、明确发布日期或未标注、访问日期、实际阅读范围、原文结论、适用限制、采纳／不采纳及理由、标准落点、验证办法。

对于待验证的本项目推导，明确写"设计选择"，不冒充文章结论；没有新结论时只记录不采纳。写卡后即修改对应标准并检查回指，再读下一篇。原文不可访问时记录断点，不把搜索摘要写成原文阅读完成。

**本文不要求继续无限增加篇目。** 本轮的产出分布本身说明了原因：真实项目文档与厂商一手材料贡献了多数可检查条款，二手综述里有三篇整篇不采纳，观点评论零采纳，一篇论文回校的作用是**把已写进标准的表述收紧**而不是新增。后续优先级由真实项目缺口决定；当前未覆盖的领域和验证边界见[覆盖与采用检查](../覆盖与采用检查.md)。本轮集成证据以完善记录（标准仓 `docs/审计记录/本轮完善记录.md`）为入口。
