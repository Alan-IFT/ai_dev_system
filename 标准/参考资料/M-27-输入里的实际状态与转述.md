# M-27 · 输入里的实际状态与转述：本仓自己这一轮的九条观察

## 来源与阅读边界

- 对象：**本仓库自己 2026-09 这一轮的运行记录**——调度者的口述稿、执行者的报告、审核者与审计的意见、已落地的提交，以及只读关联的私有生产项目 `RCMS_FullStack`。
- 类型：**项目直接观察**（同 [M-26](M-26-多仓系统的工件分布观察.md) 那一档）。它读到的是现场当下的状态而非经筛选的发布集；同时**不可被第三方复核**——下面九条里，落在本仓 git 与磁盘上的可由拿到本仓的人重算；落在会话产物（方案与审核意见）上的，被本卡引用的那几份已归档进 `docs/审计记录/`（047–051），同样可由拿到本仓的人重算，未被引用的仍只在本机。引用时两面同时带上。
- 观察日：2026-09-10。方法：`grep` / `git log` / 逐行读文件，未改动被观察的私有项目。
- 未做：未实地触发被观察项目的任何钩子或脚本（受 [01 §5.5](../01-项目管理标准.md#controlled-actions) 授权边界约束），故凡"这个钩子会不会真跑起来"一律取自配置文本，未验证。
- 引用坐标：本卡引别的文件时锚句必给，行号只作辅助（写卡日坐标），两者冲突以锚句为准。来由是 B 组第 7 条初稿只给行号，被引的两份冻结件随后加了文件头、行号整体漂移，指针就断了。

## 观察到的事实

**共同形态**：作出判断的人拿到的是**上游对某个对象的转述**，没有去看对象本身；转述里的事实错了，判断就跟着错。九条按它绑到哪一处条款分成两组。

### 第七条是本卡自己的反例

证据 7 的原始写法出现在**本条规则自己的证据清单里**，形态与它要防的失败一模一样：作出判断（"这条证据成立"）的人只读了转述，没去看对象（`P9-审核意见.md`）。它被独立审核者去核原文时当场抓住并纠正。这一条既是本卡最强的一条依据，也是它诚实边界的一部分——**本规则不保证事实为真，它保证每条声明可被下一环重跑而当场证伪**。

### C 类 · 反向的一条，已被既有条款覆盖，本次不作新增依据

执行者报告某仓 `.git/hooks/pre-commit`"没被动过、漂移检查触发且通过"，去看那个文件发现它已被清成 5 行注释 + `exit 0`，所谓"通过"是空跑（`cat .git/hooks/pre-commit`；同目录另有 1749 字节的 `pre-commit.before-hook-purge`）。这条落在**输出侧**，[01 §4.2](../01-项目管理标准.md#session-protocol) 收工前证据六字段②"不许只写结论""证据取自落盘工件或可重读的状态变化"已完整覆盖，故本次**一字不改**，不因它再动条款。它同时是本卡形态的边界证明：一句带机制名的自核声明骗得过任何存在性检查。

## 缺口、采纳与不采纳

缺口不在"没人说过要核实"，而在**两处已经在说这件事的条款把对象写窄了**：§4.2 开工前第 3 条写的是"实际代码"对"工作项描述"，§4.4 写的是"复述上一环结论"。A 组五条与 B 组四条都落在这两句的语义之内、字面之外。

- [01 §4.2](../01-项目管理标准.md#session-protocol) 开工前第 3 条（**改写**）：对象放宽为"实际对象"对"上游对它的描述"；新增**来源标注**（自核给可复算方式／转述给来源），只由转述支撑的判断按 N1 记未定；执行点写明是开工或接手的执行者人工核。**绑定依据取自 A 组 1–5。**
- [01 §4.4](../01-项目管理标准.md#review-flow) 独立性判据那一句（**改写**）：把"复述上一环结论"放宽为"或复述上一环对对象状态的转述"，补来源标注与 N1 处置，执行点写明是评审者本人人工核。**绑定依据取自 B 组 6–9。** 这两句在改写前**正文里都没有写绑定依据**（无 M- 链接），按 N3 本就欠着一份；本次合并把欠账一并补上，[§3.7](../01-项目管理标准.md#budget) 要求的重放即上表逐条重算。
- **不新增独立条款。** 按 [§3.7](../01-项目管理标准.md#budget)"先查有没有已经说过同一件事，有就合并到那一处"，本条语义在 01 里已有三处：上面两句，加上 §4.2 收工前六字段②（输出侧，一字不改）。再开一条就是第四处同义文本，按 N2 判缺陷。
- **不写检查器。** 两条独立理由任一成立即足够：① 对象（评审记录、工作项目录）本仓今天不存在，`check_evidence` 与 `check_freshness` 现就各报一条"工作项目录不存在"的未定，加检查器只多产未定；② 唯一机械可判的形态"结论里必须给出至少一条可复算命令"是**存在性检查**，会被上面 C 类那条击穿——那份报告确实写了机制名，存在性检查照样给 PASS。做成闸门等于给假声明发通行证。
- **不采纳"承重的事实"这个判据。** 方案原稿要求"承重的事实必须来自对象本身"，"承重"把判断权交给被约束者自己，是自评自放，与 [§4.3](../01-项目管理标准.md#change-level)"执行者为 agent 时不得自评为轻量并自行放行"同型；按 [§1](../01-项目管理标准.md) G5"检查不出的原则等于没有"，写进去等于没写。改用来源标注：**"标注在不在"可判，"重不重要"不可判**，且标注是 O(事实数) 的抄写，去核是作者为把未定换成通过而自愿付的价，成本有上界——这才没有和 §4.4"人的判断带宽"那条冲突。
- **不重复**：[§4.4](../01-项目管理标准.md#review-flow) 那条"评审的输入范围须覆盖变更跨越的全部仓库与层"（来源 [M-24](M-24-三处退化叠加与内部试用构建.md)）管的是**范围**（哪几个仓在输入里），本条管的是**形态**（输入是实物还是转述），两条可以分别被违反，不合并。[§1](../01-项目管理标准.md) G4"完成需要证据"管输出侧的完成声明，本条管输入侧——B 组第 6 条正是"输入全靠转述而输出证据齐全"的形态。

## 四类出口（写进条款，不是本卡的注解）

一条"去看实物"的规则如果没有出口，会退化成"什么都要复核一遍"。写死四类：单次核不动记**未定**并写明为什么核不动（不是"不适用"——不适用是确定结论）；**人的意图、授权与验收判定不适用本条**，它们没有下一层实物可核，去"核实"一条人的决定是越权；去核不得越过 [§5.5](../01-项目管理标准.md#controlled-actions) 的授权边界，越不过的记未定；**转述已附可复算的原始证据时，读那份证据即视同已核**，不必重跑。第四类是关键——少了它，"实物／转述"的二分就没有中间档。

本卡自己撞上过第三类：A 组第 1 条那半句"本机真正会跑的是 `.ps1`"，要实地触发钩子才能核死，本次停在只读边界内，按未定处理。

第四类还有一个前提：**判据集没变**。本仓两份审计记录（`docs/审计记录/047-工具审计.md`、`docs/审计记录/049-P9审核意见.md`）附了命令与完整输出，按第四类本可"读那份证据即视同已核"；但它们钉住的检查器身份与今天现跑的不是同一个，条数与逐条结论只对产出时那一版成立——判据集身份可复算不等于结论可复算。该前提的条款文本与处置在 [01 §4.2](../01-项目管理标准.md#session-protocol) 四类出口段。据旧口径误引尚未观察到，这一条是风险预防不是失败绑定；两份记录头部的口径说明是它的对象，规则文本只在 01 §4.2 一处。

## 验证办法

取三份最近的结论产物（一份执行报告、一份评审意见、一份方案），逐条数它引用的上游事实有没有标来源，再抽两条标了"自核"的按其给的命令重跑一次，看数对不对、口径是不是同一个。抽两条标了"转述"的，看结论有没有被记成通过。**这个验收本身是人工的**，没有检查器，也不该有。

本卡的观察本身**未经这套验收**——它是发现问题的过程，不是已通过的证据。改写后的两句条款在真实评审里的收益与代价未定。
