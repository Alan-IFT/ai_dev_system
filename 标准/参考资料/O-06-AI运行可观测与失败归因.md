## 原文结论与适用限制

规模化使用编码 Agent 后，关注点从"单次结果对不对"扩展为三问：耗时花在模型推理还是工具执行、Token 集中在哪些会话与模型、失败与中断发生在哪一步且过程能否回溯（图 4）。宿主自带的轨迹视图与事件落盘作用域是**本机、单会话、实时**，能解调试问题，不能解跨会话聚合、跨机汇聚、长期留存与告警。Agent 的循环轮数与工具序列由模型在运行时决定，**执行结构在运行前无法确定**，因此按时间排列的事件序列不等于调用关系，需要还原成带父子关系与时间区间的调用树。设计取向三条：一次任务一条链路、多轮用会话 ID 横向关联；每次真实模型调用独立成条、重试不合并；流未收尾、步先于工具结束、用户中断都要补出带错误码的记录。失败定位靠每层独立状态与可自定义错误类型，区分模型侧失败、工具侧失败与循环中断。内容捕获（提示词、模型输出、工具参数与结果）默认开启、可关闭；上报队列有上限，超限丢弃最旧记录。

适用限制：**这是产品接入说明，不是踩坑实录**——正文没有任何真实故障案例、复盘或前后对比，唯一的"实践"是一次演示会话的两张截图。截图中的用量与耗时来自单一演示账号、无对照、无任务描述。五层结构、事件名、配置默认值均绑定 DSH 与该插件版本（插件支持 `>=0.1.0-rc.6 <0.2.0`，文章发布后一周即改了批量上限并修了四个上报缺陷），不能当作跨宿主的稳定接口。方案要求宿主提供事件总线与可包装的流式管道；不具备这一条件的宿主无法照搬。

## 缺口

04 原有六节全部是生产服务视角，没有一处回答"AI 这条生产线自身的一次运行失败了，靠什么定位、需要留什么才能事后重建"。[03 §11](../03-Agent信息获取与上下文管理.md#measurement) 管会话内的上下文预算与调查信号，[03 §11.1](../03-Agent信息获取与上下文管理.md#context-evals) 管离线评估的记录字段，两者都不管**已发生的真实运行**的留存、归因与访问控制；[01 §4.6](../01-项目管理标准.md) 的事故流程也不覆盖"未达事故级但无法解释的 Agent 失败"。

## 采纳

- 新增 [04 §6 AI 协作运行的可观测、可重复与运行开销](../04-可靠性安全与运行维护.md#agent-run-observability) 作为本节落点，原"可复制的运行验收记录"顺延为 §7（锚点 `operational-acceptance` 不变）。
- [04 §6.1](../04-可靠性安全与运行维护.md#agent-run-observability)：三问框架（慢在哪 / 花了多少 / 做对了吗）转为"一次运行至少要能事后回答的三件事，各自指出证据位置"。**触发**：Agent 承担会改动仓库、发布或生产的动作，或出现一次无法解释的运行失败。**责任**：工具维护者定义与保留记录，任务负责人在结论中引用。
- [04 §6.1](../04-可靠性安全与运行维护.md#agent-run-observability)：执行结构运行前不可知 → 记录不得预设固定步骤表，须带父子关系与时间区间；重试各自成条不合并；中断、超时、未收尾的调用补记错误类型。**失败依据**：只记成功路径与只记总耗时的记录，无法区分模型侧、工具/环境侧与循环中断，导致重跑成为唯一处置。
- [04 §6.1](../04-可靠性安全与运行维护.md#agent-run-observability)：本机、单会话、随会话销毁的记录不能支撑数日后的复现，属已知盲区须写明；留存位置与期限按 [§3](../04-可靠性安全与运行维护.md#recovery-data) 的数据目录登记。**失败依据**：换机器、换人、会话已关闭后无法重建当时输入。
- [04 §6.1](../04-可靠性安全与运行维护.md#agent-run-observability)：采集不得改变被观测运行的行为或使其失败；采样、限流、队列丢弃使统计静默偏低，丢弃量须可见，未采到的区间按 [§1](../04-可靠性安全与运行维护.md#service-objectives) 记未知。**失败依据**：本文自述队列超限丢弃最旧记录，且该插件在发文后一周才修复"进程退出丢最后一批"。
- [04 §6.1](../04-可靠性安全与运行维护.md#agent-run-observability)：运行记录默认含提示词、模型输出、工具参数与返回，可能带凭据、客户数据与源码；捕获开关、脱敏、访问范围与保留期由数据负责人会同安全责任人确定，第三方托管观测平台按 [§4](../04-可靠性安全与运行维护.md#security-supply-chain) 当外部依赖处理。**失败依据**：默认开启内容捕获，把这三类数据送进项目外的日志主题。

## 不采纳

- 五层 Span 层级（entry/agent/step/chat/tool）与具体属性名、事件名：绑定 DSH 的 ReAct 结构与该插件版本，不同宿主层级不同；本项目只要求"父子关系与时间区间可还原"。
- OpenTelemetry GenAI 语义约定作为强制口径：本卡未直接核验该约定文本，且文章自称"遵循"已被 WX-37 核为部分成立；只在 04 写"口径版本化、换宿主后分段标注"，不点名具体规范。
- 安装步骤、插件配置项默认值（批量条数、队列上限、刷新间隔、最大字符数）、控制台功能清单与分位数面板：产品实现细节，非标准内容，且版本敏感。
- 演示截图中的 Token 总量、单链路耗时与费用：单账号单时段、无对照，不作为任何规则的论据。
- "不插桩、不改代码、异常隔离不向宿主抛出"的实现方式：是该插件的工程选择；本项目只保留"采集不得改变或拖垮被观测运行"这一结果要求。
- 告警与仪表盘的具体指标组合：04 §1/§2 已管告警的责任与升级路径，不在 §6 重复一套。
- 文中"请使用……Skill 帮我把当前应用接入"的提示词：那是对读者工具的操作指令，不是对本项目的要求，未执行。

## 验证办法

取一次真实发生过的 Agent 失败运行，走查：能否定位到失败的那一步；能否取回该步的输入与输出；能否把失败归到模型侧、工具/环境侧、编排或循环中断之一；证据保留到何时、谁能访问。四项中任一做不到即记缺口工作项，不以"观测平台已接入"代替。另用一次被采集丢弃或采样跳过的运行确认统计中能看见丢弃量。
