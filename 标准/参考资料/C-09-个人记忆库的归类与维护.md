## 原文结论与适用限制

作者的起点是两个具体痛点：同一份个人信息要向多个 AI 工具重复讲；积累的上下文与判断经验绑在特定工具上，换工具即丢。做法是把个人记忆放在一个与工具解耦的库里，按层分目录，硬约束目录只有两级、二级目录下只放文件、内容多了用文件名前缀区分而不新建层级；区分稳定层（身份、原则）与动态层（偏好、当前上下文、知识）；归类的灰色地带用一套固定判据裁，而不是每次临时判断；每个文件带一小组元数据（类型、标题、一句话"是什么 + 何时调用"、状态、敏感度、标签、沉淀日期）；建两层索引（全库总索引收标题与一句话说明、每个目录一份 README 说明装什么不装什么），AI 先扫索引再决定读哪篇正文；用两个跨工具的 skill 分管召回与维护，维护流程是"读路由权威 → 提取候选 → 人确认 → 按路由定位 → 输出含排除理由的决策 → 人批准 → 写入并同步索引 → 每条独立提交"。作者明确说明记忆维护故意没做成全自动，每条写入前都要本人确认，理由是全自动会把临时的、不够好的判断也沉淀进去。

适用限制：单人、个人记忆场景，不是团队共享记忆，也没有多人并发写入与权限治理。没有对照实验，收益是主观体感描述。作者自己列出两处未解决：经验到技能的升级仍靠人工判断；记忆冲突与过期缺自动检测，靠被动发现。两级目录、五层分类与七个字段都是该作者按自己习惯的取舍，不是可移植结论。

## 缺口、采纳与不采纳

03 §10 本轮已按 C-07（V1 一手，团队侧）重写。本篇补个人侧与日常维护动作上的四处细节，落点均在 [03 §10](../03-Agent信息获取与上下文管理.md#memory-governance)。

**采纳一：归类判据写进唯一路由文档，灰色地带按固定判据裁。** 03 §10.1 列了候选的几个去向，但没说"同一条同时像两处时按什么裁"，也没说这套判据放哪。作者的做法（判据集中在一份路由文档、每次运行前完整读一遍、不靠记忆跳过）与 03 §1 原则 4"只有一份默认加载清单"和 §2 路径规则同构。失败依据：作者报告早期全靠人工临场判断，同类信息因约束不明确而越积越乱。

**采纳二：区分稳定条目与动态条目，动态条目带复核周期。** 作者的具体失败模式是"把易变的当前阶段状态误当成长期身份"，且他自陈过期检测目前靠被动发现。03 §10.2 有生效与失效时间、§10.4 有"源变化触发归属人复核"，都是事件触发；没有触发事件的条目就一直不被看。补一条按周期到期复核，成本低且可检查。

**采纳三：索引与条目同批更新。** 03 §4 已要求上下文清单每项能在 `INDEX.md` 找到，§10.3 已要求召回先给入口再展开细则，但没写"入口从哪来、谁维护"。作者的做法是写入条目时顺手同步总索引。落点是把"索引落后即缺陷"写进 §10.3——否则渐进召回的第一层本身不可信。

**采纳四：记忆变更逐条可回退。** 作者一条记忆一次提交，理由是可追溯、可回退。03 §10.4 有降级与撤回，但没规定回退粒度；批量写入且不能单条撤销时，一条被污染的条目只能整批回滚，会连带撤掉正确条目——这正是 03 §10 关心的记忆污染处置。

**采纳五（跨到敏感度）：个人记忆中含他人与组织信息的条目，进入共享或委托上下文前核对访问范围。** 作者的元数据里专门有一个内部／公开的标记，其最详细的实例是一份含人员、职责、汇报关系与"谁能拍板"的组织协作关系文档。03 §10.1 只写了"项目事实不复制进个人记忆"，没写反方向：个人记忆里的组织与人员信息被带进项目会话或子执行者上下文时，同样受 §6.1 的数据可见范围与 §6.2 的脱敏约束。

**不采纳一：五层分类（身份／原则／偏好／上下文／知识）与二级目录划分。** 03 §2 与 §5 已按"回答什么问题"给了信息层级与按需触发，引入第二套分类违反单一权威；且该分类绑定个人场景。

**不采纳二："有且只有两级目录"的硬约束。** 理由有二：这是单人偏好的取舍，无对照证据；03 的一贯口径是采用项目映射到自己既有的权威载体，不规定目录深度。其背后可采的意思（层级深会增加定位成本）已由 03 §2 的"按问题选路而不是按目录遍历"表达。

**不采纳三：七字段元数据清单。** 与 03 §10.2 的四类组成（抽象／证据／作用域／验证状态）重叠，且缺证据与验证状态两项。只取其中 03 缺的敏感度方向（见采纳五），不搬字段表。

**不采纳四：五级权重与"目录决定权重"的裁决方式。** 03 §10.3 已按置信分级（强／弱／背景），判据是作用域匹配与验证证据；按目录赋权是位置决定可信度，与 03 "结论 + 成立条件"的口径冲突。冲突裁决 03 §10.4 已规定按作用域与版本，仍冲突交归属人。

**不采纳五：两个 skill 的具体实现与运行记录、公共基线同步到各工具全局配置的做法。** 属工具实现；"同步到各工具全局配置"还会产生多份副本，与 03 §1 原则 4 冲突，采用项目须自行处理副本漂移。

**跨方向建议：** 无新增。个人记忆与项目记忆的归属、审批与提交粒度若要成为组织约定，属 01 的周期维护范畴，本卡不改 01。

## 验证办法

- 归类判据：取若干条同时像两处的条目，两个人（或两次独立运行）分别按路由文档归类，结果不一致即判据不足，须补判据而非逐次临时裁。
- 周期复核：检查动态类条目的最近复核时间是否都在登记周期内；存在长期未复核且无失效标记的条目即失败。
- 索引一致性：比对索引条目与实际文件集合，缺项或多项即缺陷；写入条目而未同步索引的那一次变更判失败。
- 回退粒度：撤销一条已写入的记忆，检查是否会连带撤掉同批的其他条目；会则回退粒度不足。
- 敏感度：在一次委托中检索子执行者上下文里是否出现未经核对的他人或组织信息；出现即按 §6.2 处置。
