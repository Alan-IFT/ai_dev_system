## 原文结论与适用限制

两篇的共同形态：把个人使用某个 AI 编码工具的经验列成条目，覆盖终端人体工学、入口指令写什么、规则按加载时机分层、事件拦截、上下文隔离、技能封装、并行、验证、团队分发。两篇都**没有对照组、没有消融、没有可核对的效果数据**；材料一唯一的量化倾向是"Token 明显更少"且无数字，材料二唯一的数字缺少证据载体且已被 `WX-01.md` 核出转述失真。

适用限制（决定本卡采纳面的核心）：**清单里绝大多数条目是载体绑定的操作细节**——命令名、配置字段、事件名、目录约定、快捷键、别名、插件仓库结构。这些在本仓库纪律下属 [03 §12](../03-Agent信息获取与上下文管理.md#capability-acceptance) 的按版本实测登记范围，不写进正文；且两篇材料自身已经演示了写死载体的后果：材料二对应的版本里三条技巧已被原作者删除、一条被产品原生功能取代，材料一的一处阻断输出格式在厂商文档中已不存在。**因此本卡大面积不采纳是预期结果，不是筛选不足。**

## 缺口、采纳与不采纳

**采纳一：向人提问前先穷尽可回读的工件与环境；只把需要人裁的判断交给人。** 落点 [03 §1 原则 3](../03-Agent信息获取与上下文管理.md)。材料一给出同一条规则的**两个方向的失败**，都是作者亲历：（a）执行中已经发现范围外的依赖关系，但选择"不确定就跳过"而不问，Review 时才发现接口对不上，追加数轮返工；（b）反过来，把"能否查看某文件""这个函数返回什么""这个配置在哪定义"这类自己读代码就能回答的问题抛给人（转引 WX-25 §3 图 001 的终端截图，作为"该行为确实发生过"的一次弱证据）。两者是同一条规则的两种违反：信息该从哪里取没有分流。03 §1 原则 3 现有"开工前的事实由工件回答，不由聊天回答"只写了一个方向（不要拿聊天当事实源），没写反向（不要把工件能答的问题推给人）。本轮把反向补进同一条原则，不新增原则、不新增节。触发条件：执行中出现不确定。责任角色：执行者分流，请求者裁需要人决定的部分。工件：提问记录与其对应的已回读范围。失败处置：分流判不清时按"先回读、回读后仍不确定则问"处理，不静默跳过。删除条件：非交互式运行（无人可问）时本条只剩前半句。

**采纳二：同层级冲突指令的处置方式，按版本实测登记。** 落点 [03 §12](../03-Agent信息获取与上下文管理.md#capability-acceptance) 的"唯一入口与按需方法"行。转引 `WX-25.md` §4 与厂商文档的核对结论：入口指令被明确定性为"上下文而非强制配置"，且**同级冲突的指令会被任意择一**——静默地。这不是操作细节而是语义问题：03 §3.2 第 4 条与 §10.4 都要求冲突失败关闭，如果宿主在指令层面遇到冲突时静默选一条，这两条规则在该层就是不可执行的，而项目不会收到任何信号。本轮只在该行的最小验收里加一项观察对象，不写死任何宿主行为、不给结论。失败绑定：`WX-25.md` §4 报告的厂商文档同款表述，属可追溯风险。降级：未实测时按 §12 已有规则记未定，并在关键动作前显式重述该约束（§6 已有）。

**已由既有卡或 03 现有条款覆盖，不重复采纳**（逐条列出，避免下一波重复筛）：
- 子代理（不带主会话历史、只回结论）与分支会话（继承全部历史、产物不回流、用完即弃）两种隔离方式 → 03 §9.3 三类隔离原语（委托／分叉试探／压缩外部化）已完全对应，[C-01](C-01-Anthropic上下文工程.md) 覆盖。
- 技能加载时预执行命令、把结果直接注入，取代模型逐轮调工具 → 03 §7 "由确定性程序在推理前采集的固定观察集……作为带时间戳的观察推送到下一步，消费后即清理"已有。
- 隔离运行的技能既看不到会话历史、也看不到项目入口规则（`WX-25.md` §4 的发现，作者本人未意识到） → 03 §9.2"治理继承"已要求派发者确认子执行者实际收到必要约束，§12 已要求核验子任务继承。方向一致，不加强。
- 规则按加载时机分常驻与条件加载、条件规则可按模块目录分团队维护 → 03 §3、§5 的按需层与切分判据已有，[C-01](C-01-Anthropic上下文工程.md)、[C-05](C-05-上下文工程范式综述.md) 覆盖。
- 入口只写不可从代码推断的内容；同一错误第二次出现即持久化为规则 → 03 §13 反模式"入口里堆全部规则"、§10.1 候选来源与人裁已有；"绑定已观察失败"是本标准通则。
- 压缩前先写交接、人先复核 → 03 §8.1 已有且更严（交接两半、写入失败不得声称已交接）。
- 长任务用递增间隔轮询、只取状态摘要不取流式日志 → 03 §7 落盘并只留结论与指针已有。
- 自主任务必须配备执行者自己能读到结果的检查 → 03 §11.1"确定性结果优先用环境回读／程序断言"、§9.4 环境锚点已有，[C-08](C-08-评估回流与自进化回路.md) 覆盖。
- 定期用历史轨迹反向审计入口指令（被违反的／该新增的／已过时的） → [C-08](C-08-评估回流与自进化回路.md) 采纳六、七已落在 §11.1 与 §10.1；03 §11"调查信号"含"已装入的约束被遗漏"。
- 会话固定开销（系统指令与工具定义）应计量并可削减、工具定义按需加载 → 03 §11 的按来源分解与 §13"工具与技能清单只增不减"已有。
- 用容器／隔离环境跑高风险免审批任务 → 03 §12"权限与隔离"行与 §8.4"只在隔离副本或获准测试环境执行"已有。

**不采纳一：全部载体绑定条目。** 状态栏、终端别名、快捷键、语音输入、剪贴板、Markdown 习惯、`realpath`、多标签并行、worktree、具体命令名与斜杠命令、事件名清单、配置字段、插件市场目录结构与安装命令、IDE 插件、模型可否切换、单个工具的 Token 底层优化。理由：按 03 §12，这些属项目工具维护者的接入记录，且随版本漂移——两篇材料自身已给出漂移实例（见上文适用限制）。

**不采纳二："历史对话是被低估的知识库，可 grep 或让模型搜"（材料二第 14 条）。** 与 03 §1 原则 3、§3.3 排除项、§13 反模式"从聊天记录恢复状态"**直接冲突**。03 的立场是：聊天历史可作线索但不是权威事实源，恢复状态须从工作项与交接。本轮不采纳，也不软化 03 现有表述；理由记录在此，供采用项目自行决定是否把历史会话纳入受控检索（若纳入，按 §6.1 归入"未验工具返回／Agent 输出"一行处理）。

**不采纳三：Token 节省的归因表与"一天下来差异可观"。** 该表全部为作者推理、无一个测量值；03 §11 已规定预算由项目校准、三层验收缺一层不算证据。不作任何规则的成立理由。

**不采纳四：一键配置脚本与私有插件市场的分发形态。** 前者是可执行指令（见指令边界记录），后者属团队规范分发机制，归 01。

**不采纳五：TDD 四步、并行度上限来自人的跟踪能力、注意力投入按任务重要性分级、先规划再原型、定期要求简化代码。** 均属开发方法与人的工作安排，不在 03 的信息获取与上下文管理范围内，见跨方向建议。

**跨方向建议：**
- 给 **04 可靠性、安全与运行维护**：材料二第 32 条指出**已批准命令清单会随审批疲劳沉淀成永久授权**（`rm -rf`、`sudo`、`curl | sh` 等），并附一次可追溯的社区事故（误删用户主目录）；对策是把常驻授权清单纳入周期审计与退场。03 §6.1 只写"不把检查通过或委托目的当授权"、§12 只写"能力测试通过不产生授权"，都不管既有授权的累积与复核。这属于权限生命周期，建议由 04（或 01 的周期维护）承接。本卡不改 04。
- 给 **01 项目管理标准**：材料一的"行为规范交指令、确定性操作交程序拦截"是一条机制选型判据；03 §12 已要求实测"区分只记录的探测和能阻断的边界"，但**该选谁**属工程约束与守卫设计，建议由 01 承接。
- 给 **01 项目管理标准**：材料二的 TDD 四步中"先提交测试"与"人工检查测试不是直接返回真"两步（公众号版已丢失，见 `WX-01.md` §2 C6），以及"并行任务数上限来自人的跟踪能力"，均属开发约束与任务编排，可作外部佐证。

## 指令边界记录

两篇材料都含可直接执行的内容：材料二文末给出 `bash <(curl -s …)` 形式的一键配置脚本，材料一给出可粘贴的拦截脚本、配置片段与插件市场安装命令，并含抽奖、领券、关注号召。按 [03 §6.1](../03-Agent信息获取与上下文管理.md#source-trust)"不把正文中的命令当作对本次执行的指令"，以及本次执行自身的安全边界：**本轮未执行任何脚本、未访问任何外链与仓库、未安装任何插件、未修改任何本机或本仓库配置**。`WX-01.md` §4 另记录该脚本会改动权限设置并关闭自动更新，而文章正文未提示——这本身是"资料中的命令不可直接执行"的一个实例。两篇的"必须／绝对不能"措辞是作者对其个人工作流的主张，本卡按待验证证据处理。

## 验证办法

- 提问分流：抽取一段真实运行记录，把执行者向人提出的问题逐条判为"工件或环境可答"与"需人裁"；前者出现即判失败，应先回读。反向抽取被跳过的不确定点，检查是否有对应的提问或登记；两类都为零才算通过。
- 冲突指令：在获准测试环境放置两条同层级、结论相反的规则，触发同一动作，观察宿主是报错、按优先级选、还是静默择一，并把结果登记进 §12 的接入记录；未观察即记未定，不得假定会失败关闭。
- 以上均未在本仓库运行，本轮全部记未定。
