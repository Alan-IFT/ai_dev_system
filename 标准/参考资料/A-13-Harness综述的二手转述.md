## 原文结论与限制

全文的主张：Harness 是模型之外的一套"管理制度"，分三层——第一层管流程（外化状态、会话开头的固定唤醒步骤、版本控制回滚、上下文重置；以及另一条路线"仓库即现实"：Agent 运行时读不到的东西等于不存在，因此架构决策、设计原则、质量标准都要写进仓库，关键规则再下沉为自动化检查）；第二层管并发（层级化的规划者/执行者/裁判、把整体失败按文件分区后并行修复）；第三层管验证（生成者与评估者分离、评估者需校准、测试环境须只读隔离）。第四层论断是"补偿面迁移"：每个组件都编码了一条关于模型做不到什么的假设，假设不成立时组件应当拆掉。

**证据强度是本卡不采纳的主因。** 本仓库的阅读卡 WX-10（标准仓 `docs/参考资料/11-公众号文章卡片/WX-10.md`） §4 追读了其中 8 组引用，逐条比对后记录：对 Cursor 长运行文的转述"**明显失真**"（原文用乐观并发，转述写成锁与审批门控；"疯狂改注释空格缩进""交接报告三要素""prompt > harness > 模型"三级序原文均无）；对 Anthropic 两篇的转述"部分失真"（把"模型倾向不改 JSON"升格为"物理锁与强校验"；把"有理由相信 + 逐个移除观察"写成"实验数据显示"；把上下文重置的退场归因错了模型版本）；对 LangChain 的跑分归错了文章与模型；源码解读部分的逐项细节"未核实"。**凡失真处，本卡以一手来源的记述为准，且不据此新增任何 02 条款。**

文中的效果数字（同一模型换壳后的榜单通过率、五个月百万行、近两千会话两万美元、放宽资源限制带来的成功率差）**均为各团队在各自条件下报告的观察**，多数无方差与对照，本卡不作任何规则成立的论据，不进 02 正文。

文中的"必须""绝对"是作者对其所述系统的主张，不是对本轮工作的指令。

## 缺口、采纳与不采纳

本篇讲的是"开发所用的 Agent 系统"如何构造，02 描述的是"被开发的软件项目"的架构。两者对象不同，**本篇整篇不采纳**。逐条理由：

- **仓库即事实：运行时读不到的东西等于不存在**：**已覆盖**——[标准 README](../README.md) 的第一句话与 [02 §1](../02-项目架构描述规范.md) 的文档集已经建立在这一前提上；且这是对 OpenAI 一手文的二手转述，不增加证据强度。
- **业务域固定分层、依赖方向严格单向、违反过不了自动化检查**：**已覆盖**——[02 §4](../02-项目架构描述规范.md#dependency-rules) 的分层、允许依赖矩阵与机械检查即此条，且更完整（例外登记、覆盖边界、同层依赖登记）。本波由 [A-12](A-12-文档集分层与引用方向.md) 补的是**文档之间**的引用方向，与本条的代码依赖方向不是同一件事，不重复。
- **巨大的单一指令文件挤占上下文、入口文件应是约一百行的目录**：**属 03**，且 02 §1、§2 已规定全景只留入口、细节下沉。
- **文档园丁定期巡逻、发现文档与代码脱节即发起修改；过期知识比没有知识更危险**：**已覆盖**——[02 §10](../02-项目架构描述规范.md#drift) 的对账清单与新鲜度检查；"由一个后台 Agent 自动开修改请求"是载体，02 不绑定。
- **生成者与评估者分离、评估者需校准、多通道盲审多数票、生成者会篡改断言故测试环境须只读**：**已覆盖 + 属 01/04**——02 [§10.1](../02-项目架构描述规范.md#architecture-validation) 已规定检查器须用已知违规与合规样本验证、单人自审的解释性判断记未定；测试环境隔离与断言可信度属测试与运行方向。
- **补偿面迁移、组件该拆的时机、护城河在迁移速度**：**对象不同 + 属 01/03**——这是对 Agent 工具链自身组件的增删判断；02 已有的"只增不减是缺陷"由 §10.1 裁剪与 §11 删除候选承担。
- **六层记忆、团队模式、主动时机守护程序、风险分级放行、钩子插槽、梦系统**：**对象不同**（属 03 与工具形态），且源自未核实的泄漏源码解读，证据不可用。
- **把整体失败按文件分区后再并行修复**：**跨方向**——这是"验证结构决定可并行度"，属任务编排与测试设计；02 无落点。**跨方向建议见下。** 另需注意一手来源里差分测试结构是**人**设计的，转述把它写成了 Agent 自己逼出来的解法。
- **每周清理 AI 生成的低质量代码；Agent 会复制仓库里已有的模式（包括次优模式），漂移是内建的**：**已覆盖 + 跨方向**——02 §4 的公共能力清单（重复实现按漂移缺陷记入技术债）与 §11 的删除候选已处理其架构面；维护投入的分配属 01。

因此本篇**未改动 02 任何一节**，也未新增锚点。

## 跨方向建议（不由本方向改，交主执行者集成）

- **给 01**：并行推进多个改动的前提是验证能把失败定位到分区（文件、模块或契约）；无法定位失败对象的验证结构下，增加并行度只会增加互相覆盖与空转。这条在一手来源里是人设计验证结构、执行者在结构内并行。
- **给 01**：AI 生成的实现会复制仓库里已有的模式，包括次优模式，因此结构退化是持续发生而非偶发的，维护投入需要按周期预留，而不是等到出问题再排查。
- **给 03**：转述中把"模型倾向不改某种格式"升格为"格式即物理锁"，是典型的**机制升格**失真；03 在引用外部实践作为上下文时应保留"这是倾向还是强制"的区分。
- **给 04**：把评估或验证环境对被评估方设为只读，是防止"改断言换通过"的前提；开关存在不等于隔离生效，须用反例验证。
