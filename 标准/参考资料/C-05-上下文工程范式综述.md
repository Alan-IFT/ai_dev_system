## 原文结论与适用限制

主张把"上下文"扩展为模型生成前看到的全部内容（系统指令、用户提示、状态与历史、长期记忆、检索信息、工具定义、输出格式七类），并主动策展而非堆砌。给出三条它称为"物理约束"的现象：位置效应（关键内容夹在中段时被使用的概率下降）、上下文腐化（长任务中早期约束被稀释，表现为规则漂移而非崩溃）、注意力预算（自注意力的二次代价）。工程对策为即时检索与渐进式披露、压缩、结构化外部笔记、子 Agent 隔离；反模式为"更多上下文更安全""工具越多越好""系统提示越详细越可靠""不清理工具返回""用大窗口代替上下文管理"。

适用限制：全篇是综述与教学，不含作者自己的对照实验；被引的 U 型曲线、腐化线性下降、Token 估算全部来自转述，模型与年份都较旧，本卡未核对。文中"70%～80% 触发压缩""保留最近 5 个文件""2～5 个示例"等数字是对特定产品与场景的描述，不构成跨宿主阈值。代码示例是教学玩具（按字符数除以 4 估算 Token），不可作为实现依据。

## 缺口、采纳与不采纳

**采纳一：工具与技能清单的职责边界。** 03 此前只要求 skill 简介"可发现"，没有规则处理简介之间边界重叠——重叠时触发条件不可判定，装配者与模型都无法确定该读哪一份。落点 [03 §5](../03-Agent信息获取与上下文管理.md#on-demand)。失败依据：文中把"功能重叠的工具集导致选择错误率上升"列为已观察反模式（S1，属可追溯风险而非本项目已观察失败），本仓库 `.agents/skills` 目录形态同样会出现该风险。

**采纳二：检索结果的取舍与截断纪律。** 03 §6 有"定向检索"，但没有规定"检索命中多条时怎么办"。文中的"检索到不相关内容比没有检索更糟"与 03 §1 原则 2 同向，可以把它落成一条可检查的动作：按相关性排序取舍并写下取舍理由，不把整批命中注入。落点 [03 §6](../03-Agent信息获取与上下文管理.md#retrieval)。

**采纳三：承重约束的位置按版本实测。** 位置效应本身未核对，但它指向一个 03 已有的机制——§12 的"含头／中／尾不同约束的正反任务均需观察"。本轮只在 §6 加一句把"位置"明确为需要按采用版本登记的变量，不写死"放开头或结尾"这类做法。落点 [03 §6](../03-Agent信息获取与上下文管理.md#retrieval)、[§12](../03-Agent信息获取与上下文管理.md#capability-acceptance)（已有条目，不改）。

**采纳四：两条反模式。** "用更大的上下文窗口代替上下文管理"与"工具／技能清单只增不减"进 [03 §13](../03-Agent信息获取与上下文管理.md) 反模式表。

**不采纳一：七类要素的分类框架。** 03 §11 已有按来源（系统指令、能力描述、历史、工具返回、人的输入、模型输出）× 是否重复携带的分解，与七类要素是同一件事的两种切法。引入第二套分类会造成同一事实两处定义，违反单一权威。

**不采纳二：CoALA 的情节／语义／程序记忆三分。** 该三分来自未核对的论文，且 03 §10 的分类判据是"候选从哪来、谁批准、何时失效"，是可检查的；认知科学分类不产生新的可检查动作。

**不采纳三：全部数字与阈值。** 压缩触发比例、Token 估算、正确率、示例条数、保留文件数一律不进正文，也不作为任何规则成立的理由。文中所有效果表述只作"该作者转述的观察"。

**不采纳四：Context Engineering ⊇ ReAct ⊇ Prompt Engineering 的范式演进叙事、LLM OS 类比、与 Harness 四组件的映射。** 属论述与类比，不产生带触发条件和验收的规则。

**不采纳五：Goldilocks Zone（系统指令粒度适中）。** 03 §13 已有"入口里堆全部规则"及其改法，§5 已有"必须已在上下文里吗"的切分判据，重复。

**跨方向建议：** 无。本篇未产生属于 01／02／04 的结论。

## 验证办法

- 技能／工具边界：取现有 skill 与工具简介两两比对，构造一批只有唯一正确选择的任务，记录选错与不触发的次数；出现同一任务落到两份简介都"看起来适用"时判失败，须合并或补"不适用场景"。本轮未运行该测试，记未定。
- 检索取舍：同一问题分别注入"仅最相关命中"与"全部命中"，比较结论正确性、回源次数与总成本，并检查取舍理由是否写下。基线数据本仓库尚无，记未定。
- 位置：按 §12 已有条目，在采用版本上用头／中／尾三种放置跑同一组正反任务，登记实测结果，不预设结论。
